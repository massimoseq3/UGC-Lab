# CLAUDE.md — UGC OS

## Project Identity

You are building **UGC OS** — a browser-based, macOS-style workspace that unifies eight tools for UGC ad production into one environment with shared data banks. Every in-app AI call goes through **kie.ai**: one user-supplied Bearer key gives access to every model the app uses (chat, vision, image, video, TTS, music). The one exception is **Edit**, which generates nothing in the browser — it hands out a Claude skill the member runs locally.

**Who it's for / why.** A private Skool community of solo creators and small teams producing AI UGC ads at scale — access is gated by an email allowlist synced from Skool, so non-members can't sign up even with the URL. The pitch is one workspace instead of seven tabs: the same product, character, script, voice, and B-Roll flow across every app via the shared banks. Inference cost is on the member (BYO kie.ai key), so the operator only pays for hosting + storage.

Dock order: **Dashboard** (own 'system' group) | **Bank** | **the Create apps** (Characters → Scripts → Voiceovers → B-Roll → Playground → **Edit**, which closes the row — cut what you produced; Playground sits beside B-Roll because it's the other place footage gets made, so it belongs next to it rather than a divider away with the research tools) | **Tools** (Outliers → Ad Analyzer, in that order because the loop runs left to right: find a winning ad, then tear it down) | Settings utility tile. The dock groups **by `category`**, so moving an app between rows means changing that field, not just its array position — and `category` is also what splits Meet the Team into its Create pipeline and its on-call group, so the `TEAM` entry moves with it. Fresh visits land on the Dashboard (`DEFAULT_SLUG`). Display names are terse nouns, not action verbs. Folder names and the `id` strings in `src/utils/constants.ts` are **stable** — they key per-app model selections in localStorage. Do not rename them.

## Core Rules

**Code philosophy.** Simple > clever. Obvious > terse. Components small and single-purpose. No premature optimisation. Comments explain *why*, not *what*.

**Architecture.**
- **Self-contained apps.** Each app under `src/apps/<name>/` owns its types, components, and service. Cross-app communication goes through the bank store (persistent) or the inter-app payload (one-shot handoffs).
- **No prop drilling.** Zustand stores for global state; local React state for ephemeral UI.
- **Model registry is the single source of truth.** Add or change a model only by editing `src/utils/models.ts`. Don't sprinkle slugs through service files.

**Styling.** Tailwind only. Per-app accent palettes are custom Tailwind families (`influencers-*`, `scripts-*`, `voice-*`, `broll-*`, `playground-*`) defined in the `@theme` block of `index.css` (Ad Analyzer uses literal `#FF5257`); the matching hexes for sidebar/bank chrome live in `constants.ts`. Change an accent there, not by sprinkling new color classes. Tracking-tight text. Transitions 200–300 ms for panels, 150 ms for hover. Tags use `TAG_STYLES` from `models.ts` (Recommended green / New fuchsia / Fast sky / Cheap zinc). **Single-line inputs, select-style triggers, chips, and buttons are fully rounded (`rounded-full`), not rectangles** — Massimo's preferred aesthetic; multi-line textareas use `rounded-2xl`.

**Shared UI idioms.** Reach for these instead of re-implementing — each one had drifted into 3–4 near-identical copies before it was extracted:
- `components/VideoLightbox.tsx` — the full-screen clip view: the video large on the left, its **first / last frame** grabbed out of the file on the right (save either to the B-Rolls bank as a reusable start frame, or download it), then the prompt and Copy prompt / Download Video. Grew out of the Playground preview modal, which still renders its `VideoFrameActions` half. Every B-Roll video tile reaches it through `ExpandVideoButton` (`chrome='stack'` inside a `TileActionStack`, `'plain'` on the Continuous take gallery's bespoke overlay row), which owns its own open state and portals the overlay to the body.
- `components/tileActions.tsx` — the hover action column on every generated media tile. `TileActionStack` + `TileActionButton` + `TileStarButton` + `TileDeleteButton`, in the order **[Star] → Download → Save → Copy → extras → Delete**. 32px circles, `bg-black/55`, no backdrop-blur (it stutters under the opacity fade).
- `TileDeleteButton` is the **only** delete idiom: two-click, arms into a red "Confirm" pill, reverts after 3s. Never a confirm modal. `variant='chrome'` for panel surfaces, `size='sm'` for compact history rows.
- `components/GeneratingMedia.tsx` — the one "this is generating" face. `GeneratingMediaFill` drops into any `relative overflow-hidden` frame (a card face); `PendingMedia` is the standalone aspect-sized tile for gallery grids. A card mid-generation and that same generation inside its detail modal must look identical, so both render this: blob backdrop (`GeneratingBackdrop`), mode glyph top-left, model name, rotating status line (same size + accent tint as the model name — never a dim grey), prompt fading out along the bottom. Status-line copy lives in `components/generatingMessages.ts`.
- `components/GeneratingChip.tsx` — `GeneratingChip` (pulsing accent dot + label) and `GeneratingPulseRing` (thumbnail overlay) mark a **history row** whose work is still running. **History is the queue view**: fire a batch, switch away, and the list keeps reporting progress. Wired in the Ad Analyzer rail (its own literal-hex copy), B-Roll History (counts tallied from each row's snapshotted in-flight queues, TTL-swept at 30 min), Voiceovers History (an "In progress" section above the finished rows), and Playground / Influencers galleries (their own in-flight tiles).
- **Generate buttons never disable while a generation is in flight.** Every media surface queues gens in parallel; the in-flight tile is the feedback, not a locked button or a spinner swapped into the label. Guard duplicate fires of the *same* card with a `startingRef`-style set, not by disabling. The only legitimate blocks are structural (Continuous' sequential keyframe chain, nothing to generate yet).
- `components/GridCanvas.tsx` — the graph-paper canvas an **output** panel works on (Characters' Single view, Scripts' Output tab, B-Roll's storyboard): a static, deliberately faint `.stage-grid` layer, edge-masked, with the content in its own positioned column (an absolute layer paints over in-flow siblings whatever the DOM order — that's the bug this shape prevents). **It marks an empty stage, not a backdrop:** Scripts and B-Roll show it only while the panel holds nothing final (empty, cleared, or generating) and drop it the moment the takes/storyboard render — behind finished work it's texture under the reading. Characters is the exception and keeps it in both its empty gallery and its Single view, since one picture never fills the column. `AwaitingBody` / `AwaitingCanvas` are the empty state, paired with the **+** each panel puts in its `h-[57px]` header: + empties the canvas so the last run isn't on camera mid-recording, keyed to a signature of what was cleared so the next generation refills it on its own. It never deletes — the copy says so, because a blank panel otherwise reads as data loss. **History surfaces keep the plain background** — the grid marks the stage, not the reel.
- `components/video/refInputParts.tsx` — the **one reference-thumbnail shape**: a 64px `ImageTile` and the dashed `AddTile` that matches its footprint, wrapping in a plain `flex flex-wrap gap-1.5` row with the add tile joined into it (Playground's `RefTiles` is this plus an upload/bank menu). Every attach-an-image surface uses it — Playground's ref strip, B-Roll's `ExtraRefsRow` in all three card modals, Characters' `InfluencerEditModal`. Two surfaces had hand-rolled it as a four-up `grid` of `aspect-square` cells instead, which is a fixed count rather than a fixed size: in a half-modal column that drew each attached photo at ~110px, three times the same reference in Playground and the biggest thing in a panel whose point is the prompt. A reference is a reference at any size — if you need a bigger one, it's a frame slot (`FrameSlot`), not a ref tile.
- `components/SectionCard.tsx` — the grouped section card, lifted out of Influencers' controls column (August 2026) and now the shape of every **input** column: a faint `rounded-2xl` block with a **centred** icon + title over a hairline, small utilities pinned to the header's left/right edges (Influencers' `TabDivider` shape folded into the header — a 25%-wide pane can't spare a row for two 10px pills). Wired as **References** in Scripts, B-Roll and Playground, and as **Voice** / **Delivery** in Voiceovers. It also dresses every **card workspace** and **Bank form** (August 2026, the second pass): References in B-Roll's per-line card modal and Continuous' frame modal, **Keyframes** in Continuous' clip modal, **Voice** on a dialogue card, References in Characters' `InfluencerEditModal`, and one card per section in `ProductForm` / per DNA group in `ModelForm` / per field group in Script, Voice and Style. All three B-Roll modals now read **style note → group card → prompt → footer**; the clip modal used to open on its keyframes, which made each of the three start with something different. Its header is a `grid-cols-[1fr_auto_1fr]`, NOT absolute edge slots: the equal gutters keep the title genuinely centred, and a narrow pane squeezes the pills instead of dropping one on top of the title (which is exactly what happened in B-Roll's column). Two rules: **don't card a lone control** — the border is what says "these belong together", and around one row it says nothing for 24px — and **don't card what isn't part of the group** (the free-text steer boxes stay outside; they're where you type, not what you attach). A card that holds a growing box takes plain `flex-1`, never `flex-1 basis-0`: with basis-0 it splits the leftover evenly with its sibling and the box inside pays for the card's other rows out of its own height. The floor still lives on the **section**, as everywhere else — a card whose root is `min-h-0` on top of a `min-h-0` content column lets its growing child collapse to nothing.
- `StatusDot` / `SectionLabel` (same file) — Influencers' filled/empty field dot, with a third state the other panels need. Influencers' 28 fields are all the same kind of optional, so empty is always red; every other column mixes inputs that GATE the run with ones that don't, and a red dot on something nothing is waiting for reads as an error to go and fix. So: **green** filled · **red** required and empty · **neutral** optional and empty, and red means exactly one thing — "this is why Generate is grey". The dot rides at the row's own left edge (before the icon disc), so a card's dots stack into one column you can scan without reading a word; the ~14px inset that costs each row is deliberate, and part of what makes the contents read as inside the card. Only put a dot where it can ever be red or neutral — Voiceovers' Voice/Style/Pace/Accent always hold a value, and a permanent row of green dots is decoration that teaches members to stop reading dots. Same reason Playground's frame slots have none: a picture versus a dashed box already outshouts a 6px dot, which is also why the reference slot cards in every B-Roll and Characters modal carry none. `filled` is **optional** — omit it for a row that needs the label and no dot (the convention `RefGroup` already used). The honest reds in the modals are exactly three: B-Roll's Animate **Start frame**, Continuous' two clip **keyframe** endpoints, and Playground's Motion Control pair — each one really is why that Generate is grey or why the run refuses. Continuous' Animate **Motion** box deliberately stays neutral-when-empty, because it does *not* gate that button.
- `components/DayPill.tsx` — the day separator on **every** history surface (Characters, Playground, Scripts, B-Roll, the B-Roll card-detail galleries) and on the two day-grouped B-Roll listings (the Bank's B-Rolls tab, `BankPicker`'s B-Rolls tab): a small centred pill reading "Today" / "Yesterday" / a full date (`sectionLabel`), or an in-flight label like "In progress". Never a left-aligned heading with a hairline rule — that shape was tried on the two card grids and read as a divider between unrelated blocks. `className` sets the vertical margin only (pass `""` when the list already spaces its groups).
- `components/ModelPill.tsx` — **the one way a FINISHED output names the model that made it.** Three variants: `media` (literal white-on-black, for a pill sitting on a still or clip), `chrome` (a panel surface, one step brighter than the meta pills beside it — the model is the answer being looked for, the resolution and aspect are the fine print), and `quiet` (no pill at all, dim text, for a caption line UNDER a card where the model rides beside a label of its own). No backdrop-blur, since every one of these fades with its card's hover and blur stutters under an opacity transition (same reason `TileActionStack` drops it). Wired on Playground's history **list rows only** (the grid is a wall of pictures; a caption on each is chrome the grid exists to avoid) and on B-Roll's Continuous card faces + card-detail gallery tiles — bottom-left, `group-hover:opacity-0`, because on every one of those faces the hover action row lands on that exact strip. **B-Roll's Line-by-Line variation cards are the exception and use `quiet`** (August 2026): they already carry an A-Roll / B-Roll caption under the picture, so the model joins it there — a white-on-black chip was the loudest thing on a still whose whole job is to be judged, and on that face it had to fade on hover anyway. **In-flight surfaces are deliberately NOT routed through it** (`GeneratingMedia`, `GeneratingTile`, the in-flight list rows all name their model in their own layout): they report on work in progress, and a member watching a generation can't be shown less than one watching a finished tile. Visibility comes from `stores/generationInfoStore.ts` — per-browser, own localStorage key, ON unless an explicit `'off'` is stored, and the switch renders **only** on the operator-only gate Settings → Advanced already uses for the demo seeder (`!isCloudEnabled() || is_admin`). It exists for screen recording, where naming the model on every tile is one more thing on camera; a member has no reason to want their own outputs unlabelled, which is why they never see the row.
- `BracketHighlightArea` (`components/ExpandableText.tsx`) — the prompt field that paints `[bracketed placeholders]` red, used by Playground's inline prompt box and by `ExpandTextModal`. **The textarea never scrolls itself:** it's grown to its full content height and the WRAPPER scrolls, carrying the highlight layer and the text on one compositor scroll. The obvious shape — a scrolling textarea whose overlay is synced from its `onScroll` — always lands a frame or more behind (the browser scrolls the field off-main-thread and hands JS the event afterwards), and the red boxes visibly chase the words. The cost of the fix is that the browser no longer reveals the caret for us, so `revealCaret` does it on every text change and on the caret-moving keys; a drag-select past the edge doesn't auto-scroll. Both layers take the same `padClass`/`textClass` and the scrollbar gutter is on the wrapper, so they wrap identically by construction.
- `components/AutoGrowTextarea.tsx` — **a field inside a scrolling form grows, it doesn't scroll.** A textarea that scrolls internally is a scroll trap: the wheel over it moves the field, not the column, so a form whose boxes are all full (an auto-filled product) can't be scrolled by dragging through the middle of it. Drop-in for `<textarea>`; the optional `maxHeight` is for a paste box with no natural ceiling (the Bank's Listing copy), where scrolling past the cap is the right answer. Used by `ProductForm`'s section fields and `ModelForm`'s DNA rows. The other half of the same rule lives in the panel input columns: a box that owns leftover height takes `flex-1 basis-0` with the **floor on the section** (`min-h-[…]`), never `min-h-0` on the section plus a min-height on the textarea — that pair lets the section collapse while the field holds its floor, and the box's `overflow-hidden` then slices its own footer toolbar.
- **A history panel next to an input panel is `memo`'d, and its props are stable.** The history banks are uncapped (only `brollHistory` has a cap), so a working member's gallery is hundreds of rows, each with its own asset lookup — and it sits in the same component as the box they're typing into. One fresh callback identity per render means every character typed re-renders the whole list: measured at ~70 ms (Playground) and ~85 ms (Characters) per keystroke at 300 items, versus ~4–10 ms once the subtree is skipped. `PlaygroundHistoryGrid` and Characters' `GalleryPanel` are the two wired this way — `memo` on the panel, `useCallback` with only stable deps on every handler it takes, and the live draft read through a ref rather than closed over. The React Compiler does this on its own for components it can compile, so the explicit `memo` is a belt-and-braces for the app roots that still bail (see Tech Stack).
- `components/MobilePaneTabs.tsx` — **on a phone a two-pane app shows ONE pane at a time.** Every workspace app is a desktop split: what you fill in on the left, what comes out on the right. Stacking those two columns under `md` was tried first and doesn't work — each panel is built as a full-height column with its own internal scroll and a pinned footer, so stacked they collapse into a pair of ~200px scroll windows with the Generate bar lying across the fields it belongs to, and the output pane sits below a fold nobody finds. The bar is `md:hidden` and the panes swap with `hidden md:flex` (`paneClass`, same file), so there is no JS media query and the desktop layout is untouched by construction — `paneClass` deliberately sets nothing on `flex` above `md`, leaving each app's own `md:w-1/2` / `md:flex-1` to win. Wired in Characters (Controls / Gallery), Scripts (Setup / Output), Voiceovers (Script / Voice), B-Roll (Setup / Storyboard), Playground (Prompt / History) and Ad Analyzer (Analyses / Analysis). **Firing Generate flips to the output pane** — on a phone that's the only way to see the thing you just paid for.
- **`max-md:` is where a growing box stops sharing height.** The input columns hand their leftover height to the boxes that grow (`flex-1`, `flex-1 basis-0`, `flex-[5]`). On a phone there IS no leftover — the column is shorter than its own contents — so `flex-1` just squeezes every box until the card's `overflow-hidden` slices it. Under `md` those boxes take `max-md:flex-none` plus a real `max-md:min-h-[…]` floor and the column scrolls. The floor still lives on the section, exactly as on desktop.
- **The gap above a generate band belongs to the BAND, not to the scrolling column** (`pt-2` on the band, `pb-0` on the scroller — Scripts, B-Roll and Playground). Padding on the bottom of a scroll container is part of the scrolled content, so it slides out of view the moment the column overflows — which is its normal state once a member pastes a script or picks an input-heavy model. Measured in Scripts: the last input box sat **2.5px** off the band at scroll-top (reading as touching, which is how it was reported) and 8.5px scrolled to the bottom. A gap that changes as you scroll isn't a gap. On the band it is always exactly 8px, because it renders below the scroller's clip edge where nothing can scroll it away.
- **An app fills its pane exactly — one scroller, the app's own** (`h-full` inside `App.tsx`'s per-app wrapper, with **no layout floor under it**). A `min-h-[600px]` floor lived there for a while so that browser zoom — a short viewport in CSS px; 200% on a laptop leaves ~450px, which members do to make the UI readable on camera — scrolled the whole app instead of crushing its scrolling middle (Scripts' input column measured a **20px** scroll port against 606px of content). It came out in August 2026 because of what it cost below the floor: the pane became a **second scroller wrapping the entire app**, and every piece of pinned chrome inside — B-Roll's Storyboard/History header and its `sticky` "N Scenes" batch bar most visibly — slid up the screen as the member scrolled the storyboard. A bar that is `sticky` inside a panel cannot hold its ground against a scroller ABOVE that panel, and the two ports rubber-band against each other in between; it was reported as the bar being "elastic". Chrome that stays pinned is worth more than a graceful 450px viewport, and each panel's own column still scrolls at zoom. **Don't reintroduce a height floor here** — fix a crushed column on the column. The other half of the same rule survives: **no app footer may be `position: fixed`.** Scripts' was, under `md` only, and at 200% zoom it detached to the window's bottom edge and covered the whole input column; it's a static `shrink-0` band like every other app's now.
- **`backdrop-filter` is for small chrome, and `filter: blur()` never animates.** The one rule behind a whole class of "the app feels laggy" reports, fixed in August 2026. A `backdrop-filter` element is a **backdrop root**: a repaint anywhere inside it invalidates its entire backdrop. `App.tsx`'s window frame — which contains the whole workspace — carried `backdrop-blur-xl`, so every animating pixel in every app dragged a full-viewport filter recompute behind it. What it bought was nothing: behind it is `AppBackground`, a smooth dithered gradient, and a blurred smooth gradient is the same gradient. It's a plain translucent fill now, and removing it is why generation animations stopped stuttering, why zoom stopped lagging (a zoom re-rasters everything, backdrops included), and why images stopped looking blocky — a browser under that much compositing pressure drops its raster scale. Keep `backdrop-filter` on small static chrome over real content, and never put one on a full-window container. **`GeneratingBackdrop`'s three `blur-2xl` blobs are the deliberate exception** and are NOT to be "optimised" again: they were rewritten as radial gradients on exactly this reasoning (three animated blur filters per tile, on a surface whose job is to appear a dozen at a time) and it was reverted within the hour, because a gradient's falloff is a linear ramp where a Gaussian blur's is a smooth curve — the plateau edge reads as banded lobes instead of one soft wash, and this is a glow whose whole job is to look good while someone waits. Their bulk cost is handled where it actually bites, by `offscreen-idle` (`content-visibility: auto`, #459) skipping tiles that are off screen. If the on-screen cost ever needs to come down, take the `scale()` out of the `blob-drift-*` keyframes before touching the blur — scaling is what re-rasters a blurred layer; translating it doesn't.
- **Pinned panel chrome is glass, and anything that FADES on hover is not.** Two halves of one backdrop-filter rule. A bar that stays put (B-Roll's panel header, both storyboard strips) takes `supports-[backdrop-filter]:bg-surface-0/80 + backdrop-blur-xl + backdrop-saturate-150` over an opaque `bg-surface-0` fallback: content passing under it blurred is what makes it read as a fixed pane of the panel rather than a card-shaped hole, and a nested backdrop-filter DOES blur inside the window frame's own `backdrop-blur-xl` (the earlier "it can't re-blur" note was wrong — what made a translucent strip read as scrolling was too little blur and no saturation). The opposite holds for anything animating its own opacity: a backdrop-filter re-samples its backdrop every frame, so a hover-faded overlay over a real generated still stutters — which is why `TileActionStack` has never had one, and why B-Roll's variation-card shortcut row, tag chip and status badges dropped theirs (an empty card never showed it; a flat face is nothing to blur).
- **Fields render at 16px under `md`** (one rule at the bottom of `index.css`). iOS Safari zooms the page in whenever a focused field's font-size is under 16px and never zooms back out, so the app's 12–14px chrome type made every prompt box a one-way trip into a zoomed viewport with the dock off screen. Don't "fix" a phone-only field size by shrinking it again.
- `hooks/useCloseOnEscape.ts` — every dismissible overlay takes it, alongside the existing backdrop click (and `useCloseOnAppSwitch` when body-portaled).
- `hooks/useBackdropClose.ts` — **the only way a backdrop may close its overlay.** Never write `onClick={onClose}` on a backdrop: a text-selection drag that starts inside the panel and releases over the backdrop fires a `click` on their common ancestor (the backdrop), so a bare handler closes the overlay and throws the member's edit away — `stopPropagation` on the panel can't help, since that click never originated there. The hook closes only when mousedown and click report the **same target**, which leaves every existing dismiss path intact (including the lightboxes, which dismiss on clicks bubbling up from a transparent centering wrapper — `e.target === e.currentTarget` would have silently killed those). It keeps the panel-side contract unchanged: a panel that must not dismiss still needs its own `onClick={(e) => e.stopPropagation()}`. Call it at the top of the component, above any early `return null`, then spread onto the backdrop. Sibling backdrops (`<div className="fixed inset-0" onClick={onClose} />` with no children, as in `SlideOver` / `BankPicker` / `ModelSidePanel` / `AnchoredPopover`) can't exhibit the bug and are left alone.
- `hooks/useInlineVideo.ts` — **one clip plays at a time, app-wide.** Every video tile that can make noise (B-Roll's variation + clip cards, the detail-modal galleries, Playground's history grid) uses `useInlineVideo`: spread `hoverProps` on the tile root (never the `<video>` — the overlay buttons aren't its DOM children, so hovering one would read as a mouseleave) and `videoProps` on the element. Hover autoplays muted; the Play button is a user gesture, so it plays with sound, claims the single module-level playback slot, and pauses whoever held it (across apps — background apps stay mounted). A silent hover preview stands down while another clip holds the slot, and Play only *pauses* what it started, so clicking it during a preview means "let me hear it". `watching` (playing **and** unmuted) is the "user is watching this" flag: pass it to `TileActionStack hidden={…}` and hide the tile's other hover affordances, leaving only play/pause + mute on the media. **Nothing opts into `hidden` any more** — Playground's history grid, B-Roll's variation cards, the Continuous clip cards and the modal galleries all keep their actions on screen while a clip plays. Watching a take is exactly when you decide to keep it, and having Download / Save / Copy / Delete vanish under the pointer meant pausing to reach them. Every one of those stacks is top-right, clear of the play/pause + mute buttons on the left, and still only fades in on hover, so it never covers a clip you're merely watching. The prop stays on `TileActionStack` for a surface that genuinely wants it; think twice before using it. Players that keep native `controls` (the Playground lightbox, the Ad Analyzer source clip) take `useExclusiveVideo` for the same one-at-a-time rule and nothing else.
- `components/Dropdown.tsx` — the rounded-full select, portaled through `AnchoredPopover` so it escapes a scrolling panel's clip. `placement='above'` pins the menu upward regardless of viewport room — `AnchoredPopover`'s default 'auto' measures against the viewport, so on a tall screen a footer menu "fits" below while still covering the Generate button you're heading for. Takes an `accent` (voice / scripts / broll, plus `neutral` for chrome that belongs to no app) and an optional dim `label` inside the trigger, for a control whose value alone ("3", "30s") doesn't say what it sets. UI chrome must use the semantic tokens from `index.css`, never literal white/zinc/dark hexes:
- `ink` — fg chrome (white in dark, near-black in light): `border-ink/10`, `bg-ink/5`, `text-ink`. `paper` is its inverse (`bg-ink text-paper` buttons).
- `surface-0/1/2` — page → panel → popover elevation.
- `ink-50…950` — text ramp; dark equals zinc, light is mirrored (ink-100 stays "bright", ink-500 mid, ink-700 dim). Inverse elements self-flip (`bg-ink-100 text-ink-900`).
- Accent families auto-flip their 100–400/600 tints in light mode.
Exceptions that stay literal: anything overlaying user media (badges/scrims/play buttons → `text-white`, `bg-black/60`, `from-black/85`), white text on solid accent buttons, modal backdrops. **Errors.** End-user generation surfaces show friendly copy via `humanizeError()` (see `utils/friendlyError.ts`). It always returns a **complete sentence** — toast it verbatim and name the operation in the `fallback`; never prefix the result (``addToast(`Video generation failed: ${msg}`)`` printed the operation twice). Infra/admin/Settings surfaces still surface the raw kie.ai message — the operator debugs there. ## Tech Stack

- React 19 + TypeScript + Vite (`npm run dev` → http://localhost:5173). Tailwind CSS 4. Zustand for global state.
- **The React Compiler is on** (`babel-plugin-react-compiler` in `vite.config.ts`), so don't hand-write `useMemo`/`useCallback` for ordinary render work — it memoizes every component and hook it can compile. Two things make it silently **skip a whole component**, and both are worth avoiding in new code: an `// eslint-disable` of any `react-hooks/*` rule anywhere in the file, and a `try`/`finally` or catch-less `try` inside the component (move that work to a module-scope helper, as `finishResumedTask` in `playground/Playground.tsx` does). `npx eslint .` reports the first kind; for the second, the ground truth is whether the dev server's output for a file imports `react/compiler-runtime`. Coverage is partial today — the app roots that still bail are a known list, not an oversight. The compiler also memoizes **plain calls**, which is a trap for mutable state read through a stable function: `const get = useSettingsStore((s) => s.getAppModel)` then `get(key)` in the body compiles to a cache keyed on two things that never change, so it runs once per mount and the component renders that first answer forever (this is exactly how both model pickers came to show a model you hadn't picked). **Read store state through the selector** — `useSettingsStore((s) => s.getAppModel(key))` — never by calling a getter you pulled out of the store.
- IndexedDB (`assetStore.ts`) for blobs, mirrored to Cloudflare R2 when cloud sync is active. localStorage for bank metadata, settings, picker selections.
- **Cloud (opt-in):** Supabase (auth + Postgres) + R2. Enabled when `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` are set; absent → local-only mode (100% client-side). Access gated by email allowlist synced from Skool via Zapier.
- kie.ai Bearer token sent directly from the client (no proxy).

## kie.ai client (`src/utils/kie.ts`)

Four transports — pick by task type. Endpoints and result shapes live in `kie.ts`; the gotchas worth knowing here:

**Every call that CREATES a generation goes through `submitToKie` (`utils/kieSubmitGate.ts`), and it has to stay that way.** kie rate-limits an account to ~20 new generation requests per 10 seconds, and a rejected one is **not** queued server-side — it comes back 429 and that generation never happens. Every batch surface in this app fires its whole run in one tick (B-Roll's "Generate all images / videos" over a dozen-plus cards, Continuous' clip run, a Playground or Voiceovers batch), so a big storyboard walked past the ceiling and a chunk of the tiles came back as errors. The gate spaces submissions `MIN_SUBMIT_GAP_MS` apart app-wide (one queue across every app — a member can have two batches running), and a 429 that still lands calls `noteRateLimited`, which stands the **whole** queue down instead of letting each queued card discover the limit for itself. This is invisible because every generation surface pushes its in-flight tile BEFORE the network call: the run looks started the instant the button is pressed, and only the POST waits. Wired into `createTask`, `kieVeoCreate`, `kieMusicGenerate` and the two omni creates. Polling, reference-image uploads and chat completions are deliberately outside it — see the note in the file before adding anything.

**Every response body is read on a deadline, and it has to stay that way.** `fetch()` settles at the *headers*, so a timeout that stops there is disarmed while the body is still streaming — and a stalled body read never settles, which is a hang with no error, no cancel and no exit but a page reload. `fetchWithRetry` therefore hands back a Response whose `json`/`text`/`blob` are re-armed with a fresh budget (`armBodyTimeout`), so every transport routed through it is covered by construction. **A new call site that reaches kie with a bare `fetch` opts out of this.** The *result download* is the other half of the same rule and has its own helper: **`fetchGeneratedAsset(url, { signal })`** bounds the CDN hop that pulls a finished image / video / audio / cover off kie (one controller for the request AND the body read, `ASSET_DOWNLOAD_TIMEOUT_MS`, caller-cancellable). Every result download goes through it — `downloadAsBase64`, `finishVideoAssetTask`, `finishVoiceTask`, `finishPlaygroundMusicTask` — because that hop runs AFTER kie has generated and billed, so a stall there parked the tile on "generating" with no error and no cancel. The only remaining legitimate bare fetch is `downloadAssetFromR2` (`lib/r2.ts`), which carries its own timeout; anything new must too.

1. **Async task** (`createTask` → `pollTask` → `parseResult`) — `POST /jobs/createTask` → poll `GET /jobs/recordInfo`. Result URLs are string-encoded JSON inside `resultJson.resultUrls`. Outputs expire in 3 days — always `downloadAsBase64` + `saveAsset`. The shared tails `finishImageAssetTask` (`utils/imageTask.ts`) and `finishVideoAssetTask` (`utils/videoTask.ts`) wrap poll→download→save for every image/video surface; the video one adds the black-tile guards (0-byte / non-video content-type / `probeVideoBlob` decode check).
2. **Chat completions** (`kieChatCompletions`) — `POST /<slug>/v1/chat/completions`, streaming SSE, falls back to JSON parse then surfaces the body's first 400 chars on failure. Vision via `image_url` blocks (data URIs work, no upload). Get the endpoint path from `getChatEndpointPath()` — never hardcode slugs.
3. **Veo** (`kieVeoCreate` → `kieVeoPoll`) — custom `/veo/generate` + `/veo/record-info`. Variant (`veo3` / `veo3_fast` / `veo3_lite`) via the `model` field, not the URL. Results nest under `response.resultUrls`.
4. **Suno music** (`kieMusicGenerate` → `pollMusicTask`) — custom `/generate` + `/generate/record-info`. Suno-specific status values; `callBackUrl` is required by the schema but we pass a no-op and poll. Audio at `response.sunoData[].audioUrl` (v1 uses the first track).
5. **Omni create** (`kieOmniAudioCreate` / `kieOmniCharacterCreate`) — synchronous `POST /omni/audio/create` and `/omni/character/create`, no polling. Mint persistent `kieAudioId` / `characterId` values (scoped to the member's kie account) that `gemini-omni-video` consumes as `audio_ids` / `character_ids`. Success can come back as envelope code 0 *or* 200.

`ensureHostedUrl(apiKey, source)` uploads `data:` URIs to kie's file host (image→image and frame-conditioned video models need public URLs; hosted files expire in 3 days). `kieTestConnection` checks the credit balance (Settings).

## Non-obvious files

Most files are self-explanatory. These carry behaviour worth knowing before you touch them:

- `stores/bankStore.ts` — all banks + history + `migrateVoiceShape`.
- `utils/orphanCleanup.ts` — once-per-sign-in asset sweep. Its bank list **must** cover every bank (compile-time `satisfies Record<BankKey, true>` guard) or it deletes that bank's live assets from IDB + R2. Asset refs come in two shapes (bare `asset-x` and `asset://asset-x`); anything comparing refs against `assets.id` must normalise via `assetIdFromRef` first — unnormalised comparison once purged every B-Roll video. Its `assets` read is **paged** (`selectAllRows`) for the same reason: this list is the delete-candidate set, so a truncated read pairs a partial asset list against a partial ref set and purges live blobs the unread rows referenced. Both halves have to stay paged together.
- `utils/assetStore.ts` — IndexedDB blobs + fire-and-forget R2 mirror; `getBlob()` falls back to R2 on miss. **Two tiers, and neither may latch.** `fallbackStore` is a memory holding pen for blobs IndexedDB *individually* refused — it is consulted before IDB on read and written alongside it on failure, but it must never short-circuit IDB, and a failed `openDB` must never be cached (`dbPromise` is nulled on rejection). Both used to latch for the life of the tab, so one transient eviction made every later save memory-only — saved to all appearances, gone on reload — which is why reloading "fixed" saving. `openDB` also carries a deadline and an `onblocked` handler: `indexedDB.open` fires neither `onsuccess` nor `onerror` while another tab holds an older version, and `saveAsset` awaits it, so an unbounded open meant Save did nothing at all. Writes/deletes handle `tx.onabort` as well as `onerror` — a quota-exceeded transaction aborts, and without it the promise never settles.
- `lib/r2.ts` — presign → PUT → `assets` row upsert, the R2 mirror behind every `saveAsset`. **All three hops retry, and the mirror runs under a concurrency cap** (`MAX_CONCURRENT_UPLOADS`), because a batch's outputs all land at once — `finishImageAssetTask` / `finishVideoAssetTask` are the tail of every generation — and a dozen simultaneous multi-MB PUTs starve the small requests sharing the uplink. That surfaced as `assets row insert failed: TypeError: Load failed`, which is WebKit's wording for *any* network-layer fetch failure (Chromium: "Failed to fetch") stringified into supabase-js's `error.message` — the same text a backgrounded tab, a dropped hop and a saturated uplink all produce, so transience is judged by `TransientError` where we already know (a 5xx, a stall we timed out ourselves) and by `TRANSIENT_MARKERS` where the browser tells us nothing else. A retry **never re-PUTs a binary that already landed** — the row insert is the half that fails, and re-sending tens of MB to fix a 5-column row feeds the saturation that caused it. Requests carry a real `AbortController` (`fetchWithDeadline`), covering the body read as well as the headers: the old `withTimeout` race only rejected the wrapper, so a retry would have competed with the zombie upload whose stall triggered it. A run that exhausts its attempts is still recovered by `cloudSync`'s `reconcileAssets` on the next load, which is what the toast promises.
- `utils/friendlyError.ts` — `humanizeError(err, fallback)`, the ordered rule table for end-user error copy. The status-code rules are plain substring matches, so the message is first **cut at its debug tail** (`taskId=` / `url=` / `record=` / `body=` / `size=` / `endpoint=`): those payloads carry arbitrary digits, and `…video (size=402B…)` used to tell a member with a full balance to buy credits while any blob size containing `401` told them to replace a working key. Keep new debug context behind one of those keys, or behind a new one added to `DEBUG_TAIL`.
- `api/fetch-media.ts` — the only server-side URL fetcher in the app (Outliers → Ad Analyzer). It is an SSRF primitive by construction, so it keeps a **suffix-matched host allowlist** checked on the parsed hostname AND re-checked after redirects, never a substring match on the URL. Auth-gated like the R2 routes.
- `utils/team.ts` + `dashboard/SolarSystem.tsx` — **one crew member per dock app, and one `ORBITS` entry per crew member**: the two arrays are zipped by index, so a member with no orbit silently never renders on the Dashboard. Meet the Team derives its groups from `category` and counts the roster for its headline, so only the orbit list needs a hand-edit when an app is added.
- `utils/voiceProfile.ts` — `VOICE_PROFILE_SPEC`, the one wording for "describe how this voice sounds". Scripts WRITES one at the end of a scene blueprint, the Ad Analyzer READS one off an existing ad; they must agree, or a profile can't move between the two. B-Roll keeps its own phrasing inside `<VOICE_PROFILE>` because it's written against that prompt's character contract.
- `utils/mockData.ts` — the Settings demo seeder. Covers **every** tab: both banks and every history stream, a worked Line-by-Line session AND a Continuous keyframe chain (History row, since the workspace holds one session), styles, product extra angles, canvas-drawn stills, MediaRecorder clips and synthesized audio. Two rules: seeded rows match the real thing's shape (3 variations per scene, 3 concepts per frame — a short row reads as an app bug), and everything is reversible via the id manifest. The `usageDays` ledger is the exception worth knowing — it feeds the Dashboard, is priced through the real `foldUsageEvent`, and is written **only for days with no existing row**, so removal can never take a member's genuine activity with it.
- `hooks/useCloseOnAppSwitch.ts` — every body-portaled overlay (slide-over, picker, modal) must call it: portals escape the opacity-0 wrapper that hides background apps, so an open overlay would float over the next app after a dock switch.
- `lib/cloudSync.ts` — pull on sign-in + debounced diff-push + persistent localStorage outbox + non-destructive hydrate. `saveRow`/`deleteRow` are serialised per row (a stalled upsert can't land after a delete) and outbox markers are token-guarded (a late success can't clear a newer pending write). `walkAssetRefs` normalises `asset://` refs to bare ids so the sweep/reconcile match the bare-keyed `assets` table.
- `lib/supabase.ts` — `ensureFreshSession()` (3s race + cached-token fallback) and a custom non-blocking `auth.lock`.
- `hooks/useAssetUrl.ts` — resolves `asset://` refs to blob URLs.

## Banks

Persisted to `localStorage` under `ai-ugc-lab-banks`. Asset blobs live in IndexedDB (mirrored to R2 in cloud mode); rows store `asset://<id>` refs. `useAssetUrl(ref)` turns a ref into a blob URL. Types are in `stores/types.ts`.

`products`, `models` (from Influencers), `scripts`, `voices`, `brolls`, `styles`, plus auto-pushed history banks: `voiceHistory`, `videoHistory`, `imageHistory`, `musicHistory`, `scriptHistory`, `brollHistory`, `characterHistory`, `adAnatomyHistory`, and the Dashboard's `usageDays` ledger (all cloud-synced — every bank table has a Postgres mirror). Gotchas:

- **`usageDays`** — accumulate-only usage ledger: one row per local calendar day (`id: 'YYYY-MM-DD'`), holding per-kind generation counts + estimated kie credits + official-API USD. Written by `bankStore.recordUsage`, which is called inside the `add*History` actions (plus B-Roll's `finishImageTask` and the Ad Analyzer complete-flip) — new generation surfaces get counted for free if they push history. Deleting/clearing history never subtracts. One-time backfill from history (`backfillUsageLedger`, flag `ugc-lab:usage-backfill:<uid>`) runs post-hydrate in cloudSync (local-only: Dashboard mount) and skips ids in the mock-data manifest. Mock seeding suppresses live recording via `setUsageRecordingSuppressed`. Its Postgres table `usage_days` (migration 0016) uses a **composite PK (user_id, id)** because day keys repeat across users — run the migration before deploying, or every hydrate reports a per-table error (which also skips the auto orphan sweep).

- **Starring.** `products` / `models` / `scripts` / `brolls` / `styles` items carry `starred?: boolean` — flipped by bankStore's silent `toggleStar` (no toast) from a star button in the Bank cards' hover stack. Starred items sort first in every `BankPicker` (`starredFirst` in `finder/bankSort.ts`, amber badge on the card); the Bank browser's own sort order is deliberately untouched (B-Rolls are day-grouped).

- **`styles`** — visual looks for B-Roll (name + `brief` + up to four `thumbRefs`). The brief IS the style: it's the paragraph appended to every prompt rendered in that look, so it must describe the LOOK only, never anything from the frames it was read from. Thumbnails are this bank's own assets (nothing else links them), so delete/replace purges them outright. Postgres table `styles` (migration 0017) — run it before deploying, or every hydrate reports a per-table error (which also skips the auto orphan sweep).
- **`swipes`** — the swipe file behind Outliers: ads saved from a search, filed by the Bank's **Swipe File** tab. A row is the ad's identity (`platform` + `sourceId` + `postUrl`), a **snapshot of its numbers AS SAVED** (a swipe is a record of what a winner looked like when you found it, not a live feed), its caption, and its transcript when one had already been fetched — never re-billed for the sake of the save. The **thumbnail is copied into our own storage** (`saveThumbnail` → `thumbRef`), because every media URL a search returns is a signed CDN link that expires within days; a row that merely remembered the URL would be a broken image by the time it mattered. Following the same rule as `brolls`, the **video is deliberately not stored** — a swipe file is meant to hold hundreds of ads and a few MB each would eat the 10 GB cap for footage that `postUrl` can re-reach. `getSwipeBySource` keys off platform + source id so the Save button reads as saved and the same ad can't be filed twice from two searches; the card opens the ORIGINAL rather than an edit form, since there's nothing here that's yours to edit. It is **shaped exactly like the Outliers card it was saved from** — picture in its own 4:5 frame, then a static block of author / caption / snapshotted engagement row underneath — five across to match. It used to read its caption off a gradient laid over the frame, which put text across the ad's own hook (the one thing you saved it for) and left the numbers nowhere to live. Postgres table `swipes` (migration 0019) — run it before deploying, or every hydrate reports a per-table error (which also skips the auto orphan sweep).
- **`brolls`** — only **stills** are saveable to the bank (reusable as start frames / references); videos are download-only, so no UI writes new `videos[]` entries anymore (the save-to-bank action is hidden on video tiles in B-Roll + Playground). The `videos[]` field and its render/edit/cleanup paths stay for back-compat — older saved-video entries (and the video-only-broll render path in `BankList`) still display and download. Saved video-history items stamp `linkedBRollId`; deletion only purges the blob if not linked.
- **`videoHistory`** is shared by B-Roll and Playground (for refresh-resume); Playground's grid filters out `sourceApp === 'broll-studio'`. No automatic retention — entries persist until the user deletes/clears them. Only `brollHistory` is capped (`BROLL_HISTORY_CAP`, FIFO); the other history banks (`videoHistory`/`imageHistory`/`musicHistory`/…) grow unbounded **in memory and in the cloud, by design** — a member's outputs are never evicted behind their back. The localStorage copy is what gives: `flushSaveToStorage` writes the full blob first and only sheds the oldest history rows (`PERSIST_TRIM_STEPS`) when the browser actually refuses the write, because localStorage is a boot cache and hydrate refills memory from Postgres. Treat a quota failure as a **local** problem, never as a reason to delete a row. Both writes used to swallow `QuotaExceededError` silently — the bank blob *and* `cloudSync`'s outbox, which is the replay guarantee behind every fire-and-forget push — so a full disk lost a new row from both copies at once while the member watched a green "Saved". A local-only member is now toasted once per session, since for them the shed rows really are gone.
- **`characterHistory`** carries `imageRef` + the full `profile` snapshot; `linkedModelId` is set on save-to-bank and gates blob purge. Presets aren't a bank — reuse a recipe by saving to `models` and reloading via the Controls header dropdown. The nine built-in starters (`PRESET_*` in `character-studio/types.ts`) **fill all 28 fields and pick the starred option wherever the field offers one** — a one-word `skinTexture: 'Glass skin'` leaves the model to invent the rest and what it invents is the plastic look the presets exist to avoid, and an empty field drops out of the prompt entirely. "Starred" is `ChipField`'s `isDetailed` (a chip over 30 chars), so a preset value only shows as a picked row when it's EXACTLY one of that field's own detailed chips — which is why the age-appropriate skin tiers and the per-character hair styles were added to the chip lists rather than written as preset-only free text. `No makeup` on the men and the free-text `facialFeatures` / `distinguishingMarks` / `accessories` fields are correct as-is, not gaps.
- **`VoicePreset` / `VoiceHistoryItem`** carry the Gemini TTS param set (`voiceId` = `voice_name`, `style`, `pace`, `accent`, `temperature`, optional `scene` / `sampleContext`). `migrateVoiceShape` strips the legacy ElevenLabs numeric fields (`stability` / `similarityBoost` / `speed`, and the old numeric `style`) and backfills the new string defaults (`Natural` / `Natural` / `Neutral`, temp `1`).

## Auth + cloud sync

`AuthGate` wraps the app: bootstrapping → spinner; signed-out → `AuthScreen`; signed-in → workspace + `UserMenu`. No cloud env vars → local-only mode with a bottom banner. Full deploy stack is in `DEPLOYMENT.md`; threat model in `SECURITY.md`.

- **Onboarding.** `components/ApiKeyGuide.tsx` (menu-bar alert + the Dashboard banner) and `MeetTheTeam` both **take the kie.ai key inline** — they used to explain three steps and send the member to Settings, which left the intro with the one blocking task undone. Both go through `useKeyConnect` (exported from ApiKeyGuide): the key is checked against the live balance BEFORE it is saved, so nothing is ever stored that can't generate. Both are infra surfaces — a failed check shows kie.ai's own message, not `humanizeError` copy. `MeetTheTeam` stages the Create chain as a five-card pipeline with the blurbs in one hover-driven caption slot (eight rows of copy is a reading task, not an introduction); `components/apiKeySteps.tsx` is now only its read-only summary.
- **Allowlist.** Postgres trigger `enforce_allowlist` blocks signups not in `public.allowlist` (no client bypass). A global `public.app_config.enforce_allowlist` flag (Admin → Allowlist toggle) short-circuits the trigger when off — open signups while Zapier isn't wired; flip back on to re-gate. `on_allowlist_delete` sets `profiles.disabled_at` → app signs the user out on hydration; `on_allowlist_insert` clears it. A disabled account (sign-in or stale session) sets `authStore.accessRevoked`, and `AuthScreen` shows a "members only" popup linking to `SKOOL_COMMUNITY_URL`. Zapier syncs Skool events in. **Signup access code** (migration 0021): the Create account form has an **Access code** field, checked inside the same `enforce_allowlist` trigger against `app_config.signup_code` (default `3500`, edited in Admin → Allowlist; blank turns it off). It runs **before** the allowlist kill-switch — the switch exists to let un-synced members in, and the code is what keeps that door from being open to everyone. The expected value is **never shipped to the browser**: the client posts what was typed as signup metadata and the trigger compares, then strips the key off `raw_user_meta_data` so it never lands in a member's JWT. New signups only — nothing changes for existing accounts. **Names:** signup collects First name + Surname → passed as auth user metadata; `on_auth_user_created` seeds `profiles.first_name/last_name` from the allowlist row, falling back to that metadata (migration 0015) so members who sign up with a non-Skool email are still identifiable.
- **Cloud sync** (`cloudSync.ts`). Pulls profile + all bank tables on sign-in. `bankStore` writes local (Zustand + localStorage) first, then fires the cloud push in the **background** — `pushRow`/`dropRow` are fire-and-forget (return `void`, never awaited). The UI must never `await` a cloud round-trip: awaiting it was the "save stuck loading, then times out after ~15s" hang, and it could drop the row on a mid-hang refresh. Durability comes from the outbox, not the await — `recordPendingUpsert`/`recordPendingDelete` persist the row to a per-user localStorage outbox (`ugc-lab:sync-outbox:<uid>`) **synchronously** before the push fires, so a failed/timed-out push is replayed by `drainOutbox()` (startup + tab focus + backoff timer) and overlaid onto the next hydrate. Background push failures are logged, not toasted — local is the source of truth, sync is eventual. **Hydrate is non-destructive:** a per-table fetch error keeps local rows (never `[]`), and outbox-pending rows are overlaid so an unsynced row survives a refresh. **Every whole-table read is paged** through `selectAllRows` (`lib/supabase.ts`) — PostgREST silently caps a response at its server row limit, and the history banks are uncapped by design, so an unpaged read hands back the first page only and `persistBanksNow` then writes that truncated set to the local cache. The sweep below is why that matters beyond "missing rows": it builds its in-use ref set from these same banks.
- **Session freshness** (`supabase.ts`). Every cloud write awaits `ensureFreshSession()`, which races `getSession()` against a 3s timeout and falls back to a module-cached token (kept current by an `onAuthStateChange` listener) when the SDK's auth lock stalls after a backgrounded tab returns. The client also uses a custom `auth.lock` (`nonBlockingLock`, ~2s bound then runs unlocked) because supabase-js takes that lock on every request. `visibilitychange` recovers the token on focus.
- **kie.ai key is browser-local only.** Lives in `localStorage` under `ai-ugc-lab-settings`, never written to or read by Supabase/cloudSync. Users re-paste on each new browser. Deliberate trade-off: nothing in the DB ever holds the key. The optional **ScrapeCreators** key (Outliers) sits in the same blob under the same rule. Both are written through `snapshot(state)` rather than a hand-built literal — an earlier setter rebuilt an object naming only the fields it knew about, which silently dropped any key added to the shape later. **Both also survive sign-out, via the per-user vault** `ai-ugc-lab-keys` (`adoptUserKeys` / `rememberKeys` in `settingsStore.ts`): `wipeLocalUserData` clears the settings blob so the next person on a shared browser can't inherit a key, which used to mean re-pasting both on every sign-in — since they're the one thing in the app that isn't cloud-recoverable, the wipe was the whole cost. The vault is keyed by user id and adopted **only after** any wipe, so a member restores their own keys and never another's; a member with no entry yet has theirs seeded from the live settings (the upgrade path), and clearing both fields in Settings deletes the entry outright. Cost of the trade: a signed-out member's keys stay on that browser's disk until they clear the fields.
- **Schema.** Bank tables are JSONB (id PK, user_id FK, project_ids[] GIN-indexed, data jsonb). RLS `auth.uid() = user_id` everywhere, admin bypass via `profiles.is_admin`. Admin app (Members + Insights + Allowlist) only renders for admins.
- **Announcements** (migration 0020, Admin → Announcements). The operator's broadcast channel, and the one synced table that is **not a bank**: one global list written by admins and read by everyone, so it skips `bankStore`/`cloudSync` entirely and lives in `stores/announcementStore.ts`, loaded once per sign-in by `components/announcements/AnnouncementsHost.tsx`. Two levels, and the split is the whole design: **`update`** dots the Dashboard tile, **`alert`** *also* opens once as a modal on the member's next load (oldest unread first, one per load) and never again — so an outage can interrupt without training members to dismiss every feature note on sight. Read state is per ACCOUNT (`announcement_reads`, marked after a card holds the viewport ~0.9s, not on panel open), which is also what makes the "seen by 38 / 62" receipts in Admin real; the admin policy on that table stays SELECT-only. `published_at` in the future IS the scheduler — the member-side RLS policy only returns rows whose time has passed and whose `expires_at` hasn't — so nothing polls and drafts are invisible to members by construction. The image is a downscaled JPEG **inline in the row** (`components/announcements/media.ts` caps it), because every R2 key is signed under `auth/<userId>/` and a shared object would need a new public prefix in the presign route; the list query excludes it via the generated `has_image` column and each card fetches its own. A YouTube link needs no image at all — the card derives the thumbnail from the video id. The **preview in the admin editor renders the real `AnnouncementCard`** off the real draft (that's what the card's `preview` flag is for), with a light/dark switch that works because the `light:` variant matches any `[data-theme="light"]` ancestor. Publishing arms first, same two-click contract as delete.
- **Admin panel data.** Every tab stays mounted after first visit, and Members + Insights genuinely share one fetch — a 60s-fresh zustand store in `apps/admin/useMembers.ts` (it claimed to share one before and didn't). Remounting per tab click refired three queries and threw away sort, filters and scroll, which is what made every tab click drop the panel to a spinner. Every admin query goes through `apps/admin/adminQuery.ts`: `readyAdminSession()` first — Admin was the last cloud path not awaiting `ensureFreshSession()`, so its queries queued behind supabase-js's auth lock and only unblocked on a full page reload — then `withTimeout`, which really aborts the request so a late response can't land over fresher state. A failed refresh over loaded rows banners; it never blanks the table.
- **Deleting a member** (`apps/admin/deleteMember.ts`, driven by the Members table's row checkboxes). Disabling locks an account and keeps everything; deleting removes it — for spam signups, not for members who left. Two steps, in this order: `/api/r2-delete-user` purges every object under `auth/<userId>/` (admin-verified, fails closed; best-effort, so a storage failure warns instead of blocking), then the `admin_delete_member(target_id, remove_from_allowlist)` RPC (migration 0018) deletes the `auth.users` row and every bank/asset/usage row cascades off it. R2 first, because nothing points at those objects once the rows are gone. The RPC refuses to delete an admin or the caller, and removing the allowlist row (default ON) is what stops the person signing straight back up.

## Inter-app payloads

One-shot handoffs. Sender calls `sendToApp({ targetApp, targetField, data })`. Consumer reads `interAppPayload` in a `useEffect` keyed on `activeApp`, dispatches on `targetField`, then calls `consumePayload()`. Wired: Ad Analyzer → Scripts (transcript) / Bank (productId) / B-Roll (`adBlueprint`: an `AdBlueprintPayload` — the analysed ad's transcript as the script plus its staging, which is now the ONLY source of `BrollInput.sceneStaging`, B-Roll's Ad Format picker having been removed; cleared by "New"); Scripts → Voiceovers (script text); B-Roll Bank → Playground (`videoStartFrame` opens video mode with the still as start frame + prompt prefilled); B-Roll video → Playground (`videoSourceClip`: a `VideoSourceClipPayload` asset ref + real clip duration → video mode switched to Gemini Omni with the clip attached as the trimmed `omni-clip` source clip — the "same take, dialogue in Spanish" redub loop; the asset ref survives refresh, unlike uploaded clips); Anywhere → Playground (`prompt`, `imageRef`, `videoStartFrame`).
