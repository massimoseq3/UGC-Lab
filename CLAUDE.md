# CLAUDE.md — UGC OS

## Project Identity

You are building **UGC OS** — a browser-based, macOS-style workspace that unifies eight tools for UGC ad production into one environment with shared data banks. Every in-app AI call goes through **kie.ai**: one user-supplied Bearer key gives access to every model the app uses (chat, vision, image, video, TTS, music). The one exception is **Edit**, which generates nothing in the browser — it hands out a Claude skill the member runs locally.

**Who it's for / why.** A private Skool community of solo creators and small teams producing AI UGC ads at scale — access is gated by an email allowlist synced from Skool, so non-members can't sign up even with the URL. The pitch is one workspace instead of seven tabs: the same product, character, script, voice, and B-Roll flow across every app via the shared banks. Inference cost is on the member (BYO kie.ai key), so the operator only pays for hosting + storage.

Dock order: **Dashboard** (own 'system' group) | **Bank** | **the Create apps** (Characters → Scripts → Voiceovers → B-Roll → **Edit**, which closes the row — cut what you produced) | **Tools** (Ad Analyzer, Playground) | Settings utility tile. Fresh visits land on the Dashboard (`DEFAULT_SLUG`). Display names are terse nouns, not action verbs. Folder names and the `id` strings in `src/utils/constants.ts` are **stable** — they key per-app model selections in localStorage. Do not rename them.

Prompts stay silent — no speech, no music — and `withIphoneRealism` appends the realism stack as a trailing sentence (its CAMERA-line branch survives only for legacy structured prompts). `generateNewVariation` / `enhanceVariationPrompt` keep the `<PROMPT>` tag envelope, not JSON. **The camera is a viewpoint, not a prop:** all three prompt sites forbid naming the filming device (phone / front camera / tripod / mirror selfie) and require camera position as geometry — height, distance, angle — because any device noun gets drawn into frame; naming the iPhone as a *quality register* stays fine. PROOF is the one sanctioned exception (a screen as the subject). Every image/video gen gets a deterministic iPhone-realism suffix appended at request time (`services/realism.ts`). Video resolution follows the picked model's `videoConstraints.default` — fresh cards seed from it and the card modal snaps to it on a model flip (Gemini Omni → 1080p, which costs the same as 720p). **Continuous** (`services/generateContinuous.ts` + `ContinuousView.tsx` + `ContinuousDetailModals.tsx`): Zack-D-Films-style **keyframe-chain** ads — one storyboard LLM call splits the script into N scenes + N+1 keyframes where keyframe N+1 is simultaneously scene N's end state and scene N+1's start, so every clip is a **frames-to-video** gen (first frame = chosen keyframe N, last = keyframe N+1) and the cuts are invisible. Each keyframe fans out as **3 visual concepts** (`CONCEPTS_PER_FRAME`; same story state, different staging — any pick still chains) that are **three cameras on ONE action in ONE room**, not three ideas in three places. Each declares its own **shot size** off `SHOT_LADDER` (`<SHOT>` → `ContinuousConcept.shot`, chip on the card + frame modal header, fed back via `FrameContext.conceptShot` so a rewrite can't drift); the three must sit at three different sizes with **at least one medium-wide or wider** so there's always an un-cropped option. Sizes are picked **per beat, not by slot** — a first pass assigned fixed Wide/Detail/Character slots, which fixed the framing but made frames feel like different films: a mandated Wide on an intimate beat leaves nothing worth shooting wide, so the model invents a set + a per-frame Add-concept (drops a blank card you write or Regenerate a prompt in, like Line-by-Line's Add option — no LLM call up front); the user picks one image per frame (auto-picked on a frame's first image; `continuousSelections` keyed by frame index → `{conceptId, imageIndex}`) before any video credits burn. **Chaining a frame to the previous keyframe is ON by default** (`ContinuousFrameCardState.chainLink`, per-frame **Chained/Unchained** pill on the row header beside Generate frame; also a per-concept "Previous frame" slot in the frame modal). It shipped off for a while — all 3 concepts of a frame anchor to one image and come back similar, which weakens the pick-a-concept step — but this is continuous mode, and in practice the continuity is worth more than the spread. Legacy rows that stored an explicit `false` keep it off. The look is held by the storyboard-wide STYLE block plus the character/product refs (pre-style the character in Characters and identity holds far better than a chain image can manage), and the clip is a frames-to-video interpolation that morphs between unrelated frames fine — the `<TRANSITION>` anchor, not visual similarity, is what keeps it from cutting. When chained, frame N's gen attaches frame N-1's chosen image FIRST (`buildContinuousPreamble` chain clause, now explicitly forbidding composition/shot-size/angle reuse) plus character/product/extra refs, via `startImageTask`'s `preambleOverride` + `noRealism` opts. **Product visibility is decided per scene** (`<VISIBILITY>` → `ContinuousScene.productVisible`) and refs per concept (`<REFS>` → `ContinuousConcept.refs` → the card's toggles): a beat that attacks the category ("stop eating chalky protein bars") must NOT attach the product reference, or the model renders the member's own packaging as the thing being criticised. Visibility is the hard rule and `parseConcepts` clamps the LLM's refs to it; the prompt must also describe the bad item as an explicit unbranded stand-in ("plain unmarked grey wrapper, no logo"), because omitting the product just lets the model fill the blank from the attached reference. `buildContinuousPreamble`'s `productExcluded` clause says the exclusion out loud so a chained previous keyframe can't smuggle the branding back in. Line-by-Line carries the same doctrine (`clampRefsToVisibility` + rule 2b) and One-Shot the prompt half of it. **Continuous does NOT segment the script**: `scriptLines` splits it on newlines, the lines are handed to the LLM numbered, and it must return exactly one scene per line with `<LINE>` verbatim — no splitting, no merging, no reordering. Splitting is the user's call, via `SceneEditModal`. (Line-by-Line and One-Shot still carry the older ONE SCENE = ONE IDEA doctrine, which splits a line at a turn like "most taste like cardboard, **but** this one tastes like cookie dough".) **ONE RULE for a scene:** every keyframe is an ACTION that shows what its line SAYS — something physically happening, mid-motion — and the concepts are ${CONCEPTS_PER_FRAME} genuinely different ways to do it. Clarity is the whole point (a scrolling viewer with no sound should be able to guess the narration), which is why **MEDIUM is the default shot** and `SHOT_LADDER` stops at medium-wide: no aerials, no vast establishing shots, nothing that makes the viewer hunt for the subject. A short-lived `<WORLD>` block (one declared location for the whole ad) and a `<TRANSITION>`/anchor system (a connective device plus an element every concept on both sides had to carry) were both tried and **removed** — the world block made every beat the same corner of the same room, and the transition machinery was ceremony around a prompt whose job is "say what moves". What survives of the chain doctrine is one line: frame N+1 must be a state frame N could plausibly move into. Keyframe and motion prompts follow the same **one-flowing-paragraph + show-don't-tell** doctrine as the other two modes (no labelled fields), with keyframes adding a safe-zone note since 9:16 platform UI overlays the edges. **Safe framing constrains WHERE the subject sits, not how close the camera is** — held in the middle band (centre, or a third at most) with clear margin all round, nothing at an edge or bleeding off, nothing essential in the top/bottom eighth. That rule has now been wrong in both directions: as "centred with comfortable margins" it turned every keyframe into a centred medium, and rewritten to *encourage* off-centre framing it pushed subjects off the 9:16 edges — so it is stated as two separate axes. Camera position is geometry (lens height, distance, angle), the chest-up-portrait-square-to-the-lens shot stays banned, and the ref-copying fix lives in `buildContinuousPreamble`'s character clause: the ref is a chest-up portrait, declared an identity card whose crop must be ignored. **A motion prompt is simple** (`motionFormat()`): what moves and in which direction, how the camera moves, paced to the clip's real seconds, then one sound direction. It was a three-beat scaffold (departure → crossing → settle) with a `<TRANSITION>` device + anchor riding alongside; both were cut as over-built. One line survives because it prevents a real failure: **write the movement, never a picture of the end frame** — painting the final tableau makes the model race there and freeze. **Motion is seeded per-concept, never auto-relinked:** each of a frame's 3 concepts carries its own `motionPrompt`, and picking a keyframe syncs that concept's motion into the clip (a hand-edit sets `motionEdited` and stops the sync). An automatic **two-image vision pass** used to re-run on every keyframe change, rewriting the motion from the two rendered frames — it was removed: an LLM round-trip per pick made choosing keyframes slow and felt like it was fighting the user. The same pass is still one click away as the clip modal's **Regenerate from frames** (`regenerateContinuousMotion`), which is where it belongs — on demand, for the clip that needs it. `ContinuousScene.motionPrompt` survives only as a fallback seed (the first concept's motion) + legacy support. A storyboard-wide `<STYLE>` block rides OUTSIDE the editable prompts (appended at fire time by `buildContinuousPrompt`) so it can't drift per-frame. Style is picked for ALL THREE modes from one centred popup, `StyleModal` (opened by the left panel's single style row): a **Presets** grid (`CONTINUOUS_STYLES`, whose array order IS the grid order — UGC Realism / 3D Animated / Claymation / Papercraft / Anime / Cinematic; `getContinuousStyle`'s fallback is pinned by id, never `[0]`, so reordering can't silently change what an unknown id resolves to) over a **Your styles** grid (the `styles` bank) and a *New from images* card. **Style is a required input**, shaped like Scripts' Script Style row: the left panel's row is dashed and reads "Visual Style / Select how every clip looks" until a look is actively picked, then fills with the accent tint, the style's name (plus a `Custom` tag) over its brief, and an X to clear — and Generate stays disabled until then (`styleChosen`, persisted; a persisted custom brief counts as picked on its own so pre-flag sessions don't read as empty). "New" leaves the pick alone, exactly as Scripts does. That create view uploads or picks up to 4 frames and runs `analyzeStyleReferences` — a vision pass distilling medium/forms/palette/light/finish into a style paragraph, explicitly forbidden from carrying over the references' subjects. Nothing commits until the user edits/names the result and picks **Use without saving** or **Save to bank & use** (which writes a `StylePreset` row, frames included as `thumbRefs` assets). A custom brief always outranks the preset id; the picked style's `styleBrief` + `styleName` ride the session stamp into `brollHistory` (and `BrollResult.styleName`) so pills read the style's name, not "Custom style". Every style bypasses the app's iPhone-realism stack **except UGC Realism** (`ContinuousResult.realism` → `noRealism: !realism` on both `startImageTask` and `startVideoTask`). The picker LISTS every standard B-Roll video model (`CONTINUOUS_MODEL_IDS`) with `requireMode='frames-to-video'` greying the non-frame models (Kling Turbo, Omni, Grok) so the user sees why they're unavailable; settings key `broll-studio:continuous:video`, default **Seedance 1.5 Pro** (frames-native and materially cheaper per clip than the 2.0 family — a deliberate cost choice, not a regression; it also backs the standalone-Animate default via its `image-to-video` mode); the picker lives **in the clip modal, not the left panel** — the model only matters once there are keyframes to animate. Layout mirrors the other modes: one serif-numbered row per scene — concept cards + Add-concept in a 4-wide grid, with the `Clip N` card pinned in its own right-hand column (thick purple border marks it as the video card) behind a vertical divider, so added concepts wrap below the images and never under the clip — + a closing **Final Frame** row; each row also carries a per-row **Generate frame** button (mirrors Line-by-Line's per-row generate — `requestFrames([idx])`, disabled once that frame's keyframe is picked). **The storyboard is editable in place** (`continuousEdits.ts` — pure ops, applied by `handleEditContinuousStoryboard`): clicking a scene's narration line opens `SceneEditModal` to retype it, **split** it at the cursor (inserting a blank keyframe between the halves), **merge** it with the next scene, or **delete** it. Before this, one bad LLM segmentation meant regenerating the whole storyboard and losing every rendered keyframe. The frame cards (`${frameIndex}:${conceptId}`), clip cards (`c${sceneIndex}`) and keyframe picks are all keyed by POSITION, so every op declares one old→new index shift and `remapIndexedState` rewrites all three together — never remap one by hand. Affected clips get `motionEdited` cleared so the picked concept's motion re-seeds against the new endpoints. Reordering is deliberately absent: a move invalidates the framing each beat was written to share with its specific neighbours, which is a rewrite, not a move. "Generate frames" renders **every concept of every target frame** in parallel (the batch used to fire `concepts[0]` only, so two of the three cards stayed text and the keyframe was auto-picked before the user saw a choice) — the confirm popup prices images, not frames, and the pick is deterministic (the previously-picked concept, else the leftmost that landed) rather than whichever generation finished first. The per-row button stays live once a frame is picked (it re-arms `includeExisting` and reads **Regenerate frame**) — disabling it was a dead end out of the auto-pick. Falls back to a sequential index-order walk only when some frame in the batch is Chained and has to wait on the one before it, "Generate all clips" fires ready clips in parallel behind the same cost-confirm popup as One-Shot, and **Download all** (shown once any clip exists) zips every rendered clip via `utils/downloadZip.ts` (jszip); clip cards + gallery tiles have a hover **Download**. ## Core Rules

**Code philosophy.** Simple > clever. Obvious > terse. Components small and single-purpose. No premature optimisation. Comments explain *why*, not *what*.

**Architecture.**
- **Self-contained apps.** Each app under `src/apps/<name>/` owns its types, components, and service. Cross-app communication goes through the bank store (persistent) or the inter-app payload (one-shot handoffs).
- **No prop drilling.** Zustand stores for global state; local React state for ephemeral UI.
- **Model registry is the single source of truth.** Add or change a model only by editing `src/utils/models.ts`. Don't sprinkle slugs through service files.

**Styling.** Tailwind only. Per-app accent palettes are custom Tailwind families (`influencers-*`, `scripts-*`, `voice-*`, `broll-*`, `playground-*`) defined in the `@theme` block of `index.css` (Ad Analyzer uses literal `#FF5257`); the matching hexes for sidebar/bank chrome live in `constants.ts`. Change an accent there, not by sprinkling new color classes. Tracking-tight text. Transitions 200–300 ms for panels, 150 ms for hover. Tags use `TAG_STYLES` from `models.ts` (Recommended green / New fuchsia / Fast sky / Cheap zinc). **Single-line inputs, select-style triggers, chips, and buttons are fully rounded (`rounded-full`), not rectangles** — Massimo's preferred aesthetic; multi-line textareas use `rounded-2xl`.

**Shared UI idioms.** Reach for these instead of re-implementing — each one had drifted into 3–4 near-identical copies before it was extracted:
- `components/tileActions.tsx` — the hover action column on every generated media tile. `TileActionStack` + `TileActionButton` + `TileStarButton` + `TileDeleteButton`, in the order **[Star] → Download → Save → Copy → extras → Delete**. 32px circles, `bg-black/55`, no backdrop-blur (it stutters under the opacity fade).
- `TileDeleteButton` is the **only** delete idiom: two-click, arms into a red "Confirm" pill, reverts after 3s. Never a confirm modal. `variant='chrome'` for panel surfaces, `size='sm'` for compact history rows.
- `components/GeneratingMedia.tsx` — the one "this is generating" face. `GeneratingMediaFill` drops into any `relative overflow-hidden` frame (a card face); `PendingMedia` is the standalone aspect-sized tile for gallery grids. A card mid-generation and that same generation inside its detail modal must look identical, so both render this: blob backdrop, mode glyph top-left, model name, rotating status line (same size + accent tint as the model name — never a dim grey), prompt fading out along the bottom. Status-line copy lives in `components/generatingMessages.ts`.
- `components/GeneratingChip.tsx` — `GeneratingChip` (pulsing accent dot + label) and `GeneratingPulseRing` (thumbnail overlay) mark a **history row** whose work is still running. **History is the queue view**: fire a batch, switch away, and the list keeps reporting progress. Wired in the Ad Analyzer rail (its own literal-hex copy), B-Roll History (counts tallied from each row's snapshotted in-flight queues, TTL-swept at 30 min), Voiceovers History (an "In progress" section above the finished rows), and Playground / Influencers galleries (their own in-flight tiles).
- **Generate buttons never disable while a generation is in flight.** Every media surface queues gens in parallel; the in-flight tile is the feedback, not a locked button or a spinner swapped into the label. Guard duplicate fires of the *same* card with a `startingRef`-style set, not by disabling. The only legitimate blocks are structural (Continuous' sequential keyframe chain, nothing to generate yet).
- `hooks/useCloseOnEscape.ts` — every dismissible overlay takes it, alongside the existing backdrop click (and `useCloseOnAppSwitch` when body-portaled).
- `components/ClearAllButton.tsx` — the panel-level reset at the top of each input column. Labelled **"New"**, because it clears inputs only; outputs and history always survive.
- Panel headers are `h-[57px]` + `border-b border-ink/5` on **both** panes of a two-pane app, rendered even when a pane is empty, so the hairlines align.
- No global focus ring, on purpose. A `:focus-visible` outline was tried and reverted: `:focus-visible` matches text inputs on a plain mouse click too, so every search field and textarea drew an outline around its own border. The `focus:outline-none` resets stand — see the note in `index.css`.

**Theming (light default + dark mode).** Driven by `data-theme` on `<html>`: an inline script in `index.html` sets it pre-paint; `stores/themeStore.ts` owns the preference (`dark`/`light`/`system`, own localStorage key `ai-ugc-lab-theme`, deliberately per-browser — never cloud-synced, survives sign-out). New browsers default to `dark` — the store fallback and the index.html bootstrap must agree. Switchers: Settings → Appearance + the menu bar's top-right quick toggle. UI chrome must use the semantic tokens from `index.css`, never literal white/zinc/dark hexes:
- `ink` — fg chrome (white in dark, near-black in light): `border-ink/10`, `bg-ink/5`, `text-ink`. `paper` is its inverse (`bg-ink text-paper` buttons).
- `surface-0/1/2` — page → panel → popover elevation.
- `ink-50…950` — text ramp; dark equals zinc, light is mirrored (ink-100 stays "bright", ink-500 mid, ink-700 dim). Inverse elements self-flip (`bg-ink-100 text-ink-900`).
- Accent families auto-flip their 100–400/600 tints in light mode.
Exceptions that stay literal: anything overlaying user media (badges/scrims/play buttons → `text-white`, `bg-black/60`, `from-black/85`), white text on solid accent buttons, modal backdrops. Status tints (-100…-400 colored text on tinted bg) need a `light:` darker variant (`text-red-300 light:text-red-700`; the `light:` custom variant is defined in `index.css`). `AppBackground.tsx` holds the per-theme canvas gradient.

**Errors.** End-user generation surfaces show friendly copy via `humanizeError()` (see `utils/friendlyError.ts`). It always returns a **complete sentence** — toast it verbatim and name the operation in the `fallback`; never prefix the result (``addToast(`Video generation failed: ${msg}`)`` printed the operation twice). Infra/admin/Settings surfaces still surface the raw kie.ai message — the operator debugs there. Note: the kie envelope can return `{ code: 5xx, msg: "...maintained..." }` inside an HTTP 200 during maintenance windows — not a code bug.

## kie.ai client (`src/utils/kie.ts`)

Four transports — pick by task type. Endpoints and result shapes live in `kie.ts`; the gotchas worth knowing here:

1. **Async task** (`createTask` → `pollTask` → `parseResult`) — `POST /jobs/createTask` → poll `GET /jobs/recordInfo`. Result URLs are string-encoded JSON inside `resultJson.resultUrls`. Outputs expire in 3 days — always `downloadAsBase64` + `saveAsset`. The shared tails `finishImageAssetTask` (`utils/imageTask.ts`) and `finishVideoAssetTask` (`utils/videoTask.ts`) wrap poll→download→save for every image/video surface; the video one adds the black-tile guards (0-byte / non-video content-type / `probeVideoBlob` decode check).
2. **Chat completions** (`kieChatCompletions`) — `POST /<slug>/v1/chat/completions`, streaming SSE, falls back to JSON parse then surfaces the body's first 400 chars on failure. Vision via `image_url` blocks (data URIs work, no upload). Get the endpoint path from `getChatEndpointPath()` — never hardcode slugs.
3. **Veo** (`kieVeoCreate` → `kieVeoPoll`) — custom `/veo/generate` + `/veo/record-info`. Variant (`veo3` / `veo3_fast` / `veo3_lite`) via the `model` field, not the URL. Results nest under `response.resultUrls`.
4. **Suno music** (`kieMusicGenerate` → `pollMusicTask`) — custom `/generate` + `/generate/record-info`. Suno-specific status values; `callBackUrl` is required by the schema but we pass a no-op and poll. Audio at `response.sunoData[].audioUrl` (v1 uses the first track).
5. **Omni create** (`kieOmniAudioCreate` / `kieOmniCharacterCreate`) — synchronous `POST /omni/audio/create` and `/omni/character/create`, no polling. Mint persistent `kieAudioId` / `characterId` values (scoped to the member's kie account) that `gemini-omni-video` consumes as `audio_ids` / `character_ids`. Success can come back as envelope code 0 *or* 200.

`ensureHostedUrl(apiKey, source)` uploads `data:` URIs to kie's file host (image→image and frame-conditioned video models need public URLs; hosted files expire in 3 days). `kieTestConnection` checks the credit balance (Settings).

## Banks

Persisted to `localStorage` under `ai-ugc-lab-banks`. Asset blobs live in IndexedDB (mirrored to R2 in cloud mode); rows store `asset://<id>` refs. `useAssetUrl(ref)` turns a ref into a blob URL. Types are in `stores/types.ts`.

`products`, `models` (from Influencers), `scripts`, `voices`, `brolls`, `styles`, plus auto-pushed history banks: `voiceHistory`, `videoHistory`, `imageHistory`, `musicHistory`, `scriptHistory`, `brollHistory`, `characterHistory`, `adAnatomyHistory`, and the Dashboard's `usageDays` ledger (all cloud-synced — every bank table has a Postgres mirror). Gotchas:

- **`usageDays`** — accumulate-only usage ledger: one row per local calendar day (`id: 'YYYY-MM-DD'`), holding per-kind generation counts + estimated kie credits + official-API USD. Written by `bankStore.recordUsage`, which is called inside the `add*History` actions (plus B-Roll's `finishImageTask` and the Ad Analyzer complete-flip) — new generation surfaces get counted for free if they push history. Deleting/clearing history never subtracts. One-time backfill from history (`backfillUsageLedger`, flag `ugc-lab:usage-backfill:<uid>`) runs post-hydrate in cloudSync (local-only: Dashboard mount) and skips ids in the mock-data manifest. Mock seeding suppresses live recording via `setUsageRecordingSuppressed`. Its Postgres table `usage_days` (migration 0016) uses a **composite PK (user_id, id)** because day keys repeat across users — run the migration before deploying, or every hydrate reports a per-table error (which also skips the auto orphan sweep).

- **Starring.** `products` / `models` / `scripts` / `brolls` / `styles` items carry `starred?: boolean` — flipped by bankStore's silent `toggleStar` (no toast) from a star button in the Bank cards' hover stack. Starred items sort first in every `BankPicker` (`starredFirst` in `finder/bankSort.ts`, amber badge on the card); the Bank browser's own sort order is deliberately untouched (B-Rolls are day-grouped).

- **`styles`** — visual looks for B-Roll (name + `brief` + up to four `thumbRefs`). The brief IS the style: it's the paragraph appended to every prompt rendered in that look, so it must describe the LOOK only, never anything from the frames it was read from. Thumbnails are this bank's own assets (nothing else links them), so delete/replace purges them outright. Postgres table `styles` (migration 0017) — run it before deploying, or every hydrate reports a per-table error (which also skips the auto orphan sweep).
- **`brolls`** — only **stills** are saveable to the bank (reusable as start frames / references); videos are download-only, so no UI writes new `videos[]` entries anymore (the save-to-bank action is hidden on video tiles in B-Roll + Playground). ## Auth + cloud sync

`AuthGate` wraps the app: bootstrapping → spinner; signed-out → `AuthScreen`; signed-in → workspace + `UserMenu`. No cloud env vars → local-only mode with a bottom banner. Full deploy stack is in `DEPLOYMENT.md`; threat model in `SECURITY.md`.

- **Allowlist.** Postgres trigger `enforce_allowlist` blocks signups not in `public.allowlist` (no client bypass). A global `public.app_config.enforce_allowlist` flag (Admin → Allowlist toggle) short-circuits the trigger when off — open signups while Zapier isn't wired; flip back on to re-gate. `on_allowlist_delete` sets `profiles.disabled_at` → app signs the user out on hydration; `on_allowlist_insert` clears it. A disabled account (sign-in or stale session) sets `authStore.accessRevoked`, and `AuthScreen` shows a "members only" popup linking to `SKOOL_COMMUNITY_URL`. Zapier syncs Skool events in. **Names:** signup collects First name + Surname → passed as auth user metadata; `on_auth_user_created` seeds `profiles.first_name/last_name` from the allowlist row, falling back to that metadata (migration 0015) so members who sign up with a non-Skool email are still identifiable.
- **Cloud sync** (`cloudSync.ts`). Pulls profile + all bank tables on sign-in. `bankStore` writes local (Zustand + localStorage) first, then fires the cloud push in the **background** — `pushRow`/`dropRow` are fire-and-forget (return `void`, never awaited). The UI must never `await` a cloud round-trip: awaiting it was the "save stuck loading, then times out after ~15s" hang, and it could drop the row on a mid-hang refresh. Durability comes from the outbox, not the await — `recordPendingUpsert`/`recordPendingDelete` persist the row to a per-user localStorage outbox (`ugc-lab:sync-outbox:<uid>`) **synchronously** before the push fires, so a failed/timed-out push is replayed by `drainOutbox()` (startup + tab focus + backoff timer) and overlaid onto the next hydrate. Background push failures are logged, not toasted — local is the source of truth, sync is eventual. **Hydrate is non-destructive:** a per-table fetch error keeps local rows (never `[]`), and outbox-pending rows are overlaid so an unsynced row survives a refresh.
- **Session freshness** (`supabase.ts`). Every cloud write awaits `ensureFreshSession()`, which races `getSession()` against a 3s timeout and falls back to a module-cached token (kept current by an `onAuthStateChange` listener) when the SDK's auth lock stalls after a backgrounded tab returns. The client also uses a custom `auth.lock` (`nonBlockingLock`, ~2s bound then runs unlocked) because supabase-js takes that lock on every request. `visibilitychange` recovers the token on focus.
- **kie.ai key is browser-local only.** Lives in `localStorage` under `ai-ugc-lab-settings`, never written to or read by Supabase/cloudSync. Users re-paste on each new browser. Deliberate trade-off: nothing in the DB ever holds the key.
- **Schema.** Bank tables are JSONB (id PK, user_id FK, project_ids[] GIN-indexed, data jsonb). RLS `auth.uid() = user_id` everywhere, admin bypass via `profiles.is_admin`. Admin app (Members + Insights + Allowlist) only renders for admins; the Members table and the Insights charts share one fetch via `apps/admin/useMembers.ts`.

## Inter-app payloads

One-shot handoffs. Sender calls `sendToApp({ targetApp, targetField, data })`. Consumer reads `interAppPayload` in a `useEffect` keyed on `activeApp`, dispatches on `targetField`, then calls `consumePayload()`. Wired: Ad Analyzer → Scripts (transcript) / Bank (productId); Scripts → Voiceovers (script text); Scripts → Playground (`cinematicVideo`: a `CinematicVideoPayload` of resolved prompt + product/influencer refs + modelId + duration → opens video mode, refs attached, Seedance default); B-Roll Bank → Playground (`videoStartFrame` opens video mode with the still as start frame + prompt prefilled); B-Roll video → Playground (`videoSourceClip`: a `VideoSourceClipPayload` asset ref + real clip duration → video mode switched to Gemini Omni with the clip attached as the trimmed `omni-clip` source clip — the "same take, dialogue in Spanish" redub loop; the asset ref survives refresh, unlike uploaded clips); Anywhere → Playground (`prompt`, `imageRef`, `videoStartFrame`).
