# CLAUDE.md — UGC OS

## Project Identity

You are building **UGC OS** — a browser-based, macOS-style workspace that unifies eight tools for UGC ad production into one environment with shared data banks. Every in-app AI call goes through **kie.ai**: one user-supplied Bearer key gives access to every model the app uses (chat, vision, image, video, TTS, music). The one exception is **Edit**, which generates nothing in the browser — it hands out a Claude skill the member runs locally.

**Who it's for / why.** A private Skool community of solo creators and small teams producing AI UGC ads at scale — access is gated by an email allowlist synced from Skool, so non-members can't sign up even with the URL. The pitch is one workspace instead of seven tabs: the same product, character, script, voice, and B-Roll flow across every app via the shared banks. Inference cost is on the member (BYO kie.ai key), so the operator only pays for hosting + storage.

Dock order: **Dashboard** (own 'system' group) | **Bank** | **the Create apps** (Characters → Scripts → Voiceovers → B-Roll → **Edit**, which closes the row — cut what you produced) | **Tools** (Ad Analyzer, Playground) | Settings utility tile. Fresh visits land on the Dashboard (`DEFAULT_SLUG`). Display names are terse nouns, not action verbs. Folder names and the `id` strings in `src/utils/constants.ts` are **stable** — they key per-app model selections in localStorage. Do not rename them.

## Core Rules

**Code philosophy.** Simple > clever. Obvious > terse. Components small and single-purpose. No premature optimisation. Comments explain *why*, not *what*.

**Architecture.**
- **Self-contained apps.** Each app under `src/apps/<name>/` owns its types, components, and service. Cross-app communication goes through the bank store (persistent) or the inter-app payload (one-shot handoffs).
- **No prop drilling.** Zustand stores for global state; local React state for ephemeral UI.
- **Model registry is the single source of truth.** Add or change a model only by editing `src/utils/models.ts`. Don't sprinkle slugs through service files.

**Styling.** Tailwind only. Per-app accent palettes are custom Tailwind families (`influencers-*`, `scripts-*`, `voice-*`, `broll-*`, `playground-*`) defined in the `@theme` block of `index.css` (Ad Analyzer uses literal `#FF5257`); the matching hexes for sidebar/bank chrome live in `constants.ts`. Change an accent there, not by sprinkling new color classes. Tracking-tight text. Transitions 200–300 ms for panels, 150 ms for hover. Tags use `TAG_STYLES` from `models.ts` (Recommended green / New fuchsia / Fast sky / Cheap zinc). **Single-line inputs, select-style triggers, chips, and buttons are fully rounded (`rounded-full`), not rectangles** — Massimo's preferred aesthetic; multi-line textareas use `rounded-2xl`.

**Shared UI idioms.** Reach for these instead of re-implementing — each one had drifted into 3–4 near-identical copies before it was extracted:
- `components/VideoLightbox.tsx` — the full-screen clip view: the video large on the left, its **first / last frame** grabbed out of the file on the right (save either to the B-Rolls bank as a reusable start frame, or download it), then the prompt and Copy prompt / Download Video. Grew out of the Playground preview modal, which still renders its `VideoFrameActions` half. Every B-Roll video tile reaches it through `ExpandVideoButton` (`chrome='stack'` inside a `TileActionStack`, `'plain'` on the Continuous take gallery's bespoke overlay row), which owns its own open state and portals the overlay to the body.
- `components/tileActions.tsx` — the hover action column on every generated media tile. `TileActionStack` + `TileActionButton` + `TileStarButton` + `TileDeleteButton`, in the order **[Star] → Download → Save → Copy → extras → Delete**. 32px circles, `bg-black/55`, no backdrop-blur (it stutters under the opacity fade).
- `TileDeleteButton` is the **only** delete idiom: two-click, arms into a red "Confirm" pill, reverts after 3s. Never a confirm modal. `variant='chrome'` for panel surfaces, `size='sm'` for compact history rows.
- `components/GeneratingMedia.tsx` — the one "this is generating" face. `GeneratingMediaFill` drops into any `relative overflow-hidden` frame (a card face); `PendingMedia` is the standalone aspect-sized tile for gallery grids. The obvious shape — a scrolling textarea whose overlay is synced from its `onScroll` — always lands a frame or more behind (the browser scrolls the field off-main-thread and hands JS the event afterwards), and the red boxes visibly chase the words. The cost of the fix is that the browser no longer reveals the caret for us, so `revealCaret` does it on every text change and on the caret-moving keys; a drag-select past the edge doesn't auto-scroll. - `components/AutoGrowTextarea.tsx` — **a field inside a scrolling form grows, it doesn't scroll.** A textarea that scrolls internally is a scroll trap: the wheel over it moves the field, not the column, so a form whose boxes are all full (an auto-filled product) can't be scrolled by dragging through the middle of it. Drop-in for `<textarea>`; the optional `maxHeight` is for a paste box with no natural ceiling (the Bank's Listing copy), where scrolling past the cap is the right answer. Used by `ProductForm`'s section fields and `ModelForm`'s DNA rows. The other half of the same rule lives in the panel input columns: a box that owns leftover height takes `flex-1 basis-0` with the **floor on the section** (`min-h-[…]`), never `min-h-0` on the section plus a min-height on the textarea — that pair lets the section collapse while the field holds its floor, and the box's `overflow-hidden` then slices its own footer toolbar.
- `hooks/useCloseOnEscape.ts` — every dismissible overlay takes it, alongside the existing backdrop click (and `useCloseOnAppSwitch` when body-portaled).
- `hooks/useBackdropClose.ts` — **the only way a backdrop may close its overlay.** Never write `onClick={onClose}` on a backdrop: a text-selection drag that starts inside the panel and releases over the backdrop fires a `click` on their common ancestor (the backdrop), so a bare handler closes the overlay and throws the member's edit away — `stopPropagation` on the panel can't help, since that click never originated there. The hook closes only when mousedown and click report the **same target**, which leaves every existing dismiss path intact (including the lightboxes, which dismiss on clicks bubbling up from a transparent centering wrapper — `e.target === e.currentTarget` would have silently killed those). It keeps the panel-side contract unchanged: a panel that must not dismiss still needs its own `onClick={(e) => e.stopPropagation()}`. Call it at the top of the component, above any early `return null`, then spread onto the backdrop. Sibling backdrops (`<div className="fixed inset-0" onClick={onClose} />` with no children, as in `SlideOver` / `BankPicker` / `ModelSidePanel` / `AnchoredPopover`) can't exhibit the bug and are left alone.
- `hooks/useInlineVideo.ts` — **one clip plays at a time, app-wide.** Every video tile that can make noise (B-Roll's variation + clip cards, the detail-modal galleries, Playground's history grid) uses `useInlineVideo`: spread `hoverProps` on the tile root (never the `<video>` — the overlay buttons aren't its DOM children, so hovering one would read as a mouseleave) and `videoProps` on the element. Hover autoplays muted; the Play button is a user gesture, so it plays with sound, claims the single module-level playback slot, and pauses whoever held it (across apps — background apps stay mounted). A silent hover preview stands down while another clip holds the slot, and Play only *pauses* what it started, so clicking it during a preview means "let me hear it". `watching` (playing **and** unmuted) is the "user is watching this" flag: pass it to `TileActionStack hidden={…}` and hide the tile's other hover affordances, leaving only play/pause + mute on the media. Players that keep native `controls` (the Playground lightbox, the Ad Analyzer source clip) take `useExclusiveVideo` for the same one-at-a-time rule and nothing else.
- `components/Dropdown.tsx` — the rounded-full select, portaled through `AnchoredPopover` so it escapes a scrolling panel's clip. `placement='above'` pins the menu upward regardless of viewport room — `AnchoredPopover`'s default 'auto' measures against the viewport, so on a tall screen a footer menu "fits" below while still covering the Generate button you're heading for. Opening a menu is a decision, so it takes a click. There is no `hover` prop any more; don't add one back here or elsewhere.
- `components/ClearAllButton.tsx` — the panel-level reset at the top of each input column. Labelled **"New"**, because it clears inputs only; outputs and history always survive.
- Panel headers are `h-[57px]` + `border-b border-ink/5` on **both** panes of a two-pane app, rendered even when a pane is empty, so the hairlines align.
- No global focus ring, on purpose. A `:focus-visible` outline was tried and reverted: `:focus-visible` matches text inputs on a plain mouse click too, so every search field and textarea drew an outline around its own border. The `focus:outline-none` resets stand — see the note in `index.css`.

**Theming (light default + dark mode).** Driven by `data-theme` on `<html>`: an inline script in `index.html` sets it pre-paint; `stores/themeStore.ts` owns the preference (`dark`/`light`/`system`, own localStorage key `ai-ugc-lab-theme`, deliberately per-browser — never cloud-synced, survives sign-out). New browsers default to `dark` — the store fallback and the index.html bootstrap must agree. Switchers: Settings → Appearance + the menu bar's top-right quick toggle. UI chrome must use the semantic tokens from `index.css`, never literal white/zinc/dark hexes:
- `ink` — fg chrome (white in dark, near-black in light): `border-ink/10`, `bg-ink/5`, `text-ink`. `paper` is its inverse (`bg-ink text-paper` buttons).
- `surface-0/1/2` — page → panel → popover elevation.
- `ink-50…950` — text ramp; dark equals zinc, light is mirrored (ink-100 stays "bright", ink-500 mid, ink-700 dim). Inverse elements self-flip (`bg-ink-100 text-ink-900`).
- Accent families auto-flip their 100–400/600 tints in light mode.
Exceptions that stay literal: anything overlaying user media (badges/scrims/play buttons → `text-white`, `bg-black/60`, `from-black/85`), white text on solid accent buttons, modal backdrops. Status tints (-100…-400 colored text on tinted bg) need a `light:` darker variant (`text-red-300 light:text-red-700`; the `light:` custom variant is defined in `index.css`). `AppBackground.tsx` holds the per-theme canvas gradient.

**Errors.** End-user generation surfaces show friendly copy via `humanizeError()` (see `utils/friendlyError.ts`). It always returns a **complete sentence** — toast it verbatim and name the operation in the `fallback`; never prefix the result (``addToast(`Video generation failed: ${msg}`)`` printed the operation twice). Infra/admin/Settings surfaces still surface the raw kie.ai message — the operator debugs there. Note: the kie envelope can return `{ code: 5xx, msg: "...maintained..." }` inside an HTTP 200 during maintenance windows — not a code bug.

## kie.ai client (`src/utils/kie.ts`)

Four transports — pick by task type. Endpoints and result shapes live in `kie.ts`; the gotchas worth knowing here:

1. **Async task** (`createTask` → `pollTask` → `parseResult`) — `POST /jobs/createTask` → poll `GET /jobs/recordInfo`. Result URLs are string-encoded JSON inside `resultJson.resultUrls`. Outputs expire in 3 days — always `downloadAsBase64` + `saveAsset`. The shared tails `finishImageAssetTask` (`utils/imageTask.ts`) and `finishVideoAssetTask` (`utils/videoTask.ts`) wrap poll→download→save for every image/video surface; the video one adds the black-tile guards (0-byte / non-video content-type / `probeVideoBlob` decode check).
2. **Chat completions** (`kieChatCompletions`) — `POST /<slug>/v1/chat/completions`, streaming SSE, falls back to JSON parse then surfaces the body's first 400 chars on failure. Vision via `image_url` blocks (data URIs work, no upload). Get the endpoint path from `getChatEndpointPath()` — never hardcode slugs.
3. **Veo** (`kieVeoCreate` → `kieVeoPoll`) — custom `/veo/generate` + `/veo/record-info`. Variant (`veo3` / `veo3_fast` / `veo3_lite`) via the `model` field, not the URL. Results nest under `response.resultUrls`.
4. **Suno music** (`kieMusicGenerate` → `pollMusicTask`) — custom `/generate` + `/generate/record-info`. Suno-specific status values; `callBackUrl` is required by the schema but we pass a no-op and poll. Audio at `response.sunoData[].audioUrl` (v1 uses the first track).
5. **Omni create** (`kieOmniAudioCreate` / `kieOmniCharacterCreate`) — synchronous `POST /omni/audio/create` and `/omni/character/create`, no polling. Mint persistent `kieAudioId` / `characterId` values (scoped to the member's kie account) that `gemini-omni-video` consumes as `audio_ids` / `character_ids`. Success can come back as envelope code 0 *or* 200.

`ensureHostedUrl(apiKey, source)` uploads `data:` URIs to kie's file host (image→image and frame-conditioned video models need public URLs; hosted files expire in 3 days). `kieTestConnection` checks the credit balance (Settings).

## Non-obvious files

Most files are self-explanatory. These carry behaviour worth knowing before you touch them:

- `stores/bankStore.ts` — all banks + history + `migrateVoiceShape`.
- `utils/orphanCleanup.ts` — once-per-sign-in asset sweep. Its bank list **must** cover every bank (compile-time `satisfies Record<BankKey, true>` guard) or it deletes that bank's live assets from IDB + R2. Asset refs come in two shapes (bare `asset-x` and `asset://asset-x`); anything comparing refs against `assets.id` must normalise via `assetIdFromRef` first — unnormalised comparison once purged every B-Roll video.
- `utils/assetStore.ts` — IndexedDB blobs + fire-and-forget R2 mirror; `getBlob()` falls back to R2 on miss.
- `utils/friendlyError.ts` — `humanizeError(err, fallback)`, the ordered rule table for end-user error copy.
- `utils/mockData.ts` — the Settings demo seeder. Covers **every** tab: both banks and every history stream, a worked Line-by-Line session AND a Continuous keyframe chain (History row, since the workspace holds one session), styles, product extra angles, canvas-drawn stills, MediaRecorder clips and synthesized audio. Two rules: seeded rows match the real thing's shape (3 variations per scene, 3 concepts per frame — a short row reads as an app bug), and everything is reversible via the id manifest. The `usageDays` ledger is the exception worth knowing — it feeds the Dashboard, is priced through the real `foldUsageEvent`, and is written **only for days with no existing row**, so removal can never take a member's genuine activity with it.
- `hooks/useCloseOnAppSwitch.ts` — every body-portaled overlay (slide-over, picker, modal) must call it: portals escape the opacity-0 wrapper that hides background apps, so an open overlay would float over the next app after a dock switch.
- `lib/cloudSync.ts` — pull on sign-in + debounced diff-push + persistent localStorage outbox + non-destructive hydrate. `saveRow`/`deleteRow` are serialised per row (a stalled upsert can't land after a delete) and outbox markers are token-guarded (a late success can't clear a newer pending write). `walkAssetRefs` normalises `asset://` refs to bare ids so the sweep/reconcile match the bare-keyed `assets` table.
- `lib/supabase.ts` — `ensureFreshSession()` (3s race + cached-token fallback) and a custom non-blocking `auth.lock`.
- `hooks/useAssetUrl.ts` — resolves `asset://` refs to blob URLs.
- `UI_LAYOUT.md` (repo root) — spatial map of the rendered interface (pane splits, tab orders, button positions, modals) for every screen. Read it before any UI-driven / tutorial automation so you don't guess where a control sits.

## Banks

Persisted to `localStorage` under `ai-ugc-lab-banks`. Asset blobs live in IndexedDB (mirrored to R2 in cloud mode); rows store `asset://<id>` refs. `useAssetUrl(ref)` turns a ref into a blob URL. Types are in `stores/types.ts`.

`products`, `models` (from Influencers), `scripts`, `voices`, `brolls`, `styles`, plus auto-pushed history banks: `voiceHistory`, `videoHistory`, `imageHistory`, `musicHistory`, `scriptHistory`, `brollHistory`, `characterHistory`, `adAnatomyHistory`, and the Dashboard's `usageDays` ledger (all cloud-synced — every bank table has a Postgres mirror). Gotchas:

- **`usageDays`** — accumulate-only usage ledger: one row per local calendar day (`id: 'YYYY-MM-DD'`), holding per-kind generation counts + estimated kie credits + official-API USD. Written by `bankStore.recordUsage`, which is called inside the `add*History` actions (plus B-Roll's `finishImageTask` and the Ad Analyzer complete-flip) — new generation surfaces get counted for free if they push history. Deleting/clearing history never subtracts. One-time backfill from history (`backfillUsageLedger`, flag `ugc-lab:usage-backfill:<uid>`) runs post-hydrate in cloudSync (local-only: Dashboard mount) and skips ids in the mock-data manifest. Mock seeding suppresses live recording via `setUsageRecordingSuppressed`. Its Postgres table `usage_days` (migration 0016) uses a **composite PK (user_id, id)** because day keys repeat across users — run the migration before deploying, or every hydrate reports a per-table error (which also skips the auto orphan sweep).

- **Starring.** `products` / `models` / `scripts` / `brolls` / `styles` items carry `starred?: boolean` — flipped by bankStore's silent `toggleStar` (no toast) from a star button in the Bank cards' hover stack. Starred items sort first in every `BankPicker` (`starredFirst` in `finder/bankSort.ts`, amber badge on the card); the Bank browser's own sort order is deliberately untouched (B-Rolls are day-grouped).

- **`styles`** — visual looks for B-Roll (name + `brief` + up to four `thumbRefs`). The brief IS the style: it's the paragraph appended to every prompt rendered in that look, so it must describe the LOOK only, never anything from the frames it was read from. Thumbnails are this bank's own assets (nothing else links them), so delete/replace purges them outright. Postgres table `styles` (migration 0017) — run it before deploying, or every hydrate reports a per-table error (which also skips the auto orphan sweep).
- **`brolls`** — only **stills** are saveable to the bank (reusable as start frames / references); videos are download-only, so no UI writes new `videos[]` entries anymore (the save-to-bank action is hidden on video tiles in B-Roll + Playground). The `videos[]` field and its render/edit/cleanup paths stay for back-compat — older saved-video entries (and the video-only-broll render path in `BankList`) still display and download. Saved video-history items stamp `linkedBRollId`; deletion only purges the blob if not linked.
- **`videoHistory`** is shared by B-Roll and Playground (for refresh-resume); Playground's grid filters out `sourceApp === 'broll-studio'`. No automatic retention — entries persist until the user deletes/clears them. Only `brollHistory` is capped (`BROLL_HISTORY_CAP`, FIFO); the other history banks (`videoHistory`/`imageHistory`/`musicHistory`/…) grow unbounded, so an eventual cap is the most likely localStorage-quota mitigation if it's ever needed.
- **`characterHistory`** carries `imageRef` + the full `profile` snapshot; `linkedModelId` is set on save-to-bank and gates blob purge. Presets aren't a bank — reuse a recipe by saving to `models` and reloading via the Controls header dropdown. The nine built-in starters (`PRESET_*` in `character-studio/types.ts`) **fill all 28 fields and pick the starred option wherever the field offers one** — a one-word `skinTexture: 'Glass skin'` leaves the model to invent the rest and what it invents is the plastic look the presets exist to avoid, and an empty field drops out of the prompt entirely. "Starred" is `ChipField`'s `isDetailed` (a chip over 30 chars), so a preset value only shows as a picked row when it's EXACTLY one of that field's own detailed chips — which is why the age-appropriate skin tiers and the per-character hair styles were added to the chip lists rather than written as preset-only free text. `No makeup` on the men and the free-text `facialFeatures` / `distinguishingMarks` / `accessories` fields are correct as-is, not gaps.
- **`VoicePreset` / `VoiceHistoryItem`** carry the Gemini TTS param set (`voiceId` = `voice_name`, `style`, `pace`, `accent`, `temperature`, optional `scene` / `sampleContext`). `migrateVoiceShape` strips the legacy ElevenLabs numeric fields (`stability` / `similarityBoost` / `speed`, and the old numeric `style`) and backfills the new string defaults (`Natural` / `Natural` / `Neutral`, temp `1`).

## Auth + cloud sync

`AuthGate` wraps the app: bootstrapping → spinner; signed-out → `AuthScreen`; signed-in → workspace + `UserMenu`. No cloud env vars → local-only mode with a bottom banner. Full deploy stack is in `DEPLOYMENT.md`; threat model in `SECURITY.md`.

- **Onboarding.** `components/ApiKeyGuide.tsx` (menu-bar alert + the Dashboard banner) and `MeetTheTeam` both **take the kie.ai key inline** — they used to explain three steps and send the member to Settings, which left the intro with the one blocking task undone. Both go through `useKeyConnect` (exported from ApiKeyGuide): the key is checked against the live balance BEFORE it is saved, so nothing is ever stored that can't generate. Both are infra surfaces — a failed check shows kie.ai's own message, not `humanizeError` copy. `MeetTheTeam` stages the Create chain as a five-card pipeline with the blurbs in one hover-driven caption slot (eight rows of copy is a reading task, not an introduction); `components/apiKeySteps.tsx` is now only its read-only summary.
- **Allowlist.** Postgres trigger `enforce_allowlist` blocks signups not in `public.allowlist` (no client bypass). A global `public.app_config.enforce_allowlist` flag (Admin → Allowlist toggle) short-circuits the trigger when off — open signups while Zapier isn't wired; flip back on to re-gate. `on_allowlist_delete` sets `profiles.disabled_at` → app signs the user out on hydration; `on_allowlist_insert` clears it. A disabled account (sign-in or stale session) sets `authStore.accessRevoked`, and `AuthScreen` shows a "members only" popup linking to `SKOOL_COMMUNITY_URL`. Zapier syncs Skool events in. **Names:** signup collects First name + Surname → passed as auth user metadata; `on_auth_user_created` seeds `profiles.first_name/last_name` from the allowlist row, falling back to that metadata (migration 0015) so members who sign up with a non-Skool email are still identifiable.
- **Cloud sync** (`cloudSync.ts`). Pulls profile + all bank tables on sign-in. `bankStore` writes local (Zustand + localStorage) first, then fires the cloud push in the **background** — `pushRow`/`dropRow` are fire-and-forget (return `void`, never awaited). The UI must never `await` a cloud round-trip: awaiting it was the "save stuck loading, then times out after ~15s" hang, and it could drop the row on a mid-hang refresh. Durability comes from the outbox, not the await — `recordPendingUpsert`/`recordPendingDelete` persist the row to a per-user localStorage outbox (`ugc-lab:sync-outbox:<uid>`) **synchronously** before the push fires, so a failed/timed-out push is replayed by `drainOutbox()` (startup + tab focus + backoff timer) and overlaid onto the next hydrate. Background push failures are logged, not toasted — local is the source of truth, sync is eventual. **Hydrate is non-destructive:** a per-table fetch error keeps local rows (never `[]`), and outbox-pending rows are overlaid so an unsynced row survives a refresh.
- **Session freshness** (`supabase.ts`). Every cloud write awaits `ensureFreshSession()`, which races `getSession()` against a 3s timeout and falls back to a module-cached token (kept current by an `onAuthStateChange` listener) when the SDK's auth lock stalls after a backgrounded tab returns. The client also uses a custom `auth.lock` (`nonBlockingLock`, ~2s bound then runs unlocked) because supabase-js takes that lock on every request. `visibilitychange` recovers the token on focus.
- **kie.ai key is browser-local only.** Lives in `localStorage` under `ai-ugc-lab-settings`, never written to or read by Supabase/cloudSync. Users re-paste on each new browser. Deliberate trade-off: nothing in the DB ever holds the key.
- **Schema.** Bank tables are JSONB (id PK, user_id FK, project_ids[] GIN-indexed, data jsonb). RLS `auth.uid() = user_id` everywhere, admin bypass via `profiles.is_admin`. Admin app (Members + Insights + Allowlist) only renders for admins; the Members table and the Insights charts share one fetch via `apps/admin/useMembers.ts`.

## Inter-app payloads

One-shot handoffs. Sender calls `sendToApp({ targetApp, targetField, data })`. Consumer reads `interAppPayload` in a `useEffect` keyed on `activeApp`, dispatches on `targetField`, then calls `consumePayload()`. Wired: Ad Analyzer → Scripts (transcript) / Bank (productId) / B-Roll (`adBlueprint`: an `AdBlueprintPayload` — the analysed ad's transcript as the script plus its staging, which is now the ONLY source of `BrollInput.sceneStaging`, B-Roll's Ad Format picker having been removed; cleared by "New"); Scripts → Voiceovers (script text); B-Roll Bank → Playground (`videoStartFrame` opens video mode with the still as start frame + prompt prefilled); B-Roll video → Playground (`videoSourceClip`: a `VideoSourceClipPayload` asset ref + real clip duration → video mode switched to Gemini Omni with the clip attached as the trimmed `omni-clip` source clip — the "same take, dialogue in Spanish" redub loop; the asset ref survives refresh, unlike uploaded clips); Anywhere → Playground (`prompt`, `imageRef`, `videoStartFrame`).
