# CLAUDE.md — UGC OS

## Project Identity

You are building **UGC OS** — a browser-based, macOS-style workspace that unifies eight tools for UGC ad production into one environment with shared data banks. Every in-app AI call goes through **kie.ai**: one user-supplied Bearer key gives access to every model the app uses (chat, vision, image, video, TTS, music). The one exception is **Edit**, which generates nothing in the browser — it hands out a Claude skill the member runs locally.

**Who it's for / why.** A private Skool community of solo creators and small teams producing AI UGC ads at scale — access is gated by an email allowlist synced from Skool, so non-members can't sign up even with the URL. The pitch is one workspace instead of seven tabs: the same product, character, script, voice, and B-Roll flow across every app via the shared banks. Inference cost is on the member (BYO kie.ai key), so the operator only pays for hosting + storage.

Dock order: **Dashboard** (own 'system' group) | **Bank** | **the Create apps** (Characters → Scripts → Voiceovers → B-Roll → Playground → **Edit**, which closes the row — cut what you produced; Playground sits beside B-Roll because it's the other place footage gets made, so it belongs next to it rather than a divider away with the research tools) | **Tools** (Outliers → Ad Analyzer, in that order because the loop runs left to right: find a winning ad, then tear it down) | Settings utility tile. The dock groups **by `category`**, so moving an app between rows means changing that field, not just its array position — and `category` is also what splits Meet the Team into its Create pipeline and its on-call group, so the `TEAM` entry moves with it. Fresh visits land on the Dashboard (`DEFAULT_SLUG`). Display names are terse nouns, not action verbs. Folder names and the `id` strings in `src/utils/constants.ts` are **stable** — they key per-app model selections in localStorage. Do not rename them.

## Core Rules

**Code philosophy.** Simple > clever. Obvious > terse. Components small and single-purpose. No premature optimisation. Comments explain *why*, not *what*.

**Architecture.**
- **Self-contained apps.** Each app under `src/apps/<name>/` owns its types, components, and service. Cross-app communication goes through the bank store (persistent) or the inter-app payload (one-shot handoffs).
- **No prop drilling.** Zustand stores for global state; local React state for ephemeral UI.
- **Model registry is the single source of truth.** Add or change a model only by editing `src/utils/models.ts`. Don't sprinkle slugs through service files.

**Styling.** Tailwind only. Per-app accent palettes are custom Tailwind families (`influencers-*`, `scripts-*`, `voice-*`, `broll-*`, `playground-*`) defined in the `@theme` block of `index.css` (Ad Analyzer uses literal `#FF5257`); the matching hexes for sidebar/bank chrome live in `constants.ts`. Change an accent there, not by sprinkling new color classes. Tracking-tight text. Transitions 200–300 ms for panels, 150 ms for hover. Tags use `TAG_STYLES` from `models.ts` (Recommended green / New fuchsia / Fast sky / Cheap zinc). **Single-line inputs, select-style triggers, chips, and buttons are fully rounded (`rounded-full`), not rectangles** — Massimo's preferred aesthetic; multi-line textareas use `rounded-2xl`.

A full faint ring with one bright quarter (`border-2 border-current/25 border-t-current`, the shape Voiceovers' avatar rings already used) fixes it by construction: the silhouette is identical at every angle, so only the highlight travels. Two rules: **don't card a lone control** — the border is what says "these belong together", and around one row it says nothing for 24px — and **don't card what isn't part of the group** (the free-text steer boxes stay outside; they're where you type, not what you attach). A card that holds a growing box takes plain `flex-1`, never `flex-1 basis-0`: with basis-0 it splits the leftover evenly with its sibling and the box inside pays for the card's other rows out of its own height. The floor still lives on the **section**, as everywhere else — a card whose root is `min-h-0` on top of a `min-h-0` content column lets its growing child collapse to nothing.
- `StatusDot` / `SectionLabel` (same file) — Influencers' filled/empty field dot, with a third state the other panels need. Influencers' 28 fields are all the same kind of optional, so empty is always red; every other column mixes inputs that GATE the run with ones that don't, and a red dot on something nothing is waiting for reads as an error to go and fix. So: **green** filled · **red** required and empty · **neutral** optional and empty, and red means exactly one thing — "this is why Generate is grey". The dot rides at the row's own left edge (before the icon disc), so a card's dots stack into one column you can scan without reading a word; the ~14px inset that costs each row is deliberate, and part of what makes the contents read as inside the card. Only put a dot where it can ever be red or neutral — Voiceovers' Voice/Style/Pace/Accent always hold a value, and a permanent row of green dots is decoration that teaches members to stop reading dots. Same reason Playground's frame slots have none: a picture versus a dashed box already outshouts a 6px dot, which is also why the reference slot cards in every B-Roll and Characters modal carry none. `filled` is **optional** — omit it for a row that needs the label and no dot (the convention `RefGroup` already used). The honest reds in the modals are exactly three: B-Roll's Animate **Start frame**, Continuous' two clip **keyframe** endpoints, and Playground's Motion Control pair — each one really is why that Generate is grey or why the run refuses. Continuous' Animate **Motion** box deliberately stays neutral-when-empty, because it does *not* gate that button.

Never a left-aligned heading with a hairline rule — that shape was tried on the two card grids and read as a divider between unrelated blocks. `className` sets the vertical margin only (pass `""` when the list already spaces its groups).
- `components/ModelPill.tsx` — **the one way a FINISHED output names the model that made it.** Three variants: `media` (literal white-on-black, for a pill sitting on a still or clip), `chrome` (a panel surface, one step brighter than the meta pills beside it — the model is the answer being looked for, the resolution and aspect are the fine print), and `quiet` (no pill at all, dim text, for a caption line UNDER a card where the model rides beside a label of its own). No backdrop-blur, since every one of these fades with its card's hover and blur stutters under an opacity transition (same reason `TileActionStack` drops it). Wired on Playground's history **list rows only** (the grid is a wall of pictures; a caption on each is chrome the grid exists to avoid), in Playground's **preview modal** — the one place a grid tile does name its model, since the tile it was opened from can't, and the modal is where a clip is actually judged (`media` variant, because that modal is a literal black overlay in both themes; it takes `shrink-0`, or the side column's overflow squashes a 19px pill to 5px) — and on B-Roll's Continuous card faces + card-detail gallery tiles — bottom-left, `group-hover:opacity-0`, because on every one of those faces the hover action row lands on that exact strip. **B-Roll's Line-by-Line variation cards are the exception and use `quiet`** (August 2026): they already carry an A-Roll / B-Roll caption under the picture, so the model joins it there — a white-on-black chip was the loudest thing on a still whose whole job is to be judged, and on that face it had to fade on hover anyway. **In-flight surfaces are deliberately NOT routed through it** (`GeneratingMedia`, `GeneratingTile`, the in-flight list rows all name their model in their own layout): they report on work in progress, and a member watching a generation can't be shown less than one watching a finished tile. Visibility comes from `stores/generationInfoStore.ts` — per-browser, own localStorage key, ON unless an explicit `'off'` is stored, and the switch renders **only** on the operator-only gate Settings → Advanced already uses for the demo seeder (`!isCloudEnabled() || is_admin`). It exists for screen recording, where naming the model on every tile is one more thing on camera; a member has no reason to want their own outputs unlabelled, which is why they never see the row.
- `BracketHighlightArea` (`components/ExpandableText.tsx`) — the prompt field that paints `[bracketed placeholders]` red, used by Playground's inline prompt box and by `ExpandTextModal`. **The textarea never scrolls itself:** it's grown to its full content height and the WRAPPER scrolls, carrying the highlight layer and the text on one compositor scroll. The obvious shape — a scrolling textarea whose overlay is synced from its `onScroll` — always lands a frame or more behind (the browser scrolls the field off-main-thread and hands JS the event afterwards), and the red boxes visibly chase the words. The cost of the fix is that the browser no longer reveals the caret for us, so `revealCaret` does it on every text change and on the caret-moving keys; a drag-select past the edge doesn't auto-scroll. Both layers take the same `padClass`/`textClass` and the scrollbar gutter is on the wrapper, so they wrap identically by construction.
- `components/AutoGrowTextarea.tsx` — **a field inside a scrolling form grows, it doesn't scroll.** A textarea that scrolls internally is a scroll trap: the wheel over it moves the field, not the column, so a form whose boxes are all full (an auto-filled product) can't be scrolled by dragging through the middle of it. Drop-in for `<textarea>`; the optional `maxHeight` is for a paste box with no natural ceiling (the Bank's Listing copy), where scrolling past the cap is the right answer. It re-measures on a **width** change as well as on a window resize, via a `ResizeObserver` (height-only changes are its own doing and are ignored, or it would loop): a field that mounts inside the mobile pane swap's `display: none` half measures a `scrollHeight` of 0 and would otherwise stay an 8px sliver forever, since showing that pane fires no resize event. Used by `ProductForm`'s section fields and `ModelForm`'s DNA rows. The other half of the same rule lives in the panel input columns: a box that owns leftover height takes `flex-1 basis-0` with the **floor on the section** (`min-h-[…]`), never `min-h-0` on the section plus a min-height on the textarea — that pair lets the section collapse while the field holds its floor, and the box's `overflow-hidden` then slices its own footer toolbar.
- **A history panel next to an input panel is `memo`'d, and its props are stable.** The history banks are uncapped (only `brollHistory` has a cap), so a working member's gallery is hundreds of rows, each with its own asset lookup — and it sits in the same component as the box they're typing into. One fresh callback identity per render means every character typed re-renders the whole list: measured at ~70 ms (Playground) and ~85 ms (Characters) per keystroke at 300 items, versus ~4–10 ms once the subtree is skipped. `PlaygroundHistoryGrid` and Characters' `GalleryPanel` are the two wired this way — `memo` on the panel, `useCallback` with only stable deps on every handler it takes, and the live draft read through a ref rather than closed over. The React Compiler does this on its own for components it can compile, so the explicit `memo` is a belt-and-braces for the app roots that still bail (see Tech Stack).
- **A batch strip is ONE line that scrolls, at every width** (B-Roll's two storyboard strips). Four pills wrapped to two or three rows at 375px, which is 40px of chrome per extra row on the screen with the least to give; the work reads as a sequence anyway, so swiping along it is closer to what it is than stacking it. The row takes `w-full overflow-x-auto scrollbar-hide` with `-mx-5 px-5` (so it scrolls edge to edge while its first and last pills sit on the panel's own inset) and each pill takes `shrink-0`. `w-max min-w-full` on the inner row is what lets it be *placed* and scrollable at once: at `min-w-full` the row is exactly the port when it fits, so a `flex-1` spacer (or `justify-center`) can do its work, and exactly its content when it doesn't, so the spacer collapses and the scroll starts at pill one. A plain `justify-center` inside a scroll port centres the OVERFLOW too, which strands the first pill off the left edge with no way to scroll back to it. **The Line-by-Line strip is the current shape**: style pill left, actions right, meta and buttons on the same line at every width — which works only because NOTHING on the line shrinks (the meta included), so the collision that drove the meta off this bar twice before simply can't be expressed. Its three generate passes live behind one **Generate all** menu; three long labels were ~450px, most of the panel at every width the right pane actually gets, and they're mutually exclusive in practice. Continuous' strip has not been brought across yet.
- `components/MobilePaneTabs.tsx` — **on a phone a two-pane app shows ONE pane at a time.** Every workspace app is a desktop split: what you fill in on the left, what comes out on the right. Stacking those two columns under `md` was tried first and doesn't work — each panel is built as a full-height column with its own internal scroll and a pinned footer, so stacked they collapse into a pair of ~200px scroll windows with the Generate bar lying across the fields it belongs to, and the output pane sits below a fold nobody finds. The bar is `md:hidden` and the panes swap with `hidden md:flex` (`paneClass`, same file), so there is no JS media query and the desktop layout is untouched by construction — `paneClass` deliberately sets nothing on `flex` above `md`, leaving each app's own `md:w-1/2` / `md:flex-1` to win. Wired in Characters (Controls / Gallery), Scripts (Setup / Output), Voiceovers (Script / Voice), B-Roll (Setup / Storyboard), Playground (Prompt / History) and Ad Analyzer (Analyses / Analysis). **Firing Generate flips to the output pane** — on a phone that's the only way to see the thing you just paid for.
- `hooks/useChromeAutoHide.ts` + `stores/chromeStore.ts` — **on a phone, scrolling down rolls the DOCK away and a sustained scroll up hands it back. Nothing else moves.** A phone gives the workspace ~812px and the dock takes ~98 of them before an app draws a pixel. `useChromeAutoHide` (mounted once in `App.tsx`) listens for scroll in the **capture phase on window** — scroll doesn't bubble but it does capture, so one listener covers every scroller in the app without each one opting in — and only answers to scrollers inside `[data-app-pane="active"]`, so a body-portaled modal's own scrolling can't strand the dock hidden behind it. `NEVER_HIDE_IN` exempts whole apps — Edit and the Dashboard are one screen each, where hiding the dock hands the pane ~98px it has no use for and the page visibly jumps under a thumb that was only nudging it.
  **A panel's own toggle header lives OUTSIDE its phone scroller.** Four input panels made their ROOT the `max-md:overflow-y-auto` box (so the fields and the Generate band read as one page), which put the `h-[57px]` tab bar inside it — and that bar then scrolled away with the fields, taking the way back to the other tab with it. B-Roll, Characters, Scripts and Playground all now keep the header as a sibling and wrap everything below it in `<div className="flex min-h-0 flex-1 flex-col max-md:overflow-y-auto">`. Above `md` that wrapper is inert and each panel's own inner scroller still does the work.
  **The dock is the only thing that hides, and that boundary is the whole design** (Massimo's call, August 2026, after two passes took too much). The menu bar stays: `App.tsx`'s pane insets go `bottom-[~98px]` → `bottom-0` and the top stays at `top-9` in every state, because the menu bar is `fixed` and opaque, so a pane that also claimed its 36px only slid each app's **first row** out of sight behind it — the Setup/Storyboard tabs on a two-pane app, the platform tabs in Outliers. And nothing inside an app hides either: a `CollapsingBar` wrapped the search / filter / sort rows for a week (Outliers' vault and platform filters, B-Roll's history search + mode pills + sort, Scripts' and Voiceovers' history search, the Ad Analyzer rail's phone row) and the component is **deleted** — a bar that rolls away going down and unrolls coming back up moves the list under the thumb reading it, and every one of those rows is now a plain static row. `MobilePaneTabs` and the `h-[57px]` panel headers had already lost theirs for the older version of the same reason: that bar is how you reach the other half of the app. **Don't reintroduce any of it** — the phone's answer to a crowded surface is a shorter bar (see the vault's two-row filter panel), not a bar that comes and goes.
  **A scroll the app started itself is not a gesture either** (`suspendChromeAutoHide`, same file). An in-app jump — the Ad Analyzer's Breakdown / Transcript / Scenes toggle, Characters' tab jump, `ProductForm`'s section jump, Scripts' scroll to Generate — travels most of a screen in one direction, which from inside the tracker is indistinguishable from a deliberate swipe down. So the dock hid MID-ANIMATION, the pane's inset went 98px → 0, and the browser's own smooth scroll relayouted underneath itself: measured on the Ad Analyzer at 375px, a jump to Scenes landed **670px past** its target from the top of the read and did **nothing at all** from halfway down. Every such call site announces itself and the dock simply holds still for the length of the jump — which is right anyway, since the member tapped a tab rather than swiping. **Any new programmatic scroll inside the pane has to call it.**
  Four things keep the dock from twitching. Direction has to be sustained, and **asymmetrically** — `HIDE_TRAVEL_PX` is a nudge (40px) where `SHOW_TRAVEL_PX` is about a third of a screen (260px), because showing the dock puts it back over the Generate button the member was reaching for, so a false positive costs more than a missed one; the accumulator resets on every direction change. The top of a scroller always shows it. It won't hide for a scroller with less than `MIN_OVERFLOW_PX` of overflow. And **a scroll nobody made is not a gesture**: every flip mutes the tracker for `SETTLE_MS` (hiding the dock makes the pane taller, which shortens every scroller inside it, so a list parked near its end is CLAMPED back up by the browser — without the mute that reads as "scrolled up", which shows the dock, which shrinks the pane again, and the dock flaps once a frame), and `lastMax` catches the same clamp arriving late or from elsewhere (a mobile URL bar, the keyboard closing, a lazily-sized tile resolving) by discarding an upward delta no bigger than the height the scroller just LOST. That test is deliberately narrow rather than "any event where the extent changed": the grids run `content-visibility: auto`, so their `scrollHeight` moves under every scroll and the blunter version threw real gestures away. The inset flip is **deliberately not transitioned** — `bottom` is layout, and relayouting a whole storyboard every frame for 300ms is the one thing this was supposed to buy back. Above `md` none of it applies.
- **`touch:` is how a hover-only affordance stays reachable** (`@custom-variant touch (@media (hover: none))`, `index.css`). On a phone there is no pointer to hover with and a tap goes to whatever the tile itself does, so a `group-hover` reveal isn't merely hidden there — it's unreachable. Two shapes, and which one to use depends on how many controls are behind it. A LONE control just appears: `touch:opacity-100` on the remove button of a reference thumbnail or a frame slot, the Bank's "Animate in Playground" pill, the Voiceovers history row actions and its scrubber thumb, the character name on a gallery tile. A COLUMN of them gets a **doorway** instead — `TileActionStack` renders a touch-only `⋯` that opens the stack (`TouchDisclosure`, `components/tileActions.tsx`), because showing all four circles is 140px of chrome down the side of a tile, permanently, over the still it exists to let you judge. The disclosure carries its own `display` rather than a `useIsTouch()`: under a pointer it is `display: none`, so it can never be pressed, `open` can never become true, and the hover behaviour is untouched by construction. **A `touch:` that MOVES something has to move whatever was clearing it too.** B-Roll's centred type chip dropped to `touch:top-11` to get out of the top corners (where the touch disclosure is permanent and a video cover's play button sits opposite it) — and the text face under it kept the `pt-9` that cleared the chip's desktop position, so on a phone the tag sat squarely across the second line of the prompt. **Both came back to the top row in August 2026**: the phone storyboard is `grid-cols-2`, which leaves a clear lane between the two corner buttons, and a chip a row down read as floating in the middle of the still rather than labelling it. The two numbers are still a pair; change one and check the other. While the stack is shut its children take `pointer-events-none` on touch — an `opacity-0` button still swallows taps, which under a pointer never shows because hovering reveals the column anyway.
- **`max-md:` is where a growing box stops sharing height.** The input columns hand their leftover height to the boxes that grow (`flex-1`, `flex-1 basis-0`, `flex-[5]`). On a phone there IS no leftover — the column is shorter than its own contents — so `flex-1` just squeezes every box until the card's `overflow-hidden` slices it. Under `md` those boxes take `max-md:flex-none` plus a real `max-md:min-h-[…]` floor and the column scrolls. The floor still lives on the section, exactly as on desktop. The same shortage decides where a **generate band** goes: on a desktop it's the column's pinned footer, but on a phone a column that's already too short for its own fields can't also lend the bottom of the screen to a settings row and a button — so B-Roll's band moved INSIDE the scroll (August 2026, a `max-md:overflow-y-auto` wrapper around the inputs column and the band; the inputs column keeps its own `md:overflow-y-auto`). It is simply the end of the page there: fill the fields in, keep scrolling, press Generate. The `h-[57px]` header above it stays outside the wrapper and stays pinned.
- **A wide data table becomes a CARD LIST below `md`, never a sideways scroller** (Admin's Members and Allowlist, August 2026). A ten-column table has nowhere to go on a phone: made to scroll horizontally, the name is off screen the moment you reach for the status, which is the one pairing the table exists to show. So the `<table>` takes `hidden md:block` and a `md:hidden` list of cards renders beside it — identity and status on the first line, the remaining columns as a two-up meta grid, then the row's own actions at full card width (a 24px text button is a desktop target). Two things the table gave away for free have to be rebuilt: **sort**, which lived in the clickable column headers and comes back as a `Dropdown` + direction toggle on its own phone row, and **select-all**, which lived in the header checkbox and joins that row. Long values that identify a record (an email) wrap with `break-all` rather than truncate — the local part is the half you're reading. Keep the actions in ONE shared component used by both shapes, or the table and the card drift apart.
- **A bare `grid` is a horizontal-overflow bug waiting to happen.** With no `grid-template-columns` the children land in an *implicit* `auto` track whose floor is the widest child's **min-content** — and a `truncate` span's min-content is its whole nowrap sentence, since `min-w-0` is a floor override, not a cap on intrinsic contribution. Admin's announcement editor (`grid gap-5 lg:grid-cols-[…]`, unstyled below `lg`) grew its one track past the viewport and scrolled the entire pane sideways, taking the panel's left inset with it. Always declare the small-screen columns too — `grid-cols-1` is `repeat(1, minmax(0,1fr))`, which caps the track. And prefer **wrapping a hint under its label** on a phone over truncating it: a hint you can't read is chrome.
- **The gap above a generate band belongs to the BAND, not to the scrolling column** (`pt-2` on the band, `pb-0` on the scroller — Scripts, B-Roll and Playground). Padding on the bottom of a scroll container is part of the scrolled content, so it slides out of view the moment the column overflows — which is its normal state once a member pastes a script or picks an input-heavy model. Measured in Scripts: the last input box sat **2.5px** off the band at scroll-top (reading as touching, which is how it was reported) and 8.5px scrolled to the bottom. A gap that changes as you scroll isn't a gap. On the band it is always exactly 8px, because it renders below the scroller's clip edge where nothing can scroll it away.
- **An app fills its pane exactly — one scroller, the app's own** (`h-full` inside `App.tsx`'s per-app wrapper, with **no layout floor under it**). A `min-h-[600px]` floor lived there for a while so that browser zoom — a short viewport in CSS px; 200% on a laptop leaves ~450px, which members do to make the UI readable on camera — scrolled the whole app instead of crushing its scrolling middle (Scripts' input column measured a **20px** scroll port against 606px of content). It came out in August 2026 because of what it cost below the floor: the pane became a **second scroller wrapping the entire app**, and every piece of pinned chrome inside — B-Roll's Storyboard/History header and its `sticky` "N Scenes" batch bar most visibly — slid up the screen as the member scrolled the storyboard. A bar that is `sticky` inside a panel cannot hold its ground against a scroller ABOVE that panel, and the two ports rubber-band against each other in between; it was reported as the bar being "elastic". Chrome that stays pinned is worth more than a graceful 450px viewport, and each panel's own column still scrolls at zoom. **Don't reintroduce a height floor here** — fix a crushed column on the column. The other half of the same rule survives: **no app footer may be `position: fixed`.** Scripts' was, under `md` only, and at 200% zoom it detached to the window's bottom edge and covered the whole input column; it's a static `shrink-0` band like every other app's now.
- **`backdrop-filter` is for small chrome, and `filter: blur()` never animates.** The one rule behind a whole class of "the app feels laggy" reports, fixed in August 2026. A `backdrop-filter` element is a **backdrop root**: a repaint anywhere inside it invalidates its entire backdrop. `App.tsx`'s workspace pane — which contains the whole workspace — carried `backdrop-blur-xl`, so every animating pixel in every app dragged a full-viewport filter recompute behind it. What it bought was nothing: behind it is `AppBackground`, a smooth dithered gradient, and a blurred smooth gradient is the same gradient. It's a plain unpainted pane now (the rounded, bordered floating "window" frame around it came off in August 2026 too — the pane fills the space between the menu bar and the dock flush, so nothing draws a box around the apps), and removing it is why generation animations stopped stuttering, why zoom stopped lagging (a zoom re-rasters everything, backdrops included), and why images stopped looking blocky — a browser under that much compositing pressure drops its raster scale. Keep `backdrop-filter` on small static chrome over real content, and never put one on a full-window container. **`GeneratingBackdrop`'s three `blur-2xl` blobs are the deliberate exception** and are NOT to be "optimised" again: they were rewritten as radial gradients on exactly this reasoning (three animated blur filters per tile, on a surface whose job is to appear a dozen at a time) and it was reverted within the hour, because a gradient's falloff is a linear ramp where a Gaussian blur's is a smooth curve — the plateau edge reads as banded lobes instead of one soft wash, and this is a glow whose whole job is to look good while someone waits. Their bulk cost is handled where it actually bites, by `offscreen-idle` (`content-visibility: auto`, #459) skipping tiles that are off screen. **The on-screen half was paid down in August 2026 by taking the `scale()` out of the `blob-drift-*` keyframes**, exactly as this note had said to do first: scaling re-rasters a blurred layer every frame, translating one is a compositor move of a texture that already exists, and a clip batch puts a backdrop on every card at once. The reach the scale used to give is baked into each blob's own width/height instead; what's gone is the breathe, and the drift that stayed is the half that reads as movement. The blur itself is still untouchable — if this ever needs to come down further, take an animated blob out entirely rather than lowering `blur-2xl` or going back to gradients.
- **Chrome that must not move lives OUTSIDE the scroller, not `sticky` inside it.** B-Roll's two storyboard strips were `sticky top-0` glass bars inside the scroll port, and they visibly came loose from the top edge on the way back up a long storyboard: a backdrop-filter element re-samples its backdrop on the main thread while the scroller is scrolled by the compositor, so the bar lagged its own container by a frame or two and snapped back. Both are static `shrink-0` rows above the scroll port now — a sibling of the scrolling box, exactly like the panel header above them — which makes the pinning structural rather than something the compositor has to keep agreeing to. Ask first whether the bar ever actually scrolls away: neither of these did (both were pinned at `top-0` from the first pixel), so `sticky` was buying nothing but the artifact. The cost is that content no longer passes under them blurred, so they take the **opaque** fill (glass over a panel background that never moves is a backdrop root's cost for no picture) and keep `relative z-20` so a card's own positioned hover chrome can't paint over them. When a bar genuinely does have to scroll away and come back, `sticky` is still the tool — just don't also make it glass.
- **Pinned panel chrome is glass, and anything that FADES on hover is not.** Two halves of one backdrop-filter rule. A bar that stays put over content it doesn't scroll with (B-Roll's panel header) takes `supports-[backdrop-filter]:bg-surface-0/80 + backdrop-blur-xl + backdrop-saturate-150` over an opaque `bg-surface-0` fallback: content passing under it blurred is what makes it read as a fixed pane of the panel rather than a card-shaped hole, and a nested backdrop-filter DOES blur inside a parent `backdrop-blur-xl` (the earlier "it can't re-blur" note was wrong — what made a translucent strip read as scrolling was too little blur and no saturation). The opposite holds for anything animating its own opacity: a backdrop-filter re-samples its backdrop every frame, so a hover-faded overlay over a real generated still stutters — which is why `TileActionStack` has never had one, and why B-Roll's variation-card shortcut row, tag chip and status badges dropped theirs (an empty card never showed it; a flat face is nothing to blur).
- **Fields render at 13px under `md`, and the viewport is capped at `maximum-scale=1`** (one rule at the bottom of `index.css`, one meta tag in `index.html` — they are ONE fix and only work together). iOS Safari zooms the page in whenever a focused field's font-size is under 16px and never zooms back out, so the app's 12–14px chrome type made every prompt box a one-way trip into a zoomed viewport with the dock off screen. That was bought off with a blanket 16px until August 2026, and the biggest boxes paid for it: B-Roll's 13px script field rendering at 16px is a fifth fewer lines of a pasted script, on the screen where lines matter most. The viewport cap holds the zoom off instead — it does not take pinch-zoom away, since Safari has ignored scale caps for user-initiated gestures since iOS 10 — which frees the fields to render at the app's own field size. It is a FLOOR, not a size: nothing on a phone is smaller than a desktop field and nothing is bigger, and the rule only lifts the 11–12px compact controls to something a thumb can hit. Don't put 16px back without also removing the cap. **The old blanket rule was still in the file for a month after the floor landed and silently won the whole time** — `font-size: 16px !important` on `input, textarea, select` under 1024px, from the first commit — because `!important` outranks the floor whatever the source order, so nothing about #501 actually reached a phone until it was deleted (August 2026, reported as "the text is a bit too big in all the forms"). This rule is also **unlayered**, where every Tailwind utility sits in `@layer utilities`, so it beats a `text-base` on the element too: the field size on a phone is set HERE and nowhere else. **A highlight mirror is a DIV and the rule can't reach it, so it opts in with `.field-mirror`** — declared in the same block, because a mirror that renders a point off its textarea wraps on a different character and every wash slides further off its word the further down the paragraph you read. `TokenField` carried its own `max-lg:text-[16px]` — the size the floor used to impose, at a breakpoint it no longer uses — and painted Scripts' `[CHARACTER]` washes from a 16px copy of a 13px paragraph, landing them lines away from their tokens (fixed August 2026); `BracketHighlightArea` had the milder 14-against-13 version in `ExpandTextModal`. Don't set a phone size on a mirror in its own component.
- **A touch screen reserves no scrollbar gutter** (`@media (hover: none)` at the top of `index.css`, plus an early return in `utils/autoHideScrollbars.ts`). Native webkit scrollbars are kept invisible but 11px wide, so the layout doesn't shift when one appears — and that 11px is real layout, taken out of every scroller's width. On a phone it bought nothing (there's no pointer to drag one with) and cost two things: 11px off every grid, and a visible STEP down the right edge wherever a bar pinned INSIDE a scroller sat under one outside it — the Ad Analyzer's sticky section toggle painted 11px short of the pane while the pane tabs above it ran full width.
- **Nothing rubber-bands** (`overscroll-behavior: none` on `html, body, #root` and on the overflow utilities, `index.css`). Pulling past the end of a scroller on a phone dragged the surface up and showed a band of empty page under it — reported on the Dashboard and Edit, where the pane's own scroller is the one being pulled. It also stops a nested scroller chaining its leftover scroll into its parent, which is the other half of the same feel.
- **Anything anchored to the bottom of the window holds back `env(safe-area-inset-bottom)`.** In a browser tab that inset is 0 — the browser's own bar owns the strip — so nothing changes and the numbers are what they always were. INSTALLED to an iPhone home screen it isn't: `viewport-fit=cover` plus no browser bar means the page runs to the physical bottom edge and the inset reports the ~34px the home indicator sits in. The **dock** has always padded itself up by `max(env(safe-area-inset-bottom),0.5rem)`, but `App.tsx`'s workspace pane reserved a flat pixel count for it — nav height plus that floor — so installed, the dock stood ~22px taller than the pane held back and **covered the bottom of every pinned Generate button**. The pane now uses the dock's own expression (`calc(90px+max(env(safe-area-inset-bottom),0.5rem))`), so the two derive from the same numbers and can't drift — change the dock's own padding and this has to move with it; it keeps the bare inset even with the dock rolled away, since content under the home indicator is content you can't reliably touch. `SlideOver` takes `pb-[env(safe-area-inset-bottom)]` on the PANEL (not its footer), so the scrolling list and the footer both end above it. A new bottom-anchored surface needs the same.
- **The app installs as ONE app** (`public/manifest.webmanifest` + the iOS meta tags in `index.html`). Without a manifest, iOS gives a home-screen web clip a scope of the exact URL it was saved at, so the first in-app route change reads as leaving the app and Safari pops its in-app browser chrome over the top — the URL, a back chevron and a reload, on every dock switch. `scope: "/"` covers every route the router can push and `display: standalone` drops the chrome. The status bar is `black`, not `black-translucent`: the menu bar is `fixed top-0` at 36px, and translucent would put the clock and the battery on top of it.
- **`.glass-fill` (`index.css`) is the one definition of frosted glass**, and it dresses the two accent-filled surfaces in the app: the dock's app tiles and every primary Generate CTA. It lays two background-image layers — a broad diffuse bloom off the top-left, then a body gradient from lit top to shaded bottom — over whatever `background-color` the element already carries, so ONE class works for a dock tile (an inline hex) and a `bg-broll-500` button alike. Deliberately not a tight bright glint: a hot specular reads as polished gloss, and what makes glass read as *frosted* is a diffuse, milky highlight. Strength rides on three custom properties rather than a forked class, and `.glass-fill-soft` turns them down for a **broad** surface: the defaults are set for a 48px tile, where the falloff crosses the whole shape and reads as thickness, but stretched across a 400px pill the identical ramp becomes a vignette. The **rim is not in the class**, because the two callers need different ones — a squircle takes an inset box-shadow that follows its contour, a pill already draws its own `inset 0 1px 0` — and a linear-gradient rim would cut a straight band across a rounded top and read as a seam. Both rims are LIT (top brighter than bottom) with the shaded band just *above* the bottom one: light entering the top of a solid piece of glass exits along its far edge, so a dark bottom rim reads as a printed sticker. The light-mode CTA rims are repeated inside `btn-soft-shadow`, which is unlayered and therefore REPLACES the button's own `shadow-[…]` utility there — change one and change the other, or a light-mode CTA loses its rims. **A solid accent CTA hovers with `hover:brightness-110`, never with a tint token.** Every one of them hovered to `bg-<accent>-400`, and the accent ramp's 100–400 tints FLIP direction between themes (they darken in light mode so a tint stays legible on white) — so the same class lightened in dark (oklab L 0.604 → 0.683) and DARKENED in light (0.604 → 0.574), on a button whose saturated fill and white label are identical in both. The Ad Analyzer's `hover:bg-[#FF5257]/90` had the mirror-image bug: the same colour at 90% alpha darkens over a dark page. `brightness` is theme-independent by construction — it lifts whatever is painted, glass layers included — and Tailwind wraps it in `@media (hover: hover)`, so a phone never sticks in the hovered state. Pair it with `disabled:hover:brightness-100` wherever the button has a disabled state, and make sure the button's transition is `transition-all`: `filter` is not a colour and never fades under `transition-colors`.
- **A deploy must never white-screen a member mid-session** (`components/AppErrorBoundary.tsx` + `hooks/useAppUpdateCheck.ts`, August 2026). Every dock app is a hash-named lazy chunk, so a deploy renames all of them — and a tab left open across one asks for a file that no longer exists the first time it opens an app it hadn't opened yet. Vercel's SPA rewrite answers that request with `index.html`, so the import dies on a MIME error rather than a 404, and with nothing catching it above `<Suspense>` React unmounted the entire tree: the blank page members were refreshing their way out of, with no idea why. Two halves. `AppErrorBoundary` wraps **each app pane** (and the root, as a floor), so the blast radius is one pane — every other app stays mounted with its work in it — and it renders **"UGC OS was updated / Reload"**, because to the member this is not an error. Don't give it a retry: the chunk is gone, and only a reload learns the new names. The other half gets in FRONT of that — `vite.config.ts` bakes a `BUILD_ID` into the bundle and emits the same value as `/version.json`, and `useAppUpdateCheck` re-reads that file every 10 minutes and whenever the tab comes back to the front (which is where most deploys are caught: the tab was backgrounded for the whole thing), raising a dismissible pill the moment the two disagree. Vite's own `vite:preloadError` arms the same pill. The reload leaves a `sessionStorage` crumb so the fresh load can toast what it was for — a page that reloads itself and says nothing is its own kind of confusing. Everything hangs off the build id being **different per build** and `/version.json` being served **uncached** (see `vercel.json` and `DEPLOYMENT.md`).
- `hooks/useCloseOnEscape.ts` — every dismissible overlay takes it, alongside the existing backdrop click (and `useCloseOnAppSwitch` when body-portaled).
- `hooks/useBackdropClose.ts` — **the only way a backdrop may close its overlay.** Never write `onClick={onClose}` on a backdrop: a text-selection drag that starts inside the panel and releases over the backdrop fires a `click` on their common ancestor (the backdrop), so a bare handler closes the overlay and throws the member's edit away — `stopPropagation` on the panel can't help, since that click never originated there. The hook closes only when mousedown and click report the **same target**, which leaves every existing dismiss path intact (including the lightboxes, which dismiss on clicks bubbling up from a transparent centering wrapper — `e.target === e.currentTarget` would have silently killed those). It keeps the panel-side contract unchanged: a panel that must not dismiss still needs its own `onClick={(e) => e.stopPropagation()}`. Call it at the top of the component, above any early `return null`, then spread onto the backdrop. Sibling backdrops (`<div className="fixed inset-0" onClick={onClose} />` with no children, as in `SlideOver` / `BankPicker` / `ModelSidePanel` / `AnchoredPopover`) can't exhibit the bug and are left alone.
- `hooks/useInlineVideo.ts` — **one clip plays at a time, app-wide.** Every video tile that can make noise (B-Roll's variation + clip cards, the detail-modal galleries, Playground's history grid) uses `useInlineVideo`: spread `hoverProps` on the tile root (never the `<video>` — the overlay buttons aren't its DOM children, so hovering one would read as a mouseleave) and `videoProps` on the element. Hover autoplays muted; the Play button is a user gesture, so it plays with sound, claims the single module-level playback slot, and pauses whoever held it (across apps — background apps stay mounted). A silent hover preview stands down while another clip holds the slot, and Play only *pauses* what it started, so clicking it during a preview means "let me hear it". `watching` (playing **and** unmuted) is the "user is watching this" flag: pass it to `TileActionStack hidden={…}` and hide the tile's other hover affordances, leaving only play/pause + mute on the media. **Nothing opts into `hidden` any more** — Playground's history grid, B-Roll's variation cards, the Continuous clip cards and the modal galleries all keep their actions on screen while a clip plays. Watching a take is exactly when you decide to keep it, and having Download / Save / Copy / Delete vanish under the pointer meant pausing to reach them. Every one of those stacks is top-right, clear of the play/pause + mute buttons on the left, and still only fades in on hover, so it never covers a clip you're merely watching. The prop stays on `TileActionStack` for a surface that genuinely wants it; think twice before using it. Players that keep native `controls` (the Playground lightbox, the Ad Analyzer source clip) take `useExclusiveVideo` for the same one-at-a-time rule and nothing else.
- `components/Dropdown.tsx` — the rounded-full select, portaled through `AnchoredPopover` so it escapes a scrolling panel's clip. `placement='above'` pins the menu upward regardless of viewport room — `AnchoredPopover`'s default 'auto' measures against the viewport, so on a tall screen a footer menu "fits" below while still covering the Generate button you're heading for. Takes an `accent` (voice / scripts / broll, plus `neutral` for chrome that belongs to no app) and an optional dim `label` inside the trigger, for a control whose value alone ("3", "30s") doesn't say what it sets. Options are plain strings, or `{ value, label }` pairs when the stored value is a code ('US', 'VIDEO') rather than the words on screen. `fitContent` shrinks the trigger to its own content for a wrapping filter row (and gives the menu a width floor, since such a trigger can be narrower than its longest option); `menuMinWidth` raises that floor for a list whose options run much longer than the trigger — the Outlier Vault's hook patterns carry a count after the name, and the default 168px clipped "Conditional callout 76" to "Conditional callou…". Only the menu moves, so the filter row keeps its shape. It lived in `voice-studio/` until Scripts paired two of them above its Generate button. **It is the app's only select** — a native `<select>` renders the browser's own unstyled popup, which ignores the theme entirely; Outliers' filter row was the last one and came across in July 2026. **Reach for it when a segmented toggle would cost a full-width slab** — Scripts' Variations and Length were two 48px `SegmentedToggle`s stacked over Generate in a column that also has to fit a brief; as dropdowns they're one 36px row, and neither is a control you sweep through.
- `components/ConstraintChip.tsx` — the compact aspect / duration / resolution / audio picker on every generate bar. **Click-only, and it must stay that way.** Playground's footer chips opted into hover-to-open for a while; it came out in July 2026 because a menu that opens on pointer-cross fires while you're on your way somewhere else — crossing from the prompt box to Generate flashed the resolution and aspect menus open in passing. Opening a menu is a decision, so it takes a click. There is no `hover` prop any more; don't add one back here or elsewhere.
- `components/PromptToolbar.tsx` — the strip under every editable prompt box: Enhance / Regenerate / Clear, a hairline, undo-redo, then Expand on the right. Six hand-rolled copies had drifted apart (Playground, Scripts ×2, B-Roll's card modal, Continuous' frame + clip modals); labels are single verbs because "Enhance Prompt / Clear Prompt" says "Prompt" twice inside a box that is nothing but a prompt. No rule above it and none under the box either — the modals' footers dropped theirs too, so the prompt field runs straight into the controls it belongs to.
- `components/BatchCountStepper.tsx` — the **how many** control on every generate bar: a −/+ stepper in a chip-height pill, tinted in the host accent once the count leaves 1. Two shape opts for the one surface that stands beside a Generate button rather than in a chip row (Voiceovers): `size='fill'` takes its height from an `items-stretch` row so it matches the button by construction rather than by a duplicated number, and `stacked` puts the count over its label. One press then fires N gens in parallel — N kie tasks, N in-flight tiles, N history rows, which is exactly what pressing Generate N times already produced. Capped at **4** and defaulting to **1** (`utils/batchCount.ts`; Voiceovers passes `max={3}` — three reads is a choice, more is an audition), and every persisted read goes through `clampBatchCount`, so a hand-edited blob can't arm a bigger run than the cap. A stepper can't price its own rungs the way the resolution menu does, so **the run's total rides on the Generate button beside it**: every caller multiplies (`imageCount: n` for images, which the registry's `priceFor` already handles; `× n` for video and TTS, which have no count dimension), and the per-option credits in the same footer are priced for the armed count too — nothing in one bar may quote two different numbers. Wired in Influencers, Playground **Image + Video** (not Music: Suno already returns a pair of tracks per call — and there it shares the model row at `size='xl'` rather than sitting in the constraint band, which a four-dimension video model already fills), Voiceovers, and all three B-Roll card workspaces. Deliberately NOT on B-Roll's header batches, which already multiply by scene × option — a count there turns a twelve-clip run into thirty-six — nor in Scripts, which has owned this idea since it shipped as a "3 / 5 / 10 Variations" dropdown.
- `components/ClearAllButton.tsx` — the panel-level reset at the top of each input column. Labelled **"New"**, because it clears inputs only; outputs and history always survive. `iconOnly` drops the word for the 36px **+ circle** the output panels use to clear their canvas — Scripts uses it, since a labelled pill beside a full-width mode toggle was the only thing in that row asking to be read.
- **A panel header is a hairline, not a surface.** It draws no fill: the pane's background runs from the app's top edge straight through to the content, and the only thing marking the band is its `border-b`. B-Roll's right panel was the one exception and wore glass over an opaque `bg-surface-0` — on the theory that cards pass under it blurred, which they never did (it's a SIBLING of the scroll port). What that actually bought was three surfaces in the first 150px of the panel, each a step darker or lighter than the last: the header, the batch strip under it (also opaque), then the storyboard. Both fills are gone (August 2026). The rule in the "pinned panel chrome is glass" note below still holds for a bar that content genuinely scrolls under — there just isn't one here.
- Panel headers are `h-[57px]` + `border-b border-ink/5` on **both** panes of a two-pane app, rendered even when a pane is empty, so the hairlines align — and **`px-5`, the same inset the panel body takes**, so everything in a column shares one left edge. That matters most on a phone, where `MobilePaneTabs` stacks a second bar directly on top of the header: at `px-2` (what it and Characters' own toggle header both wore) the pane tabs stood 12px proud of the pill right underneath them, and the pair read as two widths of the same control. If a header needs more room than `px-5` leaves, shorten its labels — don't move the edge.
- **`SegmentedToggle`'s `fitContent` takes `'md'`** for a control in a header row that WRAPS on a phone: fit-to-content from `md` up, full-width below. Fitting its content is what keeps a toggle from eating a desktop line it has to share with a search field and a button — but once the header wraps and the toggle owns its own row, shrinking only leaves dead space beside its last label (Outliers' Outlier Vault / TikTok / Meta Ads). It's the container's width AND the segments' `flex-1` in one prop, since the two have to flip together; the indicator follows on its own, because it's already re-measured by a `ResizeObserver`.
- **A full-size `SegmentedToggle` segment runs tighter below `sm`** — `gap-1.5 px-2.5 text-[12.5px]` against the desktop's `gap-2 px-4 text-[13px]`. These are the second-row toggles (three-up section jumps, mode switches), and at 375px they were truncating their own labels for want of exactly that: the Ad Analyzer's read jump rendered as "Break… / Transc… / Scenes". `dense` is already sized for a tight row and is left alone. When a label still won't fit, SHORTEN IT for the phone rather than shrinking the control again — B-Roll's storyboard tab says "Storyboard" there instead of "Line by Line Storyboard", since the mode it qualifies is already picked one row up. `SegmentedToggleOption.label` is a `ReactNode`, so that's two spans and no JS media query.
- **Control heights are shared across the input columns.** A **picker row** is 58px — a 36px icon disc at `px-4 gap-3` — and every trigger that owns its own row uses it: the bank/style rows, `ScriptModelRow`, `ModelPicker row`. A **pill** is 48px (`ConstraintChip size='lg'`, `SegmentedToggle h-12`), for a value chip or a switch, including a `ModelPicker large` that shares its row with chips. Rows sit **8px** apart. Every **Generate button** is `px-7 py-4` (54px). Matching these is what makes a column read as one stack; the sizes below them (`md`/`sm` chips, `compact` pickers) are for modals and inline rows.
- No global focus ring, on purpose. A `:focus-visible` outline was tried and reverted: `:focus-visible` matches text inputs on a plain mouse click too, so every search field and textarea drew an outline around its own border. The `focus:outline-none` resets stand — see the note in `index.css`.

**Theming (light default + dark mode).** Driven by `data-theme` on `<html>`: an inline script in `index.html` sets it pre-paint; `stores/themeStore.ts` owns the preference (`dark`/`light`/`system`, own localStorage key `ai-ugc-lab-theme`, deliberately per-browser — never cloud-synced, survives sign-out). New browsers default to `dark` — the store fallback and the index.html bootstrap must agree. Switchers: Settings → Appearance + the menu bar's top-right quick toggle. UI chrome must use the semantic tokens from `index.css`, never literal white/zinc/dark hexes:
- `ink` — fg chrome (white in dark, near-black in light): `border-ink/10`, `bg-ink/5`, `text-ink`. `paper` is its inverse (`bg-ink text-paper` buttons).
- `surface-0/1/2` — page → panel → popover elevation.
- `ink-50…950` — text ramp; dark equals zinc, light is mirrored (ink-100 stays "bright", ink-500 mid, ink-700 dim). Inverse elements self-flip (`bg-ink-100 text-ink-900`).
- Accent families auto-flip their 100–400/600 tints in light mode.
Exceptions that stay literal: anything overlaying user media (badges/scrims/play buttons → `text-white`, `bg-black/60`, `from-black/85`), white text on solid accent buttons, modal backdrops. Status tints (-100…-400 colored text on tinted bg) need a `light:` darker variant (`text-red-300 light:text-red-700`; the `light:` custom variant is defined in `index.css`). `AppBackground.tsx` holds the per-theme canvas gradient.

**Errors.** End-user generation surfaces show friendly copy via `humanizeError()` (see `utils/friendlyError.ts`). It always returns a **complete sentence** — toast it verbatim and name the operation in the `fallback`; never prefix the result (``addToast(`Video generation failed: ${msg}`)`` printed the operation twice). Infra/admin/Settings surfaces still surface the raw kie.ai message — the operator debugs there. Note: the kie envelope can return `{ code: 5xx, msg: "...maintained..." }` inside an HTTP 200 during maintenance windows — not a code bug. **The rule table matches on SUBSTRINGS, so a new "timed out" is a new rule, not a free ride on an old one:** the asset-download deadline (`Timed out downloading…`) fell through to the poll-timeout copy and told members a clip that had already finished and billed was "still running on kie.ai" — three separate timeouts now say three different true things, and the one that matters most is the last (kie finished, the download didn't) — with a fourth added in August 2026 for the failures that happen on THIS machine (`probeVideoBlob`'s decode budget, a blob the `<video>` element rejects), which said "timed out" too and sent members off to kie.ai to look for a task that had already finished. **The other half of that rule is the button underneath it:** a Retry offered on anything we still hold a kie `taskId` for must RESUME the task, never re-submit it — see B-Roll's `resumeInFlightVideo` — and the surface must SAY so, because a member who reads "check kie.ai before generating it again" reasonably assumes Retry costs another generation and dismisses the tile instead. B-Roll's amber "Not saved" state (its own file) is that idiom: free-retry copy, and a two-click Dismiss on anything still recoverable. **A refused prompt is a content rule, not a validation rule, and the moderation test is written in the VENDORS' vocabulary** — it arrives as a 422 as often as not, so it sits above the validation rule and matches what each provider actually says (`InputTextSensitiveContentDetected`, "text risk not passed", "suspected of violating", PROHIBITED_CONTENT), not what we'd call it. Everything it misses falls through to "adjust your inputs (prompt, reference images, or settings)", which sends a member off swapping pictures when the words are the problem. Add a vendor phrase when you see one; keep loose words out (bare `blocked` catches a throttle, bare `explicit` catches "explicit aspect_ratio required").

**A capability claim in UI copy names no model.** Toasts and inline notes that said "Switch to Seedance 2.0 or Gemini Omni" were written when those were the only two ref-capable entries; the registry grew to where most of the picker takes reference images and the copy still named two, reading as the complete list — and one of them, Gemini Omni, can't take a start frame at all, so the animate-tab copy was recommending a model that would refuse. The same rule applies to the capability itself — check what the model DECLARES before telling a member it can't do something, and check what `buildVideoInput` does with the input before refusing the run over it.

## Tech Stack

- React 19 + TypeScript + Vite (`npm run dev` → http://localhost:5173). Tailwind CSS 4. Zustand for global state.
- **The React Compiler is on** (`babel-plugin-react-compiler` in `vite.config.ts`), so don't hand-write `useMemo`/`useCallback` for ordinary render work — it memoizes every component and hook it can compile. Two things make it silently **skip a whole component**, and both are worth avoiding in new code: an `// eslint-disable` of any `react-hooks/*` rule anywhere in the file, and a `try`/`finally` or catch-less `try` inside the component (move that work to a module-scope helper, as `finishResumedTask` in `playground/Playground.tsx` does). `npx eslint .` reports the first kind; for the second, the ground truth is whether the dev server's output for a file imports `react/compiler-runtime`. Coverage is partial today — the app roots that still bail are a known list, not an oversight. The compiler also memoizes **plain calls**, which is a trap for mutable state read through a stable function: `const get = useSettingsStore((s) => s.getAppModel)` then `get(key)` in the body compiles to a cache keyed on two things that never change, so it runs once per mount and the component renders that first answer forever (this is exactly how both model pickers came to show a model you hadn't picked). **Read store state through the selector** — `useSettingsStore((s) => s.getAppModel(key))` — never by calling a getter you pulled out of the store.
- IndexedDB twice over: `assetStore.ts` for media blobs (mirrored to Cloudflare R2 when cloud sync is active) and `bankPersist.ts` for the local bank cache (its own DB, one record). localStorage for settings, picker selections, per-app drafts, and `cloudSync`'s outbox.
- **Cloud (opt-in):** Supabase (auth + Postgres) + R2. Enabled when `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` are set; absent → local-only mode (100% client-side). Access gated by email allowlist synced from Skool via Zapier.
- kie.ai Bearer token sent directly from the client (no proxy).

## kie.ai client (`src/utils/kie.ts`)

Four transports — pick by task type. Endpoints and result shapes live in `kie.ts`; the gotchas worth knowing here:

**Every call that CREATES a generation goes through `submitToKie` (`utils/kieSubmitGate.ts`), and it has to stay that way.** kie rate-limits an account to ~20 new generation requests per 10 seconds, and a rejected one is **not** queued server-side — it comes back 429 and that generation never happens. Every batch surface in this app fires its whole run in one tick (B-Roll's "Generate all images / videos" over a dozen-plus cards, Continuous' clip run, a Playground or Voiceovers batch), so a big storyboard walked past the ceiling and a chunk of the tiles came back as errors. The gate spaces submissions `MIN_SUBMIT_GAP_MS` apart app-wide (one queue across every app — a member can have two batches running), and a 429 that still lands calls `noteRateLimited`, which stands the **whole** queue down instead of letting each queued card discover the limit for itself. This is invisible because every generation surface pushes its in-flight tile BEFORE the network call: the run looks started the instant the button is pressed, and only the POST waits. Wired into `createTask`, `kieVeoCreate`, `kieMusicGenerate` and the two omni creates. Polling, reference-image uploads and chat completions are deliberately outside it — see the note in the file before adding anything.

**Every response body is read on a deadline, and it has to stay that way.** `fetch()` settles at the *headers*, so a timeout that stops there is disarmed while the body is still streaming — and a stalled body read never settles, which is a hang with no error, no cancel and no exit but a page reload. `fetchWithRetry` therefore hands back a Response whose `json`/`text`/`blob` are re-armed with a fresh budget (`armBodyTimeout`), so every transport routed through it is covered by construction. **A new call site that reaches kie with a bare `fetch` opts out of this.** The *result download* is the other half of the same rule and has its own helper: **`fetchGeneratedAsset(url, { signal })`** bounds the CDN hop that pulls a finished image / video / audio / cover off kie (one controller for the request AND the body read, `ASSET_DOWNLOAD_TIMEOUT_MS`, caller-cancellable). Every result download goes through it — `downloadAsBase64`, `finishVideoAssetTask`, `finishVoiceTask`, `finishPlaygroundMusicTask` — because that hop runs AFTER kie has generated and billed, so a stall there parked the tile on "generating" with no error and no cancel. The only remaining legitimate bare fetch is `downloadAssetFromR2` (`lib/r2.ts`), which carries its own timeout; anything new must too.

**A chat response cut off at the token limit throws, it is never returned.** `kieChatCompletions` reads the stop reason on every transport and both body shapes — `finish_reason: 'length'` (openai-chat), `stop_reason: 'max_tokens'` (claude-messages, top-level when buffered and inside `delta` on the streamed `message_delta`), `incomplete_details.reason: 'max_output_tokens'` (openai-responses, nested under `response` while streaming, on the terminal `response.incomplete` event) — and raises `TruncatedResponseError`. It is thrown rather than returned with a flag because a truncated answer is silently **salvageable** downstream: `services/xmlBlocks.ts` is deliberately tolerant of a missing closing tag, so a cut-off storyboard rendered as a short one with no error and the member fired paid image/video gens against scenes the script never got. Throwing makes it honest in all ~20 call sites at once, since every one already has a catch. **The partial text rides on `err.partial`** so a caller can salvage it without changing the signature; nothing does today. `openai-chat` deliberately still sends **no `max_tokens`** — only `claudeBody` caps output (16384) — because kie's gateway default is unknown, and our own number could as easily lower the ceiling as raise it; set one from a real truncation, not from a guess.

1. **Async task** (`createTask` → `pollTask` → `parseResult`) — `POST /jobs/createTask` → poll `GET /jobs/recordInfo`. Result URLs are string-encoded JSON inside `resultJson.resultUrls`. Outputs expire in 3 days — always `downloadAsBase64` + `saveAsset`. The shared tails `finishImageAssetTask` (`utils/imageTask.ts`) and `finishVideoAssetTask` (`utils/videoTask.ts`) wrap poll→download→save for every image/video surface; the video one adds the black-tile guards (0-byte / non-video content-type / `probeVideoBlob` decode check).
2. **Chat completions** (`kieChatCompletions`) — `POST /<slug>/v1/chat/completions`, streaming SSE, falls back to JSON parse then surfaces the body's first 400 chars on failure. Vision via `image_url` blocks (data URIs work, no upload). Get the endpoint path from `getChatEndpointPath()` — never hardcode slugs. **A chat call that must survive a page reload goes through transport 1 instead**: `createTask` accepts a chat model (named by its `chatSlug ?? id`) with `{ messages, stream: false }`, the taskId is persisted so the poll can be re-attached, and `extractChatTaskText(record)` reads the several shapes kie returns the answer in. A model with no job route 400s at `createTask`, so both surfaces that do this — the Ad Analyzer's video read and B-Roll's storyboard — **fall back to streaming and treat that run as unresumable**. Nothing else needs it: the streaming transport is simpler and every other chat call is short.
3. **Veo** (`kieVeoCreate` → `kieVeoPoll`) — custom `/veo/generate` + `/veo/record-info`. Variant (`veo3` / `veo3_fast` / `veo3_lite`) via the `model` field, not the URL. Results nest under `response.resultUrls`.
4. **Suno music** (`kieMusicGenerate` → `pollMusicTask`) — custom `/generate` + `/generate/record-info`. Suno-specific status values; `callBackUrl` is required by the schema but we pass a no-op and poll. Audio at `response.sunoData[].audioUrl` (v1 uses the first track).
5. **Omni create** (`kieOmniAudioCreate` / `kieOmniCharacterCreate`) — synchronous `POST /omni/audio/create` and `/omni/character/create`, no polling. Mint persistent `kieAudioId` / `characterId` values (scoped to the member's kie account) that `gemini-omni-video` consumes as `audio_ids` / `character_ids`. Success can come back as envelope code 0 *or* 200.

`ensureHostedUrl(apiKey, source)` uploads `data:` URIs to kie's file host (image→image and frame-conditioned video models need public URLs; hosted files expire in 3 days). `kieTestConnection` checks the credit balance (Settings).

## Non-obvious files

Most files are self-explanatory. These carry behaviour worth knowing before you touch them:

- `stores/bankStore.ts` — all banks + history + `migrateVoiceShape`.
- `utils/appUsageTracker.ts` — the **only** signal in the app for which app a member is in and for how long. Everything else the Admin panel reports is derived from OUTPUTS (assets, bank rows, generation counts), which measures what members produced and never what they used — so Outliers (no history bank), Bank, Edit and the Dashboard were invisible, and "is anyone opening Outliers?" was unanswerable. Three rules keep the number honest rather than flattering, and all three are load-bearing: it is **attention** time, accruing only while the tab is visible and someone has interacted inside `IDLE_AFTER_MS` (an unbounded "app was open" figure makes whichever app people leave on top look like the most-used one in the community); it **samples** on a `TICK_MS` interval rather than integrating wall clock, so a sleeping machine simply stops firing and can never wake up and bank eight hours; and it **buffers** across dock switches, committing every `COMMIT_EVERY_MS`, because each commit is a bank-row write plus a cloud upsert and rapid dock-hopping would otherwise be one of each per hop. `stopAppUsageTracking` **discards** the buffer on purpose — the only thing that stops it is the workspace unmounting on a user change, and a commit there races the sign-out wipe, so losing minutes beats landing one member's time in the next member's ledger on a shared browser.
- `scripts/build-vault.py` — one of the two build steps in this repo that aren't `npm run build` (`build-character-presets.py` is the other, and follows the same pattern), and the source of `public/vault/` (the Outlier Vault's 872 rows + one 400px cover each). It reads a corpus that lives OUTSIDE the repo, in Massimo's `1000 Outliers` folder, so nothing in CI can regenerate it: the committed output is the source of truth and the script is how it gets refreshed when the corpus grows. Static files rather than a bank table on purpose — the library is identical for every member and read-only, so a synced copy would be 872 rows of the same thing per account. See the vault section of [`src/apps/discover/CLAUDE.md`](src/apps/discover/CLAUDE.md).
- `scripts/build-character-presets.py` — the same shape, for `public/presets/` (the Characters app's 81 starter characters: one flat DNA row each in `library.json`, one 400px cover each under `thumbs/`). Reads a folder of paired `<slug>.json` / `<slug>.jpeg` exports that lives outside the repo, so the committed output is the source of truth here too. These were nine `PRESET_*` consts and nine bundled JPEGs inside `character-studio/types.ts` until August 2026; at 81 they are data, not code, and nothing but the preset picker ever read one. It also **names** every row `<Scene> <Gender> <n>` (numbered within its group, always — a group of one included, or a grid reads as two naming schemes), keeping the export's own descriptive name as `title` for the tooltip and the search haystack. Skips a `__alt` second take, and derives each row's scene facet from the source folder's own numbering — the profile's `location` is free text and makes no facet.
- `utils/orphanCleanup.ts` — once-per-sign-in asset sweep. Its bank list **must** cover every bank (compile-time `satisfies Record<BankKey, true>` guard) or it deletes that bank's live assets from IDB + R2. Asset refs come in two shapes (bare `asset-x` and `asset://asset-x`); anything comparing refs against `assets.id` must normalise via `assetIdFromRef` first — unnormalised comparison once purged every B-Roll video. Its `assets` read is **paged** (`selectAllRows`) for the same reason: this list is the delete-candidate set, so a truncated read pairs a partial asset list against a partial ref set and purges live blobs the unread rows referenced. Both halves have to stay paged together.
- `utils/assetStore.ts` — IndexedDB blobs + fire-and-forget R2 mirror; `getBlob()` falls back to R2 on miss. **Two tiers, and neither may latch.** `fallbackStore` is a memory holding pen for blobs IndexedDB *individually* refused — it is consulted before IDB on read and written alongside it on failure, but it must never short-circuit IDB, and a failed `openDB` must never be cached (`dbPromise` is nulled on rejection). Both used to latch for the life of the tab, so one transient eviction made every later save memory-only — saved to all appearances, gone on reload — which is why reloading "fixed" saving. `openDB` also carries a deadline and an `onblocked` handler: `indexedDB.open` fires neither `onsuccess` nor `onerror` while another tab holds an older version, and `saveAsset` awaits it, so an unbounded open meant Save did nothing at all. Writes/deletes handle `tx.onabort` as well as `onerror` — a quota-exceeded transaction aborts, and without it the promise never settles.
- `lib/r2.ts` — presign → PUT → `assets` row upsert, the R2 mirror behind every `saveAsset`. **All three hops retry, and the mirror runs under a concurrency cap** (`MAX_CONCURRENT_UPLOADS`), because a batch's outputs all land at once — `finishImageAssetTask` / `finishVideoAssetTask` are the tail of every generation — and a dozen simultaneous multi-MB PUTs starve the small requests sharing the uplink. That surfaced as `assets row insert failed: TypeError: Load failed`, which is WebKit's wording for *any* network-layer fetch failure (Chromium: "Failed to fetch") stringified into supabase-js's `error.message` — the same text a backgrounded tab, a dropped hop and a saturated uplink all produce, so transience is judged by `TransientError` where we already know (a 5xx, a stall we timed out ourselves) and by `TRANSIENT_MARKERS` where the browser tells us nothing else. A retry **never re-PUTs a binary that already landed** — the row insert is the half that fails, and re-sending tens of MB to fix a 5-column row feeds the saturation that caused it. Requests carry a real `AbortController` (`fetchWithDeadline`), covering the body read as well as the headers: the old `withTimeout` race only rejected the wrapper, so a retry would have competed with the zombie upload whose stall triggered it. A run that exhausts its attempts is still recovered by `cloudSync`'s `reconcileAssets` on the next load, which is what the toast promises.
- `utils/friendlyError.ts` — `humanizeError(err, fallback)`, the ordered rule table for end-user error copy. The status-code rules are plain substring matches, so the message is first **cut at its debug tail** (`taskId=` / `url=` / `record=` / `body=` / `size=` / `endpoint=`): those payloads carry arbitrary digits, and `…video (size=402B…)` used to tell a member with a full balance to buy credits while any blob size containing `401` told them to replace a working key. Keep new debug context behind one of those keys, or behind a new one added to `DEBUG_TAIL`.
- `api/fetch-media.ts` — the only server-side URL fetcher in the app (Outliers → Ad Analyzer). It is an SSRF primitive by construction, so it keeps a **suffix-matched host allowlist** checked on the parsed hostname AND re-checked after redirects, never a substring match on the URL. Auth-gated like the R2 routes.
- `utils/team.ts` + `dashboard/SolarSystem.tsx` — **one crew member per dock app, and one `ORBITS` entry per crew member**: the two arrays are zipped by index, so a member with no orbit silently never renders on the Dashboard. Meet the Team derives its groups from `category` and counts the roster for its headline, so only the orbit list needs a hand-edit when an app is added.
- `utils/voiceProfile.ts` — `VOICE_PROFILE_SPEC`, the one wording for "describe how this voice sounds". Scripts WRITES one at the end of a scene blueprint, the Ad Analyzer READS one off an existing ad; they must agree, or a profile can't move between the two. B-Roll keeps its own phrasing inside `<VOICE_PROFILE>` because it's written against that prompt's character contract.
- `utils/mockData.ts` — the Settings demo seeder. Covers **every** tab: both banks and every history stream, a worked Line-by-Line session AND a Continuous keyframe chain (History row, since the workspace holds one session), styles, product extra angles, canvas-drawn stills, MediaRecorder clips and synthesized audio. Two rules: seeded rows match the real thing's shape (3 variations per scene, 3 concepts per frame — a short row reads as an app bug), and everything is reversible via the id manifest. The `usageDays` ledger is the exception worth knowing — it feeds the Dashboard, is priced through the real `foldUsageEvent`, and is written **only for days with no existing row**, so removal can never take a member's genuine activity with it.
- `hooks/useCloseOnAppSwitch.ts` — every body-portaled overlay (slide-over, picker, modal) must call it: portals escape the opacity-0 wrapper that hides background apps, so an open overlay would float over the next app after a dock switch.
- `lib/cloudSync.ts` — pull on sign-in + debounced diff-push + persistent localStorage outbox + non-destructive hydrate. `saveRow`/`deleteRow` are serialised per row (a stalled upsert can't land after a delete) and outbox markers are token-guarded (a late success can't clear a newer pending write). `walkAssetRefs` normalises `asset://` refs to bare ids so the sweep/reconcile match the bare-keyed `assets` table.
- `lib/supabase.ts` — `ensureFreshSession()` (3s race + cached-token fallback) and a custom non-blocking `auth.lock`.
- `hooks/useAssetUrl.ts` — resolves `asset://` refs to blob URLs.

## Banks

Cached locally in **IndexedDB** (`utils/bankPersist.ts` — DB `ai-ugc-lab-banks-db`, one record under one key, written by structured clone rather than a JSON string). It lived in a single localStorage key and outgrew it: one `BrollHistoryItem` carries whole session snapshots and measures ~43 KB, so the capped-at-50 B-Roll bank alone is ~2 MB and the blob passed what Safari takes in one `setItem` — a `QuotaExceededError` on a browser holding 0.44 MB in total, i.e. a per-value ceiling, not a full disk. The old key (`ai-ugc-lab-banks`, exported as `LEGACY_STORAGE_KEY`) survives in exactly two places and no more: `readLegacySync` reads it once for the synchronous first paint, and `dropLegacy` removes it as soon as the IndexedDB copy is written. **This copy is a boot cache, never the source of truth** — the cloud is, and hydrate refills memory from Postgres — so `flushSaveToStorage` logs a failed write and never toasts one; telling a member their work is at risk because a speed optimisation missed would be false. Asset blobs live in their own IndexedDB store (mirrored to R2 in cloud mode); rows store `asset://<id>` refs. `useAssetUrl(ref)` turns a ref into a blob URL. Types are in `stores/types.ts`.

`products`, `models` (from Influencers), `scripts`, `voices`, `brolls`, `styles`, plus auto-pushed history banks: `voiceHistory`, `videoHistory`, `imageHistory`, `musicHistory`, `scriptHistory`, `brollHistory`, `characterHistory`, `adAnatomyHistory`, and the Dashboard's `usageDays` ledger (all cloud-synced — every bank table has a Postgres mirror). Gotchas:

- **`usageDays`** — accumulate-only usage ledger: one row per local calendar day (`id: 'YYYY-MM-DD'`), holding per-kind generation counts + estimated kie credits + official-API USD, **plus per-app attention time** (`apps`, see below). Written by `bankStore.recordUsage`, which is called inside the `add*History` actions (plus B-Roll's `finishImageTask` and the Ad Analyzer complete-flip) — new generation surfaces get counted for free if they push history. Deleting/clearing history never subtracts. One-time backfill from history (`backfillUsageLedger`, flag `ugc-lab:usage-backfill:<uid>`) runs post-hydrate in cloudSync (local-only: Dashboard mount) and skips ids in the mock-data manifest. Mock seeding suppresses live recording via `setUsageRecordingSuppressed`. Its Postgres table `usage_days` (migration 0016) uses a **composite PK (user_id, id)** because day keys repeat across users — run the migration before deploying, or every hydrate reports a per-table error (which also skips the auto orphan sweep). 

  **`apps`** is the row's other half: `{ [appId]: { seconds, opens } }`, written by `utils/appUsageTracker.ts` through `bankStore.recordAppUsage`. It rides this row rather than a bank of its own because it answers the same question ("what happened on this day") and because `usage_days` already carries the sync wiring and the admin-read policy the Admin panels read through. Two things follow and must stay true: a day can hold app time and **no** generations, so everything measuring output (streaks, savings, the heatmap, `computeUsageMetrics`) keys off `counts` and correctly ignores a browse-only row — and `backfillUsageLedger` therefore guards on real counts and **folds onto** the existing rows rather than replacing the array, or the first browse of a session would skip a member's whole history backfill and delete the time that triggered it. Aggregated for the admin by the `member_app_usage` view (migration 0022) — run it before deploying, alongside 0016.

- **Starring.** `products` / `models` / `scripts` / `brolls` / `styles` items carry `starred?: boolean` — flipped by bankStore's silent `toggleStar` (no toast) from a star button in the Bank cards' hover stack. Starred items sort first in every `BankPicker` (`starredFirst` in `finder/bankSort.ts`, amber badge on the card); the Bank browser's own sort order is deliberately untouched (B-Rolls are day-grouped).

- **`styles`** — visual looks for B-Roll (name + `brief` + up to four `thumbRefs`). The brief IS the style: it's the paragraph appended to every prompt rendered in that look, so it must describe the LOOK only, never anything from the frames it was read from. Thumbnails are this bank's own assets (nothing else links them), so delete/replace purges them outright. Postgres table `styles` (migration 0017) — run it before deploying, or every hydrate reports a per-table error (which also skips the auto orphan sweep).
- **`swipes`** — the swipe file behind Outliers: ads saved from a search, filed by the Bank's **Swipe File** tab. A row is the ad's identity (`platform` + `sourceId` + `postUrl`), a **snapshot of its numbers AS SAVED** (a swipe is a record of what a winner looked like when you found it, not a live feed), its caption, and its transcript when one had already been fetched — never re-billed for the sake of the save. The **thumbnail is copied into our own storage** (`saveThumbnail` → `thumbRef`), because every media URL a search returns is a signed CDN link that expires within days; a row that merely remembered the URL would be a broken image by the time it mattered. Following the same rule as `brolls`, the **video is deliberately not stored** — a swipe file is meant to hold hundreds of ads and a few MB each would eat the 10 GB cap for footage that `postUrl` can re-reach. `getSwipeBySource` keys off platform + source id so the Save button reads as saved and the same ad can't be filed twice from two searches. **The card opens the same detail view Outliers does** (`finder/SwipeDetail.tsx` → `swipeToResult` → the one `ResultDetailModal`), never an edit form — there's nothing here that's yours to edit, but tearing the ad down later is the entire reason you filed it, so Analyze Ad / Remix Transcript / the permalink all have to be where they were when you saved it. It opened the permalink outright until August 2026, which made the swipe file a bookmarks folder. What that costs is the video: `mediaUrl` is signed and expires, so a saved row plays only while it's fresh and then offers **Restore video — 1 credit** (`refreshResultMedia`, 1 ScrapeCreators credit, `/v2/tiktok/video` or `/v1/facebook/adLibrary/ad`), writing the new link back to the row so a second visit inside its lifetime is free. **A refresh re-resolves MEDIA ONLY, never the stats** — the snapshotted numbers are what make this a swipe file rather than a bookmark. A dead link is dropped from the result rather than re-rendered, because a failed `<video>` keeps its transport controls and reads as something you could press; the greyed Analyze beside the Restore button is the honest state, and the auto-refresh inside `downloadWithRefresh` only covers the case where the link looks alive and 403s at fetch time. A transcript bought here is written back to the row too, so it's paid for once rather than once a visit. It is **shaped exactly like the Outliers card it was saved from** — picture in its own 4:5 frame, then a static block of author / caption / snapshotted engagement row underneath — five across to match. It used to read its caption off a gradient laid over the frame, which put text across the ad's own hook (the one thing you saved it for) and left the numbers nowhere to live. Postgres table `swipes` (migration 0019) — run it before deploying, or every hydrate reports a per-table error (which also skips the auto orphan sweep).
- **`brolls`** — only **stills** are saveable to the bank (reusable as start frames / references); videos are download-only, so no UI writes new `videos[]` entries anymore (the save-to-bank action is hidden on video tiles in B-Roll + Playground). The `videos[]` field and its render/edit/cleanup paths stay for back-compat — older saved-video entries (and the video-only-broll render path in `BankList`) still display and download. Saved video-history items stamp `linkedBRollId`; deletion only purges the blob if not linked.
- **`videoHistory`** is shared by B-Roll and Playground (for refresh-resume); Playground's grid filters out `sourceApp === 'broll-studio'`. No automatic retention — entries persist until the user deletes/clears them. Only `brollHistory` is capped (`BROLL_HISTORY_CAP`, FIFO); the other history banks (`videoHistory`/`imageHistory`/`musicHistory`/…) grow unbounded **in memory and in the cloud, by design** — a member's outputs are never evicted behind their back. Nothing is trimmed to fit any more: the local cache moved to IndexedDB (see above), which has no comparable per-value ceiling, so `flushSaveToStorage` writes the whole set or logs the failure — it never sheds a row to make one succeed. Treat a cache-write failure as a **local** problem, never as a reason to delete a row. `cloudSync`'s outbox is still on localStorage and still matters: it's the replay guarantee behind every fire-and-forget push, it used to swallow `QuotaExceededError` silently (so a full disk lost a new row while the member watched a green "Saved"), and it now `console.error`s once per run of failures.
- **`characterHistory`** carries `imageRef` + the full `profile` snapshot; `linkedModelId` is set on save-to-bank and gates blob purge. Presets aren't a bank — reuse a recipe by saving to `models` and reloading via the Controls header dropdown. The nine built-in starters (`PRESET_*` in `character-studio/types.ts`) **fill all 28 fields and pick the starred option wherever the field offers one** — a one-word `skinTexture: 'Glass skin'` leaves the model to invent the rest and what it invents is the plastic look the presets exist to avoid, and an empty field drops out of the prompt entirely. "Starred" is `ChipField`'s `isDetailed` (a chip over 30 chars), so a preset value only shows as a picked row when it's EXACTLY one of that field's own detailed chips — which is why the age-appropriate skin tiers and the per-character hair styles were added to the chip lists rather than written as preset-only free text. `No makeup` on the men and the free-text `facialFeatures` / `distinguishingMarks` / `accessories` fields are correct as-is, not gaps.
- **`VoicePreset` / `VoiceHistoryItem`** carry the Gemini TTS param set (`voiceId` = `voice_name`, `style`, `pace`, `accent`, `temperature`, optional `scene` / `sampleContext`). `migrateVoiceShape` strips the legacy ElevenLabs numeric fields (`stability` / `similarityBoost` / `speed`, and the old numeric `style`) and backfills the new string defaults (`Natural` / `Natural` / `Neutral`, temp `1`).

## Auth + cloud sync

`AuthGate` wraps the app and picks one of five screens, in this order: bootstrapping → spinner; **recovery** → `ResetPasswordScreen`; signed-out → `AuthScreen`; **lapsed** → `LapsedScreen`; signed-in → workspace + `UserMenu`. The order is load-bearing at both ends — a recovery link carries a real session, so checking it after the session check would drop the member into the workspace with the password they came to change still set; and a lapsed member holds a session whose RLS refuses every bank table, so their screen has to come before the sync that would hydrate against them. `syncBlocked` keeps `startCloudSync` from firing in either state. The three signed-out screens share `components/auth/AuthShell.tsx` (wallpaper + brand + `max-w-sm` column + legal row) and its `AuthField`. No cloud env vars → local-only mode with a bottom banner. Full deploy stack is in `DEPLOYMENT.md`; threat model in `SECURITY.md`.

- **Onboarding.** `components/ApiKeyGuide.tsx` (menu-bar alert + the Dashboard banner) and `MeetTheTeam` both **take the kie.ai key inline** — they used to explain three steps and send the member to Settings, which left the intro with the one blocking task undone. Both go through `useKeyConnect` (exported from ApiKeyGuide): the key is checked against the live balance BEFORE it is saved, so nothing is ever stored that can't generate. Both are infra surfaces — a failed check shows kie.ai's own message, not `humanizeError` copy. `MeetTheTeam` stages the Create chain as a five-card pipeline with the blurbs in one hover-driven caption slot (eight rows of copy is a reading task, not an introduction); `components/apiKeySteps.tsx` is now only its read-only summary. Its two group headings (`GroupHeading`) wear the shared **`SectionLabel`** treatment — the same eyebrow Characters' GENDER / AGE RANGE and every Bank form get — with this screen's own trailing hairline as a sibling beside it. They were 10px semibold at `0.14em` in ink-400, which is one house style too many for a word doing the same job in both places; the same fix `WidgetLabel` took on the Dashboard.
- **Allowlist.** Postgres trigger `enforce_allowlist` blocks signups not in `public.allowlist` (no client bypass). A global `public.app_config.enforce_allowlist` flag (Admin → Allowlist toggle) short-circuits the trigger when off — open signups while Zapier isn't wired; flip back on to re-gate. `on_allowlist_delete` sets `profiles.lapsed_at` (see Member status below) → app locks the member out on hydration; `on_allowlist_insert` clears both flags. A **disabled** account (sign-in or stale session) sets `authStore.accessRevoked`, and `AuthScreen` shows a "members only" popup linking to `SKOOL_COMMUNITY_URL`; a **lapsed** one keeps its session and gets the code screen instead. Zapier syncs Skool events in. **Signup access code** (migration 0021): the Create account form has an **Access code** field, checked inside the same `enforce_allowlist` trigger against `app_config.signup_code` (default `3500`, edited in Admin → Allowlist; blank turns it off). It runs **before** the allowlist kill-switch — the switch exists to let un-synced members in, and the code is what keeps that door from being open to everyone. The expected value is **never shipped to the browser**: the client posts what was typed as signup metadata and the trigger compares, then strips the key off `raw_user_meta_data` so it never lands in a member's JWT. New signups only — nothing changes for existing accounts. **Names:** signup collects First name + Surname → passed as auth user metadata; `on_auth_user_created` seeds `profiles.first_name/last_name` from the allowlist row, falling back to that metadata (migration 0015) so members who sign up with a non-Skool email are still identifiable.
- **Member status** (migration 0023). Three states, and the split exists because cancelling and banning are not the same event: **Active** · **Lapsed** (data intact, app locked, the member reopens it themselves) · **Disabled** (data intact, app locked, only an admin reopens it). `is_active()` is false for both locked states, so RLS refuses every bank table exactly as it always did — **no status has ever deleted anything**, and deletion is still `admin_delete_member` (0018). Lapsed is the status that finally makes rotating the access code mean something: `enforce_allowlist` is a `BEFORE INSERT ON auth.users` trigger, so it fires on **signup only** and a returning member signing into an account they already have was never asked for a code, however often it changed. `redeem_access_code(code)` is the way back — SECURITY DEFINER, compares against the same `app_config.signup_code`, clears `lapsed_at`, and **returns a jsonb verdict rather than raising on a wrong code**, because a raise would roll back the attempt counter that throttles guessing (5/hour). It refuses for a *disabled* caller and when the code is blank, or every ban would carry its own way out. `prevent_privilege_escalation` (0010) guards `lapsed_at` and the counters alongside `is_admin`/`disabled_at` — `profiles_self_update` doesn't restrict columns, so without that a lapsed member would just clear their own flag; the RPC announces itself with a transaction-local `app.redeeming_code` GUC, which is unreachable from PostgREST. Admin → Members carries the third pill, a Lapse/Restore action and a `lapsed` filter, all derived from one `memberStatus()` helper so the pill, filter, counts and CSV can't disagree.
- **Password recovery.** `AuthScreen`'s **Forgot your password?** → `resetPasswordForEmail` with `redirectTo` = `RECOVERY_PATH` (`/reset-password`). Two things make that path work in this app: `RECOVERY_ON_LOAD` is read at **module scope** in `authStore` (supabase-js consumes the token out of the URL as the client is created, and `RouterSync` rewrites any unrecognised path to `/dashboard` — by render time neither piece of evidence is left), and AuthGate short-circuits on it before RouterSync ever mounts. The confirmation copy says "**if** that email has an account" on purpose: confirming which addresses are registered would answer that for anyone who asked. Needs two Supabase settings, both in `DEPLOYMENT.md` — the redirect URL allowlisted, and real SMTP, since the built-in sender is testing-grade.
- **Cloud sync** (`cloudSync.ts`). Pulls profile + all bank tables on sign-in. `bankStore` writes local (Zustand + localStorage) first, then fires the cloud push in the **background** — `pushRow`/`dropRow` are fire-and-forget (return `void`, never awaited). The UI must never `await` a cloud round-trip: awaiting it was the "save stuck loading, then times out after ~15s" hang, and it could drop the row on a mid-hang refresh. Durability comes from the outbox, not the await — `recordPendingUpsert`/`recordPendingDelete` persist the row to a per-user localStorage outbox (`ugc-lab:sync-outbox:<uid>`) **synchronously** before the push fires, so a failed/timed-out push is replayed by `drainOutbox()` (startup + tab focus + backoff timer) and overlaid onto the next hydrate. Background push failures are logged, not toasted — local is the source of truth, sync is eventual. **Hydrate is non-destructive:** a per-table fetch error keeps local rows (never `[]`), and outbox-pending rows are overlaid so an unsynced row survives a refresh. **Every whole-table read is paged** through `selectAllRows` (`lib/supabase.ts`) — PostgREST silently caps a response at its server row limit, and the history banks are uncapped by design, so an unpaged read hands back the first page only and `persistBanksNow` then writes that truncated set to the local cache. The sweep below is why that matters beyond "missing rows": it builds its in-use ref set from these same banks.
- **Session freshness** (`supabase.ts`). Every cloud write awaits `ensureFreshSession()`, which races `getSession()` against a 3s timeout and falls back to a module-cached token (kept current by an `onAuthStateChange` listener) when the SDK's auth lock stalls after a backgrounded tab returns. The client also uses a custom `auth.lock` (`nonBlockingLock`, ~2s bound then runs unlocked) because supabase-js takes that lock on every request. `visibilitychange` recovers the token on focus.
- **kie.ai key is browser-local only.** Lives in `localStorage` under `ai-ugc-lab-settings`, never written to or read by Supabase/cloudSync. Users re-paste on each new browser. Deliberate trade-off: nothing in the DB ever holds the key. The optional **ScrapeCreators** key (Outliers) sits in the same blob under the same rule. Both are written through `snapshot(state)` rather than a hand-built literal — an earlier setter rebuilt an object naming only the fields it knew about, which silently dropped any key added to the shape later. **Both also survive sign-out, via the per-user vault** `ai-ugc-lab-keys` (`adoptUserKeys` / `rememberKeys` in `settingsStore.ts`): `wipeLocalUserData` clears the settings blob so the next person on a shared browser can't inherit a key, which used to mean re-pasting both on every sign-in — since they're the one thing in the app that isn't cloud-recoverable, the wipe was the whole cost. The vault is keyed by user id and adopted **only after** any wipe, so a member restores their own keys and never another's; a member with no entry yet has theirs seeded from the live settings (the upgrade path), and clearing both fields in Settings deletes the entry outright. Cost of the trade: a signed-out member's keys stay on that browser's disk until they clear the fields.
- **Schema.** Bank tables are JSONB (id PK, user_id FK, project_ids[] GIN-indexed, data jsonb). RLS `auth.uid() = user_id` everywhere, admin bypass via `profiles.is_admin`. Admin app (Members + Insights + Allowlist) only renders for admins.
- **Announcements** (migration 0020, Admin → Announcements). The operator's broadcast channel, and the one synced table that is **not a bank**: one global list written by admins and read by everyone, so it skips `bankStore`/`cloudSync` entirely and lives in `stores/announcementStore.ts`, loaded once per sign-in by `components/announcements/AnnouncementsHost.tsx`. Two levels, and the split is the whole design: **`update`** dots the Dashboard tile, **`alert`** *also* opens once as a modal on the member's next load (oldest unread first, one per load) and never again — so an outage can interrupt without training members to dismiss every feature note on sight. Read state is per ACCOUNT (`announcement_reads`, marked after a card holds the viewport ~0.9s, not on panel open), which is also what makes the "seen by 38 / 62" receipts in Admin real; the admin policy on that table stays SELECT-only. `published_at` in the future IS the scheduler — the member-side RLS policy only returns rows whose time has passed and whose `expires_at` hasn't — so nothing polls and drafts are invisible to members by construction. The image is a downscaled JPEG **inline in the row** (`components/announcements/media.ts` caps it), because every R2 key is signed under `auth/<userId>/` and a shared object would need a new public prefix in the presign route; the list query excludes it via the generated `has_image` column and each card fetches its own. A YouTube link needs no image at all — the card derives the thumbnail from the video id. The **preview in the admin editor renders the real `AnnouncementCard`** off the real draft (that's what the card's `preview` flag is for), with a light/dark switch that works because the `light:` variant matches any `[data-theme="light"]` ancestor. Publishing arms first, same two-click contract as delete.
- **Admin panel data.** Every tab stays mounted after first visit, and Members + Insights genuinely share one fetch — a 60s-fresh zustand store in `apps/admin/useMembers.ts` (it claimed to share one before and didn't). Remounting per tab click refired three queries and threw away sort, filters and scroll, which is what made every tab click drop the panel to a spinner. Every admin query goes through `apps/admin/adminQuery.ts`: `readyAdminSession()` first — Admin was the last cloud path not awaiting `ensureFreshSession()`, so its queries queued behind supabase-js's auth lock and only unblocked on a full page reload — then `withTimeout`, which really aborts the request so a late response can't land over fresher state. A failed refresh over loaded rows banners; it never blanks the table. It fetches four things: `profiles`, the `member_storage` and `member_activity` views, and **`member_app_usage`** (migration 0022) — the last one **paged** through `selectAllRows`, unlike the other three, because it returns a row per member PER APP and so crosses PostgREST's 1000-row cap at ~90 members; a silently truncated read there would report an active member as having opened nothing. Insights renders **every** tracked app including the ones at zero (an app merely missing from the chart doesn't answer "is anyone using Outliers", a row reading `Outliers · 0m` does), and Members carries the per-member `Top app / 30d` column and the same figures in the CSV as raw minutes.
- **Deleting a member** (`apps/admin/deleteMember.ts`, driven by the Members table's row checkboxes). Disabling locks an account and keeps everything; deleting removes it — for spam signups, not for members who left. Two steps, in this order: `/api/r2-delete-user` purges every object under `auth/<userId>/` (admin-verified, fails closed; best-effort, so a storage failure warns instead of blocking), then the `admin_delete_member(target_id, remove_from_allowlist)` RPC (migration 0018) deletes the `auth.users` row and every bank/asset/usage row cascades off it. R2 first, because nothing points at those objects once the rows are gone. The RPC refuses to delete an admin or the caller, and removing the allowlist row (default ON) is what stops the person signing straight back up.

## Inter-app payloads

One-shot handoffs. Sender calls `sendToApp({ targetApp, targetField, data })`. Consumer reads `interAppPayload` in a `useEffect` keyed on `activeApp`, dispatches on `targetField`, then calls `consumePayload()`. Wired: Ad Analyzer → Scripts (transcript) / Bank (productId) / B-Roll (`adBlueprint`: an `AdBlueprintPayload` — the analysed ad's transcript as the script plus its staging, which is now the ONLY source of `BrollInput.sceneStaging`, B-Roll's Ad Format picker having been removed; cleared by "New"); Scripts → Voiceovers (script text); B-Roll Bank → Playground (`videoStartFrame` opens video mode with the still as start frame + prompt prefilled); B-Roll video → Playground (`videoSourceClip`: a `VideoSourceClipPayload` asset ref + real clip duration → video mode switched to **Gemini Omni Flash 1.1** with the clip attached as the trimmed `omni-clip` source clip — the Omni family is what takes a video input at all, and Flash 1.1 is the newer of the two at the same flat clip-input price — the "same take, dialogue in Spanish" redub loop; the asset ref survives refresh, unlike uploaded clips); Anywhere → Playground (`prompt`, `imageRef`, `videoStartFrame`).
