# CLAUDE.md — UGC OS

## Project Identity

You are building **UGC OS** — a browser-based, macOS-style workspace that unifies eight tools for UGC ad production into one environment with shared data banks. Every in-app AI call goes through **kie.ai**: one user-supplied Bearer key gives access to every model the app uses (chat, vision, image, video, TTS, music). The one exception is **Edit**, which generates nothing in the browser — it hands out a Claude skill the member runs locally.

**Who it's for / why.** A private Skool community of solo creators and small teams producing AI UGC ads at scale — access is gated by an email allowlist synced from Skool, so non-members can't sign up even with the URL. The pitch is one workspace instead of seven tabs: the same product, character, script, voice, and B-Roll flow across every app via the shared banks. Inference cost is on the member (BYO kie.ai key), so the operator only pays for hosting + storage.

Dock order: **Dashboard** (own 'system' group) | **Bank** | **Tools** (Outliers → Ad Analyzer, in that order because the loop runs left to right: find a winning ad, then tear it down — fenced by a divider on each side, since research happens before the production line rather than after it) | **the Create apps** (Characters → Scripts → Voiceovers → B-Roll → Playground; Playground sits beside B-Roll because it's the other place footage gets made, so it belongs next to it rather than a divider away with the research tools) | **Edit**, fenced in a group of its own (`deliver`) so a hairline falls to the right of Playground — it closes the row, it is where the production line ENDS (cut what you produced), and it is the one app that generates nothing in the browser | Settings utility tile. The dock's group ORDER lives in `SECTION_ORDER` (`utils/constants.ts`, beside `dockOrderedApps()` which flattens it), not in the registry array; membership is **by `category`**, so moving an app between rows means changing that field, not just its array position. It moved out of `Dock.tsx` in September 2026 because a second surface reads it: **Meet Your Team lays the crew out as ONE chain in this exact order**, so an app moving group moves in the intro too and the two can't drift. Fresh visits land on the Dashboard (`DEFAULT_SLUG`). **Outliers is the one app a member can switch off, and it ships ON** (`stores/appVisibilityStore.ts` — a browser-local opt-out list, never cloud-synced, switched in Settings → **Experimental**, its own rail pane): it shipped OFF on the reasoning that ad research is a side quest next to the production line, and flipped in September 2026 (Massimo's call) because enough members went looking for it that the tile is worth more than the row it costs. A default here is only the fallback for a member who has never touched the switch, so the flip alone would have moved everyone who never opted out and nobody who did — and the members asking for Outliers back are exactly the ones who had switched it off. Hence `RESETS` in the same file: a listed id has its stored value dropped **once per browser**, under its own marker key, so the flip reaches everyone. It is a reset, not a lock — the next flick of that switch writes a choice no later run touches. Hiding it takes the whole app, not just the tile — its dock entry, its planet on the Dashboard, its card in Meet the Team, its route (`RouterSync` bounces `/outliers` to the Dashboard, the same guard `admin` gets), the Bank's **Swipe File** tab and the **ScrapeCreators** key field in Settings, all of which point at an app that isn't there. Nothing is deleted and switching it back on restores every one of them. An app NOT in `OPTIONAL_APPS` is always visible — this is a short opt-out list, not a permissions layer. The same store and the same Experimental pane also carry `OPTIONAL_FEATURES`, for a switch that is not a whole app: **B-Roll's Continuous mode is the one, and it ships OFF too** — off holds B-Roll in Line-by-Line (no mode toggle, and its 57px bar goes with it) and drops Continuous sessions out of History, the rule the retired One-Shot rows already follow. Nothing is deleted there either. Display names are terse nouns, not action verbs. Folder names and the `id` strings in `src/utils/constants.ts` are **stable** — they key per-app model selections in localStorage. Do not rename them.

## Core Rules

**The reasoning behind these rules lives in five other files**, because its detail
only pays off when you are doing that kind of work and it is dead weight in every
other session. Every rule is still stated in one line below, where it can't be
missed — those files are the *why*, and the rule points at each one:

- [`src/components/CLAUDE.md`](src/components/CLAUDE.md) — **the shared UI idioms**: every shared component, hook and CSS idiom, and what was tried before it. Loads automatically under `src/components/`.
- [`src/utils/CLAUDE.md`](src/utils/CLAUDE.md) — **the model registry**: why each default holds its slot, what has held it and handed it back, the pricing caveats to re-verify. Loads automatically under `src/utils/`.
- [`src/lib/CLAUDE.md`](src/lib/CLAUDE.md) — **auth, cloud sync and the Postgres schema**: onboarding, allowlist, member status, the sync contract, the key vault, admin reads. Loads automatically under `src/lib/`.
- [`docs/mobile.md`](docs/mobile.md) — **read before any responsive work**: breakpoints, `touch:`, `max-md:`, the dock's auto-hide, the phone field size, safe-area insets, the PWA manifest.
- [`docs/performance.md`](docs/performance.md) — **read before adding a `backdrop-filter`, making a bar `sticky`, animating opacity over generated media, or putting a list beside an input.**

The three `src/` files load on their own **only** for work under their own folder.
Several of their rules govern code elsewhere (`src/hooks/`, `src/App.tsx`,
`src/apps/admin/`) — the one-liners here are the pointer, so follow the link
rather than assuming the file already loaded.

A rule you are about to change, work around, or break is a rule whose file you
read first — that is where the thing already tried and reverted is written down.

**Code philosophy.** Simple > clever. Obvious > terse. Components small and single-purpose. No premature optimisation. Comments explain *why*, not *what*.

**Architecture.**
- **Self-contained apps.** Each app under `src/apps/<name>/` owns its types, components, and service. Cross-app communication goes through the bank store (persistent) or the inter-app payload (one-shot handoffs).
- **No prop drilling.** Zustand stores for global state; local React state for ephemeral UI.
- **Model registry is the single source of truth.** Add or change a model only by editing `src/utils/models.ts`. Don't sprinkle slugs through service files.

**Styling.** Tailwind only. Per-app accent palettes are custom Tailwind families (`influencers-*`, `scripts-*`, `voice-*`, `broll-*`, `playground-*`) defined in the `@theme` block of `index.css` (Ad Analyzer uses literal `#FF5257`); the matching hexes for sidebar/bank chrome live in `constants.ts`. Change an accent there, not by sprinkling new color classes. Tracking-tight text. Transitions 200–300 ms for panels, 150 ms for hover. Tags use `TAG_STYLES` from `models.ts` (Recommended green / New fuchsia / Fast sky / Cheap zinc). **Single-line inputs, select-style triggers, chips, and buttons are fully rounded (`rounded-full`), not rectangles** — Massimo's preferred aesthetic; multi-line textareas use `rounded-2xl`.

**Shared UI idioms.** Reach for these instead of re-implementing — each one had drifted into 3–4 near-identical copies before it was extracted. **The reasoning behind every one of them — what was tried first, what it measured, and why it was reverted — lives in [`src/components/CLAUDE.md`](src/components/CLAUDE.md), which loads automatically when you work under that folder. Read it before changing or working around one of these.**
- `components/VideoLightbox.tsx` — the one full-screen clip view: the video left, its **first / last frame** grabbed out of the file on the right, then the prompt and downloads. Every B-Roll video tile reaches it through `ExpandVideoButton`.
- `components/AppGlassTile.tsx` — **the one app icon** (the accent-filled `glass-fill` squircle), so Meet Your Team wears the same icon the dock does. `GlassTile` is that material addressed by `icon` + `accent`, for a mark that is not a dock app. No hover sprites.
- `components/Menu.tsx` — **the one popup menu**: `MenuSurface` + `MenuItem` (+ `MenuSeparator`), full-bleed 38px rows, 184px min width. **Deliberately opaque** — never `backdrop-blur`. A scrolling list goes in an inner `overflow-y-auto` div, never on the surface; `toneClassName` REPLACES a row's resting colours, since an accent appended through `className` looks like it works and doesn't.
- `components/tileActions.tsx` — the hover action column on every generated media tile, in the order **[Star] → Download → Save → Copy → extras → Delete**. 32px circles, no backdrop-blur. **Past four circles a tile needs a doorway, not a longer column** — `TileMenuButton` opens the house `Menu` with every remaining action spelled out. `chrome` drops the hover fade for an always-on panel row.
- `TileDeleteButton` is the **only** delete idiom: two-click, reverts after 3s, never a confirm modal. **Arming does not resize it** — same footprint, solid red fill, check glyph.
- `components/GeneratingMedia.tsx` — the one "this is generating" face (`GeneratingMediaFill` in a card frame, `PendingMedia` as a gallery tile). A card mid-generation and that same generation inside its detail modal must look identical. Status copy lives in `components/generatingMessages.ts`.
- `components/GeneratingChip.tsx` — `GeneratingChip` + `GeneratingPulseRing` mark a **history row** whose work is still running. **History is the queue view**: fire a batch, switch away, and the list keeps reporting progress.
- `components/Spinner.tsx` — **the one busy spinner, and it is a RING, not a spinning icon** (`border-2 border-current/25 border-t-current`). A bare `Loader2` arc carries its mass opposite the gap and reads as wobbling off its axis. Size and colour ride in on `className`.
- **Generate buttons never disable while a generation is in flight.** Every media surface queues gens in parallel; the in-flight tile is the feedback, not a locked button or a spinner swapped into the label. Guard duplicate fires of the *same* card with a `startingRef`-style set, not by disabling. The only legitimate blocks are structural (Continuous' sequential keyframe chain, nothing to generate yet).
- `components/GridCanvas.tsx` — the graph-paper canvas an **output** panel works on, with `AwaitingBody` / `AwaitingCanvas` as its empty state and a **+** in the panel's header to clear back to it (it never deletes — the copy says so). **It marks an empty stage, not a backdrop**: drop it once real output renders (Characters is the deliberate exception). History surfaces keep the plain background.
- `components/video/refInputParts.tsx` — the **one reference-thumbnail shape**: a 64px `ImageTile` and the dashed `AddTile` that matches its footprint, in a plain `flex flex-wrap` row. Never a four-up `grid` of `aspect-square` cells — that is a fixed count rather than a fixed size. A reference that needs to be bigger is a frame slot (`FrameSlot`), not a ref tile; an empty slot is a 40px `MediaAddCard`.
- `components/SectionCard.tsx` — the grouped section card: the shape of every **input** column, card workspace and Bank form. Two rules: **don't card a lone control**, and **don't card what isn't part of the group**. A card holding a growing box takes plain `flex-1`, never `flex-1 basis-0`, and the height floor lives on the **section**. `SectionPresetPill` is the heading that IS the way into that section's presets.
- `StatusDot` / `SectionLabel` (same file) — **green** filled · **red** required and empty · **neutral** optional and empty, and red means exactly one thing: "this is why Generate is grey". Only put a dot where it can ever be red or neutral — a permanent row of green teaches members to stop reading dots. `filled` is optional.
- `components/DropOverlay.tsx` — **the one "drop a file anywhere on this surface" overlay**: a full-bleed dashed frame with a single centred pill naming what the drop will do. Never a card on a dimming scrim — that shape covers the drop zone it is describing. Accents are a closed set, and it arrives like a modal.
- `components/DayPill.tsx` — the section separator on **every** history surface, gallery picker and day-grouped bank listing, and for any other label a list groups by. Never a left-aligned heading with a hairline rule. `className` sets the vertical margin only.
- `components/RailNewButton.tsx` — the primary button a history rail leads with, in the host accent. **Single click, no arm**: what it clears is a row in the list directly underneath. A caller that genuinely needs the two-click promise wants `ClearAllButton`, not a flag here.
- `components/HistoryRailToggle.tsx` — **the one control that opens and shuts a history rail** (Scripts, Voiceovers, B-Roll): a 38px circle in the app's own icon-button material, and **a laid-out element, never an overlay**. Shut, `HistoryRailClosed` keeps a column holding it, labelled *History* with a count pill. The rail is a column only where all three fit — **980px**, not a Tailwind breakpoint — so each app pairs `min-[980px]:` classes with one `useMinWidth(980)` read and the two must be kept in step. State persists per app (`:historyRail`) and defaults to that same answer.
- `components/ModelPill.tsx` — **the one way a FINISHED output names the model that made it**: `media` / `chrome` / `quiet`. No backdrop-blur — these fade with their card's hover. **In-flight surfaces are deliberately NOT routed through it**: a member watching a generation can't be shown less than one watching a finished tile. Visibility comes from `stores/generationInfoStore.ts` and the switch renders only on the operator-only gate.
- `BracketHighlightArea` (`components/ExpandableText.tsx`) — the prompt field that paints `[bracketed placeholders]` red; `BracketGrowArea` / `BracketInput` are the form-field variants. **The textarea never scrolls itself** — it is grown to full content height and the WRAPPER scrolls, or the red boxes visibly chase the words. Chrome goes on the wrapper, so `focus:` becomes `focus-within:`.
- `components/AutoGrowTextarea.tsx` — **a field inside a scrolling form grows, it doesn't scroll**: a scrolling textarea is a scroll trap that stops the column moving under the wheel. Re-measures on a **width** change via `ResizeObserver`. The other half of the rule: a box owning leftover height takes `flex-1 basis-0` with the floor on the **section**, never `min-h-0` on the section plus a min-height on the field.
- **A history panel next to an input panel is `memo`'d, and its props are stable.** The history banks are uncapped, so a working member's gallery is hundreds of rows sitting in the same component as the box they're typing into — one fresh callback identity per render re-renders the whole list on every keystroke. `PlaygroundHistoryGrid` and Characters' `GalleryPanel` are the two wired this way. → [docs/performance.md](docs/performance.md)
- **A list of media resolves its pictures near the window, not on mount** (`hooks/useNearViewport.ts`, observing the SCROLLER). `loading="lazy"` does not do this — it defers a fetch, and the read, the object URL and the decode have all already happened. Only gate a surface whose placeholder is sized by its own geometry, and whose tile actions don't read the gated URL. **Releasing is OPT-IN (`release: true`) and it is for CLIPS only** — the scarce thing is the decoder, and a still holds none, so a still is read on approach and then kept. A release fires ~400px ABOVE the scroll position, so a tile sized by its picture changes height there and drags the grid under the pointer — which is what "scrolling back up goes crazy" was, twice. → [docs/performance.md](docs/performance.md)
- **A tile in a media grid renders the asset's THUMBNAIL, never the original** (`utils/mediaThumbs.ts`, read through `useAssetThumb` for a still and `useAssetPoster` for a clip's first frame — `hooks/useAssetUrl.ts`). A 1024px-edge JPEG made once per asset per browser, at save time or on first view, kept in its own IndexedDB. The original stays behind `getUrl` for every download, lightbox and generation input. A released clip tile shows its poster, and the returning `<video>` wears it until its first frame decodes, so releasing is invisible. Wired in Playground's grid and list, Characters' grid and list, `ClipDownloadModal`, B-Roll's history mosaic and the Bank's B-Rolls tab. → [docs/performance.md](docs/performance.md)
- **A batch strip is ONE line that scrolls, at every width** (B-Roll's two storyboard strips). Never let it wrap to a second row; `w-max min-w-full` on the inner row is what lets it be both placed and scrollable. → [docs/mobile.md](docs/mobile.md)
- `components/MobilePaneTabs.tsx` — **on a phone a two-pane app shows ONE pane at a time**, never two stacked columns, and firing Generate flips to the output pane. Wired in Characters, Scripts, Voiceovers, B-Roll, Playground and Ad Analyzer; `paneClass` (its sibling module) is the class string every pane wrapper takes. → [docs/mobile.md](docs/mobile.md)
- `hooks/useChromeAutoHide.ts` + `stores/chromeStore.ts` — **on a phone, scrolling down rolls the DOCK away and a sustained scroll up hands it back. Nothing else moves** — not the menu bar, not a panel header, not a search, filter or sort row, and don't reintroduce any of it. A panel's own toggle header lives OUTSIDE its phone scroller, and **any new programmatic scroll inside the pane has to call `suspendChromeAutoHide`**. → [docs/mobile.md](docs/mobile.md)
- **`touch:` is how a hover-only affordance stays reachable** (`@custom-variant touch (@media (hover: none))`). A LONE control just appears (`touch:opacity-100`); a COLUMN of them gets the `⋯` doorway `TileActionStack` renders instead. A `touch:` that MOVES something has to move whatever was clearing it too. → [docs/mobile.md](docs/mobile.md)
- **`max-md:` is where a growing box stops sharing height** — `max-md:flex-none` plus a real `max-md:min-h-[…]` floor on the section, and the column scrolls. The same shortage is why B-Roll's generate band sits inside the scroll on a phone rather than pinned under it. → [docs/mobile.md](docs/mobile.md)
- **A wide data table becomes a CARD LIST below `md`, never a sideways scroller** (Admin's Members and Allowlist). Sort and select-all lived in the column headers and have to be rebuilt as their own phone row; keep the row's actions in ONE shared component used by both shapes. → [docs/mobile.md](docs/mobile.md)
- **A bare `grid` is a horizontal-overflow bug waiting to happen** — with no `grid-template-columns` the implicit track's floor is the widest child's min-content. Always declare the small-screen columns too (`grid-cols-1`), and prefer wrapping a hint under its label over truncating it. → [docs/mobile.md](docs/mobile.md)
- **The gap above a generate band belongs to the BAND, not to the scrolling column** (`pt-2` on the band, `pb-0` on the scroller — Scripts, B-Roll and Playground). Padding on the bottom of a scroll container is part of the scrolled content, so it slides out of view the moment the column overflows — which is its normal state once a member pastes a script or picks an input-heavy model. Measured in Scripts: the last input box sat **2.5px** off the band at scroll-top (reading as touching, which is how it was reported) and 8.5px scrolled to the bottom. A gap that changes as you scroll isn't a gap. On the band it is always exactly 8px, because it renders below the scroller's clip edge where nothing can scroll it away.
- **An app fills its pane exactly — one scroller, the app's own** (`h-full` inside `App.tsx`'s per-app wrapper, with **no layout floor under it**): a second scroller wrapping the whole app unpins every `sticky` bar inside it and the two ports rubber-band. Don't reintroduce a height floor — fix a crushed column on the column — and **no app footer may be `position: fixed`.** → [docs/performance.md](docs/performance.md)
- **A page that is idle produces no frames — nothing may animate forever, however cheaply.** "It's only a composited transform" is an argument about the animation, not about the page: ask what is layered over the thing that moves. The Dashboard's orrery and its drifting sky were both deleted for this. → [docs/performance.md](docs/performance.md)
- **`backdrop-filter` is for small chrome, `filter: blur()` never animates, and nothing on the generating backdrop moves.** A `backdrop-filter` element is a backdrop root, so a repaint anywhere inside it invalidates the whole backdrop — **never put one on a full-window container**, and never put one over a surface that animates. `GeneratingBackdrop`'s three lobes keep a real Gaussian BAKED into a mask image (never a live filter; never "optimised" into gradients, which was tried and banded) and they are **static**: a moving element is a composited layer of its own, three per tile at ~2× the tile, on every card of a batch — which is why baking the blur alone didn't finish the job. The tile's only motion is the progress bar plus one alpha breathe over the lobes as a group. → [docs/performance.md](docs/performance.md)
- **A loading pane breathes as a GROUP; individual skeletons don't shimmer.** `.skeleton` is a flat block and `.skeleton-group` animates the WRAPPER's opacity — one composited layer per pane instead of one per skeleton (B-Roll's storyboard loader renders eighteen). The bar and status line above already say the work is running. → [docs/performance.md](docs/performance.md)
- **Chrome that must not move lives OUTSIDE the scroller, not `sticky` inside it.** Ask first whether the bar ever actually scrolls away; if it doesn't, make it a static `shrink-0` sibling above the scroll port. When a bar genuinely must scroll away and come back, `sticky` is still the tool — just don't also make it glass. → [docs/performance.md](docs/performance.md)
- **Pinned panel chrome is glass, and anything that FADES on hover is not.** Two halves of one backdrop-filter rule. → [docs/performance.md](docs/performance.md)
- **Fields render at 13px under `md`, and the viewport is capped at `maximum-scale=1`** — one rule at the bottom of `index.css`, one meta tag in `index.html`, and they are ONE fix that only works together. It is a FLOOR, not a size. Don't put a blanket 16px back without also removing the cap. A highlight mirror is a DIV and opts in with `.field-mirror`; **never set a phone size on a mirror in its own component.** → [docs/mobile.md](docs/mobile.md)
- **A touch screen reserves no scrollbar gutter** (`@media (hover: none)` in `index.css`, plus an early return in `utils/autoHideScrollbars.ts`). → [docs/mobile.md](docs/mobile.md)
- **Nothing rubber-bands** (`overscroll-behavior: none` on `html, body, #root` and on the overflow utilities). → [docs/mobile.md](docs/mobile.md)
- **Anything anchored to the bottom of the window holds back `env(safe-area-inset-bottom)`.** In a browser tab that inset is 0; installed to a home screen it is the ~34px the home indicator sits in. The pane and the dock must derive from the same expression so they can't drift. → [docs/mobile.md](docs/mobile.md)
- **The app installs as ONE app** (`public/manifest.webmanifest` + the iOS meta tags in `index.html`): `scope: "/"` so a route change isn't leaving the app, `display: standalone`, and a `black` — never `black-translucent` — status bar. → [docs/mobile.md](docs/mobile.md)
- **`.glass-fill` (`index.css`) is the one definition of frosted glass** — the dock's app tiles and every primary Generate CTA. Diffuse and milky, never a tight specular glint; `.glass-fill-soft` turns it down for a **broad** surface. The **rim is not in the class**, and both rims are LIT (top brighter than bottom) — the light-mode pair is repeated in `btn-soft-shadow`, so change one and change the other. **A solid accent CTA hovers with `hover:brightness-110`, never a tint token** (accent ramps flip direction between themes); pair it with `disabled:hover:brightness-100` and `transition-all`.
- **A deploy must never white-screen a member mid-session** (`components/AppErrorBoundary.tsx` + `hooks/useAppUpdateCheck.ts`). Every dock app is a hash-named lazy chunk, so a tab left open across a deploy dies on a MIME error the first time it opens an app it hadn't opened yet. The boundary wraps **each app pane**, decides its screen from BOTH the error's wording and `isUpdateAvailable()`, and offers **Reload** — never a retry. `BUILD_ID` plus an uncached `/version.json` are the half that gets in front of it.
- `utils/audioPlayback.ts` + `components/AudioScrubber.tsx` + `hooks/useAudioPlayback.ts` — **a generated audio clip is played by the app, never by a native `<audio controls>`, and there is ONE transport for every kind of audio.** No waveform: it was deleted in September 2026 along with `waveformPeaks`, and bringing one back means bringing both back. `audioPlayback.ts` owns the app-wide one-clip-at-a-time slot; the element is built on first press, so a list of dozens opens no media elements.
- `hooks/useCloseOnEscape.ts` — every dismissible overlay takes it, alongside the existing backdrop click (and `useCloseOnAppSwitch` when body-portaled).
- `hooks/useBackdropClose.ts` — **the only way a backdrop may close its overlay.** Never write `onClick={onClose}` on one: a text-selection drag that starts in the panel and releases over the backdrop fires a click on their common ancestor and throws the member's edit away. Call it above any early `return null`; a panel that must not dismiss still needs its own `stopPropagation`.
- `hooks/useInlineVideo.ts` — **one clip plays at a time, app-wide.** Spread `hoverProps` on the tile root (never the `<video>`) and `videoProps` on the element. `watching` is the "user is watching this" flag, but **nothing opts into `TileActionStack hidden` any more** — watching a take is exactly when you decide to keep it. Players that keep native `controls` take `useExclusiveVideo`.
- `components/Dropdown.tsx` — the rounded-full select, portaled through `AnchoredPopover`, and **the app's only select** (a native `<select>` ignores the theme entirely). `tier` picks the overlay tier and defaults to the app's LOWEST, so a caller mounted above it needs `tier="panel"`; `placement='above'` for a footer menu; `fitContent` / `menuMinWidth` for filter rows. Reach for it when a segmented toggle would cost a full-width slab.

**Theming (light default + dark mode).** Driven by `data-theme` on `<html>`: an inline script in `index.html` sets it pre-paint; `stores/themeStore.ts` owns the preference (`dark`/`light`/`system`, own localStorage key `ai-ugc-lab-theme`, deliberately per-browser — never cloud-synced, survives sign-out). New browsers default to `dark` — the store fallback and the index.html bootstrap must agree. Switchers: Settings → Appearance + the menu bar's top-right quick toggle. UI chrome must use the semantic tokens from `index.css`, never literal white/zinc/dark hexes:
- `ink` — fg chrome (white in dark, near-black in light): `border-ink/10`, `bg-ink/5`, `text-ink`. `paper` is its inverse (`bg-ink text-paper` buttons).
- `surface-0/1/2` — page → panel → popover elevation.
- `ink-50…950` — text ramp; dark equals zinc, light is mirrored (ink-100 stays "bright", ink-500 mid, ink-700 dim). Inverse elements self-flip (`bg-ink-100 text-ink-900`).
- Accent families auto-flip their 100–400/600 tints in light mode.
Exceptions that stay literal: anything overlaying user media (badges/scrims/play buttons → `text-white`, `bg-black/60`, `from-black/85`), white text on solid accent buttons, modal backdrops. Status tints (-100…-400 colored text on tinted bg) need a `light:` darker variant (`text-red-300 light:text-red-700`; the `light:` custom variant is defined in `index.css`). `AppBackground.tsx` holds the per-theme canvas gradient.

**Errors.** End-user generation surfaces show friendly copy via `humanizeError()` (see `utils/friendlyError.ts`). It always returns a **complete sentence** — toast it verbatim and name the operation in the `fallback`; never prefix the result (``addToast(`Video generation failed: ${msg}`)`` printed the operation twice). Infra/admin/Settings surfaces still surface the raw kie.ai message — the operator debugs there. Note: the kie envelope can return `{ code: 5xx, msg: "...maintained..." }` inside an HTTP 200 during maintenance windows — not a code bug. **The rule table matches on SUBSTRINGS, so a new "timed out" is a new rule, not a free ride on an old one:** the asset-download deadline (`Timed out downloading…`) fell through to the poll-timeout copy and told members a clip that had already finished and billed was "still running on kie.ai" — three separate timeouts now say three different true things, and the one that matters most is the last (kie finished, the download didn't) — with a fourth added in August 2026 for the failures that happen on THIS machine (`probeVideoBlob`'s decode budget, a blob the `<video>` element rejects), which said "timed out" too and sent members off to kie.ai to look for a task that had already finished. **The other half of that rule is the button underneath it:** a Retry offered on anything we still hold a kie `taskId` for must RESUME the task, never re-submit it — see B-Roll's `resumeInFlightVideo` — and the surface must SAY so, because a member who reads "check kie.ai before generating it again" reasonably assumes Retry costs another generation and dismisses the tile instead. B-Roll's amber "Not saved" state (its own file) is that idiom: free-retry copy, and a two-click Dismiss on anything still recoverable. **A refused prompt is a content rule, not a validation rule, and the moderation test is written in the VENDORS' vocabulary** — it arrives as a 422 as often as not, so it sits above the validation rule and matches what each provider actually says (`InputTextSensitiveContentDetected`, "text risk not passed", "suspected of violating", PROHIBITED_CONTENT), not what we'd call it. Everything it misses falls through to "adjust your inputs (prompt, reference images, or settings)", which sends a member off swapping pictures when the words are the problem. Add a vendor phrase when you see one; keep loose words out (bare `blocked` catches a throttle, bare `explicit` catches "explicit aspect_ratio required").

**`humanizeError` is a translator for VENDOR wording, so anything we raise ourselves throws `FriendlyError`.** The rule table can only recognise phrasing it has seen; a message we wrote — a file we measured, a browser capability we probed, a limit we know the number of — falls through it and lands on the generic fallback, losing exactly the detail that made it worth writing. `FriendlyError` (`utils/friendlyError.ts`) is handed straight back instead. It is not a way to smuggle raw API text past the table: it is for sentences written for a member in the first place, and each one still has to be a complete sentence naming what to do next.

**A capability claim in UI copy names no model.** Toasts and inline notes that said "Switch to Seedance 2.0 or Gemini Omni" were written when those were the only two ref-capable entries; the registry grew to where most of the picker takes reference images and the copy still named two, reading as the complete list — and one of them, Gemini Omni 1.0, couldn't take a start frame at all, so the animate-tab copy was recommending a model that would refuse (that entry has since been removed, which changes nothing about the rule — the next stale list will name different models). Point at the picker instead ("the ones that can't are greyed out"): its greying is derived from `modes`, so it can't go stale. The same rule applies to the capability itself — check what the model DECLARES before telling a member it can't do something, and check what `buildVideoInput` does with the input before refusing the run over it.

## Tech Stack

- React 19 + TypeScript + Vite (`npm run dev` → http://localhost:5173). Tailwind CSS 4. Zustand for global state.
- **The React Compiler is on** (`babel-plugin-react-compiler` in `vite.config.ts`), so don't hand-write `useMemo`/`useCallback` for ordinary render work — it memoizes every component and hook it can compile. Two things make it silently **skip a whole component**, and both are worth avoiding in new code: an `// eslint-disable` of any `react-hooks/*` rule anywhere in the file, and a `try`/`finally` or catch-less `try` inside the component (move that work to a module-scope helper, as `finishResumedTask` in `playground/Playground.tsx` does). `npx eslint .` reports the first kind; for the second, the ground truth is whether the dev server's output for a file imports `react/compiler-runtime`. Coverage is partial today — the app roots that still bail are a known list, not an oversight. The compiler also memoizes **plain calls**, which is a trap for mutable state read through a stable function: `const get = useSettingsStore((s) => s.getAppModel)` then `get(key)` in the body compiles to a cache keyed on two things that never change, so it runs once per mount and the component renders that first answer forever (this is exactly how both model pickers came to show a model you hadn't picked). **Read store state through the selector** — `useSettingsStore((s) => s.getAppModel(key))` — never by calling a getter you pulled out of the store.
- IndexedDB twice over: `assetStore.ts` for media blobs (mirrored to Cloudflare R2 when cloud sync is active) and `bankPersist.ts` for the local bank cache (its own DB, one record). localStorage for settings, picker selections, per-app drafts, and `cloudSync`'s outbox.
- **Cloud (opt-in):** Supabase (auth + Postgres) + R2. Enabled when `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` are set; absent → local-only mode (100% client-side). Access gated by email allowlist synced from Skool via Zapier.
- kie.ai Bearer token sent directly from the client (no proxy).

## kie.ai client (`src/utils/kie.ts`)

Four transports — pick by task type. Endpoints and result shapes live in `kie.ts`; the gotchas worth knowing here:

**Every call that CREATES a generation goes through `submitToKie` (`utils/kieSubmitGate.ts`), and it has to stay that way.** kie rate-limits an account to ~20 new generation requests per 10 seconds, and a rejected one is **not** queued server-side — it comes back 429 and that generation never happens. Every batch surface in this app fires its whole run in one tick (B-Roll's "Generate all images / videos" over a dozen-plus cards, Continuous' clip run, a Playground or Voiceovers batch), so a big storyboard walked past the ceiling and a chunk of the tiles came back as errors. The gate spaces submissions `MIN_SUBMIT_GAP_MS` apart app-wide (one queue across every app — a member can have two batches running), and a 429 that still lands calls `noteRateLimited`, which stands the **whole** queue down instead of letting each queued card discover the limit for itself. This is invisible because every generation surface pushes its in-flight tile BEFORE the network call: the run looks started the instant the button is pressed, and only the POST waits. Wired into `createTask`, `kieVeoCreate`, `kieMusicGenerate` and the two omni creates. Polling, reference-image uploads and chat completions are deliberately outside it — see the note in the file before adding anything.

**Every response body is read on a deadline, and it has to stay that way.** `fetch()` settles at the *headers*, so a timeout that stops there is disarmed while the body is still streaming — and a stalled body read never settles, which is a hang with no error, no cancel and no exit but a page reload. `fetchWithRetry` therefore hands back a Response whose `json`/`text`/`blob` are re-armed with a fresh budget (`armBodyTimeout`), so every transport routed through it is covered by construction. **A new call site that reaches kie with a bare `fetch` opts out of this.** The *result download* is the other half of the same rule and has its own helper: **`fetchGeneratedAsset(url, { signal })`** bounds the CDN hop that pulls a finished image / video / audio / cover off kie (one controller for the request AND the body read, `ASSET_DOWNLOAD_TIMEOUT_MS`, caller-cancellable). Every result download goes through it — `finishImageAssetTask`, `finishVideoAssetTask`, `finishVoiceTask`, `finishPlaygroundMusicTask` — because that hop runs AFTER kie has generated and billed, so a stall there parked the tile on "generating" with no error and no cancel. The only remaining legitimate bare fetch is `downloadAssetFromR2` (`lib/r2.ts`), which carries its own timeout; anything new must too.

**A chat response cut off at the token limit throws, it is never returned.** `kieChatCompletions` reads the stop reason on every transport and both body shapes — `finish_reason: 'length'` (openai-chat), `stop_reason: 'max_tokens'` (claude-messages, top-level when buffered and inside `delta` on the streamed `message_delta`), `incomplete_details.reason: 'max_output_tokens'` (openai-responses, nested under `response` while streaming, on the terminal `response.incomplete` event) — and raises `TruncatedResponseError`. It is thrown rather than returned with a flag because a truncated answer is silently **salvageable** downstream: `services/xmlBlocks.ts` is deliberately tolerant of a missing closing tag, so a cut-off storyboard rendered as a short one with no error and the member fired paid image/video gens against scenes the script never got. Throwing makes it honest in all ~20 call sites at once, since every one already has a catch. **The JOBS transport reads the same stop reason** (`chatTaskHitTokenLimit`, September 2026) — it never did, and that is the transport the app's longest output takes, since B-Roll's storyboard runs there precisely so it survives a reload; a cut-off run therefore arrived looking clean and B-Roll "cut out half way through the script". It answers off `resultJson`, checking all three envelope shapes together because the record doesn't say which transport produced it. **The partial text rides on `err.partial`** so a caller can salvage it without changing the signature; nothing does today. `openai-chat` deliberately still sends **no `max_tokens`** — only `claudeBody` caps output (16384) — because kie's gateway default is unknown, and our own number could as easily lower the ceiling as raise it; set one from a real truncation, not from a guess.

**A chat error arrives inside an HTTP 200, so `kieChatCompletions` reads kie's `{ code, msg }` envelope before it reads the content** (`chatEnvelopeError`) — the same check `authedFetch` has always run on every jobs-API call. It didn't until August 2026, and the cost was one wrong sentence everywhere: a bad key, an empty balance, a 429, a maintenance window and a 5xx all came back as a body with no `choices`, fell through to the "Empty response from chat model" throw, and reached the member as *"The model returned an empty result. Try again, or simplify your prompt."* on all ~20 chat call sites — reported from the Ad Analyzer, where a whole video is uploaded before it says so. Verified live: an unauthenticated POST to a chat endpoint answers `HTTP/2 200` with `{"code":401,...}`. The same helper reads the OpenAI-style `{ error: { message, code } }` a gateway emits, and runs over an SSE body that produced no content (`emptyStreamError`, event by event AND on the whole body, since kie sometimes sends the envelope under an event-stream content type) — so the vendor's own wording reaches `humanizeError`'s rule table instead of being cut away as a debug tail.

1. **Async task** (`createTask` → `pollTask` → `parseResult`) — `POST /jobs/createTask` → poll `GET /jobs/recordInfo`. Result URLs are string-encoded JSON inside `resultJson.resultUrls`. Outputs expire in 3 days — always `fetchGeneratedAsset` + `saveAsset` (as a Blob end to end, never via a base64 string: the round trip built three copies of the file on the main thread at the exact moment the rest of the batch was still animating). The shared tails `finishImageAssetTask` (`utils/imageTask.ts`) and `finishVideoAssetTask` (`utils/videoTask.ts`) wrap poll→download→save for every image/video surface; the video one adds the black-tile guards (0-byte / non-video content-type / `probeVideoBlob` decode check).
2. **Chat completions** (`kieChatCompletions`) — `POST /<slug>/v1/chat/completions`, streaming SSE, falls back to JSON parse then surfaces the body's first 400 chars on failure. Vision via `image_url` blocks (data URIs work, no upload). Get the endpoint path from `getChatEndpointPath()` — never hardcode slugs. **A chat call that must survive a page reload goes through transport 1 instead**: `createTask` accepts a chat model (named by its `chatSlug ?? id`) with `{ messages, stream: false }`, the taskId is persisted so the poll can be re-attached, and `extractChatTaskText(record)` reads the several shapes kie returns the answer in. A model with no job route 400s at `createTask`, so both surfaces that do this — the Ad Analyzer's video read and B-Roll's storyboard — **fall back to streaming and treat that run as unresumable**. Nothing else needs it: the streaming transport is simpler and every other chat call is short.
3. **Veo** (`kieVeoCreate` → `kieVeoPoll`) — custom `/veo/generate` + `/veo/record-info`. Variant (`veo3` / `veo3_fast` / `veo3_lite`) via the `model` field, not the URL. Results nest under `response.resultUrls`.
4. **Suno music** (`kieMusicGenerate` → `pollMusicTask`) — custom `/generate` + `/generate/record-info`. Suno-specific status values; `callBackUrl` is required by the schema but we pass a no-op and poll. Audio at `response.sunoData[].audioUrl` (v1 uses the first track).
5. **Omni create** (`kieOmniAudioCreate` / `kieOmniCharacterCreate`) — synchronous `POST /omni/audio/create` and `/omni/character/create`, no polling. Mint persistent `kieAudioId` / `characterId` values (scoped to the member's kie account) that `google/gemini-omni-flash-1-1` consumes as `audio_ids` / `character_ids`. Success can come back as envelope code 0 *or* 200.

`ensureHostedUrl(apiKey, source)` uploads `data:` URIs to kie's file host (image→image and frame-conditioned video models need public URLs; hosted files expire in 3 days). `kieTestConnection` checks the credit balance (Settings).

OutputPanel resumes pending tasks on mount; entries older than 30 min are evicted with a Reset link.

Per-model detail — why each default holds its slot, what held it before, and the pricing caveats to re-verify — lives in [`src/utils/CLAUDE.md`](src/utils/CLAUDE.md), which loads automatically when you work under that folder.

## Non-obvious files

Most files are self-explanatory. These carry behaviour worth knowing before you touch them:

- `stores/bankStore.ts` — all banks + history + `migrateVoiceShape`.
- `utils/appUsageTracker.ts` — the **only** signal in the app for which app a member is in and for how long. Everything else the Admin panel reports is derived from OUTPUTS (assets, bank rows, generation counts), which measures what members produced and never what they used — so Outliers (no history bank), Bank, Edit and the Dashboard were invisible, and "is anyone opening Outliers?" was unanswerable. Three rules keep the number honest rather than flattering, and all three are load-bearing: it is **attention** time, accruing only while the tab is visible and someone has interacted inside `IDLE_AFTER_MS` (an unbounded "app was open" figure makes whichever app people leave on top look like the most-used one in the community); it **samples** on a `TICK_MS` interval rather than integrating wall clock, so a sleeping machine simply stops firing and can never wake up and bank eight hours; and it **buffers** across dock switches, committing every `COMMIT_EVERY_MS`, because each commit is a bank-row write plus a cloud upsert and rapid dock-hopping would otherwise be one of each per hop. `stopAppUsageTracking` **discards** the buffer on purpose — the only thing that stops it is the workspace unmounting on a user change, and a commit there races the sign-out wipe, so losing minutes beats landing one member's time in the next member's ledger on a shared browser.
- `scripts/build-vault.py` — one of the two build steps in this repo that aren't `npm run build` (`build-character-presets.py` is the other, and follows the same pattern), and the source of `public/vault/` (the Outlier Vault's 872 rows + one 400px cover each). It reads a corpus that lives OUTSIDE the repo, in Massimo's `1000 Outliers` folder, so nothing in CI can regenerate it: the committed output is the source of truth and the script is how it gets refreshed when the corpus grows. Static files rather than a bank table on purpose — the library is identical for every member and read-only, so a synced copy would be 872 rows of the same thing per account. See the vault section of [`src/apps/discover/CLAUDE.md`](src/apps/discover/CLAUDE.md).
- `scripts/build-character-presets.py` — the same shape, for `public/presets/` (the Characters app's 81 starter characters: one flat DNA row each in `library.json`, then **two** image tiers — a 502x900 card cover under `thumbs/` and the source's own 768x1376 portrait under `full/`, fetched only when a member saves that template into the Characters bank). Reads a folder of paired `<slug>.json` / `<slug>.jpeg` exports that lives outside the repo, so the committed output is the source of truth here too. These were nine `PRESET_*` consts and nine bundled JPEGs inside `character-studio/types.ts` until August 2026; at 81 they are data, not code, and nothing but the preset picker ever read one. It also **names** every row `<Scene> <Gender> <n>` (numbered within its group, always — a group of one included, or a grid reads as two naming schemes), keeping the export's own descriptive name as `title` for the tooltip and the search haystack. Skips a `__alt` second take, and derives each row's scene facet from the source folder's own numbering — the profile's `location` is free text and makes no facet.
- `utils/orphanCleanup.ts` — once-per-sign-in asset sweep. Its bank list **must** cover every bank (compile-time `satisfies Record<BankKey, true>` guard) or it deletes that bank's live assets from IDB + R2. Asset refs come in two shapes (bare `asset-x` and `asset://asset-x`); anything comparing refs against `assets.id` must normalise via `assetIdFromRef` first — unnormalised comparison once purged every B-Roll video. Its `assets` read is **paged** (`selectAllRows`) for the same reason: this list is the delete-candidate set, so a truncated read pairs a partial asset list against a partial ref set and purges live blobs the unread rows referenced. Both halves have to stay paged together.
- `utils/assetStore.ts` — IndexedDB blobs + fire-and-forget R2 mirror; `getBlob()` falls back to R2 on miss. **Two tiers, and neither may latch.** `fallbackStore` is a memory holding pen for blobs IndexedDB *individually* refused — it is consulted before IDB on read and written alongside it on failure, but it must never short-circuit IDB, and a failed `openDB` must never be cached (`dbPromise` is nulled on rejection). Both used to latch for the life of the tab, so one transient eviction made every later save memory-only — saved to all appearances, gone on reload — which is why reloading "fixed" saving. `openDB` also carries a deadline and an `onblocked` handler: `indexedDB.open` fires neither `onsuccess` nor `onerror` while another tab holds an older version, and `saveAsset` awaits it, so an unbounded open meant Save did nothing at all. Writes/deletes handle `tx.onabort` as well as `onerror` — a quota-exceeded transaction aborts, and without it the promise never settles.
- `lib/r2.ts` — presign → PUT → `assets` row upsert, the R2 mirror behind every `saveAsset`. **All three hops retry, and the mirror runs under a concurrency cap** (`MAX_CONCURRENT_UPLOADS`), because a batch's outputs all land at once — `finishImageAssetTask` / `finishVideoAssetTask` are the tail of every generation — and a dozen simultaneous multi-MB PUTs starve the small requests sharing the uplink. That surfaced as `assets row insert failed: TypeError: Load failed`, which is WebKit's wording for *any* network-layer fetch failure (Chromium: "Failed to fetch") stringified into supabase-js's `error.message` — the same text a backgrounded tab, a dropped hop and a saturated uplink all produce, so transience is judged by `TransientError` where we already know (a 5xx, a stall we timed out ourselves) and by `TRANSIENT_MARKERS` where the browser tells us nothing else. A retry **never re-PUTs a binary that already landed** — the row insert is the half that fails, and re-sending tens of MB to fix a 5-column row feeds the saturation that caused it. Requests carry a real `AbortController` (`fetchWithDeadline`), covering the body read as well as the headers: the old `withTimeout` race only rejected the wrapper, so a retry would have competed with the zombie upload whose stall triggered it. A run that exhausts its attempts is still recovered by `cloudSync`'s `reconcileAssets` on the next load, which is what the toast promises. **Downloads are capped too** (`MAX_CONCURRENT_DOWNLOADS`, September 2026): every history bank resolves its media through `getBlob`, so a gallery of hundreds misses IndexedDB hundreds of times on a browser that hasn't seen this account — a second device, cleared site data, or Safari evicting a site it hasn't opened in a week — and each miss is THREE round trips (the `assets` row select, the presign, the CDN GET) that were all fired in one tick. The gate wraps the whole function so one asset's three hops share one slot; gating only the binary GET would leave the selects and presigns to stampede on their own.
- `utils/friendlyError.ts` — `humanizeError(err, fallback)`, the ordered rule table for end-user error copy. The status-code rules are plain substring matches, so the message is first **cut at its debug tail** (`taskId=` / `url=` / `record=` / `body=` / `size=` / `endpoint=`): those payloads carry arbitrary digits, and `…video (size=402B…)` used to tell a member with a full balance to buy credits while any blob size containing `401` told them to replace a working key. Keep new debug context behind one of those keys, or behind a new one added to `DEBUG_TAIL`.
- `api/fetch-media.ts` — the only server-side URL fetcher in the app (Outliers → Ad Analyzer). It is an SSRF primitive by construction, so it keeps a **suffix-matched host allowlist** checked on the parsed hostname AND re-checked after redirects, never a substring match on the URL. Auth-gated like the R2 routes.
- `utils/team.ts` — **one crew member per dock app.** Meet the Team reads the roster off `dockOrderedApps()` rather than off this array's own order, so adding an app needs no hand-edit here beyond its own entry. The Dashboard used to zip this array against an `ORBITS` list to fly the crew around a sun; that orrery is gone (September 2026) — see the idle-page rule in [docs/performance.md](docs/performance.md).
- `utils/voiceProfile.ts` — `VOICE_PROFILE_SPEC`, the one wording for "describe how this voice sounds". Scripts WRITES one at the end of a scene blueprint, the Ad Analyzer READS one off an existing ad; they must agree, or a profile can't move between the two. B-Roll keeps its own phrasing inside `<VOICE_PROFILE>` because it's written against that prompt's character contract.
- `utils/mockData.ts` — the Settings demo seeder. Covers **every** tab: both banks and every history stream, a worked Line-by-Line session AND a Continuous keyframe chain (History row, since the workspace holds one session), styles, product extra angles, canvas-drawn stills, MediaRecorder clips and synthesized audio. Two rules: seeded rows match the real thing's shape (3 variations per scene, 3 concepts per frame — a short row reads as an app bug), and everything is reversible via the id manifest. The `usageDays` ledger is the exception worth knowing — it feeds the Dashboard, is priced through the real `foldUsageEvent`, and is written **only for days with no existing row**, so removal can never take a member's genuine activity with it.
- `hooks/useCloseOnAppSwitch.ts` — every body-portaled overlay (modal, picker, lightbox) must call it: portals escape the opacity-0 wrapper that hides background apps, so an open overlay would float over the next app after a dock switch.
- `lib/cloudSync.ts` — pull on sign-in + debounced diff-push + persistent localStorage outbox + non-destructive hydrate. `saveRow`/`deleteRow` are serialised per row (a stalled upsert can't land after a delete) and outbox markers are token-guarded (a late success can't clear a newer pending write). `walkAssetRefs` normalises `asset://` refs to bare ids so the sweep/reconcile match the bare-keyed `assets` table.
- `lib/supabase.ts` — `ensureFreshSession()` (3s race + cached-token fallback) and a custom non-blocking `auth.lock`.
- `hooks/useAssetUrl.ts` — resolves `asset://` refs to blob URLs.

## Banks

Cached locally in **IndexedDB** (`utils/bankPersist.ts` — DB `ai-ugc-lab-banks-db`, one record under one key, written by structured clone rather than a JSON string). It lived in a single localStorage key and outgrew it: one `BrollHistoryItem` carries whole session snapshots and measures ~43 KB, so the capped-at-50 B-Roll bank alone is ~2 MB and the blob passed what Safari takes in one `setItem` — a `QuotaExceededError` on a browser holding 0.44 MB in total, i.e. a per-value ceiling, not a full disk. The old key (`ai-ugc-lab-banks`, exported as `LEGACY_STORAGE_KEY`) survives in exactly two places and no more: `readLegacySync` reads it once for the synchronous first paint, and `dropLegacy` removes it as soon as the IndexedDB copy is written. **This copy is a boot cache, never the source of truth** — the cloud is, and hydrate refills memory from Postgres — so `flushSaveToStorage` logs a failed write and never toasts one; telling a member their work is at risk because a speed optimisation missed would be false. **Which banks reach that cache is a compile-time exhaustiveness check**, not a hand-kept list: `BANK_DATA_KEYS` is an object literal under `satisfies Record<keyof BankData, true>`, the same guard `orphanCleanup` uses. It was an array of key strings, which only proved that every key listed is a real bank and never that every real bank is listed — so a bank added to `BankData` and forgotten there simply stopped being cached, silently, and only on a reload. Asset blobs live in their own IndexedDB store (mirrored to R2 in cloud mode); rows store `asset://<id>` refs. `useAssetUrl(ref)` turns a ref into a blob URL. Types are in `stores/types.ts`.

`products`, `models` (from Influencers), `scripts`, `voices`, `brolls`, `styles`, `swipes`, `trackedAccounts`, plus auto-pushed history banks: `voiceHistory`, `videoHistory`, `imageHistory`, `musicHistory`, `scriptHistory`, `brollHistory`, `characterHistory`, `adAnatomyHistory`, and the Dashboard's `usageDays` ledger (all cloud-synced — every bank table has a Postgres mirror). Gotchas:

- **`usageDays`** — accumulate-only usage ledger: one row per local calendar day (`id: 'YYYY-MM-DD'`), holding per-kind generation counts + estimated kie credits + official-API USD, **plus per-app attention time** (`apps`, see below). Written by `bankStore.recordUsage`, which is called inside the `add*History` actions (plus B-Roll's `finishImageTask` and the Ad Analyzer complete-flip) — new generation surfaces get counted for free if they push history. Deleting/clearing history never subtracts. One-time backfill from history (`backfillUsageLedger`, flag `ugc-lab:usage-backfill:<uid>`) runs post-hydrate in cloudSync (local-only: Dashboard mount) and skips ids in the mock-data manifest. Mock seeding suppresses live recording via `setUsageRecordingSuppressed`. Its Postgres table `usage_days` (migration 0016) uses a **composite PK (user_id, id)** because day keys repeat across users — run the migration before deploying, or every hydrate reports a per-table error (which also skips the auto orphan sweep). 

  **`apps`** is the row's other half: `{ [appId]: { seconds, opens } }`, written by `utils/appUsageTracker.ts` through `bankStore.recordAppUsage`. It rides this row rather than a bank of its own because it answers the same question ("what happened on this day") and because `usage_days` already carries the sync wiring and the admin-read policy the Admin panels read through. Two things follow and must stay true: a day can hold app time and **no** generations, so everything measuring output (streaks, savings, the heatmap, `computeUsageMetrics`) keys off `counts` and correctly ignores a browse-only row — and `backfillUsageLedger` therefore guards on real counts and **folds onto** the existing rows rather than replacing the array, or the first browse of a session would skip a member's whole history backfill and delete the time that triggered it. Aggregated for the admin by the `member_app_usage` view (migration 0022) — run it before deploying, alongside 0016.

- **Starring.** `products` / `models` / `scripts` / `brolls` / `styles` items carry `starred?: boolean` — flipped by bankStore's silent `toggleStar` (no toast) from a star button in the Bank cards' hover stack. Starred items sort first in every `BankPicker` (`starredFirst` in `finder/bankSort.ts`, amber badge on the card); the Bank browser's own sort order is deliberately untouched (B-Rolls are day-grouped).

- **`styles`** — visual looks for B-Roll (name + `brief` + up to four `thumbRefs`). The brief IS the style: it's the paragraph appended to every prompt rendered in that look, so it must describe the LOOK only, never anything from the frames it was read from. Thumbnails are this bank's own assets (nothing else links them), so delete/replace purges them outright. Postgres table `styles` (migration 0017) — run it before deploying, or every hydrate reports a per-table error (which also skips the auto orphan sweep).
- **`swipes`** — the swipe file behind Outliers: ads saved from a search, filed by the Bank's **Swipe File** tab. A row is the ad's identity (`platform` + `sourceId` + `postUrl`), a **snapshot of its numbers AS SAVED** (a swipe is a record of what a winner looked like when you found it, not a live feed), its caption, and its transcript when one had already been fetched — never re-billed for the sake of the save. The **thumbnail is copied into our own storage** (`saveThumbnail` → `thumbRef`), because every media URL a search returns is a signed CDN link that expires within days; a row that merely remembered the URL would be a broken image by the time it mattered. Following the same rule as `brolls`, the **video is deliberately not stored** — a swipe file is meant to hold hundreds of ads and a few MB each would eat the 10 GB cap for footage that `postUrl` can re-reach. `getSwipeBySource` keys off platform + source id so the Save button reads as saved and the same ad can't be filed twice from two searches. **The card opens the same detail view Outliers does** (`finder/SwipeDetail.tsx` → `swipeToResult` → the one `ResultDetailModal`), never an edit form — there's nothing here that's yours to edit, but tearing the ad down later is the entire reason you filed it, so Analyze Ad / Remix Transcript / the permalink all have to be where they were when you saved it. It opened the permalink outright until August 2026, which made the swipe file a bookmarks folder. What that costs is the video: `mediaUrl` is signed and expires, so a saved row plays only while it's fresh and then offers **Restore video — 1 credit** (`refreshResultMedia`, 1 ScrapeCreators credit, `/v2/tiktok/video`, `/v1/instagram/post` or `/v1/facebook/adLibrary/ad`), writing the new link back to the row so a second visit inside its lifetime is free. **A refresh re-resolves MEDIA ONLY, never the stats** — the snapshotted numbers are what make this a swipe file rather than a bookmark. A dead link is dropped from the result rather than re-rendered, because a failed `<video>` keeps its transport controls and reads as something you could press; the greyed Analyze beside the Restore button is the honest state, and the auto-refresh inside `downloadWithRefresh` only covers the case where the link looks alive and 403s at fetch time. A transcript bought here is written back to the row too, so it's paid for once rather than once a visit. It is **shaped exactly like the Outliers card it was saved from** — picture in its own 4:5 frame, then a static block of author / caption / snapshotted engagement row underneath — five across to match. It used to read its caption off a gradient laid over the frame, which put text across the ad's own hook (the one thing you saved it for) and left the numbers nowhere to live. Postgres table `swipes` (migration 0019) — run it before deploying, or every hydrate reports a per-table error (which also skips the auto orphan sweep).
- **`trackedAccounts`** — the creators a member watches in Outliers' **Accounts** tab. A row is the CURATION plus a snapshot: the handle, Instagram's numeric id, the avatar copied into our own storage (signed urls rot, same rule as a swipe's thumbnail), and the follower count / median plays / sample size as of the last refresh. The **reels are deliberately not on it** — they carry signed CDN urls that expire, there can be fifty an account, and one credit re-buys the lot, so Outliers caches them in browser-local state and this bank stays a short, durable list worth syncing across devices. The snapshot is what makes a second machine useful before it has spent anything: the rail says what each account normally does with no reels loaded. `addTrackedAccount` dedupes on the handle, so the same creator can't be filed twice. Postgres table `tracked_accounts` (migration 0024) — run it before deploying, or every hydrate reports a per-table error (which also skips the auto orphan sweep).
- **`brolls`** — only **stills** are saveable to the bank (reusable as start frames / references); videos are download-only, so no UI writes new `videos[]` entries anymore (the save-to-bank action is hidden on video tiles in B-Roll + Playground). The `videos[]` field and its render/edit/cleanup paths stay for back-compat — older saved-video entries (and the video-only-broll render path in `BankList`) still display and download. Saved video-history items stamp `linkedBRollId`; deletion only purges the blob if not linked.
- **`videoHistory`** is shared by B-Roll and Playground (for refresh-resume); Playground's grid filters out `sourceApp === 'broll-studio'`. No automatic retention — entries persist until the user deletes/clears them. Only `brollHistory` is capped (`BROLL_HISTORY_CAP`, FIFO); the other history banks (`videoHistory`/`imageHistory`/`musicHistory`/…) grow unbounded **in memory and in the cloud, by design** — a member's outputs are never evicted behind their back. Nothing is trimmed to fit any more: the local cache moved to IndexedDB (see above), which has no comparable per-value ceiling, so `flushSaveToStorage` writes the whole set or logs the failure — it never sheds a row to make one succeed. Treat a cache-write failure as a **local** problem, never as a reason to delete a row. `cloudSync`'s outbox is still on localStorage and still matters: it's the replay guarantee behind every fire-and-forget push, it used to swallow `QuotaExceededError` silently (so a full disk lost a new row while the member watched a green "Saved"), and it now `console.error`s once per run of failures.
- **`characterHistory`** carries `imageRef` + the full `profile` snapshot; `linkedModelId` is set on save-to-bank and gates blob purge. Presets aren't a bank — reuse a recipe by saving to `models` and reloading via the Controls header dropdown. The nine built-in starters (`PRESET_*` in `character-studio/types.ts`) **fill all 28 fields and pick the starred option wherever the field offers one** — a one-word `skinTexture: 'Glass skin'` leaves the model to invent the rest and what it invents is the plastic look the presets exist to avoid, and an empty field drops out of the prompt entirely. "Starred" is `ChipField`'s `isDetailed` (a chip over 30 chars), so a preset value only shows as a picked row when it's EXACTLY one of that field's own detailed chips — which is why the age-appropriate skin tiers and the per-character hair styles were added to the chip lists rather than written as preset-only free text. `No makeup` on the men and the free-text `facialFeatures` / `distinguishingMarks` / `accessories` fields are correct as-is, not gaps.
- **`VoicePreset` / `VoiceHistoryItem`** carry the Gemini TTS param set (`voiceId` = `voice_name`, `style`, `pace`, `accent`, `temperature`, optional `scene` / `sampleContext`). `migrateVoiceShape` strips the legacy ElevenLabs numeric fields (`stability` / `similarityBoost` / `speed`, and the old numeric `style`) and backfills the new string defaults (`Natural` / `Natural` / `Neutral`, temp `1`).

## Auth + cloud sync

`AuthGate` wraps the app and picks one of five screens, in this order: bootstrapping → spinner; **recovery** → `ResetPasswordScreen`; signed-out → `AuthScreen`; **lapsed** → `LapsedScreen`; signed-in → workspace + `UserMenu`. The order is load-bearing at both ends — a recovery link carries a real session, so checking it after the session check would drop the member into the workspace with the password they came to change still set; and a lapsed member holds a session whose RLS refuses every bank table, so their screen has to come before the sync that would hydrate against them. `syncBlocked` keeps `startCloudSync` from firing in either state. The three signed-out screens share `components/auth/AuthShell.tsx` (wallpaper + brand + `max-w-sm` column + legal row) and its `AuthField`. No cloud env vars → local-only mode with a bottom banner. Full deploy stack is in `DEPLOYMENT.md`; threat model in `SECURITY.md`.

- **Onboarding.** `components/ApiKeyGuide.tsx` and `MeetTheTeam` both **take the kie.ai key inline** rather than sending the member to Settings, both through `useKeyConnect` — which checks the key against the live balance **before** it is saved, so nothing is ever stored that can't generate. Both are infra surfaces: a failed check shows kie.ai's own message, not `humanizeError` copy. `MeetTheTeam` is **ONE chain** in `dockOrderedApps()` order.
- **Allowlist.** Postgres trigger `enforce_allowlist` blocks signups not in `public.allowlist`, with no client bypass; `app_config.enforce_allowlist` is the global kill-switch and a signup **access code** (`app_config.signup_code`) runs *before* it, so opening the switch isn't opening the door to everyone. The expected code is **never shipped to the browser** — the client posts what was typed and the trigger compares, then strips it off `raw_user_meta_data`. Zapier syncs Skool events in.
- **Member status** (migration 0023). Three states — **Active** · **Lapsed** (member reopens it themselves) · **Disabled** (only an admin does). `is_active()` is false for both locked states, so RLS refuses every bank table; **no status has ever deleted anything.** `redeem_access_code(code)` is the way back and **returns a jsonb verdict rather than raising**, because a raise would roll back the attempt counter that throttles guessing. `prevent_privilege_escalation` guards `lapsed_at`, or a lapsed member would clear their own flag.
- **Password recovery.** **Forgot your password?** → `resetPasswordForEmail` with `redirectTo` = `RECOVERY_PATH`. Two things make that path work: `RECOVERY_ON_LOAD` is read at **module scope** in `authStore` (by render time neither piece of evidence is left), and AuthGate short-circuits on it before `RouterSync` mounts. The confirmation says "**if** that email has an account" on purpose. Needs two Supabase settings — see `DEPLOYMENT.md`.
- **Cloud sync** (`cloudSync.ts`). Pulls profile + all bank tables on sign-in. `bankStore` writes local first, then fires the push in the **background** — `pushRow`/`dropRow` are fire-and-forget. **The UI must never `await` a cloud round-trip** (that was the "save stuck loading, then times out" hang, and it could drop the row on a mid-hang refresh). Durability comes from the **outbox**, not the await: the row is persisted to localStorage **synchronously** before the push fires and replayed by `drainOutbox()`. **Hydrate is non-destructive** — a per-table error keeps local rows, never `[]`. **Every whole-table read is paged** through `selectAllRows`, or a truncated read gets written to the local cache and feeds the orphan sweep a partial ref set.
- **Session freshness** (`supabase.ts`). Every cloud write awaits `ensureFreshSession()`, which races `getSession()` against a 3s timeout and falls back to a module-cached token (kept current by an `onAuthStateChange` listener) when the SDK's auth lock stalls after a backgrounded tab returns. The client also uses a custom `auth.lock` (`nonBlockingLock`, ~2s bound then runs unlocked) because supabase-js takes that lock on every request. `visibilitychange` recovers the token on focus.
- **kie.ai key is browser-local only.** It lives in `localStorage` under `ai-ugc-lab-settings` and is **never written to or read by Supabase/cloudSync** — nothing in the DB ever holds it. The optional **ScrapeCreators** key follows the same rule. Both are written through `snapshot(state)`, never a hand-built literal that would silently drop a field added later. Both survive sign-out via the per-user vault `ai-ugc-lab-keys`, adopted **only after** any wipe so a member restores their own keys and never another's.
- **Schema.** Bank tables are JSONB (id PK, user_id FK, project_ids[] GIN-indexed, data jsonb). RLS `auth.uid() = user_id` everywhere, admin bypass via `profiles.is_admin`. Admin app (Members + Insights + Allowlist) only renders for admins.
- **Announcements** (migration 0020). The operator's broadcast channel, and the one synced table that is **not a bank** — it skips `bankStore`/`cloudSync` and lives in `stores/announcementStore.ts`. Two levels: **`update`** dots the Dashboard tile, **`alert`** also opens once as a modal, so an outage can interrupt without training members to dismiss every feature note. Read state is per account. **`published_at` in the future IS the scheduler** — the member-side RLS policy filters on it, so nothing polls and drafts are invisible by construction.
- **Admin panel data.** Every tab stays mounted after first visit and shares one 60s-fresh fetch (`apps/admin/useMembers.ts`); remounting per tab click was what dropped the panel to a spinner. Every admin query goes through `apps/admin/adminQuery.ts` — `readyAdminSession()` then `withTimeout`, which really aborts so a late response can't land over fresher state. A failed refresh over loaded rows banners; it never blanks the table. **`member_app_usage` is paged** through `selectAllRows` (a row per member per app crosses the 1000-row cap at ~90 members).
- **Deleting a member** (`apps/admin/deleteMember.ts`). Disabling locks an account and keeps everything; deleting removes it — for spam signups, not for members who left. Two steps **in this order**: `/api/r2-delete-user` purges every object under `auth/<userId>/`, then the `admin_delete_member` RPC drops the `auth.users` row and everything cascades. R2 first, because nothing points at those objects once the rows are gone. The RPC refuses to delete an admin or the caller.

The reasoning behind each of these — what was tried, what broke, and why the shape is what it is — lives in [`src/lib/CLAUDE.md`](src/lib/CLAUDE.md). Full deploy stack is in `DEPLOYMENT.md`; threat model in `SECURITY.md`.

## Inter-app payloads

One-shot handoffs. Sender calls `sendToApp({ targetApp, targetField, data })`. Consumer reads `interAppPayload` in a `useEffect` keyed on `activeApp`, dispatches on `targetField`, then calls `consumePayload()`. ## When making changes

After non-trivial changes to behaviour, file structure, or the model lineup:

1. Keep this file accurate — it's both your guardrail and per-session context, so keep it **lean**. Don't add a changelog; that's what `git log` is for.
2. Update the model table when you register or remove a model.
3. **Detail belongs in the file that loads with the code it governs, not here.** This file is loaded whole by every session in the repo; the others load only when Claude works under their folder. App detail → `src/apps/<folder>/CLAUDE.md`. A shared component, hook or CSS idiom → `src/components/CLAUDE.md`. Per-model rationale → `src/utils/CLAUDE.md`. Add a row to the app table above only when an app is added, and keep its cell to one line + the link.

A pointer alone gets skipped, and a rule with no reasoning gets re-broken. The split is by *when you need the reasoning*, not by importance.
