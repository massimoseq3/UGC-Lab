# CLAUDE.md — shared UI idioms (`src/components/`)

The reasoning behind every shared component, hook and CSS idiom in this app. Each
rule is also stated in one line in the root `CLAUDE.md`, which is what makes it
unmissable; **this file is the *why*** — what was tried first, what it measured,
and why it was reverted. Read the relevant group before changing one of these,
and especially before working around one.

> Every one of these had drifted into 3-4 near-identical copies before it was
> extracted. Reach for them instead of re-implementing.

## Tiles and generated media

- `components/VideoLightbox.tsx` — the full-screen clip view: the video large on the left, its **first / last frame** grabbed out of the file on the right (save either to the B-Rolls bank as a reusable start frame, or download it), then the prompt and Copy prompt / Download Video. Grew out of the Playground preview modal, which still renders its `VideoFrameActions` half. Every B-Roll video tile reaches it through `ExpandVideoButton` (`chrome='stack'` inside a `TileActionStack`, `'plain'` on the Continuous take gallery's bespoke overlay row), which owns its own open state and portals the overlay to the body.
- `components/tileActions.tsx` — the hover action column on every generated media tile. `TileActionStack` + `TileActionButton` + `TileStarButton` + `TileDeleteButton`, in the order **[Star] → Download → Save → Copy → extras → Delete**. 32px circles, `bg-black/55`, no backdrop-blur (it stutters under the opacity fade). **Past four circles a tile needs a doorway, not a longer column** — `TileMenuButton` + `TileMenuItem` (September 2026, Massimo's call): a ⋮ that opens the house `Menu` with every remaining action SPELLED OUT beside its glyph. Characters' grid tile had seven unlabelled circles, where a copy page, a left arrow, a frame and a grid all had to be learned by hovering for a tooltip; it keeps Download, Save, Edit and Delete and puts Copy Prompt / Reuse Prompt / Show in Single View / Make Character Sheet behind the ⋮. Labels are Title Case. Open state lives with the CALLER, since the stack has to be held visible (`forceVisible`) while the pointer is over the menu rather than the tile. **`chrome` drops the hover fade**: it sits in a panel row's own line of always-on buttons, and those rows are not `group`s — which is how Characters' list-row Delete had been `opacity-0` at every width.
- `TileDeleteButton` is the **only** delete idiom: two-click, reverts after 3s. Never a confirm modal. **Arming does not resize it** — the circle holds its footprint and swaps its fill to solid red and its glyph to a check. It used to grow into a red pill labelled "Confirm" at 9px uppercase, in a translucent red over the translucent black scrim; the label was the smallest type in the app and the red read as whatever was behind it, but the growth was the worse half — this sits in a right-aligned column on tiles as narrow as 110px, so a 32px circle jumped to ~74px across most of the still, instantly, under the pointer heading for it. `variant='chrome'` for panel surfaces, `size='sm'` for compact history rows.
- `components/GeneratingMedia.tsx` — the one "this is generating" face. `GeneratingMediaFill` drops into any `relative overflow-hidden` frame (a card face); `PendingMedia` is the standalone aspect-sized tile for gallery grids. A card mid-generation and that same generation inside its detail modal must look identical, so both render this: blob backdrop (`GeneratingBackdrop`), mode glyph top-left, model name, rotating status line (same size + accent tint as the model name — never a dim grey), prompt fading out along the bottom. Status-line copy lives in `components/generatingMessages.ts`.
- `components/GeneratingChip.tsx` — `GeneratingChip` (pulsing accent dot + label) and `GeneratingPulseRing` (thumbnail overlay) mark a **history row** whose work is still running. **History is the queue view**: fire a batch, switch away, and the list keeps reporting progress. Wired in the Ad Analyzer rail (its own literal-hex copy), B-Roll History (counts tallied from each row's snapshotted in-flight queues, TTL-swept at 30 min — **plus the storyboard call itself**, whose row is written before the call and reads "Writing storyboard…" until it lands; see the app's own file), Voiceovers History (an "In progress" section above the finished rows), and Playground / Influencers galleries (their own in-flight tiles).
- `components/ModelPill.tsx` — **the one way a FINISHED output names the model that made it.** Three variants: `media` (literal white-on-black, for a pill sitting on a still or clip), `chrome` (a panel surface, one step brighter than the meta pills beside it — the model is the answer being looked for, the resolution and aspect are the fine print), and `quiet` (no pill at all, dim text, for a caption line UNDER a card where the model rides beside a label of its own). No backdrop-blur, since every one of these fades with its card's hover and blur stutters under an opacity transition (same reason `TileActionStack` drops it). Wired on Playground's history **list rows only** (the grid is a wall of pictures; a caption on each is chrome the grid exists to avoid), in Playground's **preview modal** — the one place a grid tile does name its model, since the tile it was opened from can't, and the modal is where a clip is actually judged (`media` variant, because that modal is a literal black overlay in both themes; it takes `shrink-0`, or the side column's overflow squashes a 19px pill to 5px) — and on B-Roll's Continuous card faces + card-detail gallery tiles — bottom-left, `group-hover:opacity-0`, because on every one of those faces the hover action row lands on that exact strip. **B-Roll's Line-by-Line variation cards are the exception and use `quiet`** (August 2026): they already carry an A-Roll / B-Roll caption under the picture, so the model joins it there — a white-on-black chip was the loudest thing on a still whose whole job is to be judged, and on that face it had to fade on hover anyway. **In-flight surfaces are deliberately NOT routed through it** (`GeneratingMedia`, `GeneratingTile`, the in-flight list rows all name their model in their own layout): they report on work in progress, and a member watching a generation can't be shown less than one watching a finished tile. Visibility comes from `stores/generationInfoStore.ts` — per-browser, own localStorage key, ON unless an explicit `'off'` is stored, and the switch renders **only** on the operator-only gate Settings → Advanced already uses for the demo seeder (`!isCloudEnabled() || is_admin`). It exists for screen recording, where naming the model on every tile is one more thing on camera; a member has no reason to want their own outputs unlabelled, which is why they never see the row.
- `hooks/useInlineVideo.ts` — **one clip plays at a time, app-wide.** Every video tile that can make noise (B-Roll's variation + clip cards, the detail-modal galleries, Playground's history grid) uses `useInlineVideo`: spread `hoverProps` on the tile root (never the `<video>` — the overlay buttons aren't its DOM children, so hovering one would read as a mouseleave) and `videoProps` on the element. Hover autoplays muted; the Play button is a user gesture, so it plays with sound, claims the single module-level playback slot, and pauses whoever held it (across apps — background apps stay mounted). A silent hover preview stands down while another clip holds the slot, and Play only *pauses* what it started, so clicking it during a preview means "let me hear it". `watching` (playing **and** unmuted) is the "user is watching this" flag: pass it to `TileActionStack hidden={…}` and hide the tile's other hover affordances, leaving only play/pause + mute on the media. **Nothing opts into `hidden` any more** — Playground's history grid, B-Roll's variation cards, the Continuous clip cards and the modal galleries all keep their actions on screen while a clip plays. Watching a take is exactly when you decide to keep it, and having Download / Save / Copy / Delete vanish under the pointer meant pausing to reach them. Every one of those stacks is top-right, clear of the play/pause + mute buttons on the left, and still only fades in on hover, so it never covers a clip you're merely watching. The prop stays on `TileActionStack` for a surface that genuinely wants it; think twice before using it. Players that keep native `controls` (the Playground lightbox, the Ad Analyzer source clip) take `useExclusiveVideo` for the same one-at-a-time rule and nothing else.
- `utils/audioPlayback.ts` + `components/AudioScrubber.tsx` + `hooks/useAudioPlayback.ts` — **a generated audio clip is played by the app, never by a native `<audio controls>`, and there is ONE transport for every kind of audio.** The browser's own player is the one control that ignores the theme entirely, and it was under every track in Playground's music history. The shape is Voiceovers': something you press (the voice avatar there, the cover art at avatar size in Playground), a progress line that opens on play and closes when the clip ends, and the elapsed clock either side of it. `AudioScrubber` is that line — 6px track, played portion in the host accent (`accentClass`), a thumb while you're on it, drag with pointer capture. **A waveform was the other half of this rule for a month and is gone** (September 2026, Massimo's call): speech dropped it first — on a six-second read it was decoration over the one thing a player has to say, which is where you are in it — and music followed when its tiles became rows, since these are short beds under an ad, judged by pressing play rather than scanned for the drop. `components/Waveform.tsx` was deleted with the last caller rather than left standing, and `waveformPeaks` went with it: peaks cost a `fetch` plus a full `decodeAudioData` of every track on its first press, which is real work for a strip nothing draws. Bringing a waveform back means bringing both back, and it needs a surface where scanning a long clip by eye is the actual task. `utils/audioPlayback.ts` owns the app-wide **one-clip-at-a-time slot** (the audio counterpart of `useInlineVideo`) and the asset-ref resolver. `useAudioPlayback` is the transport, held **per card**: the element is built on the first press, so a list of dozens of tracks opens no media elements until one is asked for. Voiceovers' History keeps its own list-level copy, which predates the hook.

## Overlays, menus and pickers

- `components/Modal.tsx` — **the one panel overlay, and it is CENTRED. Nothing slides in from the right any more** (September 2026, Massimo's call). Title bar (with an optional back arrow and subtitle), a scrolling body, an optional pinned footer, on BankPicker's geometry: centred, `rounded-3xl`, an `86vh` ceiling, and a bottom sheet below `md`. It was `SlideOver`, a 380/460/560px right-edge drawer, and every one of its nine callers had outgrown it the same way the bank picker had — a grid of preset tiles, a model list beside a provider rail, a fourteen-field product form, all read at a width chosen so the panel could sit *beside* the app, which is worth nothing once a backdrop is over the app anyway. `size` picks the width (`default` 512 for a column of rows, `medium` 672 for a list beside a rail, `wide` 768 for a two-column body of rows or form fields, **`gallery` 1152 — BankPicker's and the Characters preset picker's own width — for a body that is a wall of pictures or a sectioned list you browse**); `layer='below-pickers'` drops it under the z-70/80 pickers, for a modal that opens a `BankPicker` on top of itself (StyleModal). **`fill` is the height decision and it is not cosmetic**: a body that filters itself — a search box over a list — holds the full `86vh`, or the panel resizes on every keystroke and moves the rows under the pointer; everything else hugs its content, because a four-row hook picker standing in a tall empty box is the other half of the same mistake (Characters' DNA library takes `fill` only once its list is long enough to carry a search). `ModelPickerModal` (the image/video picker, ex-`ModelSidePanel`) keeps its own bespoke header and rail but wears the same geometry inline — it is the one panel whose chrome isn't this component's. **A `gallery` panel takes a `rail`** and hands its scroller back through `bodyRef`/`onBodyScroll` — see `SectionRail` below. **`toolbar` is the band pinned under the title bar** — a search row, a drop zone, anything the body scrolls beneath: a static `shrink-0` sibling of the scroll port, never `sticky top-0` inside it (BankPicker's own toolbar shape, and the app-wide rule). Characters' DNA library carries its drop zone there, which is the whole reason it exists — that dropzone is the panel's one action and a long library used to scroll it out of reach.
- `components/BankPicker.tsx` — **picking from a bank looks like browsing one.** A centred modal (September 2026, Massimo's call) at the Characters preset picker's exact geometry — `h-[86vh] max-w-6xl` in a `p-4` wrapper, `grid-cols-3 sm:4 md:5 xl:6`, rail from `lg` — so every tile in both lands at ~150px and two pickers a click apart read as one thing. It was a 560px right-edge drawer, which is the wrong shape for a wall of pictures. **A picker that can reach more than one bank mounts the Bank's own `BankSidebar`** (the reference-image pickers: "a product photo or a character or a saved still" is one question); a single-bank picker gets no rail — one row in a 204px column is a label wearing a control's clothes — **except Characters, whose rail is its eleven looks.** Its counts are what the tab would actually SHOW (per-tab filter + the caller's filter applied), never the raw bank length. One toolbar row: search, then what narrows it, then sort, then **Add New** — the Bank's own Add position and weight. It was a full-width primary slab across the bottom, which made the loudest thing in the modal a button you rarely want, next to a second "Manage in Bank" way out of a modal that already has a close button and a dock tile; both are gone, and a single-select picker has no footer at all now (Massimo's call, September 2026). The footer is the **multi-select confirm and nothing else**, at an ordinary button height, which is also why Add New isn't offered there — leaving for a form would abandon the selection. Below `lg` the rail doesn't render and a `SegmentedToggle` / `Dropdown` on that row stands in for it, and below `md` the whole thing is a bottom sheet. **The Characters rail NAVIGATES, it never filters** — the same rule, and the same scroll-spy shape, as the preset picker it borrows from: clicking a look scrolls to that section and the highlight follows the scroll back. Filtering by style was tried in both places and reads as a set of tabs, hiding the ten other looks the moment you glance at one. Gender and search stay real filters — they cut ACROSS the sections rather than picking one. **A saved template stays in its style section**, listed there as well as under Your Characters, exactly as `PresetPickerModal` has always listed one: it used to be dropped from the library the moment it was picked, so the face you found under "Desk & Office" simply wasn't there next time and every section's count quietly shrank on each pick. Picking it again costs nothing (`materialize` re-finds the row rather than making a second one), and multi-select dedupes by resolved row id so the pair can't add one character twice.
- `components/SectionRail.tsx` + `sectionSpy.ts` — **the table of contents down the left of a `Modal size="gallery"`**, lifted out of the Characters preset picker in September 2026 (Massimo's call) once four other pickers wanted the same shape: Choose a Visual Style, Playground's UGC Prompt Presets & Visual Styles, Choose a Script Style, Choose a Voice. **One rule, and it is the whole design: the rail SAYS WHERE YOU ARE.** Every row is a place in the ONE scrolling body — clicking it scrolls there and the highlight follows the scroll back; nothing on it filters, because a filtering rail reads as a set of tabs and hides every other section the moment you glance at one. Search and the like stay real filters on a toolbar above the body, since they cut ACROSS the sections rather than picking one — **which dimension goes in the rail is decided by which one the body is SECTIONED by**, not by which is more important — and a dimension of TWO values is a pill row, never a rail (Voice: the three accent groups in the rail, All / Female / Male centred on the toolbar above them; the pair was tried the other way round for a day). `useSectionSpy` lives in its own module because `SectionRail.tsx` exports components and react-refresh can't hot-reload a file mixing the two — the split `styleArt.ts` already made. **Don't give a rail one row**, and think twice about two: BankPicker's rule holds — a lone row in a 204px column is a label wearing a control's clothes, which is why the hook picker has none. Below `lg` the rail doesn't render at all and the sections are simply scrolled to. `GALLERY_GRID` (same module) is the one tile track: **the TILE SIZE is the constant, not the column count** (`auto-fill` at a 116px floor from `sm`, a literal three across on a phone), so a gallery gives up columns as it narrows instead of shrinking the picture — a hardcoded `grid-cols-3` is what put seven style previews on four rows of a 512px panel.
- **A picker's title is "Choose a …" in Title Case, and it carries no subtitle** (September 2026, Massimo's call). "The look every clip is rendered in" under a wall of style previews, "how the argument is built" under a heading that says Structures — a line restating what the panel already shows is a line nobody reads, and six of them came out at once. A subtitle survives only where it teaches something the panel can't show (the create half of the style picker: the look is read from the frames, never their subjects). Section headings are written Title Case at the source — "Presets", "Your Visual Styles", "Prompt Presets" — and `GallerySectionHeading` is the one component that renders them and it IS `DayPill` — the house separator, the same centred pill that heads a day of history and a style in the Characters preset picker (Massimo's call). It was a left-aligned uppercase micro-label for a day and read as a caption for whatever sat above it. The rail and the heading therefore say the same words the same way, and neither can drift by being written differently in two places.
- **`.modal-pop` / `.modal-fade` (`index.css`) are how a centred modal ARRIVES**: 200ms, ease-out, 98% → 100% under a fading backdrop. `PresetPickerModal` wears them because it unmounts on close and so has no closed state to transition FROM; `BankPicker` plays the identical move as a `transition`, because it stays mounted while closed and can animate both ways. Keep the two in step — same duration, same easing, same 0.98.
- `components/Dropdown.tsx` — the rounded-full select, portaled through `AnchoredPopover` so it escapes a scrolling panel's clip. **`tier` picks which overlay tier the menu paints on**, and the default is deliberately the app's LOWEST (`z-[60]` over a `z-[55]` catcher): the popover's job is escaping a clip, not covering a modal, which is what lets a modal at the same tier win on DOM order instead of painting over its own menus (`PresetPickerModal` relies on exactly that). A caller mounted ABOVE that tier has the mirror-image problem and needs `tier="panel"` — `BankPicker`'s panel is `z-[80]` so it can sit over B-Roll's card modal, and a default-tier menu opened from inside it renders behind the panel, i.e. a trigger that visibly opens onto nothing. `placement='above'` pins the menu upward regardless of viewport room — `AnchoredPopover`'s default 'auto' measures against the viewport, so on a tall screen a footer menu "fits" below while still covering the Generate button you're heading for. Takes an `accent` (voice / scripts / broll / influencers / playground, plus `neutral` for chrome that belongs to no app) and an optional dim `label` inside the trigger, for a control whose value alone ("3", "30s") doesn't say what it sets. Options are plain strings, or `{ value, label }` pairs when the stored value is a code ('US', 'VIDEO') rather than the words on screen. `fitContent` shrinks the trigger to its own content for a wrapping filter row (and gives the menu a width floor, since such a trigger can be narrower than its longest option); `menuMinWidth` raises that floor for a list whose options run much longer than the trigger — the Outlier Vault's hook patterns carry a count after the name, and the default (`MENU_MIN_WIDTH`) clipped "Conditional callout 76" to "Conditional callou…". Only the menu moves, so the filter row keeps its shape. The MENU itself is `components/Menu.tsx`; only the trigger is this file's. It lived in `voice-studio/` until Scripts paired two of them above its Generate button. **It is the app's only select** — a native `<select>` renders the browser's own unstyled popup, which ignores the theme entirely; Outliers' filter row was the last one and came across in July 2026. **Reach for it when a segmented toggle would cost a full-width slab** — Scripts' Variations and Length were two 48px `SegmentedToggle`s stacked over Generate in a column that also has to fit a brief; as dropdowns they're one 36px row, and neither is a control you sweep through.
- `components/Menu.tsx` — **the one popup menu**: `MenuSurface` + `MenuItem` (+ `MenuSeparator`). Full-bleed rows at `MENU_ROW_HEIGHT` (38px, `px-3.5 py-2`, 13px, a 16px icon slot on the left), in an `overflow-hidden rounded-2xl` card with a `MENU_MIN_WIDTH` (184px) floor. There were four of these and they had all drifted (the `Dropdown`'s `rounded-full` pills, `ConstraintChip`'s pills, `SlotActionMenu`'s full-bleed icon rows, B-Roll's Generate All at `rounded-xl`/12px, plus the Bank's sort menu and two one-off upload menus); the shape that won is `SlotActionMenu`'s (Massimo's call, September 2026), scaled up from the 34px pills and then tightened back from 42 once a six-row menu was on screen. **Deliberately opaque** — every one of them wore `bg-surface-2/95` + `backdrop-blur-xl`, which at 95% over a panel buys no picture and makes the menu a backdrop root, and two of them scroll. A heavier shadow separates instead. A scrolling list goes in an inner `overflow-y-auto` div, never on the surface (which is `overflow-hidden`, so stacking the two leaves the winner to stylesheet order). `toneClassName` REPLACES a row's resting colours for an accented action — appending an accent through `className` looks like it works and doesn't, since two same-specificity text utilities are resolved by stylesheet order. Wired in `Dropdown`, `ConstraintChip`, `SlotActionMenu`, `ModelPicker`'s dropdown, B-Roll's Generate All, Playground's voice menu, the Bank's sort menu and Characters' `TileMenuButton`.
- `hooks/useBackdropClose.ts` — **the only way a backdrop may close its overlay.** Never write `onClick={onClose}` on a backdrop: a text-selection drag that starts inside the panel and releases over the backdrop fires a `click` on their common ancestor (the backdrop), so a bare handler closes the overlay and throws the member's edit away — `stopPropagation` on the panel can't help, since that click never originated there. The hook closes only when mousedown and click report the **same target**, which leaves every existing dismiss path intact (including the lightboxes, which dismiss on clicks bubbling up from a transparent centering wrapper — `e.target === e.currentTarget` would have silently killed those). It keeps the panel-side contract unchanged: a panel that must not dismiss still needs its own `onClick={(e) => e.stopPropagation()}`. Call it at the top of the component, above any early `return null`, then spread onto the backdrop. Sibling backdrops (`<div className="fixed inset-0" onClick={onClose} />` with no children, as in `Modal` / `BankPicker` / `ModelPickerModal` / `AnchoredPopover`) can't exhibit the bug and are left alone.
- `components/DropOverlay.tsx` — **the one "drop a file anywhere on this surface" overlay**: a full-bleed dashed frame with a light accent tint over the panel and a SINGLE centred pill naming what the drop will do. Never a card on a dimming scrim — that shape covers the drop zone it is describing, which is what the Ad Analyzer had until September 2026 (Massimo's call): dragging a clip over the panel replaced the thing you were aiming at with an opaque slab quoting the file formats already written on it. It **arrives like a modal** (`modal-fade` on the frame, `modal-pop` on the pill), because a drag overlay is the one piece of chrome that appears while the pointer is already moving and snapping in at full strength reads as a flash; the 200ms one-shot over a static panel is the one case where opacity above a `backdrop-filter` is fine. Accents are a closed set (`green` for Characters' DNA extraction, `emerald` for the Bank's two product dropzones, `analyzer` for the Ad Analyzer's literal hex), so a new caller picks a look that exists rather than inventing a fifth tint; the z-index rides in on `className`, since the stacking context belongs to the host panel.

## Panels, headers and history rails

- `components/SectionCard.tsx` — the grouped section card, lifted out of Influencers' controls column (August 2026) and now the shape of every **input** column: a faint `rounded-2xl` block with a **centred** icon + title over a hairline, small utilities pinned to the header's left/right edges (Influencers' `TabDivider` shape folded into the header — a 25%-wide pane can't spare a row for two 10px pills). Wired as **References** in Scripts, B-Roll and Playground, and as **Voice** / **Delivery** in Voiceovers. It also dresses every **card workspace** and **Bank form** (August 2026, the second pass): References in B-Roll's per-line card modal and Continuous' frame modal, **Keyframes** in Continuous' clip modal, **Voice** on a dialogue card, References in Characters' `InfluencerEditModal`, and one card per section in `ProductForm` / per DNA group in `ModelForm` / per field group in Script, Voice and Style. All three B-Roll modals now read **style note → group card → prompt → footer**; the clip modal used to open on its keyframes, which made each of the three start with something different. Its header is a `grid-cols-[1fr_auto_1fr]`, NOT absolute edge slots: the equal gutters keep the title genuinely centred, and a narrow pane squeezes the pills instead of dropping one on top of the title (which is exactly what happened in B-Roll's column). Two rules: **don't card a lone control** — the border is what says "these belong together", and around one row it says nothing for 24px — and **don't card what isn't part of the group** (the free-text steer boxes stay outside; they're where you type, not what you attach). A card that holds a growing box takes plain `flex-1`, never `flex-1 basis-0`: with basis-0 it splits the leftover evenly with its sibling and the box inside pays for the card's other rows out of its own height. The floor still lives on the **section**, as everywhere else — a card whose root is `min-h-0` on top of a `min-h-0` content column lets its growing child collapse to nothing. `SectionPresetPill` (same file) is the other half of the idiom: a section heading that IS the way into that section's presets — a dashed ring plus a chevron, in the influencers tint on Characters' tab dividers and in plain ink on every section title under them. It was Characters' local `PresetPillButton` until Playground's Voice card wanted the same shape. `size` picks the type without touching the tone, and `sm` is `SectionCard`'s own 13px title — for a pill standing in for that heading in a column of ordinary cards, where 14px under a 13px "References" one card up reads as two title sizes.
- `StatusDot` / `SectionLabel` (same file) — Influencers' filled/empty field dot, with a third state the other panels need. Influencers' 28 fields are all the same kind of optional, so empty is always red; every other column mixes inputs that GATE the run with ones that don't, and a red dot on something nothing is waiting for reads as an error to go and fix. So: **green** filled · **red** required and empty · **neutral** optional and empty, and red means exactly one thing — "this is why Generate is grey". The dot rides at the row's own left edge (before the icon disc), so a card's dots stack into one column you can scan without reading a word; the ~14px inset that costs each row is deliberate, and part of what makes the contents read as inside the card. Only put a dot where it can ever be red or neutral — Voiceovers' Voice/Style/Pace/Accent always hold a value, and a permanent row of green dots is decoration that teaches members to stop reading dots. Same reason Playground's frame slots have none: a picture versus a dashed box already outshouts a 6px dot, which is also why the reference slot cards in every B-Roll and Characters modal carry none. `filled` is **optional** — omit it for a row that needs the label and no dot (the convention `RefGroup` already used). The honest reds in the modals are exactly three: B-Roll's Animate **Start frame**, Continuous' two clip **keyframe** endpoints, and Playground's Motion Control pair — each one really is why that Generate is grey or why the run refuses. Continuous' Animate **Motion** box deliberately stays neutral-when-empty, because it does *not* gate that button.
- `components/GridCanvas.tsx` — the graph-paper canvas an **output** panel works on (Characters' Single view, Scripts' Output tab, B-Roll's storyboard): a static, deliberately faint `.stage-grid` layer, edge-masked, with the content in its own positioned column (an absolute layer paints over in-flow siblings whatever the DOM order — that's the bug this shape prevents). **It marks an empty stage, not a backdrop:** Scripts and B-Roll show it only while the panel holds nothing final (empty, cleared, or generating) and drop it the moment the takes/storyboard render — behind finished work it's texture under the reading. Characters is the exception and keeps it in both its empty gallery and its Single view, since one picture never fills the column. `AwaitingBody` / `AwaitingCanvas` are the empty state, paired with the **+** each panel puts in its `h-[57px]` header: + empties the canvas so the last run isn't on camera mid-recording, keyed to a signature of what was cleared so the next generation refills it on its own. It never deletes — the copy says so, because a blank panel otherwise reads as data loss. **History surfaces keep the plain background** — the grid marks the stage, not the reel.
- **A panel header is a hairline, not a surface.** It draws no fill: the pane's background runs from the app's top edge straight through to the content, and the only thing marking the band is its `border-b`. B-Roll's right panel was the one exception and wore glass over an opaque `bg-surface-0` — on the theory that cards pass under it blurred, which they never did (it's a SIBLING of the scroll port). What that actually bought was three surfaces in the first 150px of the panel, each a step darker or lighter than the last: the header, the batch strip under it (also opaque), then the storyboard. Both fills are gone (August 2026). The rule in the "pinned panel chrome is glass" note below still holds for a bar that content genuinely scrolls under — there just isn't one here.
- Panel headers are `h-[57px]` + `border-b border-ink/5` on **both** panes of a two-pane app, rendered even when a pane is empty, so the hairlines align — **Scripts, Voiceovers and B-Roll are the exceptions** (September 2026, Massimo's call), and both for the same reason: once History became a rail (see `HistoryRailToggle` below) the toggle that had been the header's whole content went with it, leaving Voiceovers' settings pane holding the word "Voice" and Scripts' output pane holding nothing at all. Drop a header only when it has genuinely nothing to carry; a header with one real control stays — and **`px-5`, the same inset the panel body takes**, so everything in a column shares one left edge. That matters most on a phone, where `MobilePaneTabs` stacks a second bar directly on top of the header: at `px-2` (what it and Characters' own toggle header both wore) the pane tabs stood 12px proud of the pill right underneath them, and the pair read as two widths of the same control. Never a left-aligned heading with a hairline rule — that shape was tried on the two card grids and read as a divider between unrelated blocks. `className` sets the vertical margin only (pass `""` when the list already spaces its groups).
- `components/RailNewButton.tsx` — the primary button a history rail leads with, in the host accent (the Ad Analyzer's "New Analysis" shape). **Single click, no arm**: every caller clears an output canvas whose contents are a row in the list directly underneath, so there is nothing to confirm — what it clears is on screen the moment it happens. Voiceovers' was the exception for a day, since it wipes a typed script, and lost the arm anyway in September 2026 (Massimo's call). A caller that genuinely needs the two-click promise wants `ClearAllButton`, not a flag here.
- `components/HistoryRailToggle.tsx` — **the one control that opens and shuts a history rail** (Scripts, Voiceovers, B-Roll). All three dropped the bar over their output pane, so an ordinary bit of chrome has nowhere to live. It is a **38px circle in the app's own icon-button material** — the ring and faint wash the `+` every output panel heads its bar with wears (`ClearAllButton iconOnly`), since a bare glyph beside a solid CTA was the one control in that band with no surface of its own; the MATERIAL is what is borrowed and not that button's 36px, because the height here is `RailNewButton`'s stated 38 so the band reads level with B-Roll's storyboard bar across the seam — and the CALLER places it: open, it leads the rail's own 57px band immediately left of that rail's New button; shut, `HistoryRailClosed` keeps a column in the rail's place holding nothing but the button, which there says **History** beside its glyph with the row count in a pill, the same ring stretched to a pill (September 2026, Massimo's call) — an icon alone made the one way back to the rail the only unlabelled control in the column. The label gives way below 980px, where the rail stops being a column at all and ~135px of it would be a third of a phone's pane. That column's band is 57px so the button sits level with whatever the pane beside it runs across its own top, and it draws **no hairline** — Scripts' and Voiceovers' output panes carry no bar for one to continue, so a line there was a stub floating over nothing. **B-Roll doesn't use the column at all where its bar can take the button**: the toggle is passed into the storyboard strip as `railToggle` (both ScenesView and ContinuousView, at the right end, outside the scroll port so it can't be swiped away), because a column narrowed the storyboard by ~135px and left the button standing on bare panel beside a frosted bar — in the bar, that glass runs under it. Two widths fall back to the column, chosen in CSS rather than by reading a breakpoint in JS: with no storyboard there is no bar, and under `md` the Continuous strip's pills wrap so neither strip is the pinned single row this sits in. **Either way it is a laid-out element, never an overlay** — that is the whole rule, and it took three tries to get to. A 40px bordered strip read as a second panel; a pull tab on the seam between the columns, and a round button floating in the pane's top-right corner, both cost no layout and both landed on the full-width bar every one of these output columns runs across its own top (B-Roll's batch strip, Voiceovers' script picker row) — costing no layout is worth nothing when the thing you overlap is chrome. **The rail is a column only where all three columns fit** — input panel + 280px rail + ~320px of readable output — which is 980px in all three (Voiceovers' settings column is 80px wider and takes the tighter fit anyway — two numbers put one window width on opposite sides of the line in two apps), not a Tailwind breakpoint: `lg` is the nearest and it is 44px too high, which put a 994px window (Safari at half a 1080p screen) on the covering side of a line it clears. Each app pairs a `min-[980px]:` class set with one `useMinWidth(980)` read (`hooks/useBreakpoint.ts`) for the one thing CSS can't say — whether picking a row should hand the pane back — and the two have to be kept in step. The open/shut state is persisted per app (`:historyRail`) and **defaults to the same `useMinWidth` answer**, so it opens beside the output and stays shut where it would cover it. That slot was renamed once while the feature was unreleased, to drop the stale `false` every browser that had shut the rail during the build was carrying — free then, and after a release a default flip needs the one-shot reset marker `stores/appVisibilityStore.ts` uses instead.

## Inputs and controls

- `components/video/refInputParts.tsx` — the **one reference-thumbnail shape**: a 64px `ImageTile` and the dashed `AddTile` that matches its footprint, wrapping in a plain `flex flex-wrap gap-1.5` row with the add tile joined into it (Playground's `RefTiles` is this plus an upload/bank menu). Every attach-an-image surface uses it — Playground's ref strip, B-Roll's `ExtraRefsRow` in all three card modals, Characters' `InfluencerEditModal`. Two surfaces had hand-rolled it as a four-up `grid` of `aspect-square` cells instead, which is a fixed count rather than a fixed size: in a half-modal column that drew each attached photo at ~110px, three times the same reference in Playground and the biggest thing in a panel whose point is the prompt. A reference is a reference at any size — if you need a bigger one, it's a frame slot (`FrameSlot`), not a ref tile. **A frame slot is two shapes**: empty it IS a `MediaAddCard` (40px, like every other attach-something control), and it opens out to a 2:1 tile only once it holds a frame — an empty slot needs room for one word and the picture's price is worth paying only when there's a picture. `MediaAddCard` takes a `className` for placement, and `RefGroup` takes a `tag` (inline, beside the label) as well as its right-aligned `note`.
- `BracketHighlightArea` (`components/ExpandableText.tsx`) — the prompt field that paints `[bracketed placeholders]` red, used by Playground's inline prompt box and by `ExpandTextModal`. **`BracketGrowArea` and `BracketInput` (same file) are the FORM-field variants** — the Bank's Product form, where the extraction deliberately leaves a placeholder wherever it had no fact, so the wash is the list of what the member still has to fill in. The grow variant needs no scroll sync at all, which is the whole reason it's a separate component: nothing scrolls (`AutoGrowTextarea` sets the field to its content height and the mirror is `inset-0` of that same box), so the two layers are pinned together by layout rather than by an event handler. All three take the chrome on a WRAPPER — the field itself has to be transparent for the wash to show through, so a `focus:` border becomes `focus-within:`. **The textarea never scrolls itself:** it's grown to its full content height and the WRAPPER scrolls, carrying the highlight layer and the text on one compositor scroll. The obvious shape — a scrolling textarea whose overlay is synced from its `onScroll` — always lands a frame or more behind (the browser scrolls the field off-main-thread and hands JS the event afterwards), and the red boxes visibly chase the words. The cost of the fix is that the browser no longer reveals the caret for us, so `revealCaret` does it on every text change and on the caret-moving keys; a drag-select past the edge doesn't auto-scroll. Both layers take the same `padClass`/`textClass` and the scrollbar gutter is on the wrapper, so they wrap identically by construction.
- `components/AutoGrowTextarea.tsx` — **a field inside a scrolling form grows, it doesn't scroll.** A textarea that scrolls internally is a scroll trap: the wheel over it moves the field, not the column, so a form whose boxes are all full (an auto-filled product) can't be scrolled by dragging through the middle of it. Drop-in for `<textarea>`; the optional `maxHeight` is for a paste box with no natural ceiling (the Bank's Listing copy), where scrolling past the cap is the right answer. It re-measures on a **width** change as well as on a window resize, via a `ResizeObserver` (height-only changes are its own doing and are ignored, or it would loop): a field that mounts inside the mobile pane swap's `display: none` half measures a `scrollHeight` of 0 and would otherwise stay an 8px sliver forever, since showing that pane fires no resize event. Used by `ProductForm`'s section fields and `ModelForm`'s DNA rows. The other half of the same rule lives in the panel input columns: a box that owns leftover height takes `flex-1 basis-0` with the **floor on the section** (`min-h-[…]`), never `min-h-0` on the section plus a min-height on the textarea — that pair lets the section collapse while the field holds its floor, and the box's `overflow-hidden` then slices its own footer toolbar.
- `components/ConstraintChip.tsx` — the compact aspect / duration / resolution / audio picker on every generate bar. **Click-only, and it must stay that way.** Playground's footer chips opted into hover-to-open for a while; it came out in July 2026 because a menu that opens on pointer-cross fires while you're on your way somewhere else — crossing from the prompt box to Generate flashed the resolution and aspect menus open in passing. Opening a menu is a decision, so it takes a click. There is no `hover` prop any more; don't add one back here or elsewhere. Its menu is the shared `MenuSurface`/`MenuItem`, so an aspect list and a Pick-from-Bank menu opened a second apart read as one thing.
- `components/PromptToolbar.tsx` — the strip under every editable prompt box: an optional **Presets** opener leading the row, then Enhance / Regenerate / Clear, a hairline, undo-redo, then Expand on the right. Presets is Playground's alone and is where a picker that APPENDS to the box belongs — it was a 48px labelled header row *inside* the prompt box, so the field spent 48px above and 38px below on chrome before its first line; everything in this row acts on the prompt, and appending a preset is exactly that. No rule above it and none under the box either — the modals' footers dropped theirs too, so the prompt field runs straight into the controls it belongs to.
- `components/BatchCountStepper.tsx` — the **how many** control on every generate bar: a −/+ stepper in a chip-height pill, tinted in the host accent once the count leaves 1. `size='fill'` takes its height from an `items-stretch` row so it matches its neighbour by construction rather than by a duplicated number, and `stacked` puts the count over its label — both were built for Voiceovers, which no longer uses either: its stepper shares a line with the model row at `size='xl'` (58px, the picker-row height) and carries **no label**, because stacked with the word "Voiceovers" it measured 151px and left the model row 240px for a name wanting 112, so the one control whose job is naming the model rendered as "Gemini 2…". Nothing else uses `fill`/`stacked` today; they stay for a surface that stands beside a Generate button rather than in a chip row. One press then fires N gens in parallel — N kie tasks, N in-flight tiles, N history rows, which is exactly what pressing Generate N times already produced. A stepper can't price its own rungs the way the resolution menu does, so **the run's total rides on the Generate button beside it**: every caller multiplies (`imageCount: n` for images, which the registry's `priceFor` already handles; `× n` for video and TTS, which have no count dimension), and the per-option credits in the same footer are priced for the armed count too — nothing in one bar may quote two different numbers. ## Material and app shell

- `components/AppGlassTile.tsx` — **the one app icon**: the accent-filled `glass-fill` squircle with the app's glyph. Lifted out of the dock so Meet Your Team wears the SAME icon a member reaches for afterwards. `size` scales the whole thing; `overlay` is for chrome pinned to the tile (the dock's update badge). **`GlassTile` (same file) is the tile addressed by `icon` + `accent` rather than by app**, so a mark that is not a dock app can be cut from the same material — the kie.ai key card's gold bolt is the one caller, and that is the point: the key belongs to the same set of objects as the apps it powers, where a flat tinted disc beside a row of glass icons read as a different kind of thing. **The teammate's crab used to peek out of the top-right corner on hover and came out in September 2026** (Massimo's call): a pixel sprite sliding from behind a glass icon is a different visual language from everything around it, and on a row of eight it fired eight times as the cursor crossed. The crabs stay where they are the subject rather than a garnish — the orrery's caption, Edit's skill folder, the Outliers connect card.
- **`.glass-fill` (`index.css`) is the one definition of frosted glass**, and it dresses the two accent-filled surfaces in the app: the dock's app tiles and every primary Generate CTA. It lays two background-image layers — a broad diffuse bloom off the top-left, then a body gradient from lit top to shaded bottom — over whatever `background-color` the element already carries, so ONE class works for a dock tile (an inline hex) and a `bg-broll-500` button alike. Deliberately not a tight bright glint: a hot specular reads as polished gloss, and what makes glass read as *frosted* is a diffuse, milky highlight. Strength rides on three custom properties rather than a forked class, and `.glass-fill-soft` turns them down for a **broad** surface: the defaults are set for a 48px tile, where the falloff crosses the whole shape and reads as thickness, but stretched across a 400px pill the identical ramp becomes a vignette. The **rim is not in the class**, because the two callers need different ones — a squircle takes an inset box-shadow that follows its contour, a pill already draws its own `inset 0 1px 0` — and a linear-gradient rim would cut a straight band across a rounded top and read as a seam. Both rims are LIT (top brighter than bottom) with the shaded band just *above* the bottom one: light entering the top of a solid piece of glass exits along its far edge, so a dark bottom rim reads as a printed sticker. The light-mode CTA rims are repeated inside `btn-soft-shadow`, which is unlayered and therefore REPLACES the button's own `shadow-[…]` utility there — change one and change the other, or a light-mode CTA loses its rims. **A solid accent CTA hovers with `hover:brightness-110`, never with a tint token.** Every one of them hovered to `bg-<accent>-400`, and the accent ramp's 100–400 tints FLIP direction between themes (they darken in light mode so a tint stays legible on white) — so the same class lightened in dark (oklab L 0.604 → 0.683) and DARKENED in light (0.604 → 0.574), on a button whose saturated fill and white label are identical in both. The Ad Analyzer's `hover:bg-[#FF5257]/90` had the mirror-image bug: the same colour at 90% alpha darkens over a dark page. `brightness` is theme-independent by construction — it lifts whatever is painted, glass layers included — and Tailwind wraps it in `@media (hover: hover)`, so a phone never sticks in the hovered state. Pair it with `disabled:hover:brightness-100` wherever the button has a disabled state, and make sure the button's transition is `transition-all`: `filter` is not a colour and never fades under `transition-colors`.
- **A deploy must never white-screen a member mid-session** (`components/AppErrorBoundary.tsx` + `hooks/useAppUpdateCheck.ts`, August 2026). Every dock app is a hash-named lazy chunk, so a deploy renames all of them — and a tab left open across one asks for a file that no longer exists the first time it opens an app it hadn't opened yet. Vercel's SPA rewrite answers that request with `index.html`, so the import dies on a MIME error rather than a 404, and with nothing catching it above `<Suspense>` React unmounted the entire tree: the blank page members were refreshing their way out of, with no idea why. Two halves. `AppErrorBoundary` wraps **each app pane** (and the root, as a floor), so the blast radius is one pane — every other app stays mounted with its work in it — and it renders **"UGC OS was updated / Reload"**, because to the member this is not an error. **Which of the two screens it shows is decided by TWO signals, and the second one is what makes it reliable.** The first is the error's own wording (`isStaleChunkError`) — but that is BROWSER wording: the same missing chunk comes back from Vercel as a 200 of `text/html`, and WebKit says `'text/html' is not a valid JavaScript MIME type.` or, once it parses the doctype, `SyntaxError: Unexpected token '<'`, where Chromium says `Failed to fetch dynamically imported module`. A shape the table hasn't seen lands the member on "Something went wrong" for what is only an update (reported on Safari, August 2026). So the boundary also reads `isUpdateAvailable()`: if the version poll has already established that a newer build is live, this tab is running stale code and an error from a pane it just tried to open is that and nothing else. Only the wording arms the notice, though — a genuine bug must never be the thing that tells every member to reload. Don't give it a retry: the chunk is gone, and only a reload learns the new names. The other half gets in FRONT of that — `vite.config.ts` bakes a `BUILD_ID` into the bundle and emits the same value as `/version.json`, and `useAppUpdateCheck` re-reads that file every 10 minutes and whenever the tab comes back to the front (which is where most deploys are caught: the tab was backgrounded for the whole thing), raising a dismissible pill the moment the two disagree. Vite's own `vite:preloadError` arms the same pill. The reload leaves a `sessionStorage` crumb so the fresh load can toast what it was for — a page that reloads itself and says nothing is its own kind of confusing. Everything hangs off the build id being **different per build** and `/version.json` being served **uncached** (see `vercel.json` and `DEPLOYMENT.md`).
