# Scripts — `script-architect/`

Create section of UGC OS. This file loads when Claude works with files under `src/apps/script-architect/`; the app-wide rules stay in the root [CLAUDE.md](../../../CLAUDE.md).

## Job

**The member picks who writes** — a `ScriptModelRow` pinned **directly above Generate** (it applies to both modes, it's the last thing you'd change before firing, and it's what decides what the click costs). **The model row, Length and batch size share ONE row above Generate: the model takes HALF, the two chips a quarter each** (August 2026) — `flex-[2]` against `flex-1`, both zero-basis so the ratio holds whatever is in them, all at 58px, both chips `size='xl'` and opening upward; the count anchors its menu right, being the rightmost. Equal thirds was tried first and came off: the model row is the one control here with something to say, and at a third it read "GPT 5.6…" over "The Scrip…" while the chips had spare room around two words. In **Hooks** there is no duration and the remaining pair splits 2:1. They were a chip band stacked over the model row, which spent two rows on one decision each in a column that also has to fit a brief. Both are pearls rather than fields — they were two full-width `SegmentedToggle` slabs, then full-width `Dropdown`s, each costing the brief its height for a control nobody sweeps through. The Length pearl carries a **clock glyph** instead of the dim "Length" label a `Dropdown` could afford — "15s" alone doesn't say what it measures — while the count keeps its noun ("3 Variations" / "10 Hooks"), since a bare number beside a duration reads as another measurement. Each hides on its own (the blueprint rewrite has a Length but no count since it returns one script, Remix's Length leads with **Default**). **Two mode guards keep one mode's state out of the other's chrome**, both fixed August 2026 after each had produced a controls row that lied. `blueprintActive` is gated on Remix: the blueprint is detected off the persisted `source` draft, which Write New never reads, so without it a blueprint left in the remix box took Write New's 3 / 5 / 10 picker off screen (a blueprint rewrite returns one script) with nothing on the panel explaining where it had gone. `isHooksFormat` is gated on Write New: `writeFormat` is that mode's Script / Hooks / Scenes toggle and Remix has no equivalent, so an unguarded read landed a member who last wrote hooks in Remix with its Length chip gone and its batch size counting "10 Hooks", for a pipeline that returns script variations. The service was always right — it reads `writeFormat` only inside its `mode === 'write'` branch — so both were panel-only lies. **The generate band is a static `shrink-0` footer**, never `position: fixed`. It went fixed under `md`, which is a zoom trap rather than a phone shape: browser zoom shrinks the viewport in CSS px, so 200% on a laptop lands under the breakpoint with the desktop split still on screen and the bar detached to the window's bottom edge, covering the References card and the Additional Instructions box outright (Hooks looked fine only because its footer is one row shorter). **The column runs on 8px throughout**, B-Roll's rhythm; it was 12s and 16s and read loose beside it. **The two picker rows live in a `SectionCard` titled References**, in BOTH modes (August 2026) — Script Style (or Hook Style), then Product in Write New; the source box, then Product in Remix. **Product CLOSES the card in both modes**: the rows above it are the ones you set once and leave, where the product is what changes from one script to the next, so it sits nearest the button you press next — and both modes then read the same way, what the script is made FROM over what it's made FOR. **A picked product and "Edit product details for this script" are ONE card** (August 2026), not two stacked pills: they're the same subject — which product, and what this script is told about it — and as separate rounded-full buttons with different borders they read as unrelated controls that happened to land next to each other. One `rounded-2xl` block carries the card's border and gold tint, split by an inset dashed rule (the seam the Script picker row already uses above it), with each half keeping its own hover so it's still obvious which one you're about to press; with no editable context yet the block collapses back to the single `rounded-full` pill. It led the card for a stint on the opposite reasoning (it's what the script is ABOUT, and the Generate button says "Pick a product or write a brief"), which is worth knowing before flipping it back a third time. The source box is a fixed share of the Remix card's height with its own scroller, so a row under it isn't pushed down as you paste. Each row carries a `StatusDot` at its left edge: Script Style and Hook Style are always neutral (Best Mix is a real answer, not an empty field), and **Product's tracks the blocker rather than being red on sight** — see the optional-product note below. The card takes plain `flex-1`, never `basis-0` — with basis-0 the Remix source box paid for the product row out of its own height. **Write New's Additional Instructions box is the remix box** — the same in-box header, same toolbar; its name used to sit on a `StepLabel` row above, which was ~40px of nothing between the pickers and the field, and the box `flex-1 basis-0`s so it opens tall and gives ground as the pickers above it fill. Two modes: **Remix** (one source box; format auto-detected via `detectSceneBlueprint` — a winning transcript → 3 variations, an Ad Analyzer scene blueprint (`--- Scene N` / `SCENE N —` headers) → rewritten scene prompts, with a chip to override back to plain remix) and **Write New** (brief + style + 10/15/20/30/60/90s → 3 human-sounding takes, as plain script or scene blueprint). **Both modes pick a length** above Generate, but Remix's list leads with **Default** (`REMIX_LENGTHS`, its own persisted slot `:remixLength`) — the source ad already has a length and keeping it is usually the point of remixing a winner, so 'default' sends no target and the numbers re-cut the source to a duration. **The blueprint rewrite gets the same control**: on 'default' it inherits the source's own scene count and timings (what a rewrite usually wants), and on a picked length `runReverseEngineer` re-times the scenes, drops or merges whole ones out of the middle while keeping the opener and the CTA scene, and renumbers the headers — the two clauses that otherwise promise to preserve scene count and durations stand down for it. It was hidden here until the pipeline could honour it; a length dropdown the prompt ignored would have been a placebo. The three LLM pipelines and `ScriptMode` ('write' / 'remix' / 'reverse-engineer') survive unchanged in the service and history rows — only the UI toggle merged. Write New's **Output** toggle: Script / Hooks / Scenes. **Script Style is two groups in one picker** (`WriteStyleGroup`, sectioned in the slide-over, **Structures on top here** — the question this app asks is how the argument is built; B-Roll passes `ScriptStyleList formatsFirst` and leads with Formats, since it's picking the kind of ad to SHOOT and a format is the half that stages the shots. Same shared component, same slugs, only the reading order differs): **Formats** — the kind of organic content the ad imitates (podcast clip, street interview, green-screen reaction, comment reply, expert explainer, how-to, GRWM), the higher-converting half because the ad reads as content before it reads as an ad, and the only half that decides the shots — over **Structures**, the persuasion mechanic (PAS, story, 3 Reasons, callout, curiosity, before/after, demo, us-vs-them, objection-crusher, founder). Only formats carry `WRITE_STYLE_SCENE_DIRECTION`, appended in the **Scenes** output so the blueprint actually stages the format (boom mic + studio angles, a handheld mic entering frame off a street, an on-screen review card) instead of defaulting to selfie-to-camera; a structure implies no camera, so its shots stay free. B-Roll reaches the same block through `sceneStagingFor` when an analysed ad supplies the staging (it no longer has a format picker of its own — see its row) — `ScriptStyleList` is likewise shared, since the slugs are persisted and two copies of the list would drift into a wrong label on somebody's saved session. When a format's way of opening collides with the take's opening device, `FORMAT_OVERRIDES_TAKE` gives the format the delivery and the take keeps its angle. Style slugs are **stable** — they key persisted picks and history rows. **Hooks** (`writeFormat: 'hooks'`) writes a user-picked **10 / 20 / 50** standalone opening lines (`HOOK_COUNTS`, default 10, its own persisted slot `:hookCount` — one call, not a batch of parallel takes, so it doesn't share `VARIATION_COUNTS`; `runHooks` scales the Best Mix spread rules with the count, since "at least 4 families, never more than 3 from one" was written for ten and asks near one family per line at five) from the "1,000 Viral Hooks" swipe file distilled into 8 formula families (`HOOK_CATEGORY_META`: **Curiosity Gap** / Educational / Comparison / Myth Busting / Storytelling / Authority / Day in the Life / Pattern Interrupt — the picker's order IS this object's key order, and Curiosity Gap leads it deliberately; see the corpus note below); the Hook Style picker defaults to **Best Mix** (LLM picks a count-scaled minimum of fitting families) or locks one family; no length/style controls; a single LLM call returns `<FAMILY>`-tagged lines (`parseHooks`) rendered as per-hook rows with a family chip + copy — copy/save strip the tags, and there are no send buttons. **Every block in an output card is edited IN PLACE** (August 2026) — the line, the paragraph, the scene body, the spoken line — not by entering a mode that swaps the rendered take for one raw box. `EditableText` is the shared idiom: a textarea styled as the prose it replaces, with no chrome until you're in it. **Every field is ALWAYS on, and none of them fills a box when the caret lands** (August 2026, the second pass). Two things made editing read as "an editor opened over the script" rather than as writing on the page, which is what an in-place edit is for: the field went `bg-surface-0` — near-black — on focus, and scene direction and the dialogue-free scene body were **click-to-edit**, a rendered paragraph that swapped itself for a field. The swap existed for one reason: those two are the blocks whose render adds the `[CHARACTER]` / `[PRODUCT]` tint, and a textarea can't colour one range of its own text. `TokenField` removes the reason — the shape `BracketHighlightArea` already uses for Playground's prompt box, a transparent-text mirror painting ONLY the highlight behind a real textarea that owns every visible, selectable, clickable character. Nothing to sync, no cursor drift, and the slots stay marked while you type. Two consequences, both deliberate: the mark is a **background wash, not a text colour** (the mirror can only paint behind the glyphs), and the token reads `[CHARACTER]` rather than the lowercased `[character]` the old render printed — lowercasing changes glyph widths, so the two layers would wrap on different characters and the wash would slide off its word. Both layers take the same `padClass`/`textClass`, plus the metrics `index.css` gives form controls and nothing else (`font-light`, `-0.025em`, and `.field-mirror` for the phone size) — a mirror that misses any of those wraps differently from the field it sits behind. The size half is the one that bit: the mirror carried a hardcoded `max-lg:text-[16px]`, the size the field floor used to impose and at a breakpoint it had since stopped using, so on a phone the wash was measured from a 16px copy of a 13px paragraph and landed lines away from its token (fixed August 2026). `.field-mirror` is declared inside the floor's own media query, so the two can't drift again — don't give a mirror a phone size of its own. **Every Copy button in this panel is glyph-only below `md`** (August 2026, Massimo's call) — the take toolbar's Copy Full Script / Copy All, and the per-scene, per-hook and voice-profile pills. Each of them shares a row with something longer than it is (a `SCENE N — A-ROLL CHARACTER` header, the Raw / Scene Prompts toggle plus a scene count) and at 375px the two collided; the copy icon says what the button does without being read. The word survives as the `title` AND the `aria-label` — a button whose only label is hidden has to say what it copies somewhere — and the green tick is the same feedback at both widths.

**A scene can be deleted or folded from its own header.** Deleting is the house two-click `TileDeleteButton` (`variant='chrome'`) and cuts the scene's whole REGION — header line, body, and the blank lines up to the next header — out of the take, so `SceneChunk` carries `start`/`end` beside its body span. It is the same splice as every other edit here, through `commitText`, so **Undo restores a deleted scene** like any other change. `renumberScenes` then rewrites the remaining `SCENE N` digits, because 1, 2, 4 reads as a bug in the take; the **timecodes are deliberately left alone**, since they're the model's own timing and re-cutting them here would be a guess printed as a fact. Two things the parse has to get right for this: the last scene's `end` is the end of `rest` (the prefix `splitVoiceProfile` hands over), never the take's, or deleting the final scene takes the appended voice profile with it; and each surviving scene runs to the next SURVIVING one, so a bodiless header in between — which renders nothing — leaves with the scene above it instead of being stranded in the text with nothing on screen to remove it. Folding is view-only (a `Set` of indices in `VariationCard`, remapped on a delete and cleared when the take is replaced by a new run or a history row): the card collapses to its header plus one dim truncated line of the body, and the take text is untouched — a folded scene is still copied, still saved, still sent. The header's **Raw** button therefore now covers ADDING only.

**A remix is an ADAPTATION of the source, and four things in the prompt used to make it write a fresh script instead** (August 2026). The source box was wired correctly the whole time — this was prompt-side, and the four compounded: the source arrived framed as *"inspiration for structure, pacing, and tone"* followed immediately by the from-scratch imperative *"Write a UGC ad script for the following product"*; `REMIX_SYSTEM` injected `HOOK_RULES` (which teaches a model to design its own opening) and `SELF_AUDIT`, whose step 1 is "if the hook doesn't win in 3-4 words, rewrite it" — an instruction to throw away the one thing a remix inherits; **every angle opened "Lead with…"**, and since a batch is N parallel calls each carrying a different angle, the three defaults told three takes to design three different openings; and "rigorously maintaining the original's pacing" was asserted once with **no mechanism** behind it. The fix is `REMIX_SOURCE_FIDELITY`, which supplies the missing mechanism — map the source into its beats FIRST (what the opening line does, what each following line does, where the product enters, where the CTA lands and how hard it asks), then write beat for beat against that map — plus `REMIX_HOOK_RULES` and `REMIX_SELF_AUDIT` replacing the two Write-New blocks in this pipeline only, and angles rewritten as **content selectors** ("build this variation on…") rather than structural ones. **The angle decides WHAT a variation argues; the source owns how it's built** — its beats, opening device, rhythm, turn, CTA placement and speaker POV — which is also why `CREATOR_ANGLE_PRECEDENCE`, shared with Write New, needs its "variations differ in their opening device" sentence scoped out in the remix path. Two deliberate escapes: a **picked Length** is the one clause allowed to break the same-beat-count rule (it says so outright, keeps the opener and the CTA, and drops beats from the middle — same shape as the blueprint rewrite's), and the **unsourced branches** stay a genuine from-scratch write for a payload or history row that arrives with no source. When editing these prompts, the test is the one in the contract: laid beside the source, the output should show the same skeleton — a good script that doesn't is still a failed remix.

**A product is OPTIONAL in both modes** (August 2026) — a member who has described the product in the brief or the Additional Instructions shouldn't have to bank it first just to generate. What each mode still needs is a subject from SOMEWHERE, so the gate moved rather than vanished: Remix has its source script, and Write New needs the product **or** the brief, since with neither the `OPEN_BRIEF` stand-in would be asking for an ad about nothing. The Generate button names that as "Pick a product or write a brief", and the Product row's `StatusDot` is wired to the same condition (`productRequired`) rather than to a constant — the house rule is that red means exactly one thing, "this is why Generate is grey", and the only case left where an empty product is that reason is a Write New whose brief is empty too; in Remix the dot is neutral. **The service side is the half that's easy to miss.** Every spoken-copy system prompt tells the model to "mention the product name at most twice (given in the product context)", so with no product context that instruction has nothing to point at — the observed failures are a `[Product Name]` placeholder that TTS reads out word for word, and a brand invented out of thin air and put in a member's ad. `NO_PRODUCT_DETAILS` is the shared block that closes it in `runWrite` and `runHooks` (take the product from the brief, keep unsaid things general, never invent a brand/price/statistic, never write a bracketed placeholder), and it bites hardest in Hooks, where every formula is a fill-in-the-blank and the blanks come back as literal `(...)` without it. `runRemix` and `runReverseEngineer` carry their own versions, because there the source ad supplies a fallback subject the other two don't have: with instructions, those are the whole brief; with neither, it's a rewrite of the source ad for ITS OWN subject. The remix closing line is conditional for the same reason — it asked for a rewrite "for the new product" when nothing in the prompt named one, which is an invitation to invent one.

The **Voice Profile card** is edited the same way, and `splitVoiceProfile` reports its body's span for it — but only for the appended-header shape, whose boundaries are exactly known; the `extractIntro` fallback deliberately reports none, so an unrecognised shape renders read-only rather than risking a splice over the wrong characters. `VOICE_HEADER_REGEX` also accepts an optional **MASTER**: Scripts' own prompts emit `=== VOICE PROFILE … ===` and the Ad Analyzer's blueprint emits `=== MASTER VOICE PROFILE … ===`, and that one word sitting between the markers and the label meant a blueprint remixed here rendered its voice profile buried in the last scene's body instead of on its own card. **Three things kept that splice honest and one of them was wrong** (August 2026): `splitScenes` now SLICES each body out of the take at the end, from the span it recorded, instead of accumulating the string line by line — the two drifted, because a blank line between a header and its prose (which is how most models format a scene) added nothing to the string while still moving the offset, so every span in that scene sat a character left of the text it described and an edit spliced over the newline and dropped the body's last character. That is the "it randomly changes the text" report. `splitSpokenLines` also accepts the two attribution shapes it used to read as prose — `She says, "…"` with a comma or nothing where our own prompts put a colon, and the trailing `"…," [CHARACTER] says`, which is how a hook scene usually opens, since the line is the first thing in the ad. **The cue is a verb list plus a bounded adverbial tail, and both halves are load-bearing** (August 2026): `speaks` was missing from `SPEECH_VERB_SRC` outright, and the cue had to end AT the quote, so `[CHARACTER] speaks: "…"` and `[CHARACTER] says directly to camera: "…"` both fell through to the single-block fallback — which is why one scene of a remix rendered as direction + tinted line and the next as one black box. Only the tight `says:` shape our own prompt contract writes was ever parsed, and a remix is told to keep the SOURCE's attribution format while the Ad Analyzer transcribes what it heard, so most of what arrives here isn't ours. `CUE_TAIL_SRC` allows at most four plain words between verb and quote and **only when a `:` or `,` follows them** — that punctuation is what separates an attribution from prose, and the tail is peeled OFF the direction, so an unbounded one eats the shot description (`the overlay asks the viewer to tap "Learn more"` stays direction). Three exclusions earn their place: **`reads` / `shows` / `displays` / `states` are NOT speech verbs** here, because these prompts quote on-screen copy constantly (`a text overlay reading "2 weeks"`, `the label states clearly: "10g collagen"`) and a promoted caption is a caption sent to Voiceovers; and a **trailing attribution that runs into another quote is disqualified** (`NEXT_QUOTE_CUE`) — in `text "Days 1-7". [CHARACTER] says directly to camera: "…"` it belongs to the line in front of it, and read backwards it promoted the overlay copy and then skipped the cue, stranding the real line in the direction. The Ad Analyzer keeps its own parser (`ad-anatomy/utils/scenePrompt.ts`) on purpose; widening this one doesn't merge them. A blueprint rewrite is told to keep the SOURCE's attribution format and the Ad Analyzer transcribes what it heard, so both arrive here routinely; the symptom was scene 1 rendering as one plain block of prose while every scene under it split into direction plus a tinted spoken line. A quote with no attribution on either side still stays in the direction — that guard is what keeps a scare quote out of the dialogue. And `splitVoiceProfile` prefers the block that comes AFTER the last scene: taking the first match handed a remixed Ad Analyzer blueprint (whose `=== MASTER VOICE PROFILE ===` leads the document) a voice profile containing every scene in the ad, leaving the take with no scenes to render at all. `rest` is `text` or a prefix of it, never a splice — a leading block is left in place as preamble, which `splitScenes` ignores, because cutting it out would slide every span after it. **The commit is a SPLICE, never a search or a rebuild.** `SceneChunk` carries `bodyStart`/`bodyEnd` and each `SceneSegment` its offset within that body, so a block knows the exact characters of the take it was rendered from and `replaceRange` writes back over them. The two alternatives both break: a `String.replace` of the old text picks the wrong one when two scenes share a sentence, and rebuilding the take from the parse can't work at all — `splitScenes` and `splitSpokenLines` trim, strip connectives and filter empties, so they don't round-trip. Every path (in-place, hook row, scene delete, raw editor) funnels through `commitText`, so one undo stack covers all of them. The header's **Raw** button survives, relabelled: it's no longer how you fix a typo or how you remove a scene, it's the only way to ADD a scene, a line or a paragraph.

**A hook row is edited in place**: the line is an `AutoGrowTextarea` styled as the paragraph it replaces, so you click a hook and type — Enter commits (a hook is one line), Escape reverts, an emptied line reverts rather than deleting the row, and blur rewrites just that line via `hooksToText` (parseHooks' inverse) through the same commit path and undo stack the raw editor uses. The header's **Edit** survives on a hooks pack because the raw box is the only way to ADD or DELETE a line; it is no longer the way to fix a typo, which is what it was being opened for. Formulas are kept at full original length (setup + payoff, never truncated), and the same `HOOK_LIBRARY` + `HOOK_OPENING_INSTRUCTION` seed the opening line of Write New's Script and Scenes outputs.

**The transcript corpus, and what it is and isn't allowed to claim** (August 2026). `HOOK_LIBRARY` came out of the "1,000 Viral Hooks" PDF — templates, hand-grouped, with no evidence attached and, more to the point, nothing at all about what happens AFTER the opening line. The videos behind those hooks have since been fetched and transcribed (872 usable), which buys two things the app never had. **`data/exemplars.ts`** is the first: real transcripts cut down to a few-shot calibration bank, keyed by the app's own `HookCategory` slugs so it joins straight onto `HOOK_TAG` with no mapping table. `services/exemplarBlock.ts` injects a slice into the USER prompt per call, selected by `familiesForWriteStyle`, weighted toward whole scripts (the body is the half with no prior evidence). It costs ~1030 tokens a call. **It goes to Write New ONLY, and that is a measured decision, not an oversight** — see the A/B note below before wiring it anywhere else. It is GENERATED: rebuild it with `scripts/h_build_exemplars.py` in the "1000 Outliers" folder, never by hand. `pattern-interrupt` is deliberately EMPTY — the corpus has no equivalent category, so a lock on it returns `''` and degrades to the library alone rather than borrowing another family's voice. Because these are other creators' words, every prompt that injects them also forbids reproducing a line or borrowing the subject matter, and attribution rides on each entry into the bundle.

**`CORPUS_EVIDENCE`** is the second, and its framing is the load-bearing part. Three features separate the top of that corpus from the bottom, each surviving a permutation test on the extremes, a whole-corpus rank correlation AND a within-category control: digit density in the hook (rho -0.14), digit density in the body (-0.13), and first-person density (-0.09). They are written as **tiebreakers, not rules**, because every video measured was already a hand-picked outlier — this compares winners against winners, so a number-led hook is not a mistake, it just isn't the lever. Writing them as bans would be over-reading the data, and the two existing lines that actively pushed digits (`HUMAN_VOICE_RULES`' "specifics beat claims", the hooks system's fill-the-blanks note) were reworded to point at concrete nouns and exact actions FIRST rather than dropped — specificity without a digit is still specificity. **Curiosity Gap is an eighth family for the same reason**: of the 22 patterns tagged across the corpus it is the only one whose lift survived a bootstrap CI (1.71x, [1.09, 2.09], n=32 across 32 distinct creators). Its formulas all name a SPECIFIC thing, because that is the whole mechanism — "let's see what's inside Monster Energy" works where "you won't believe what's inside this drink" does not.

**The A/B, and what it says about where calibration works.** All of the above was tested against the pre-change prompts on one brief — 50 hooks and 3 takes per arm, same model, old arm restored with `git stash`. **Write New won and Hooks was a wash**, and the split is structural rather than a tuning problem. In Write New the library seeds only the opening line and the rest of the script is free, so the exemplars have room: opener similarity to the library's own formulas fell **0.59 → 0.44** (the old arm produced an opener at 0.87 — the `Yesterday I was at (place)…` template — and then never paid its loop off), first-person density fell 9.7 → 8.4 per 100 words, and no new opener came near a template. In Hooks the system prompt IS a fill-in-the-blanks contract, so a "here's how real speech sounds" block cannot compete with it: mean template similarity went the WRONG way, **0.72 → 0.76**, with near-verbatim fills rising 74% → 82%, because Curiosity Gap simply added 11 more templates to fill. Hence the injection is Write New only. If hook originality is ever the goal, loosen the fill-the-blanks contract FIRST and re-test — don't re-add the block on its own. The hook digit-rate difference was noise (0.28 → 0.24, permutation p=0.65).

**Rule 1 is worded to close a loophole the A/B found.** Its first version said "digits are allowed anywhere… but number-led openings and number-dense bodies skew weaker", and the model obeyed it by **spelling numbers out** — "Twenty four pounds, lasts two months" — rather than quoting fewer. Measured on digit characters that looks like a large win (body density 6.8 → 3.1 against a corpus top of 2.0); measured on digits AND number words it is 6.3 → 6.4, i.e. nothing moved. Any future measurement here has to count number words, or it will keep reporting orthography as substance. Rule 3 (get to the imperative sooner) went the wrong way in the same run, 0.07 → 0.00, but on n=3 takes and a crude imperative regex — too weak to act on either way, so it stands untouched and unverified. **Treat every script-level figure in this note as directional: n=3 per arm.** The hook figures are n≈50 and are the solid half.

**The hook contract — a style's first line, not just its body** (August 2026). `WRITE_STYLE_INSTRUCTION` describes the whole script, and the model read it as something the BODY does: picking **3 Reasons** returned takes with three counted reasons under an opening line that never mentioned a list, so the viewer met a listicle nobody told them to expect. The hook library is the other half of the cause — 8 families of generic openers, with nothing tying the family it hands over to the style that was picked. So `WRITE_STYLE_HOOK_CONTRACT` states, per style, what its FIRST spoken line has to establish, and `styleBlock` emits it immediately under the style instruction so a style reads as one rule instead of a rule about the body plus a separate rule about the opening. `HOOK_OPENING_INSTRUCTION` now works backwards from it — **the contract decides WHAT the line says, the library only decides HOW** — and explicitly permits dropping the formula when no family can carry the contract, since a hook that promises a different video than the one below it fails no matter how well it reads. Three supporting edits keep the other blocks from pulling the other way: `SELF_AUDIT` gains a step that reads the hook back against the contract, `FORMAT_OVERRIDES_TAKE` names the contract in its precedence chain, and `exemplarBlock` says out loud that the transcripts calibrate **sound, never structure** (they're chosen by `familiesForWriteStyle`, which maps a style to a content family — near the right register, never the right shape, and the model was taking shape from them). Each contract is one sentence describing the JOB, never a fixed opener: three parallel takes exist to open three different ways, and a canned first line per style would collapse that. The counting clause on `listicle` and `tutorial` belongs to the hook, not the body — a hook promising three and a body delivering four is the same broken promise as a hook promising nothing.

**What was tested and deliberately NOT encoded.** A `frameworks.md` circulates with that dataset ranking every pattern by lift and calling PAS the weakest structure at 0.79x; a derived `ugc-os-system-prompt.md` turns that ranking into six priority-ordered rules and bills itself as a drop-in replacement for these prompts. Do not take it. Every lift in it except curiosity_gap has a bootstrap CI crossing 1.0 (PAS included, at [0.59, 1.48]), and two of its rules are contradicted by the corpus it cites — hook length is a median 28 words in the top 200 AND the bottom 200, against its "first sentence at most 8 words", and its 130–190 word target is just the corpus median restated. Its sentence-level section is the part that reads most convincingly and replicates least: mean sentence length, sentence-length variance, rhythm breaks, short-sentence rate, contraction rate, connective density and setup-sentence rate were all tested here and NONE separated the groups — connective and setup rates actually ran slightly HIGHER in the winners. `HUMAN_VOICE_RULES` and `BANNED_AI_PATTERNS` therefore stand untouched: they are about sounding human, which an all-human corpus has no power to test in either direction. They were never evidence from this data and must not be dressed up as if they were. Two further caveats worth carrying: sentence-level features are measured on Whisper's punctuation rather than the speaker's, and the corpus is organic Instagram (13% carry any CTA language, 1% are sponsored), so its hook craft and cadence transfer to UGC ads while its ad architecture does not — which is why the angle discipline, length discipline and remix fidelity contracts were left entirely alone. **Cinematic is retired** (July 2026): a fourth `writeFormat: 'prompt'` that wrote one ≤15s single-clip AI-commercial master prompt (STYLE→TIMELINE sections, `@INFLUENCER`/`@PRODUCT` tokens) and shipped it to Playground video mode. Its toggle entry, influencer picker, service pipeline and `cinematicVideo` handoff are deleted (see git history to restore); what stays is `ScriptHistoryItem.writeFormat: 'prompt'` on rows already on members' accounts — `isWriteFormat` coerces those to `'script'` on restore, and History still badges them "Cinematic". **Scene tokens:** `[PRODUCT]` / `[CHARACTER]` are reference-image slots and belong in **visual direction only** — never inside a spoken line, which TTS and video models pronounce literally. Dialogue always names the product in plain words, at most twice (`nameSpokenTokensInDialogue` is the deterministic backstop when the model ignores that). **Batch size is user-picked — 3 / 5 / 10, default 3** (`VARIATION_COUNTS`, the Variations `Dropdown` above Generate — its options carry the noun ("3 variations") and it therefore takes no dim `label`, which would have read "Variations 3 variations"; Length keeps its label, since "15s" alone doesn't say what it measures. Hooks pick from their own `HOOK_COUNTS` in the same slot). Five parallel takes off one brief crowded each other, so 3 is the default, but the wide net stays one click away. Every angle list (`WRITE_TAKES`, `REMIX_ANGLES`) holds **10 entries ordered strongest-first** and is **sliced** to the chosen count — so picking 3 gets the three best angles, and a count can never index past its pool. **The batch spreads the angle only when the creator left it open** (`CREATOR_ANGLE_PRECEDENCE`, appended LAST to both pipelines' angle block so it beats the assigned anchor): a brief or Additional Instructions that names the angle — a pain point, benefit, feature, audience, story, hook — is written by every variation, which then differ only in opening device. Where the creator says nothing, `takeAngleBlock` tells each take, in one phrase each (`WRITE_TAKES[].label`, kept beside the instruction it summarises so the two can't drift), what its siblings are anchored to and to stay off them — takes are parallel calls blind to each other, so a product with one obvious pain point otherwise comes back as three near-identical scripts. `RemixAngle` has 10 members; `hook-led` sits LAST because as an angle it mostly restates the global hook rules. A remix **stamps the angles it used** onto `GeneratedScript` + the history row (`remixAngles`, `variationCount`) and `OutputPanel` prefers that stamp; rows saved before the picker carry no stamp and are matched by count via `remixAnglesForCount`, which keeps the pre-picker five-variation order distinct from today's first five (a different set). The Output tab's empty + generating states render on the shared `GridCanvas` (the grid goes once takes land), the generating skeleton carries the scripts glow, and the header's **+** clears the panel back to the empty canvas — every take is already a History row. **The panel scrolls back to the top on a new RUN, never on a text change** (`runId`, the active History row id — a generation stamps a new one, a history restore stamps that row's): it used to key that reset on the takes' own content, which every in-place edit changes, so committing a typo fix in take 3 threw the member back to the top of take 1. **The take switcher is a scroll-jump, not tabs** — every take stays in one continuous column and the 1/2/3 row scrolls to one (and re-highlights as you scroll past). Rendering a single take at a time was tried and rejected: reading straight through the takes is worth more than putting each take's action row on screen. **A scene card splits the spoken line out of the direction** (`splitSpokenLines`): the prompt contract quotes dialogue inline as `[CHARACTER] says: "…"`, and that quoted line — the only part that's read aloud, recorded, and sent to Voiceovers — renders as its own tinted, separately-copyable block above dim direction prose. Two guards earn their keep: a quote with **no attribution in front of it stays in the direction** (a scare quote like `a visible "wait, what?" reaction` was being promoted to dialogue and cutting the sentence in half), and the speaker can't be a connective (`…and says:` labelled the line "it over and"). Anything unrecognised falls back to the old single prose block, so no shape can render empty. `[CHARACTER]`/`[PRODUCT]` are marked inline, **not pills** — an inline-block pill fractured line-breaking and orphaned the possessive in `[CHARACTER]'s hands` (they were tinted text until `TokenField` made the mark a wash; see the in-place editing rule above). `splitHeaderLine` lets a header carry its own prose (`SCENE 2 — B-ROLL DETAIL: <prose>`), since assuming the header owned the whole line dropped the body and left blueprints of single-line scenes rendering as "0 scenes". **The timecode rides in its own pill** (`splitHeaderTime`, August 2026), one step brighter than the label and set in tabular figures so a column of scenes lines up digit for digit — how long a beat runs and where it lands is what a member scans a storyboard for, and at 10px inside a dim uppercase label it read as the label's own punctuation. It takes parens or brackets, a range or a lone stamp, any dash between the halves, and normalises the separator (one blueprint routinely mixes a hyphen and an en dash, and a column of pills is where that shows); a header with no timecode just keeps its label, and `DAYS 7-14` in a label is not a timecode. **The pill also says how long the beat RUNS** (`rangeDurationLabel` in `utils/timecode.ts`, shared with the Ad Analyzer's beat pills, which show the same ranges off the same blueprints): `00:25–00:40 · 15s`, one step dimmer so the range still leads. Where the beat SITS is what you navigate by, but how many seconds it is is what the scene gets generated at — and a range alone is two clock times to subtract, once per scene. Plain seconds at any length ("90s", not "1m 30s"), and no label at all for a lone stamp or a backwards range, which is a model error and not a duration to invent. **The Voice Profile card renders ABOVE the scenes** — it's pasted into every scene's prompt, so it's the first thing copied, and at the bottom of a ten-scene column most members never scrolled far enough to know it existed. The model still emits it last; `splitVoiceProfile` accepts either position, so only the render order moved. **A paragraph break in a plain script is worth ONE gap however many newlines produced it** (August 2026). Nothing normalises a take's whitespace — it's the model's raw text, and it has to stay that way, since it's what Copy, Save and Send to Voiceovers hand over — so the panel used to render every blank line as its own spacer and the take's whitespace became visible: the same three-paragraph script came out at 14px between paragraphs with one blank line, 28px with two, and 0px with none (a wall of flush sentences, the `-my-1` on each field having eaten the row gap). Which one a member got depended on the model and the run, not on the writing. `scriptLines` now emits one row per line that HAS words, carrying `breakBefore` — a RUN of blank lines is one break, and leading and trailing ones are dropped outright — and the two spacings are the row gap and `mt-2` with no spacer elements at all (`gap-3.5` nets 6px between sentences after the fields' negative margins, and a break is that plus 8). Rows are still keyed to their **own offset in the take**, so skipping the blanks changes nothing about which characters an in-place edit splices over.

**Every chrome row in the Output panel is `select-none`** (headers, chips, copy/edit buttons, the take switcher) so dragging across a take highlights the script and nothing else — it used to sweep up "SCENE 1 — HOOK" and the word "Copy" alongside the line you wanted. That alone made the highlight *stickier*, because Chrome deliberately leaves a selection alone when you press on unselectable chrome (the rich-text-toolbar rule) — so a click on a scene header or a copy button did nothing to it. `clearSelectionOnChrome`, one `onMouseDown` on the panel root, collapses the selection when the press lands on a `user-select: none` target, restoring what a click on ordinary background already does. **Both free-text steer boxes are labelled "Additional Instructions"** — Write New's (which doubles as the brief, state `brief`) and the remix modes' (state `additionalContext`). Only one ever renders, and they do the same job, so one name. Both identifiers are unchanged: they key persisted drafts and the service prompts, and the rename was copy only.
