# Scripts — `script-architect/`

Create section of UGC OS. This file loads when Claude works with files under `src/apps/script-architect/`; the app-wide rules stay in the root [CLAUDE.md](../../../CLAUDE.md).

## Job

**The member picks who writes** — a `ScriptModelRow` pinned **directly above Generate** (it applies to both modes, it's the last thing you'd change before firing, and it's what decides what the click costs). **The model row, Length and batch size share ONE row above Generate: the model takes HALF, the two chips a quarter each** (August 2026) — `flex-[2]` against `flex-1`, both zero-basis so the ratio holds whatever is in them, all at 58px, both chips `size='xl'` and opening upward; the count anchors its menu right, being the rightmost. Equal thirds was tried first and came off: the model row is the one control here with something to say, and at a third it read "GPT 5.6…" over "The Scrip…" while the chips had spare room around two words. In **Hooks** there is no duration and the remaining pair splits 2:1. They were a chip band stacked over the model row, which spent two rows on one decision each in a column that also has to fit a brief. Both are pearls rather than fields — they were two full-width `SegmentedToggle` slabs, then full-width `Dropdown`s, each costing the brief its height for a control nobody sweeps through. The Length pearl carries a **clock glyph** instead of the dim "Length" label a `Dropdown` could afford — "15s" alone doesn't say what it measures — while the count keeps its noun ("3 Variations" / "10 Hooks"), since a bare number beside a duration reads as another measurement. Each hides on its own (the blueprint rewrite has a Length but no count since it returns one script, Remix's Length leads with **Default**). **Two mode guards keep one mode's state out of the other's chrome**, both fixed August 2026 after each had produced a controls row that lied. `blueprintActive` is gated on Remix: the blueprint is detected off the persisted `source` draft, which Write New never reads, so without it a blueprint left in the remix box took Write New's 3 / 5 / 10 picker off screen (a blueprint rewrite returns one script) with nothing on the panel explaining where it had gone. `isHooksFormat` is gated on Write New: `writeFormat` is that mode's Script / Hooks / Scenes toggle and Remix has no equivalent, so an unguarded read landed a member who last wrote hooks in Remix with its Length chip gone and its batch size counting "10 Hooks", for a pipeline that returns script variations. The service was always right — it reads `writeFormat` only inside its `mode === 'write'` branch — so both were panel-only lies. **The generate band is a static `shrink-0` footer**, never `position: fixed`. It went fixed under `md`, which is a zoom trap rather than a phone shape: browser zoom shrinks the viewport in CSS px, so 200% on a laptop lands under the breakpoint with the desktop split still on screen and the bar detached to the window's bottom edge, covering the References card and the Additional Instructions box outright (Hooks looked fine only because its footer is one row shorter). **The column runs on 8px throughout**, B-Roll's rhythm; it was 12s and 16s and read loose beside it. **The two picker rows live in a `SectionCard` titled References**, in BOTH modes (August 2026) — Script Style (or Hook Style), then Product in Write New; the source box, then Product in Remix. **Product CLOSES the card in both modes**: the rows above it are the ones you set once and leave, where the product is what changes from one script to the next, so it sits nearest the button you press next — and both modes then read the same way, what the script is made FROM over what it's made FOR. **A picked product and "Edit product details for this script" are ONE card** (August 2026), not two stacked pills: they're the same subject — which product, and what this script is told about it — and as separate rounded-full buttons with different borders they read as unrelated controls that happened to land next to each other. One `rounded-2xl` block carries the card's border and gold tint, split by an inset dashed rule (the seam the Script picker row already uses above it), with each half keeping its own hover so it's still obvious which one you're about to press; with no editable context yet the block collapses back to the single `rounded-full` pill. It led the card for a stint on the opposite reasoning (it's what the script is ABOUT, and the Generate button says "Pick a product or write a brief"), which is worth knowing before flipping it back a third time. The source box is a fixed share of the Remix card's height with its own scroller, so a row under it isn't pushed down as you paste. Each row carries a `StatusDot` at its left edge: Script Style and Hook Style are always neutral (Best Mix is a real answer, not an empty field), and **Product's tracks the blocker rather than being red on sight** — see the optional-product note below. The card takes plain `flex-1`, never `basis-0` — with basis-0 the Remix source box paid for the product row out of its own height. **Write New's Additional Instructions box is the remix box** — the same in-box header, same toolbar; its name used to sit on a `StepLabel` row above, which was ~40px of nothing between the pickers and the field, and the box `flex-1 basis-0`s so it opens tall and gives ground as the pickers above it fill. Two modes: **Remix** (one source box; format auto-detected via `detectSceneBlueprint` — a winning transcript → 3 variations, an Ad Analyzer scene blueprint (`--- Scene N` / `SCENE N —` headers) → rewritten scene prompts, with a chip to override back to plain remix. **Detection also matches the `=== MASTER VISUAL STYLE / VOICE PROFILE … ===` markers**, not just the headers: nothing else in the app writes that marker and a spoken transcript never carries one, so it identifies a blueprint whose headers went missing on the way here — which they did, for any ad of 15 seconds or less, because the Ad Analyzer handed a single scene over with no header at all until August 2026 (fixed at the source too; see its own file). Such a source was remixed as a plain script: three spoken variations off a video prompt, and no voice profile, which only the scene-rewrite pipeline emits. This is what still routes the ones already sitting in members' Script Banks, and `runReverseEngineer` is told to head its own output when the source gave it none, so the take always parses back into scene cards. The override chip only turns detection OFF — there is no way to force the rewrite on a source it misses, which is why detection has to be the generous side of the trade) and **Write New** (brief + style + 10/15/20/30/60/90s → 3 human-sounding takes, as plain script or scene blueprint). **Both modes pick a length** above Generate, but Remix's list leads with **Default** (`REMIX_LENGTHS`, its own persisted slot `:remixLength`) — the source ad already has a length and keeping it is usually the point of remixing a winner, so 'default' sends no target and the numbers re-cut the source to a duration. **The blueprint rewrite gets the same control**: on 'default' it inherits the source's own scene count and timings (what a rewrite usually wants), and on a picked length `runReverseEngineer` re-times the scenes, drops or merges whole ones out of the middle while keeping the opener and the CTA scene, and renumbers the headers — the two clauses that otherwise promise to preserve scene count and durations stand down for it. It was hidden here until the pipeline could honour it; a length dropdown the prompt ignored would have been a placebo. The three LLM pipelines and `ScriptMode` ('write' / 'remix' / 'reverse-engineer') survive unchanged in the service and history rows — only the UI toggle merged. Write New's **Output** toggle: Script / Hooks / Scenes. **Script Style is two groups in one picker** (`WriteStyleGroup`, sectioned in the picker modal, **Structures on top here** — the question this app asks is how the argument is built; B-Roll passes `ScriptStyleList formatsFirst` and leads with Formats, since it's picking the kind of ad to SHOOT and a format is the half that stages the shots. Same shared component, same slugs, only the reading order differs): **Formats** — the kind of organic content the ad imitates (podcast clip, street interview, green-screen reaction, comment reply, expert explainer, how-to, GRWM), the higher-converting half because the ad reads as content before it reads as an ad, and the only half that decides the shots — over **Structures**, the persuasion mechanic (PAS, story, 3 Reasons, callout, curiosity, before/after, demo, us-vs-them, objection-crusher, founder). Only formats carry `WRITE_STYLE_SCENE_DIRECTION`, appended in the **Scenes** output so the blueprint actually stages the format (boom mic + studio angles, a handheld mic entering frame off a street, an on-screen review card) instead of defaulting to selfie-to-camera; a structure implies no camera, so its shots stay free. B-Roll reaches the same block through `sceneStagingFor` when an analyzed ad supplies the staging (it no longer has a format picker of its own — see its row) — `ScriptStyleList` is likewise shared, since the slugs are persisted and two copies of the list would drift into a wrong label on somebody's saved session. When a format's way of opening collides with the take's opening device, `FORMAT_OVERRIDES_TAKE` gives the format the delivery and the take keeps its angle — **and when the format opens on somebody else entirely, the anchor goes with them** (August 2026): three formats no longer open on the ad's own voice, so a take's anchor attached to "the first spoken line" had nowhere to land and the batch came back arguing one thing behind three different questions. The host asks about the take's pain point, the comment doubts the take's benefit, the thing on screen attacks what the take defends. **The seven formats were rewritten in August 2026** (Massimo's call — they were "not good enough"), and the one thing wrong with all of them was that every block staged ONE PERSON TALKING, which is not what most of these formats are: a street interview came back as one creator against three different walls, a podcast clip as a monologue with a mic in shot, a comment reply as a piece to camera about a comment the viewer never saw. Three of them now stage more than one person. **Street Interview is a vox pop** — a different stranger every scene, each mildly skeptical first and then genuinely reacting after trying it on the spot, with the turn between those two beats as the whole format and the number of people scaled by the picked length. **Podcast Clip is a two-hander that OPENS ON THE HOST'S QUESTION** — an objection, a how-does-that-work question, or a listener's problem — and `[CHARACTER]` is the GUEST, the expert, who concedes the fair part and then explains the mechanism; the host is a shoulder and the back of a head who speaks and has no identity. **Comment Reply writes the comment** — exact wording, on its own labelled line, pinned on screen as an avatar-and-handle card rendered VERBATIM in every scene it appears in, with the reply quoting its actual words back at least twice. Green Screen likewise writes each on-screen artifact in full (a review with its stars and username, a price, a headline with its publication), and re-writes it when the argument moves to a second one. **`[CHARACTER]` stays the ONE token and the ONE identity** — it is a reference-image slot, so a scene carrying it comes back as that face, and putting it on four strangers turns a vox pop into one person in four coats. `WRITE_SCENES_SYSTEM`'s second-voice rule was widened to match: a staging block may put OTHER PEOPLE in the ad, described only as far as the shot needs (an arm and a mic, a shoulder, or a plainly different person carrying two or three generic markers), each speaker attributed by ROLE (`The host asks: "…"`) and given a one-clause voice note in its own scene, since the `VOICE PROFILE` at the end still describes `[CHARACTER]` alone. **A plain script may carry labelled lines, but only where its format names them** (rule 6 of `WRITE_SCRIPT_SYSTEM`'s FORMAT RULES): `HOST:` / `GUEST:` / `INTERVIEWER:` / `PERSON N:` for a second voice, `ON SCREEN:` / `ON SCREEN COMMENT:` for copy that gets typed into the overlay. A format that names no labels gets none — an unlabelled script is one person talking, which is what most of them are. Those lines are what a multi-speaker format is SHOT from, so the bank keeps them verbatim; only the **Voiceovers handoff** sheds them, through `spokenLinesOnly` in `types.ts` (strip a short ALL-CAPS label, drop an `ON SCREEN` line outright), because Voiceovers is a single TTS speaker reading one blob and would otherwise say "HOST colon" and read the comment card aloud. It deliberately does NOT pick one speaker: a two-hander read by one voice is a draft you can hear and edit, where a script silently missing half its lines is not. `exemplarBlock`'s `STYLE_FAMILIES` moved with the rewrite — podcast to `authority` + `educational` (the guest explains a mechanism), interview to `storytelling` + `myth-busting` (a doubt that turns). Style slugs are **stable** — they key persisted picks and history rows. **Hooks** (`writeFormat: 'hooks'`) writes a user-picked **10 / 20 / 50** standalone opening lines (`HOOK_COUNTS`, default 10, its own persisted slot `:hookCount` — one call, not a batch of parallel takes, so it doesn't share `VARIATION_COUNTS`; `runHooks` scales the Best Mix spread rules with the count, since "at least 4 families, never more than 3 from one" was written for ten and asks near one family per line at five) from the "1,000 Viral Hooks" swipe file distilled into 8 formula families (`HOOK_CATEGORY_META`: **Curiosity Gap** / Educational / Comparison / Myth Busting / Storytelling / Authority / Day in the Life / Pattern Interrupt — the picker's order IS this object's key order, and Curiosity Gap leads it deliberately; see the corpus note below); the Hook Style picker defaults to **Best Mix** (LLM picks a count-scaled minimum of fitting families) or locks one family; no length/style controls; a single LLM call returns `<FAMILY>`-tagged lines (`parseHooks`) rendered as per-hook rows with a family chip + copy — copy/save strip the tags, and there are no send buttons. **Every block in an output card is edited IN PLACE** (August 2026) — the line, the paragraph, the scene body, the spoken line — not by entering a mode that swaps the rendered take for one raw box. `EditableText` is the shared idiom: a textarea styled as the prose it replaces, with no chrome until you're in it. **CLEARING a block is how it gets DELETED** (September 2026, Massimo's report): select the line, delete it, click away, and it goes. Every field used to put the text back on an empty commit — on the reasoning that prose vanishing as you clear it reads as the row deleting itself — so the only way to drop a line was the whole-take editor, and every attempt to do it in place read as the edit failing to save. It is one splice through `commitText` like every other edit here, so **Undo brings the line back**. `spliceOut` closes the seam: the separator either side is the WIDER of the two runs of whitespace, never their sum, so a line inside a paragraph closes back to one newline while a paragraph keeps its blank line — adding them turns every deleted line into a paragraph break, and dropping both runs two sentences together. An INLINE cut (a spoken line out of the middle of a scene's prose) also drops a `,`/`;`/`:` orphaned at the seam, and nothing else: what remains is exactly the words that were on screen. Four blocks define their own cut and the rest still revert — **a spoken line takes its attribution cue and its own quote marks with it** (`cutStart`/`cutEnd` on the segment, wider than the `start`/`end` an edit writes over, or `[CHARACTER] says: ""` would be left behind to re-parse as direction with stray quotes in it); a **master block takes its `=== … ===` header**, since the label alone governs nothing; a **hook** is filtered out of the pack rather than spliced, the pack being a list; and clearing the **last block in a scene deletes the whole scene**, renumbered like any other scene delete, because a header with nothing under it renders nothing and there'd be no way left on screen to remove it. The one field with no delete is the **remix run's own voice brief** — it belongs to no take, so it rides no undo stack. **Every field is ALWAYS on, and none of them fills a box when the caret lands** (August 2026, the second pass). Two things made editing read as "an editor opened over the script" rather than as writing on the page, which is what an in-place edit is for: the field went `bg-surface-0` — near-black — on focus, and scene direction and the dialogue-free scene body were **click-to-edit**, a rendered paragraph that swapped itself for a field. The swap existed for one reason: those two are the blocks whose render adds the `[CHARACTER]` / `[PRODUCT]` tint, and a textarea can't colour one range of its own text. `TokenField` removes the reason — the shape `BracketHighlightArea` already uses for Playground's prompt box, a transparent-text mirror painting ONLY the highlight behind a real textarea that owns every visible, selectable, clickable character. Nothing to sync, no cursor drift, and the slots stay marked while you type. Two consequences, both deliberate: the mark is a **background wash, not a text colour** (the mirror can only paint behind the glyphs), and the token reads `[CHARACTER]` rather than the lowercased `[character]` the old render printed — lowercasing changes glyph widths, so the two layers would wrap on different characters and the wash would slide off its word. Both layers take the same `padClass`/`textClass`, plus the metrics `index.css` gives form controls and nothing else (`font-light`, `-0.025em`, and `.field-mirror` for the phone size) — a mirror that misses any of those wraps differently from the field it sits behind. The size half is the one that bit: the mirror carried a hardcoded `max-lg:text-[16px]`, the size the field floor used to impose and at a breakpoint it had since stopped using, so on a phone the wash was measured from a 16px copy of a 13px paragraph and landed lines away from its token (fixed August 2026). `.field-mirror` is declared inside the floor's own media query, so the two can't drift again — don't give a mirror a phone size of its own. **Every Copy button in this panel is glyph-only below `md`** (August 2026, Massimo's call) — the take toolbar's Copy Full Script / Copy All, and the per-scene, per-hook and voice-profile pills. Each of them shares a row with something longer than it is (a `SCENE N — A-ROLL CHARACTER` header, the Edit / undo / redo controls plus a scene count) and at 375px the two collided; the copy icon says what the button does without being read. The word survives as the `title` AND the `aria-label` — a button whose only label is hidden has to say what it copies somewhere — and the green tick is the same feedback at both widths.

**A scene can be deleted or folded from its own header.** Deleting is the house two-click `TileDeleteButton` (`variant='chrome'`) and cuts the scene's whole REGION — header line, body, and the blank lines up to the next header — out of the take, so `SceneChunk` carries `start`/`end` beside its body span. It is the same splice as every other edit here, through `commitText`, so **Undo restores a deleted scene** like any other change. `renumberScenes` then rewrites the remaining `SCENE N` digits, because 1, 2, 4 reads as a bug in the take; the **timecodes are deliberately left alone**, since they're the model's own timing and re-cutting them here would be a guess printed as a fact. Two things the parse has to get right for this: the last scene's `end` is the end of `rest` (the prefix `splitVoiceProfile` hands over), never the take's, or deleting the final scene takes the appended voice profile with it; and each surviving scene runs to the next SURVIVING one, so a bodiless header in between — which renders nothing — leaves with the scene above it instead of being stranded in the text with nothing on screen to remove it. Folding is view-only (a `Set` of indices in `VariationCard`, remapped on a delete and cleared when the take is replaced by a new run or a history row): the card collapses to its header plus one dim truncated line of the body, and the take text is untouched — a folded scene is still copied, still saved, still sent. The header's **Edit** button therefore now covers ADDING only.

**A remix is an ADAPTATION of the source, and four things in the prompt used to make it write a fresh script instead** (August 2026). The source box was wired correctly the whole time — this was prompt-side, and the four compounded: the source arrived framed as *"inspiration for structure, pacing, and tone"* followed immediately by the from-scratch imperative *"Write a UGC ad script for the following product"*; `REMIX_SYSTEM` injected `HOOK_RULES` (which teaches a model to design its own opening) and `SELF_AUDIT`, whose step 1 is "if the hook doesn't win in 3-4 words, rewrite it" — an instruction to throw away the one thing a remix inherits; **every angle opened "Lead with…"**, and since a batch is N parallel calls each carrying a different angle, the three defaults told three takes to design three different openings; and "rigorously maintaining the original's pacing" was asserted once with **no mechanism** behind it. The fix is `REMIX_SOURCE_FIDELITY`, which states what a remix IS (the structure is what's being reused; every product fact comes from the new brief; a script that reads as freshly written is a failure however good it is), plus `REMIX_HOOK_RULES` replacing Write New's `HOOK_RULES` in this pipeline only, and angles rewritten as **content selectors** ("build this variation on…") rather than structural ones. **The angle decides WHAT a variation argues; the source owns how it's built** — its beats, opening device, rhythm, turn, CTA placement and speaker POV — which is also why `CREATOR_ANGLE_PRECEDENCE`, shared with Write New, needs its "variations differ in their opening device" sentence scoped out in the remix path. `REMIX_SOURCE_FIDELITY` also carried the *mechanism* — map the source into beats first, then write beat for beat against that map — and `REMIX_SYSTEM` carried a remix-specific `REMIX_SELF_AUDIT` and `BANNED_AI_PATTERNS`; all three came out in August 2026 to test whether the model holds the shape better when told what a remix is and left to work out how than when handed a checklist. The beat language survives in the user prompt (the Length clause, the closing instruction), so put the block back before rewriting those. Two deliberate escapes: a **picked Length** is the one clause allowed to break the same-beat-count rule (it says so outright, keeps the opener and the CTA, and drops beats from the middle — same shape as the blueprint rewrite's), and the **unsourced branches** stay a genuine from-scratch write for a payload or history row that arrives with no source. When editing these prompts, the test is the one in the contract: laid beside the source, the output should show the same skeleton — a good script that doesn't is still a failed remix.

**A product is OPTIONAL in both modes** (August 2026) — a member who has described the product in the brief or the Additional Instructions shouldn't have to bank it first just to generate. What each mode still needs is a subject from SOMEWHERE, so the gate moved rather than vanished: Remix has its source script, and Write New needs the product **or** the brief, since with neither the `OPEN_BRIEF` stand-in would be asking for an ad about nothing. The Generate button names that as "Pick a product or write a brief", and the Product row's `StatusDot` is wired to the same condition (`productRequired`) rather than to a constant — the house rule is that red means exactly one thing, "this is why Generate is grey", and the only case left where an empty product is that reason is a Write New whose brief is empty too; in Remix the dot is neutral. **The service side is the half that's easy to miss.** Every spoken-copy system prompt tells the model to "mention the product name at most twice (given in the product context)", so with no product context that instruction has nothing to point at — the observed failures are a `[Product Name]` placeholder that TTS reads out word for word, and a brand invented out of thin air and put in a member's ad. `NO_PRODUCT_DETAILS` is the shared block that closes it in `runWrite` and `runHooks` (take the product from the brief, keep unsaid things general, never invent a brand/price/statistic, never write a bracketed placeholder), and it bites hardest in Hooks, where every formula is a fill-in-the-blank and the blanks come back as literal `(...)` without it. `runRemix` and `runReverseEngineer` carry their own versions, because there the source ad supplies a fallback subject the other two don't have: with instructions, those are the whole brief; with neither, it's a rewrite of the source ad for ITS OWN subject. The remix closing line is conditional for the same reason — it asked for a rewrite "for the new product" when nothing in the prompt named one, which is an invitation to invent one.

The **Voice Profile card** is edited the same way, and `splitVoiceProfile` reports its body's span for it — plus a second, wider one covering the `=== … ===` header, which is what a delete takes — but only for the appended-header shape, whose boundaries are exactly known; the `extractIntro` fallback deliberately reports none, so an unrecognised shape renders read-only rather than risking a splice over the wrong characters. `VOICE_HEADER_REGEX` also accepts an optional **MASTER**: Scripts' own prompts emit `=== VOICE PROFILE … ===` and the Ad Analyzer's blueprint emits `=== MASTER VOICE PROFILE … ===`, and that one word sitting between the markers and the label meant a blueprint remixed here rendered its voice profile buried in the last scene's body instead of on its own card. **Three things kept that splice honest and one of them was wrong** (August 2026): `splitScenes` now SLICES each body out of the take at the end, from the span it recorded, instead of accumulating the string line by line — the two drifted, because a blank line between a header and its prose (which is how most models format a scene) added nothing to the string while still moving the offset, so every span in that scene sat a character left of the text it described and an edit spliced over the newline and dropped the body's last character. That is the "it randomly changes the text" report. `splitSpokenLines` also accepts the two attribution shapes it used to read as prose — `She says, "…"` with a comma or nothing where our own prompts put a colon, and the trailing `"…," [CHARACTER] says`, which is how a hook scene usually opens, since the line is the first thing in the ad. **The cue is a verb list plus a bounded adverbial tail, and both halves are load-bearing** (August 2026): `speaks` was missing from `SPEECH_VERB_SRC` outright, and the cue had to end AT the quote, so `[CHARACTER] speaks: "…"` and `[CHARACTER] says directly to camera: "…"` both fell through to the single-block fallback — which is why one scene of a remix rendered as direction + tinted line and the next as one black box. Only the tight `says:` shape our own prompt contract writes was ever parsed, and a remix is told to keep the SOURCE's attribution format while the Ad Analyzer transcribes what it heard, so most of what arrives here isn't ours. `CUE_TAIL_SRC` allows at most four plain words between verb and quote and **only when a `:` or `,` follows them** — that punctuation is what separates an attribution from prose, and the tail is peeled OFF the direction, so an unbounded one eats the shot description (`the overlay asks the viewer to tap "Learn more"` stays direction). Three exclusions earn their place: **`reads` / `shows` / `displays` / `states` are NOT speech verbs** here, because these prompts quote on-screen copy constantly (`a text overlay reading "2 weeks"`, `the label states clearly: "10g collagen"`) and a promoted caption is a caption sent to Voiceovers; and a **trailing attribution that runs into another quote is disqualified** (`NEXT_QUOTE_CUE`) — in `text "Days 1-7". [CHARACTER] says directly to camera: "…"` it belongs to the line in front of it, and read backwards it promoted the overlay copy and then skipped the cue, stranding the real line in the direction. The Ad Analyzer keeps its own parser (`ad-anatomy/utils/scenePrompt.ts`) on purpose; widening this one doesn't merge them. A blueprint rewrite is told to keep the SOURCE's attribution format and the Ad Analyzer transcribes what it heard, so both arrive here routinely; the symptom was scene 1 rendering as one plain block of prose while every scene under it split into direction plus a tinted spoken line. A quote with no attribution on either side still stays in the direction — that guard is what keeps a scare quote out of the dialogue. And `splitVoiceProfile` prefers the block that comes AFTER the last scene: taking the first match handed a remixed Ad Analyzer blueprint (whose `=== MASTER VOICE PROFILE ===` leads the document) a voice profile containing every scene in the ad, leaving the take with no scenes to render at all. `rest` is `text` or a prefix of it, never a splice — a leading block is left in place as preamble, which `splitScenes` ignores, because cutting it out would slide every span after it. **The commit is a SPLICE, never a search or a rebuild.** `SceneChunk` carries `bodyStart`/`bodyEnd` and each `SceneSegment` its offset within that body, so a block knows the exact characters of the take it was rendered from and `replaceRange` writes back over them. The two alternatives both break: a `String.replace` of the old text picks the wrong one when two scenes share a sentence, and rebuilding the take from the parse can't work at all — `splitScenes` and `splitSpokenLines` trim, strip connectives and filter empties, so they don't round-trip. Every path (in-place, a cleared block, hook row, scene delete, the whole-take editor) funnels through `commitText`, so one undo stack covers all of them. The header's whole-take button survives, relabelled twice: it's no longer how you fix a typo, nor how you remove a line or a scene, it's the only way to ADD a scene, a line or a paragraph. It read **Raw** until September 2026 and now reads **Edit** (Massimo's call) — "Raw" was accurate about the textarea and meaningless about the job, and the two words members reach for are *edit* and *delete*.

**A remix run carries ONE voice brief, and it belongs to the run rather than to any take** (August 2026). Remix hands back N spoken scripts and nothing else, so a member who shoots two of them gets two different-sounding people reading the same winner — the blueprint pipelines already solve this (both emit a `=== VOICE PROFILE ===` block after their scenes), but a plain spoken script has nowhere to put one: the take IS the words that get read aloud, and a paragraph of casting direction inside it is a paragraph TTS reads out. So `runRemixVoiceProfile` writes it in its OWN call, fired **alongside** the takes (it reads the same source, so there is nothing to wait for) and it **never fails the run** — it swallows its own error and returns undefined, because the takes are what Generate was pressed for and a missing card beats an error over three scripts already paid for. It is read off the SOURCE ad, which is the delivery that won and which every variation keeps the speaker, POV and rhythm of. It rides `GeneratedScript.voiceProfile` → its own persisted `outputVoiceProfile` slot → `ScriptHistoryItem.voiceProfile`, all optional, so a legacy row, a sourceless remix and a failed profile call all restore to no card. Rendered as the same `VoiceProfileCard` the scene blueprints use (hence its `label` prop) at the top of the scroller, inside it — it scrolls away with everything else, because on most runs it's a paragraph nobody touches. Editable in place like every other block, but nothing splices it back into a take: there is no take it came out of.

**A hook row is edited in place**: the line is an `AutoGrowTextarea` styled as the paragraph it replaces, so you click a hook and type — Enter commits (a hook is one line), Escape reverts, an emptied line reverts rather than deleting the row, and blur rewrites just that line via `hooksToText` (parseHooks' inverse) through the same commit path and undo stack the raw editor uses. The header's **Edit** survives on a hooks pack because the raw box is the only way to ADD or DELETE a line; it is no longer the way to fix a typo, which is what it was being opened for. Formulas are kept at full original length (setup + payoff, never truncated), and the same `HOOK_LIBRARY` + `HOOK_OPENING_INSTRUCTION` seed the opening line of Write New's Script and Scenes outputs.

**The transcript corpus, and what it is and isn't allowed to claim** (August 2026). `HOOK_LIBRARY` came out of the "1,000 Viral Hooks" PDF — templates, hand-grouped, with no evidence attached and, more to the point, nothing at all about what happens AFTER the opening line. The videos behind those hooks have since been fetched and transcribed (872 usable), which buys two things the app never had. **`data/exemplars.ts`** is the first: real transcripts cut down to a few-shot calibration bank, keyed by the app's own `HookCategory` slugs so it joins straight onto `HOOK_TAG` with no mapping table. `services/exemplarBlock.ts` injects a slice into the USER prompt per call, selected by `familiesForWriteStyle`, weighted toward whole scripts (the body is the half with no prior evidence). It costs ~1030 tokens a call. **It goes to Write New ONLY, and that is a measured decision, not an oversight** — see the A/B note below before wiring it anywhere else. It is GENERATED: rebuild it with `scripts/h_build_exemplars.py` in the "1000 Outliers" folder, never by hand. `pattern-interrupt` is deliberately EMPTY — the corpus has no equivalent category, so a lock on it returns `''` and degrades to the library alone rather than borrowing another family's voice. Because these are other creators' words, every prompt that injects them also forbids reproducing a line or borrowing the subject matter, and attribution rides on each entry into the bundle.

**`CORPUS_EVIDENCE`** is the second, and its framing is the load-bearing part. Three features separate the top of that corpus from the bottom, each surviving a permutation test on the extremes, a whole-corpus rank correlation AND a within-category control: digit density in the hook (rho -0.14), digit density in the body (-0.13), and first-person density (-0.09). They are written as **tiebreakers, not rules**, because every video measured was already a hand-picked outlier — this compares winners against winners, so a number-led hook is not a mistake, it just isn't the lever. Writing them as bans would be over-reading the data, and the two existing lines that actively pushed digits (`HUMAN_VOICE_RULES`' "specifics beat claims", the hooks system's fill-the-blanks note) were reworded to point at concrete nouns and exact actions FIRST rather than dropped — specificity without a digit is still specificity. **Curiosity Gap is an eighth family for the same reason**: of the 22 patterns tagged across the corpus it is the only one whose lift survived a bootstrap CI (1.71x, [1.09, 2.09], n=32 across 32 distinct creators). Its formulas all name a SPECIFIC thing, because that is the whole mechanism — "let's see what's inside Monster Energy" works where "you won't believe what's inside this drink" does not.

**The A/B, and what it says about where calibration works.** All of the above was tested against the pre-change prompts on one brief — 50 hooks and 3 takes per arm, same model, old arm restored with `git stash`. **Write New won and Hooks was a wash**, and the split is structural rather than a tuning problem. In Write New the library seeds only the opening line and the rest of the script is free, so the exemplars have room: opener similarity to the library's own formulas fell **0.59 → 0.44** (the old arm produced an opener at 0.87 — the `Yesterday I was at (place)…` template — and then never paid its loop off), first-person density fell 9.7 → 8.4 per 100 words, and no new opener came near a template. In Hooks the system prompt IS a fill-in-the-blanks contract, so a "here's how real speech sounds" block cannot compete with it: mean template similarity went the WRONG way, **0.72 → 0.76**, with near-verbatim fills rising 74% → 82%, because Curiosity Gap simply added 11 more templates to fill. Hence the injection is Write New only. If hook originality is ever the goal, loosen the fill-the-blanks contract FIRST and re-test — don't re-add the block on its own. The hook digit-rate difference was noise (0.28 → 0.24, permutation p=0.65).

**Rule 1 is worded to close a loophole the A/B found.** Its first version said "digits are allowed anywhere… but number-led openings and number-dense bodies skew weaker", and the model obeyed it by **spelling numbers out** — "Twenty four pounds, lasts two months" — rather than quoting fewer. Measured on digit characters that looks like a large win (body density 6.8 → 3.1 against a corpus top of 2.0); measured on digits AND number words it is 6.3 → 6.4, i.e. nothing moved. Any future measurement here has to count number words, or it will keep reporting orthography as substance. Rule 3 (get to the imperative sooner) went the wrong way in the same run, 0.07 → 0.00, but on n=3 takes and a crude imperative regex — too weak to act on either way, so it stands untouched and unverified. **Treat every script-level figure in this note as directional: n=3 per arm.** The hook figures are n≈50 and are the solid half.

**Benefits over features — what a line is allowed to be ABOUT** (`BENEFIT_OVER_FEATURE`, August 2026). Reported as scripts that "keep talking about the key specs and facts instead of the benefits and what it's going to do for the user", which is direct response's oldest rule and the one thing the shared writing DNA had no line about: every other block governs how a script SOUNDS (`HUMAN_VOICE_RULES`, `BANNED_AI_PATTERNS`) or how it OPENS (`HOOK_RULES`, the library), and nothing said what a line may be about — so with a bank product attached the model read the product sheet out loud. The block is composed into all four writing pipelines, and its POSITION differs by mode on purpose: **first, above the hook cluster** in Write New's two systems, so the opening line is benefit-led too; **below `REMIX_SOURCE_FIDELITY`** in Remix, where "what a line says" must never be read as licence to redesign the source's beats; and inside the dialogue-rewrite section of the blueprint rewrite, which is the only half of that output being written. **It is deliberately not a ban on specs and must not become one** — `objection` wants arithmetic, `comparison` a concrete difference, `expert` a mechanism, and `CORPUS_EVIDENCE`'s specificity finding is measured. What changes is a spec's JOB: it makes a benefit believable, it is never what a line is about, and the outcome leads with the spec behind it rather than the reverse. **Two things in the stack were actively pulling the other way and were fixed alongside it, or the new block would have spent every call arguing with them.** `productContextLines` is the first thing in the user prompt and the only place the product is described, so a field carrying an instruction outweighs most of what a system prompt says about the same material — and **Key Specs was the ONLY field with one**, reading "cite these concrete specifics instead of vague claims", with Benefits beside it as a bare label, i.e. data with no job. The steer now rides on Benefits and USPs, the spec line says what a spec is FOR, and **Benefits moved above USPs** so the two halves of the argument `WRITE_ANGLE_DISCIPLINE` asks for are read next to each other. Anything added to that block needs the same treatment — an unlabelled field reads as inert, and a carelessly labelled one competes with the block. The other pull was structural: `WRITE_TAKES[3]`'s anchor is literally "the single strongest USP", so `WRITE_ANGLE_DISCIPLINE` now says the committed idea is stated as an outcome **even when the assigned anchor is a feature** (the anchor picks which material the script is built on, not how it reaches the viewer), and that take claims the USP as the outcome it produces. Hooks got a **single bullet, not the block** — its system prompt is a fill-in-the-blanks contract that a competing block loses to (see the A/B above), so the rule is one line inside the existing "how to use the formulas" list saying what goes in a blank is an outcome, and the A/B-measured "fill every blank with THIS product's specifics" wording above it is untouched. **None of this is measured.** The A/B harness described above was not re-run, so treat the whole change as directional and re-test on a real product before tuning it further. **September 2026 — the field this block was written against is gone.** The Bank's Key specs & facts field was removed when auto-fill became a fifteen-field research brief, and **Proof** replaced it: the same checkable numbers, each followed by how much weight it really carries with a stranger. Its label in `productContextLines` inherits the spec line's job verbatim and adds the weighting ("never speak a weak signal as if it were a strong one"), so the rule this whole block exists to enforce is unchanged — what changed is that the field now arrives pre-weighted instead of as a flat list of the most concrete text in the prompt. Four more of the brief's fields joined that string at the same time, each with its own job and ordered so the one argument `WRITE_ANGLE_DISCIPLINE` asks for stays together: **How it works** (unique mechanism), then pain → benefit → **Before & after** → **What they do instead today**, then USPs → Proof → objections → **Who this is NOT for**, then offer/CTA. **A fifth, Hook angles, lasted a day.** It was labelled harder than anything else in `productContextLines` — raw material for ONE opener, never a menu, never lifted verbatim, rewritten in this script's own voice — and it made no difference, because the failure is not the model disobeying a label: a list of 6 to 8 finished openers is simply the most usable thing in the prompt and it wins on availability. Reported from **Remix**, which is where it costs most — the source ad's hook was excellent and its SHAPE was what the take should have adapted, and instead the take opened on a product hook angle with the source's structure gone. `REMIX_SOURCE_FIDELITY` cannot out-argue a field that hands the model a finished first line. The rule that came out of it: every field in this string is material a hook gets BUILT from, and nothing here may arrive pre-built.

**The hook contract — a style's first line, not just its body** (August 2026). `WRITE_STYLE_INSTRUCTION` describes the whole script, and the model read it as something the BODY does: picking **3 Reasons** returned takes with three counted reasons under an opening line that never mentioned a list, so the viewer met a listicle nobody told them to expect. The hook library is the other half of the cause — 8 families of generic openers, with nothing tying the family it hands over to the style that was picked. So `WRITE_STYLE_HOOK_CONTRACT` states, per style, what its FIRST spoken line has to establish, and `styleBlock` emits it immediately under the style instruction so a style reads as one rule instead of a rule about the body plus a separate rule about the opening. `HOOK_OPENING_INSTRUCTION` now works backwards from it — **the contract decides WHAT the line says, the library only decides HOW** — and explicitly permits dropping the formula when no family can carry the contract, since a hook that promises a different video than the one below it fails no matter how well it reads. Two supporting edits keep the other blocks from pulling the other way: `FORMAT_OVERRIDES_TAKE` names the contract in its precedence chain, and `exemplarBlock` says out loud that the transcripts calibrate **sound, never structure** (they're chosen by `familiesForWriteStyle`, which maps a style to a content family — near the right register, never the right shape, and the model was taking shape from them). Each contract is one sentence describing the JOB, never a fixed opener: three parallel takes exist to open three different ways, and a canned first line per style would collapse that. The counting clause on `listicle` and `tutorial` belongs to the hook, not the body — a hook promising three and a body delivering four is the same broken promise as a hook promising nothing.

**What was tested and deliberately NOT encoded.** A `frameworks.md` circulates with that dataset ranking every pattern by lift and calling PAS the weakest structure at 0.79x; a derived `ugc-os-system-prompt.md` turns that ranking into six priority-ordered rules and bills itself as a drop-in replacement for these prompts. Do not take it. Every lift in it except curiosity_gap has a bootstrap CI crossing 1.0 (PAS included, at [0.59, 1.48]), and two of its rules are contradicted by the corpus it cites — hook length is a median 28 words in the top 200 AND the bottom 200, against its "first sentence at most 8 words", and its 130–190 word target is just the corpus median restated. Its sentence-level section is the part that reads most convincingly and replicates least: mean sentence length, sentence-length variance, rhythm breaks, short-sentence rate, contraction rate, connective density and setup-sentence rate were all tested here and NONE separated the groups — connective and setup rates actually ran slightly HIGHER in the winners. `HUMAN_VOICE_RULES` and `BANNED_AI_PATTERNS` therefore stand untouched: they are about sounding human, which an all-human corpus has no power to test in either direction. They were never evidence from this data and must not be dressed up as if they were. Two further caveats worth carrying: sentence-level features are measured on Whisper's punctuation rather than the speaker's, and the corpus is organic Instagram (13% carry any CTA language, 1% are sponsored), so its hook craft and cadence transfer to UGC ads while its ad architecture does not — which is why the angle discipline, length discipline and remix fidelity contracts were left entirely alone. **Cinematic is retired** (July 2026): a fourth `writeFormat: 'prompt'` that wrote one ≤15s single-clip AI-commercial master prompt (STYLE→TIMELINE sections, `@INFLUENCER`/`@PRODUCT` tokens) and shipped it to Playground video mode. Its toggle entry, influencer picker, service pipeline and `cinematicVideo` handoff are deleted (see git history to restore); what stays is `ScriptHistoryItem.writeFormat: 'prompt'` on rows already on members' accounts — `isWriteFormat` coerces those to `'script'` on restore, and History still badges them "Cinematic". **Scene tokens:** `[PRODUCT]` / `[CHARACTER]` are reference-image slots and belong in **visual direction only** — never inside a spoken line, which TTS and video models pronounce literally. Dialogue always names the product in plain words, at most twice (`nameSpokenTokensInDialogue` is the deterministic backstop when the model ignores that). **Batch size is user-picked — 3 / 5 / 10, default 3** (`VARIATION_COUNTS`, the Variations `Dropdown` above Generate — its options carry the noun ("3 variations") and it therefore takes no dim `label`, which would have read "Variations 3 variations"; Length keeps its label, since "15s" alone doesn't say what it measures. Hooks pick from their own `HOOK_COUNTS` in the same slot). Five parallel takes off one brief crowded each other, so 3 is the default, but the wide net stays one click away. Every angle list (`WRITE_TAKES`, `REMIX_ANGLES`) holds **10 entries ordered strongest-first** and is **sliced** to the chosen count — so picking 3 gets the three best angles, and a count can never index past its pool. **The batch spreads the angle only when the creator left it open** (`CREATOR_ANGLE_PRECEDENCE`, appended LAST to both pipelines' angle block so it beats the assigned anchor): a brief or Additional Instructions that names the angle — a pain point, benefit, feature, audience, story, hook — is written by every variation, which then differ only in opening device. Where the creator says nothing, `takeAngleBlock` tells each take, in one phrase each (`WRITE_TAKES[].label`, kept beside the instruction it summarises so the two can't drift), what its siblings are anchored to and to stay off them — takes are parallel calls blind to each other, so a product with one obvious pain point otherwise comes back as three near-identical scripts. `RemixAngle` has 10 members; `hook-led` sits LAST because as an angle it mostly restates the global hook rules. A remix **stamps the angles it used** onto `GeneratedScript` + the history row (`remixAngles`, `variationCount`) and `OutputPanel` prefers that stamp; rows saved before the picker carry no stamp and are matched by count via `remixAnglesForCount`, which keeps the pre-picker five-variation order distinct from today's first five (a different set). The Output tab's empty + generating states render on the shared `GridCanvas` (the grid goes once takes land), the generating skeleton carries the scripts glow, and the header's **+** clears the panel back to the empty canvas — every take is already a History row. **The panel scrolls back to the top on a new RUN, never on a text change** (`runId`, the active History row id — a generation stamps a new one, a history restore stamps that row's): it used to key that reset on the takes' own content, which every in-place edit changes, so committing a typo fix in take 3 threw the member back to the top of take 1. **The take switcher is a scroll-jump, not tabs** — every take stays in one continuous column and the 1/2/3 row scrolls to one (and re-highlights as you scroll past). Rendering a single take at a time was tried and rejected: reading straight through the takes is worth more than putting each take's action row on screen. It **floats over the scroll port as frosted glass** rather than sitting above it, so the takes pass under it as you read — `absolute`, never `sticky`, since it's a sibling of the scroller and never moves, which is what keeps a backdrop-filter bar from lagging a frame behind its own container (the artifact that took the glass off B-Roll's storyboard strips). Its height is hand-synced in three places — the bar's `h-[53px]`, the scroller's `pt-[73px]` (that plus the column's own 20px inset) and `SWITCHER_H`, which pays the same clearance into the jump target and the active-take threshold — because a Tailwind class can't be built from a variable. **A scene card splits the spoken line out of the direction** (`splitSpokenLines`): the prompt contract quotes dialogue inline as `[CHARACTER] says: "…"`, and that quoted line — the only part that's read aloud, recorded, and sent to Voiceovers — renders as its own tinted, separately-copyable block above dim direction prose. Two guards earn their keep: a quote with **no attribution in front of it stays in the direction** (a scare quote like `a visible "wait, what?" reaction` was being promoted to dialogue and cutting the sentence in half), and the speaker can't be a connective (`…and says:` labelled the line "it over and"). Anything unrecognised falls back to the old single prose block, so no shape can render empty. `[CHARACTER]`/`[PRODUCT]` are marked inline, **not pills** — an inline-block pill fractured line-breaking and orphaned the possessive in `[CHARACTER]'s hands` (they were tinted text until `TokenField` made the mark a wash; see the in-place editing rule above). `splitHeaderLine` lets a header carry its own prose (`SCENE 2 — B-ROLL DETAIL: <prose>`), since assuming the header owned the whole line dropped the body and left blueprints of single-line scenes rendering as "0 scenes". **The timecode rides in its own pill** (`splitHeaderTime`, August 2026), one step brighter than the label and set in tabular figures so a column of scenes lines up digit for digit — how long a beat runs and where it lands is what a member scans a storyboard for, and at 10px inside a dim uppercase label it read as the label's own punctuation. It takes parens or brackets, a range or a lone stamp, any dash between the halves, and normalises the separator (one blueprint routinely mixes a hyphen and an en dash, and a column of pills is where that shows); a header with no timecode just keeps its label, and `DAYS 7-14` in a label is not a timecode. **The pill also says how long the beat RUNS** (`rangeDurationLabel` in `utils/timecode.ts`, shared with the Ad Analyzer's beat pills, which show the same ranges off the same blueprints): `00:25–00:40 · 15s`, one step dimmer so the range still leads. Where the beat SITS is what you navigate by, but how many seconds it is is what the scene gets generated at — and a range alone is two clock times to subtract, once per scene. Plain seconds at any length ("90s", not "1m 30s"), and no label at all for a lone stamp or a backwards range, which is a model error and not a duration to invent. **The Voice Profile card renders ABOVE the scenes** — it's pasted into every scene's prompt, so it's the first thing copied, and at the bottom of a ten-scene column most members never scrolled far enough to know it existed. The model still emits it last; `splitVoiceProfile` accepts either position, so only the render order moved. **The blueprint rewrite emits a MASTER VISUAL STYLE block too, and it LEADS the take** (September 2026): `=== MASTER VISUAL STYLE (every scene is shot in this look) ===`, written to `STYLE_BRIEF_SPEC` — the same five axes the Ad Analyzer and `analyzeStyleReferences` write, so a brief from any of the three is interchangeable and drops into the `styles` bank unchanged. A remix swaps the character, the product and the words; the LOOK is the half of the winner that is NOT changing, and it was the half being thrown away — the rewrite was told to start directly with the scenes, so a member who remixed a scene got prompts with no format to copy and every clip they generated off them came back in whatever look the video model reached for. Where the source already carries the block (an Ad Analyzer blueprint does) the paragraph is reproduced VERBATIM; where it doesn't, it's read off the source's own scene direction. Two clauses hold it in place: it describes HOW the ad looks and never WHAT is in it (no character, product, brand, location, or `[CHARACTER]`/`[PRODUCT]` token — it gets pasted in front of prompts for a different product), and it is IN ADDITION to the scenes, which keep their own camera, framing and lighting direction rather than having it lifted up there. It renders as a card above the Voice Profile one, and `BlueprintBlockCard` is now the shape both wear — the two masters are the same object, one paragraph governing every scene, copied on its own. Three parser notes: `splitVisualStyle` lifts it wherever it landed (offsets into the full take, so the in-place edit still splices), `splitVoiceProfile`'s region stops at a style header as well as at a scene header (a model that appends BOTH blocks after the last scene would otherwise hand the voice card the style paragraph as well), and `extractIntro` — the fallback that runs when a take carries no labelled voice block at all — drops a style block outright, or a rewrite that emitted a style and no voice profile would render the same paragraph on both cards. **A paragraph break in a plain script is worth ONE gap however many newlines produced it** (August 2026). Nothing normalises a take's whitespace — it's the model's raw text, and it has to stay that way, since it's what Copy, Save and Send to Voiceovers hand over — so the panel used to render every blank line as its own spacer and the take's whitespace became visible: the same three-paragraph script came out at 14px between paragraphs with one blank line, 28px with two, and 0px with none (a wall of flush sentences, the `-my-1` on each field having eaten the row gap). Which one a member got depended on the model and the run, not on the writing. `scriptLines` now emits one row per line that HAS words, carrying `breakBefore` — a RUN of blank lines is one break, and leading and trailing ones are dropped outright — and the two spacings are the row gap and `mt-2` with no spacer elements at all (`gap-3.5` nets 6px between sentences after the fields' negative margins, and a break is that plus 8). Rows are still keyed to their **own offset in the take**, so skipping the blanks changes nothing about which characters an in-place edit splices over. **Inside a scene, each `[0:00–0:04]` SHOT is its own block** (`groupSceneBeats`, September 2026) — its timecode as a pill (with how long it runs, the same `time · duration` shape the scene header wears, one step quieter), the direction and the line(s) that belong to it, and its own Copy. A shot is what gets generated as one clip, so it — not the scene — is the unit that leaves this app, and the only two copy targets that existed were the whole scene body and a spoken line's bare words: taking one shot meant hand-selecting a run of prose out of the middle of a paragraph. Both of those survive; this is a third. The split happens INSIDE a direction segment as well as between segments, because two consecutive shots with no dialogue between them arrive as one direction with two markers in it — and the spans ride through untouched, so every block still splices back over the exact characters it was rendered from. **Copy SLICES the shot out of the body verbatim** (`body.slice(first.start, last.end)`) rather than rebuilding it from the parse, which trims, strips connectives and peels the attribution cue off the direction; it takes back a trailing closing quote, since a line's span is the words INSIDE its marks. A beat with no marker (a single-shot scene, or the prose before the first one) renders bare, exactly as the whole scene used to — a box and a header around the only thing in the card would say nothing. **The scene's audio direction is lifted out and rendered as the scene's own footer** (`liftAudioNote`), dimmer, outside every shot box — and appended to every shot's Copy. The prompt contract writes "NO background music, NO soundtrack, NO score…" once per scene while it governs every shot in it, and a member copying one shot has no reason to know it was written at the bottom of the paragraph. Only a SUFFIX of the last direction is ever taken: cutting a sentence out of the middle would leave the prose either side of it non-contiguous, and every edit on this card is a splice of one contiguous span. It's capped at 300 characters (a real one runs ~90), so a model that drops the phrase mid-paragraph can't hand the rest of the shot over as "audio". **A shot's header carries Send to Playground beside its Copy** (September 2026) — the Playground glyph, handing that shot's exact string (direction, lines, audio note) over as `videoPrompt`. It REPLACES the prompt there and leaves the rest of that draft alone, the Voice box most of all, which is what earns it a button: copy → switch app → clear the prompt → paste was four actions with the voice profile at risk in the middle of every one, and this is one. The **scene** header carries it too, because a scene with no shot markers has no shot row at all and would otherwise have no way to be sent. **Every small Copy in this panel is glyph-only now**, at every width (Massimo's call): the word sat beside a copy glyph in rows that also hold a scene label, a timecode pill, a send button and a delete, and three of the four things in that row were explaining themselves twice. The wording survives as the tooltip and the accessible name, the green tick is unchanged, and `IconPillButton` is the one shape all of them use. The card header's **Copy Full Script** keeps its label — that one says WHAT it copies, which is the only thing distinguishing it from the per-scene button beneath it.

**Every chrome row in the Output panel is `select-none`** (headers, chips, copy/edit buttons, the take switcher) so dragging across a take highlights the script and nothing else — it used to sweep up "SCENE 1 — HOOK" and the word "Copy" alongside the line you wanted. That alone made the highlight *stickier*, because Chrome deliberately leaves a selection alone when you press on unselectable chrome (the rich-text-toolbar rule) — so a click on a scene header or a copy button did nothing to it. `clearSelectionOnChrome`, one `onMouseDown` on the panel root, collapses the selection when the press lands on a `user-select: none` target, restoring what a click on ordinary background already does. **That fixed half of it, and the other half is that the prose here is TEXTAREAS** (September 2026): the take is edited in place, so a highlight dragged across a scene direction or a spoken line is the FIELD's own selection — `window.getSelection()` doesn't own it and `removeAllRanges` can't touch it, and the browser keeps painting it for as long as the field holds focus. Pressing unselectable chrome doesn't take focus away (Safari never focuses a button on click), so the highlight outlived every click that should have cleared it and the only way out was to start another drag somewhere else. The handler now BLURS the focused field first — which is what actually clears it, and commits the edit exactly as clicking into another field already does — and returns early when the press lands inside a field, since moving the caret there is the browser's own business. **Both free-text steer boxes are labelled "Additional Instructions"** — Write New's (which doubles as the brief, state `brief`) and the remix modes' (state `additionalContext`). Only one ever renders, and they do the same job, so one name. Both identifiers are unchanged: they key persisted drafts and the service prompts, and the rename was copy only.

**A run is a History row from the moment it is fired, and the Output pane is a slot addressed by id** (September 2026). Firing used to flip a bare `isGenerating` that painted the whole Output pane as a skeleton AND greyed Generate, so the one place a member could read a script was locked for the length of the call, they couldn't start a second one, and History showed nothing at all until the takes landed — a fired run was invisible in the list that exists to show runs. All of it comes off one change: `PendingScriptRun` (types.ts) mints the run's id **before** the call, `showRunEmpty` parks the pane on that id, and the finished `ScriptHistoryItem` reuses it — so the in-progress card in History IS the card the takes land in, same badge, same title, same place in Today, nothing moving underneath the member watching it. The pane draws the writing face only for the run whose id `activeHistoryId` matches (`watchedRun`, a lookup in `pendingRuns` rather than a flag); clicking any other row while it writes loads that row, and clicking an in-progress card comes back. **Generate never stands down** — press it again and a second card joins the queue, which is the app-wide rule and is now literally true here. Runs are held in **memory, never in `scriptHistory`**: a script is a streaming chat completion with no task id to re-attach to, so a row persisted to the bank would be a zombie after a refresh — the bank holds finished work.

**Which run gets the pane when it lands** is the only genuinely contested decision in that queue, and it is decided by `watchedRunIdRef` — a ref, not state, because the answer is needed in a run's async tail, where the closure's `activeHistoryId` is whatever it was at fire time and the member has usually moved since. It holds the id of the still-writing run the pane is parked on, or null when the pane is on finished work, which is exactly the question. A landing run takes the pane when that is null (browsing finished rows — being shown the thing you pressed Generate for is the point) or is its own id (you were watching it). It does **not** when the pane is on a DIFFERENT run still being written: watching a script arrive is the one state where being yanked away loses something a click can't get back. Fire three and browse away and the newest to land wins the pane, which is the honest generalisation of one run's promise. The same ref decides the **error** path — only the pane parked on the failed run turns into its error; anyone reading something else gets the toast and keeps their page. Two things have to stay true if this grows further: the pending run's own `mode` / `writeFormat` / `hookCount` drive the loading copy — never the live left-panel selectors, which a member browsing History mid-run has already moved — and `pinRun` re-pins the output labels when the takes land, for the same reason.

**Clearing the canvas is undone by picking from History, not by the output changing shape.** `RightPanel`'s + button snapshots a signature of what it cleared so the next run refills the panel on its own — but restoring the run that was cleared produces that same signature, so the panel stayed blank and the row appeared not to open at all (reported September 2026; it also stuck for that row until a refresh). The signature now carries `activeHistoryId` as well as the takes, and — the half that actually fixes it — `showInOutput` drops the flag on **every** pick, including the pending card's: a click in History is a request to see that run, and there is no reading of it under which the answer is an empty canvas.
