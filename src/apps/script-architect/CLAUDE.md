# Scripts — `script-architect/`

Create section of UGC OS. This file loads when Claude works with files under `src/apps/script-architect/`; the app-wide rules stay in the root [CLAUDE.md](../../../CLAUDE.md).

## Job

**The member picks who writes** — a `ScriptModelRow` pinned **directly above Generate** (it applies to both modes, it's the last thing you'd change before firing, and it's what decides what the click costs). **The model row, Length and batch size share ONE row above Generate: the model takes HALF, the two chips a quarter each** (August 2026) — `flex-[2]` against `flex-1`, both zero-basis so the ratio holds whatever is in them, all at 58px, both chips `size='xl'` and opening upward; the count anchors its menu right, being the rightmost. Equal thirds was tried first and came off: the model row is the one control here with something to say, and at a third it read "GPT 5.6…" over "The Scrip…" while the chips had spare room around two words. In **Hooks** there is no duration and the remaining pair splits 2:1. They were a chip band stacked over the model row, which spent two rows on one decision each in a column that also has to fit a brief. Both are pearls rather than fields — they were two full-width `SegmentedToggle` slabs, then full-width `Dropdown`s, each costing the brief its height for a control nobody sweeps through. The Length pearl carries a **clock glyph** instead of the dim "Length" label a `Dropdown` could afford — "15s" alone doesn't say what it measures — while the count keeps its noun ("3 Variations" / "10 Hooks"), since a bare number beside a duration reads as another measurement. Each hides on its own (the blueprint rewrite has a Length but no count since it returns one script, Remix's Length leads with **Default**). **Two mode guards keep one mode's state out of the other's chrome**, both fixed August 2026 after each had produced a controls row that lied. `blueprintActive` is gated on Remix: the blueprint is detected off the persisted `source` draft, which Write New never reads, so without it a blueprint left in the remix box took Write New's 3 / 5 / 10 picker off screen (a blueprint rewrite returns one script) with nothing on the panel explaining where it had gone. `isHooksFormat` is gated on Write New: `writeFormat` is that mode's Script / Hooks / Scenes toggle and Remix has no equivalent, so an unguarded read landed a member who last wrote hooks in Remix with its Length chip gone and its batch size counting "10 Hooks", for a pipeline that returns script variations. The service was always right — it reads `writeFormat` only inside its `mode === 'write'` branch — so both were panel-only lies. **The generate band is a static `shrink-0` footer**, never `position: fixed`. It went fixed under `md`, which is a zoom trap rather than a phone shape: browser zoom shrinks the viewport in CSS px, so 200% on a laptop lands under the breakpoint with the desktop split still on screen and the bar detached to the window's bottom edge, covering the References card and the Additional Instructions box outright (Hooks looked fine only because its footer is one row shorter). **The column runs on 8px throughout**, B-Roll's rhythm; it was 12s and 16s and read loose beside it. **The two picker rows live in a `SectionCard` titled References**, in BOTH modes (August 2026) — Product, then Script Style in Write New; Product, then the source box in Remix (the source goes last, being the one that grows as you paste). **Product leads**: it's required and it's what the script is ABOUT, where Script Style is optional flavour — and the Generate button already sits down the column saying "Pick a product to generate", which used to point at the second row rather than the first. It also matches B-Roll's product → character → style order. Each row carries a `StatusDot` at its left edge: Product `required` (red when empty), Script Style and Hook Style neutral (Best Mix is a real answer, not an empty field). The card takes plain `flex-1`, never `basis-0` — with basis-0 the Remix source box paid for the product row out of its own height. **Write New's Additional Instructions box is the remix box** — the same in-box header, same toolbar; its name used to sit on a `StepLabel` row above, which was ~40px of nothing between the pickers and the field, and the box `flex-1 basis-0`s so it opens tall and gives ground as the pickers above it fill. Two modes: **Remix** (one source box; format auto-detected via `detectSceneBlueprint` — a winning transcript → 3 variations, an Ad Analyzer scene blueprint (`--- Scene N` / `SCENE N —` headers) → rewritten scene prompts, with a chip to override back to plain remix) and **Write New** (brief + style + 10/15/20/30/60/90s → 3 human-sounding takes, as plain script or scene blueprint). **Both modes pick a length** above Generate, but Remix's list leads with **Default** (`REMIX_LENGTHS`, its own persisted slot `:remixLength`) — the source ad already has a length and keeping it is usually the point of remixing a winner, so 'default' sends no target and the numbers re-cut the source to a duration. **The blueprint rewrite gets the same control**: on 'default' it inherits the source's own scene count and timings (what a rewrite usually wants), and on a picked length `runReverseEngineer` re-times the scenes, drops or merges whole ones out of the middle while keeping the opener and the CTA scene, and renumbers the headers — the two clauses that otherwise promise to preserve scene count and durations stand down for it. It was hidden here until the pipeline could honour it; a length dropdown the prompt ignored would have been a placebo. The three LLM pipelines and `ScriptMode` ('write' / 'remix' / 'reverse-engineer') survive unchanged in the service and history rows — only the UI toggle merged. Write New's **Output** toggle: Script / Hooks / Scenes. **Script Style is two groups in one picker** (`WriteStyleGroup`, sectioned in the slide-over, **Structures on top here** — the question this app asks is how the argument is built; B-Roll passes `ScriptStyleList formatsFirst` and leads with Formats, since it's picking the kind of ad to SHOOT and a format is the half that stages the shots. Same shared component, same slugs, only the reading order differs): **Formats** — the kind of organic content the ad imitates (podcast clip, street interview, green-screen reaction, comment reply, expert explainer, how-to, GRWM), the higher-converting half because the ad reads as content before it reads as an ad, and the only half that decides the shots — over **Structures**, the persuasion mechanic (PAS, story, 3 Reasons, callout, curiosity, before/after, demo, us-vs-them, objection-crusher, founder). Only formats carry `WRITE_STYLE_SCENE_DIRECTION`, appended in the **Scenes** output so the blueprint actually stages the format (boom mic + studio angles, a handheld mic entering frame off a street, an on-screen review card) instead of defaulting to selfie-to-camera; a structure implies no camera, so its shots stay free. B-Roll reaches the same block through `sceneStagingFor` when an analysed ad supplies the staging (it no longer has a format picker of its own — see its row) — `ScriptStyleList` is likewise shared, since the slugs are persisted and two copies of the list would drift into a wrong label on somebody's saved session. When a format's way of opening collides with the take's opening device, `FORMAT_OVERRIDES_TAKE` gives the format the delivery and the take keeps its angle. Style slugs are **stable** — they key persisted picks and history rows. **Hooks** (`writeFormat: 'hooks'`) writes a user-picked **10 / 20 / 50** standalone opening lines (`HOOK_COUNTS`, default 10, its own persisted slot `:hookCount` — one call, not a batch of parallel takes, so it doesn't share `VARIATION_COUNTS`; `runHooks` scales the Best Mix spread rules with the count, since "at least 4 families, never more than 3 from one" was written for ten and asks near one family per line at five) from the "1,000 Viral Hooks" swipe file distilled into 7 formula families (`HOOK_CATEGORY_META`: Educational / Comparison / Myth Busting / Storytelling / Authority / Day in the Life / Pattern Interrupt); the Hook Style picker defaults to **Best Mix** (LLM picks a count-scaled minimum of fitting families) or locks one family; no length/style controls; a single LLM call returns `<FAMILY>`-tagged lines (`parseHooks`) rendered as per-hook rows with a family chip + copy — copy/save strip the tags, and there are no send buttons. **Every block in an output card is edited IN PLACE** (August 2026) — the line, the paragraph, the scene body, the spoken line — not by entering a mode that swaps the rendered take for one raw box. `EditableText` is the shared idiom: a textarea styled as the prose it replaces, with no chrome until you're in it. Two shapes, and the rule is what the read-only render adds: where the block is plain text (a hook, a spoken line, a script paragraph) the field is always on and looks identical to the paragraph; where the render adds something — scene direction and a dialogue-free scene body, whose `TokenText` tints the `[character]` / `[product]` slots — it's click-to-edit, so a permanent field doesn't trade that away to save one click.

The **Voice Profile card** is edited the same way, and `splitVoiceProfile` reports its body's span for it — but only for the appended-header shape, whose boundaries are exactly known; the `extractIntro` fallback deliberately reports none, so an unrecognised shape renders read-only rather than risking a splice over the wrong characters. `VOICE_HEADER_REGEX` also accepts an optional **MASTER**: Scripts' own prompts emit `=== VOICE PROFILE … ===` and the Ad Analyzer's blueprint emits `=== MASTER VOICE PROFILE … ===`, and that one word sitting between the markers and the label meant a blueprint remixed here rendered its voice profile buried in the last scene's body instead of on its own card. **The commit is a SPLICE, never a search or a rebuild.** `SceneChunk` carries `bodyStart`/`bodyEnd` and each `SceneSegment` its offset within that body, so a block knows the exact characters of the take it was rendered from and `replaceRange` writes back over them. The two alternatives both break: a `String.replace` of the old text picks the wrong one when two scenes share a sentence, and rebuilding the take from the parse can't work at all — `splitScenes` and `splitSpokenLines` trim, strip connectives and filter empties, so they don't round-trip. Every path (in-place, hook row, raw editor) funnels through `commitText`, so one undo stack covers all of them. The header's **Raw** button survives, relabelled: it's no longer how you fix a typo, it's the only way to ADD or DELETE a scene, a line or a paragraph.

**A hook row is edited in place**: the line is an `AutoGrowTextarea` styled as the paragraph it replaces, so you click a hook and type — Enter commits (a hook is one line), Escape reverts, an emptied line reverts rather than deleting the row, and blur rewrites just that line via `hooksToText` (parseHooks' inverse) through the same commit path and undo stack the raw editor uses. The header's **Edit** survives on a hooks pack because the raw box is the only way to ADD or DELETE a line; it is no longer the way to fix a typo, which is what it was being opened for. Formulas are kept at full original length (setup + payoff, never truncated), and the same `HOOK_LIBRARY` + `HOOK_OPENING_INSTRUCTION` seed the opening line of Write New's Script and Scenes outputs. **Cinematic is retired** (July 2026): a fourth `writeFormat: 'prompt'` that wrote one ≤15s single-clip AI-commercial master prompt (STYLE→TIMELINE sections, `@INFLUENCER`/`@PRODUCT` tokens) and shipped it to Playground video mode. Its toggle entry, influencer picker, service pipeline and `cinematicVideo` handoff are deleted (see git history to restore); what stays is `ScriptHistoryItem.writeFormat: 'prompt'` on rows already on members' accounts — `isWriteFormat` coerces those to `'script'` on restore, and History still badges them "Cinematic". **Scene tokens:** `[PRODUCT]` / `[CHARACTER]` are reference-image slots and belong in **visual direction only** — never inside a spoken line, which TTS and video models pronounce literally. Dialogue always names the product in plain words, at most twice (`nameSpokenTokensInDialogue` is the deterministic backstop when the model ignores that). **Batch size is user-picked — 3 / 5 / 10, default 3** (`VARIATION_COUNTS`, the Variations `Dropdown` above Generate — its options carry the noun ("3 variations") and it therefore takes no dim `label`, which would have read "Variations 3 variations"; Length keeps its label, since "15s" alone doesn't say what it measures. Hooks pick from their own `HOOK_COUNTS` in the same slot). Five parallel takes off one brief crowded each other, so 3 is the default, but the wide net stays one click away. Every angle list (`WRITE_TAKES`, `REMIX_ANGLES`) holds **10 entries ordered strongest-first** and is **sliced** to the chosen count — so picking 3 gets the three best angles, and a count can never index past its pool. **The batch spreads the angle only when the creator left it open** (`CREATOR_ANGLE_PRECEDENCE`, appended LAST to both pipelines' angle block so it beats the assigned anchor): a brief or Additional Instructions that names the angle — a pain point, benefit, feature, audience, story, hook — is written by every variation, which then differ only in opening device. Where the creator says nothing, `takeAngleBlock` tells each take, in one phrase each (`WRITE_TAKES[].label`, kept beside the instruction it summarises so the two can't drift), what its siblings are anchored to and to stay off them — takes are parallel calls blind to each other, so a product with one obvious pain point otherwise comes back as three near-identical scripts. `RemixAngle` has 10 members; `hook-led` sits LAST because as an angle it mostly restates the global hook rules. A remix **stamps the angles it used** onto `GeneratedScript` + the history row (`remixAngles`, `variationCount`) and `OutputPanel` prefers that stamp; rows saved before the picker carry no stamp and are matched by count via `remixAnglesForCount`, which keeps the pre-picker five-variation order distinct from today's first five (a different set). The Output tab's empty + generating states render on the shared `GridCanvas` (the grid goes once takes land), the generating skeleton carries the scripts glow, and the header's **+** clears the panel back to the empty canvas — every take is already a History row. **The take switcher is a scroll-jump, not tabs** — every take stays in one continuous column and the 1/2/3 row scrolls to one (and re-highlights as you scroll past). Rendering a single take at a time was tried and rejected: reading straight through the takes is worth more than putting each take's action row on screen. **A scene card splits the spoken line out of the direction** (`splitSpokenLines`): the prompt contract quotes dialogue inline as `[CHARACTER] says: "…"`, and that quoted line — the only part that's read aloud, recorded, and sent to Voiceovers — renders as its own tinted, separately-copyable block above dim direction prose. Two guards earn their keep: a quote with **no attribution in front of it stays in the direction** (a scare quote like `a visible "wait, what?" reaction` was being promoted to dialogue and cutting the sentence in half), and the speaker can't be a connective (`…and says:` labelled the line "it over and"). Anything unrecognised falls back to the old single prose block, so no shape can render empty. `[CHARACTER]`/`[PRODUCT]` are tinted inline text, **not pills** — an inline-block pill fractured line-breaking and orphaned the possessive in `[CHARACTER]'s hands`. `splitHeaderLine` lets a header carry its own prose (`SCENE 2 — B-ROLL DETAIL: <prose>`), since assuming the header owned the whole line dropped the body and left blueprints of single-line scenes rendering as "0 scenes". **The Voice Profile card renders ABOVE the scenes** — it's pasted into every scene's prompt, so it's the first thing copied, and at the bottom of a ten-scene column most members never scrolled far enough to know it existed. The model still emits it last; `splitVoiceProfile` accepts either position, so only the render order moved. **Every chrome row in the Output panel is `select-none`** (headers, chips, copy/edit buttons, the take switcher) so dragging across a take highlights the script and nothing else — it used to sweep up "SCENE 1 — HOOK" and the word "Copy" alongside the line you wanted. That alone made the highlight *stickier*, because Chrome deliberately leaves a selection alone when you press on unselectable chrome (the rich-text-toolbar rule) — so a click on a scene header or a copy button did nothing to it. `clearSelectionOnChrome`, one `onMouseDown` on the panel root, collapses the selection when the press lands on a `user-select: none` target, restoring what a click on ordinary background already does. **Both free-text steer boxes are labelled "Additional Instructions"** — Write New's (which doubles as the brief, state `brief`) and the remix modes' (state `additionalContext`). Only one ever renders, and they do the same job, so one name. Both identifiers are unchanged: they key persisted drafts and the service prompts, and the rename was copy only.
