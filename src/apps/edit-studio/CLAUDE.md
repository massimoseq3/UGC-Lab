# Edit — `edit-studio/`

Create section of UGC OS. This file loads when Claude works with files under `src/apps/edit-studio/`; the app-wide rules stay in the root [CLAUDE.md](../../../CLAUDE.md).

## Job

Download + setup page for the `/video-editor` Claude skill (script + voiceover + B-roll in → finished captioned 9:16 ad out, edited locally by Claude Code — no kie.ai involvement). Hero is a hover-animated ivory folder (`SkillFolder.tsx`, orange glow, work-cards rise out on hover) that downloads `public/video-editor.skill` (keep that copy in sync with the source skill); beside it, a 4-step setup card in the ApiKeyGuide style — **one line per step**, no reassurance paragraph and no second Claude Code link (step 1 is already one); the card is read once and in the way every time after. It sits on the bare **`AppBackground` gradient**, the same one the Dashboard and every other page shows — the shared starfield the two full-page screens used to wear is gone (September 2026, see the Dashboard row) — and the setup card is still cut from the same glass as the Dashboard's widgets (translucent fill + backdrop-blur, white in light mode) rather than a flat tinted panel. Slug `/edit`; crab: Snips · Editor (clapperboard).

**On a phone the reading order is not the desktop one.** Desktop is two columns — folder left, title + benefits + setup card right — and it stays that way. A phone gets one column in the order a stranger needs it: the **title** (what this page is), then the folder and its Download button (the thing to take), then the benefits and the steps. That's done with explicit grid placement (`md:col-start-*` / `md:row-start-*`) rather than a second copy of the header, so the two orders can't drift. Two more phone-only details: the page root takes `overflow-x-clip`, because the folder's halo is a 135%-wide radial glow that hangs past both edges and was scrolling the whole page ~20px sideways; and the pop-cards fan out on `group-active:` as well as `group-hover:`, since touch has no hover and the folder was otherwise a still picture there — a tap plays the fan while the download starts, which is the only confirmation a touch member gets.

## Shipping a new cut of the skill

The skill is a **file the member installs by hand** — it never auto-updates, and nobody reopens a download page they've already used. So a new version has to announce itself. Bump `SKILL_VERSION` in `stores/skillUpdateStore.ts` and, in the same commit: replace `public/video-editor.skill` and update `SKILL_FILE_SIZE` in `EditStudio.tsx`. Until Edit is opened once on that version, the dock tile carries a red badge dot (top-**left**, because the crab peeks out of the top-right on hover) and the folder wears a "New update · vN" sticker instead of the quiet "vN" one. **That badge is the whole announcement** — the button stays "Download Skill" and no what's-new line goes on the page: a member who sees "new update" downloads it, and a changelog under the button is copy they read once and step over every visit after. Seen-state is per browser in localStorage, never cloud-synced — the skill is installed into a Claude Code setup on one machine, so "already got it" is a fact about the machine, not the account. `EditStudio` reads `fresh` once on mount and marks seen in an effect, so the badge can't vanish out from under the member reading the page it's on.
