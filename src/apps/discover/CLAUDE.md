# Outliers — `discover/`

Tools section of UGC OS. This file loads when Claude works with files under `src/apps/discover/`; the app-wide rules stay in the root [CLAUDE.md](../../../CLAUDE.md).

## Job

Search TikTok and the Meta Ad Library for ads worth stealing, then hand one straight to Ad Analyzer or Scripts. **App id is `discover`** (stable — keys the persisted platform/filters/sort); the display name is free to change. Runs on the member's own **ScrapeCreators** key (`settingsStore.scrapeCreatorsKey`, browser-local, never synced — same doctrine as the kie key, and it's optional, so it never gates the Settings alert dot). `utils/scrapecreators.ts` is the only file that knows endpoint paths; it calls the vendor **directly from the browser** — verified `access-control-allow-origin: *` plus an `x-api-key` allowance — so there is no proxy and no new env var for search. Every response carries `credits_remaining`, which is both the live balance chip and how a key is validated (`scTestConnection` spends 1 credit on a trivial search; there is no free balance endpoint). Costs are 1 credit per search page of 30, 1 per transcript. Opening the app without a key pops `ConnectScrapeCreators` — the same verify-before-save transaction as `ApiKeyGuide` (nothing is stored that can't search) but deliberately shorter: kie's version needs a two-step rail because you must go and generate a key first, whereas signing up here hands you one, so a rail would be scaffolding around a single paste. It's seeded from the store at mount and never re-armed, so a dismissal sticks; the empty state behind it keeps a **Connect key** button that reopens it, so closing the popup is never a dead end. It shows ScrapeCreators' raw message on failure (infra surface) plus one decoder line on a 402, since their text tells a member with a mistyped key to go and buy credits. **The vendor's own docs contradict their own example on the TikTok search shape** — the endpoint description says each `search_item_list` row wraps the video in `aweme_info`, the example response shows those fields at the row's top level. Reading only the top level meant every row failed its id check and **every TikTok search returned zero results**; `searchTikTokKeyword` now unwraps `row.aweme_info ?? row` so both shapes work. `warnIfAllDropped` console-warns whenever a page arrives full and normalises to nothing, because that combination means a field name moved and is otherwise indistinguishable from "no results" in the UI. **Each platform keeps its own search** (`PlatformSearch` — query + results + cursor + searched, one per tab, `patchSearch` always writing the tab it was HANDED so a page landing after a flip fills its own grid). Flipping the toggle used to clear the results, which threw away a paid page of 30 for the sake of a glance; the query rides along per-tab too, so the box always says what produced the grid under it. Deliberately **session memory, not localStorage**: a result's media urls are signed CDN links that expire within days, so a restored grid would be a wall of broken thumbnails — its real lifetime is the app staying mounted, which already covers dock switches. The header's **+** (the same idiom every panel header carries) resets **the current tab only**, since protecting the other tab's search is the whole point of the split, and it hides itself when there's nothing to clear. **The outlier score is ours, not the vendor's**: `views ÷ the creator's own follower count` (`services/scoring.ts`), banded 2x/5x/10x, and `author.follower_count` rides inline on the search response so a fully scored grid is one call. Alongside it `engagementRate` = `(likes + comments + shares + saves) ÷ views` — reverse-engineered from the reference tool and checked against four of its cards; **saves are in the numerator** and shouldn't be "simplified" out, since on a UGC ad a save is the strongest buying signal of the four. The two answer different questions (how hard a video worked the people who saw it, versus how far it travelled past its own audience) so they never merge into one figure. Two floors keep the top of the grid honest — a **min-views** floor (absolute noise: 800 views from 40 followers is 20x and meaningless) and `MIN_FOLLOWERS_FOR_SCORE` (tiny denominators). Scoring + the min-views filter are a **derived render step** (`applyMinViews`), never baked in at fetch time, so moving the filter re-ranks what's on screen instead of silently needing another paid search. **The min-views floor has to announce itself**, because it defaults to 10K and removes cards CLIENT-SIDE: a niche keyword pays for a page of 30 and renders four, which reads as a broken search rather than as a filter working. `hiddenByMinViews` (`results.length - visible.length`) prints a dim "N more hidden under 10K views" line above the grid, and when it eats the whole page the empty state says so instead of telling the member to try a broader keyword — which would send them to spend another credit on the same outcome. Note a full page is a **maximum, not a promise**: the vendor returns fewer rows for a niche query or a narrow `date_posted`, `normaliseTikTok` drops any row with no `aweme_id` or no reachable permalink (the search feed interleaves non-video modules), and `mergeResults` dedupes across pages. **Meta gets no outlier score and must never be given a fake one**: `spend` and `reach_estimate` come back `null` for every commercial ad (verified), so those cards carry `ad.daysRunning` off `total_active_time` and the sort control is honestly relabelled **"Longest running"** on that tab — `SORT_OPTIONS` is keyed by platform for exactly this reason, and `'views'` isn't offered there at all. `DiscoverResult` holds `stats`/`outlier` and `ad` as separate optional blocks so the card renders what it was given and can't invent the other. **Meta's keyword matching is loose by design** — it scores relevance its own way and matches advertiser names, so a product search returns unrelated ads; that's the platform, not a parsing bug, and the only lever the API exposes is the **Match: Exact phrase** filter (`search_type=keyword_exact_phrase`). Meta files an ad's creative in **one of four places** depending on its format (`videos` / `images` / `extra_*` / `cards` for carousels) and a plain video ad populates only `videos` — which in the live payload carries **no `video_preview_image_url` at all**. Reading just `videos[0]`/`images[0]` therefore left carousels and poster-less video ads with no cover, rendering them as **empty black tiles**; the normaliser now walks all four, and a clip with no cover anywhere becomes its own thumbnail via a `#t=0.1` src fragment, which makes the browser decode and paint that frame instead of showing an empty `<video>`. The **Media** filter (`media_type`) defaults to **VIDEO**, since a static image has no hook, no delivery and no transcript to remix. That default is applied through a `sanitize` that spreads the stored filters over `DEFAULT_FILTERS` on every hydrate, not just when the slot is empty: `usePersistedState` returns a stored blob **verbatim**, so a filter object saved before a field existed carries that field as `undefined` for good — which is how a member ends up searching with no media filter at all rather than the default. Any field added to `DiscoverFilters` from here on picks up its default on the next load. The line under the author name is **per-platform in shape as well as wording**: TikTok's follower count is dim text (it's the outlier score's denominator, context rather than a figure in its own right), Meta's page likes take a **pill**, because it's the only audience number the Ad Library publishes and as dim text beside a dim glyph it was the easiest thing on the card to miss. Both reserve their row height even when the count is absent, so captions still start level across the grid. The days-running pill is **emerald, not the house monochrome**: on the Meta tab it is the only performance signal there is, so it has to read as a score rather than another grey timestamp. The card is a **4:5 frame with the vertical video letterboxed (`object-contain`), never cropped to fill**: a true 9:16 tile is nearly twice its own width in height so barely a row fits on screen, and `object-cover` would crop exactly the top and bottom where UGC puts its hook text — cropping the hook off an ad-research tool defeats the tool. Under it sits the full engagement row (views · likes · comments · shares · saves, glyph-led and always in that order) with ER on the media and the outlier badge opposite it. **The play/mute pair and the runtime pill are always visible, never hover-gated** — they are how you tell a video card from a still one while scanning, which is most of what the grid is for, and a signal you have to hover to see isn't one. That has two consequences worth knowing. ER moved to a bottom-left COLUMN stacked above the controls: both were at `bottom-2 left-2` and only got away with it because the controls appeared on hover, so an always-on pair would have overlapped it permanently. And every video card now carries `preload="metadata"` (it was `metadata` only for the poster-less ones), because **only TikTok publishes a runtime** — Meta's payload has none at all, so the card reads `duration` off the loaded file via `onLoadedMetadata` and prefers the platform's figure when there is one. That costs a small range request per card and buys a runtime on the whole Meta tab; guard the probe, since a live/unseekable stream reports `Infinity`. The card's hover stack is deliberately **not** hidden while its clip plays (the one place that breaks the `TileActionStack hidden={watching}` idiom): on a generated tile the picture is the point, but these are research cards and Save / Analyze / Remix are decisions made WHILE watching the ad — stepping aside meant pausing the video to reach the button that saves it. **TikTok's image CDN rejects plenty of its own cover URLs from a browser**, so a `coverUrl` is never trusted: the `<img>` carries an `onError` that drops it and falls the card over to painting a video frame, which also removes the browser's broken-image placeholder box — that placeholder was the stray outline around every TikTok card. The caption block is pinned to **exactly two lines (`h-[3.25em]`, being 2 × `leading-relaxed`)**, not a min-height: the stats row is meant to be read ACROSS the grid, and a min-height short of two full lines still let a two-line caption push its own card 7px below its neighbours. **Download** (leading the hover stack per the canonical order, and a glyph-only button closing the detail modal's second footer row) saves the ad's video to disk through the same `downloadResultVideo` fetch — never an anchor with a `download` attribute, which browsers ignore cross-origin, so the click would open the video in a tab instead of saving it. The swipe file deliberately has no such button: it stores no video, and its `mediaUrl` is a signed link that has expired by the time anyone wants it — `postUrl` is the honest route there. Two handoffs: **Analyze** downloads the video (`downloadResultVideo` tries the CDN direct, then falls back to `api/fetch-media` — fbcdn sends CORS headers, TikTok's CDN sends none and 403s without a Referer) and sends a live `File` as `DiscoverVideoPayload` → Ad Analyzer's existing `handleAnalyze`; **Remix Transcript** sends the words actually SPOKEN, on **both** platforms, for 1 credit and **no kie call at all** — TikTok via its captions endpoint, Meta via `/v1/facebook/adLibrary/ad/transcript` — stripped of WEBVTT scaffolding and handed to Scripts' existing `winningTranscript` seam (zero changes on the Scripts side). Meta used to short-circuit to the ad's body copy, which is the written caption, so "remix the transcript" was quietly sending somebody's ad copy instead of the script their creator performed; the detail modal now labels **Caption** and **Transcript** as separate blocks so it's visible which one the button sends. **The transcript is TikTok-only in practice**: Meta's ad-transcript endpoint reads Facebook's *exposed captions*, which Ad Library video ads don't carry, so it came back empty every time — the modal drops the Transcript block and the Remix button on that tab and routes the words through **Analyze Ad**, which reads the video itself. `fetchResultTranscript` keeps its Meta branch so re-enabling it is a one-line change in `openCard` if that ever improves. **Opening a card costs nothing.** It used to fetch the transcript on open so the words were on screen by the time you'd read the caption — which billed a ScrapeCreators credit for the act of *looking* at a card, the one thing here anyone does idly, thirty cards to a page. The modal's Transcript block now starts `idle` and offers **Get transcript — 1 credit**; `TranscriptState` gained that phase and the modal's fallback state is `{ phase: 'idle' }`, not `{ phase: 'loading' }`. `transcriptCache` still keys by card, so pulling the words and then remixing them stays **one credit, not two**, and a card paid for once stays paid for across closing the modal. Both handoff buttons carry an `ArrowUpRight` and name their destination's job (**Analyze Ad**, **Remix Transcript**) because both leave the app; **Remix stays disabled until Get transcript has returned words** — that gate is what keeps the credit on a button the member pressed, as well as stopping a bounce to Scripts with an empty box. Fetching is `onFetchTranscript` and is deliberately separate from `onRemix`: the 10-credit `use_ai_as_fallback` retry used to call `onRemix(result, true)`, so a button labelled "Transcribe with AI" quietly left the app; both it and the error-state "Try again" now fetch in place. The card grid's hover-stack Remix is the one shortcut that still fetches on click — that's a deliberate press on a labelled button rather than an idle open, so it stays, and its title names the credit. Error copy is ScrapeCreators-specific and sits **above** the kie rules in `friendlyError.ts` (both services use 401/402, and the generic kie rule would tell a member to replace the wrong key). Note the vendor answers an **unrecognised key with 402 "out of credits", not 401** — verified live — so that one message has to name both causes. Phase 1 deliberately ships **no swipe-file bank** (that needs a migration + `orphanCleanup` entry; decide it after using the app) and **no Instagram** (their reels search is Google-indexed and self-describes as best-effort; the card shape is identical, so it's a small add later).
