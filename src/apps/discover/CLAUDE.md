# Outliers — `discover/`

Tools section of UGC OS. This file loads when Claude works with files under `src/apps/discover/`; the app-wide rules stay in the root [CLAUDE.md](../../../CLAUDE.md).

## Job

Search TikTok and the Meta Ad Library for ads worth stealing, then hand one straight to Ad Analyzer or Scripts. **App id is `discover`** (stable — keys the persisted platform/filters/sort); the display name is free to change. Runs on the member's own **ScrapeCreators** key (`settingsStore.scrapeCreatorsKey`, browser-local, never synced — same doctrine as the kie key, and it's optional, so it never gates the Settings alert dot). `utils/scrapecreators.ts` is the only file that knows endpoint paths; it calls the vendor **directly from the browser** — verified `access-control-allow-origin: *` plus an `x-api-key` allowance — so there is no proxy and no new env var for search. Every response carries `credits_remaining`, which is both the live balance chip and how a key is validated (`scTestConnection` spends 1 credit on a trivial search; there is no free balance endpoint). Costs are 1 credit per search page of 30, 1 per transcript. Opening the app without a key pops `ConnectScrapeCreators` — the same verify-before-save transaction as `ApiKeyGuide` (nothing is stored that can't search) but deliberately shorter: kie's version needs a two-step rail because you must go and generate a key first, whereas signing up here hands you one, so a rail would be scaffolding around a single paste. It's seeded from the store at mount and never re-armed, so a dismissal sticks; the empty state behind it keeps a **Connect key** button that reopens it, so closing the popup is never a dead end. It shows ScrapeCreators' raw message on failure (infra surface) plus one decoder line on a 402, since their text tells a member with a mistyped key to go and buy credits. **The vendor's own docs contradict their own example on the TikTok search shape** — the endpoint description says each `search_item_list` row wraps the video in `aweme_info`, the example response shows those fields at the row's top level. Reading only the top level meant every row failed its id check and **every TikTok search returned zero results**; `searchTikTokKeyword` now unwraps `row.aweme_info ?? row` so both shapes work. `warnIfAllDropped` console-warns whenever a page arrives full and normalises to nothing, because that combination means a field name moved and is otherwise indistinguishable from "no results" in the UI. **Each platform keeps its own search** (`PlatformSearch` — query + results + cursor + searched, one per tab, `patchSearch` always writing the tab it was HANDED so a page landing after a flip fills its own grid). Flipping the toggle used to clear the results, which threw away a paid page of 30 for the sake of a glance; the query rides along per-tab too, so the box always says what produced the grid under it. **Both tabs persist across a refresh, behind a freshness window** (August 2026). This was session-only for a real reason — every media url on a card is a signed CDN link that expires, so a stale restore is a wall of dead tiles — but "its real lifetime is the app staying mounted" quietly meant a reload binned a grid of 30 winners the member had **paid a credit for**, which is the one loss in this app that costs money. So the state is `usePersistedState` with both hooks doing work: `restoreSearches` (sanitize) drops a tab whose `fetchedAt` is past **`RESULTS_TTL_MS` (6h)** rather than rendering it broken, and `pruneSearches` (prune) caps what reaches the quota. Three rules hold it together. **`fetchedAt` is stamped by the FIRST page only** — it dates the oldest signed url in the grid, which is the one that expires first, so refreshing it on every "Load more" would keep page one alive on the strength of page three's links; a fresh search clears it alongside the rows, so a reload taken mid-search restores as "Awaiting search" rather than "No results". **The query outlives the results**: an expired tab keeps what you typed, so re-running it is one click rather than trying to remember the phrase. And **the persisted cap is 60 rows a tab, dropping whole trailing pages and the cursor with them** — localStorage is a shared, small quota — the settings blob, every app's drafts and `cloudSync`'s outbox all live there, and the outbox is the replay guarantee behind every unsynced row — so an uncapped 30-a-page grid of research would be spending it on the one thing here that's re-fetchable; the truncation takes the cursor because a "Load more" continuing past a page we didn't keep would open a hole in the middle of the grid that nothing on screen explains. The TTL is deliberately short — expiring early costs the member the empty state they used to get on **every** refresh anyway, expiring late costs them a broken-looking grid that reads as the app failing. **Transcripts persist on the same slot** (`keepSettledTranscripts`, its own key, capped at 40 and settled phases only — a restored `loading` is a spinner no fetch will ever finish): they never rot, and restoring the cards *without* the words already bought for them would hand back a card whose transcript costs a second credit, a way to re-pay that only exists BECAUSE the card now survives. The header's **+** (the same idiom every panel header carries) resets **the current tab only**, since protecting the other tab's search is the whole point of the split, and it hides itself when there's nothing to clear. **The outlier score is ours, not the vendor's**: `views ÷ the creator's own follower count` (`services/scoring.ts`), banded 2x/5x/10x, and `author.follower_count` rides inline on the search response so a fully scored grid is one call. Alongside it `engagementRate` = `(likes + comments + shares + saves) ÷ views` — reverse-engineered from the reference tool and checked against four of its cards; **saves are in the numerator** and shouldn't be "simplified" out, since on a UGC ad a save is the strongest buying signal of the four. The two answer different questions (how hard a video worked the people who saw it, versus how far it travelled past its own audience) so they never merge into one figure. Two floors keep the top of the grid honest — a **min-views** floor (absolute noise: 800 views from 40 followers is 20x and meaningless) and `MIN_FOLLOWERS_FOR_SCORE` (tiny denominators). Scoring + the min-views filter are a **derived render step** (`applyMinViews`), never baked in at fetch time, so moving the filter re-ranks what's on screen instead of silently needing another paid search. **The min-views floor has to announce itself**, because it defaults to 10K and removes cards CLIENT-SIDE: a niche keyword pays for a page of 30 and renders four, which reads as a broken search rather than as a filter working. `hiddenByMinViews` (`results.length - visible.length`) prints a dim "N more hidden under 10K views" line above the grid, and when it eats the whole page the empty state says so instead of telling the member to try a broader keyword — which would send them to spend another credit on the same outcome. Note a full page is a **maximum, not a promise**: the vendor returns fewer rows for a niche query or a narrow `date_posted`, `normaliseTikTok` drops any row with no `aweme_id` or no reachable permalink (the search feed interleaves non-video modules), and `mergeResults` dedupes across pages. **Meta gets no outlier score and must never be given a fake one**: `spend` and `reach_estimate` come back `null` for every commercial ad (verified), so those cards carry `ad.daysRunning` off `total_active_time` and the sort control is honestly relabelled **"Longest running"** on that tab — `SORT_OPTIONS` is keyed by platform for exactly this reason, and `'views'` isn't offered there at all. `DiscoverResult` holds `stats`/`outlier` and `ad` as separate optional blocks so the card renders what it was given and can't invent the other. **Meta's keyword matching is loose by design** — it scores relevance its own way and matches advertiser names, so a product search returns unrelated ads; that's the platform, not a parsing bug, and the only lever the API exposes is the **Match: Exact phrase** filter (`search_type=keyword_exact_phrase`). Meta files an ad's creative in **one of several places** depending on its format (`videos` / `images` / `extra_*` / `cards` for carousels, plus `root_reshared_post` when the ad is a boosted organic post) and a plain video ad populates only `videos` — which in the live payload carries **no `video_preview_image_url` at all**. Reading just `videos[0]`/`images[0]` therefore left carousels and poster-less video ads with no cover, rendering them as **empty black tiles**; the normaliser now walks the lot. Two rules hold it together, and both are why the tiles came back blank a second time. **Meta does not omit a creative field it has nothing for — it sends the key with an explicit `null`**, so `snap.videos?.[0] ?? snap.cards?.[0]` picks the first SLOT that exists rather than the first that holds anything: a DCO/template ad carrying `videos: [{ video_hd_url: null, … }]` locked onto that empty entry and the real creative in `cards[]` was never reached. `pickCreativeUrl` selects on the **value** (and only an absolute `http(s)` url — a non-url handle in `videoUrl` renders play controls over a frame that never loads), across **every** slot rather than index `[0]` of each, since a carousel whose first card is text-only still has its video two cards along. And **the `watermarked_video_*` / `watermarked_resized_image_url` fields are real sources, tried last**: Meta blanks the clean urls on plenty of ads (restricted categories especially) and publishes only those, so refusing to read them meant a blank tile for an ad you can watch — a watermarked render is a worse source for the Ad Analyzer's vision read, which is the only reason it isn't preferred. A clip with no cover anywhere becomes its own thumbnail via a `#t=0.1` src fragment, which makes the browser decode and paint that frame instead of showing an empty `<video>`. When an ad genuinely carries nothing fetchable **it never reaches the grid**: `dropUnpreviewable` takes out every card with no video AND no cover, on both tabs. There is no research to do on one — Analyze and Download are dead, the tile is a placeholder, and the only route left is the Ad Library, which answers with a sign-in wall — so it is a hole in a page the member paid a credit for either way, and a real ad should have the tile. The rule is `isPreviewable`, exported because **`restoreSearches` filters through it too**: a grid persisted before the rule existed still holds the blanks it was saved with, and it stays fresh for six hours. The drop carries the shape-change alarm that `warnIfAllDropped` carries for the id checks — a page where at least half the cards go console-warns, since silently binning most of a page is exactly what a moved field name looks like from the outside and is otherwise indistinguishable from a quiet keyword. Dropping happens **after** normalisation and never touches the cursor, which is computed from the raw page, so Load more still walks the vendor's paging. `ResultCard`'s no-media branch stays as a backstop (a cover that fails to LOAD on a video-less ad lands there at render time, past any filter) and is deliberately **glyph-only** — pointing that member at "the original" is the dead end the drop exists to remove. The **Media** filter (`media_type`) defaults to **VIDEO**, since a static image has no hook, no delivery and no transcript to remix. That default is applied through a `sanitize` that spreads the stored filters over `DEFAULT_FILTERS` on every hydrate, not just when the slot is empty: `usePersistedState` returns a stored blob **verbatim**, so a filter object saved before a field existed carries that field as `undefined` for good — which is how a member ends up searching with no media filter at all rather than the default. Any field added to `DiscoverFilters` from here on picks up its default on the next load. The line under the author name is **per-platform in shape as well as wording**: TikTok's follower count is dim text (it's the outlier score's denominator, context rather than a figure in its own right), Meta's page likes take a **pill**, because it's the only audience number the Ad Library publishes and as dim text beside a dim glyph it was the easiest thing on the card to miss. Both reserve their row height even when the count is absent, so captions still start level across the grid. The days-running pill is **emerald, not the house monochrome**: on the Meta tab it is the only performance signal there is, so it has to read as a score rather than another grey timestamp. The card is a **4:5 frame with the vertical video letterboxed (`object-contain`), never cropped to fill**: a true 9:16 tile is nearly twice its own width in height so barely a row fits on screen, and `object-cover` would crop exactly the top and bottom where UGC puts its hook text — cropping the hook off an ad-research tool defeats the tool. Under it sits the full engagement row (views · likes · comments · shares · saves, glyph-led and always in that order) with ER on the media and the outlier badge opposite it. **The play/mute pair and the runtime pill are always visible, never hover-gated** — they are how you tell a video card from a still one while scanning, which is most of what the grid is for, and a signal you have to hover to see isn't one. That has two consequences worth knowing. ER moved to a bottom-left COLUMN stacked above the controls: both were at `bottom-2 left-2` and only got away with it because the controls appeared on hover, so an always-on pair would have overlapped it permanently. And every video card now carries `preload="metadata"` (it was `metadata` only for the poster-less ones), because **only TikTok publishes a runtime** — Meta's payload has none at all, so the card reads `duration` off the loaded file via `onLoadedMetadata` and prefers the platform's figure when there is one. That costs a small range request per card and buys a runtime on the whole Meta tab; guard the probe, since a live/unseekable stream reports `Infinity`. The card's hover stack is deliberately **not** hidden while its clip plays (the one place that breaks the `TileActionStack hidden={watching}` idiom): on a generated tile the picture is the point, but these are research cards and Save / Analyze / Remix are decisions made WHILE watching the ad — stepping aside meant pausing the video to reach the button that saves it. **TikTok's image CDN rejects plenty of its own cover URLs from a browser**, so a `coverUrl` is never trusted: the `<img>` carries an `onError` that drops it and falls the card over to painting a video frame, which also removes the browser's broken-image placeholder box — that placeholder was the stray outline around every TikTok card. The caption block is pinned to **exactly two lines (`h-[3.25em]`, being 2 × `leading-relaxed`)**, not a min-height: the stats row is meant to be read ACROSS the grid, and a min-height short of two full lines still let a two-line caption push its own card 7px below its neighbours. **Download** (leading the hover stack per the canonical order, and a glyph-only button closing the detail modal's second footer row) saves the ad's video to disk through the same `downloadResultVideo` fetch — never an anchor with a `download` attribute, which browsers ignore cross-origin, so the click would open the video in a tab instead of saving it. **`ResultDetailModal` is shared with the swipe file** (`finder/SwipeDetail.tsx`, via `services/swipe.ts`'s `swipeToResult`), which is why three of its props are optional: `onSave` omitted drops the Save button (a filed row has nothing left to save), and `onMediaError` + `mediaOverlay` are how the Bank detects an expired `mediaUrl` and offers **Restore video — 1 credit**. `refreshResultMedia` (`services/search.ts`) is the re-resolver behind it — `/v2/tiktok/video` or `/v1/facebook/adLibrary/ad`, 1 credit, both returning the same shapes the search normalisers already read (Meta's detail endpoint hands back an identical `snapshot`, so `pickCreativeUrl` is reused unchanged; TikTok's takes `video_id` per its doc page and `url` per its own search snippet, so **both are sent** — the same self-contradicting-docs hazard that once made every TikTok search return nothing). It returns **media only, never stats**: a swipe records what a winner looked like when you found it. `saveVideoFileToDisk` is `saveResultVideoToDisk` split so a caller holding an already-fetched File (the swipe file, after a retry) doesn't download the video twice just to name it. Two handoffs: **Analyze** downloads the video (`downloadResultVideo` tries the CDN direct, then falls back to `api/fetch-media` — fbcdn sends CORS headers, TikTok's CDN sends none and 403s without a Referer) and sends a live `File` as `DiscoverVideoPayload` → Ad Analyzer's existing `handleAnalyze`; **Remix Transcript** sends the words actually SPOKEN, on **both** platforms, for 1 credit and **no kie call at all** — TikTok via its captions endpoint, Meta via `/v1/facebook/adLibrary/ad/transcript` — stripped of WEBVTT scaffolding and handed to Scripts' existing `winningTranscript` seam (zero changes on the Scripts side). Meta used to short-circuit to the ad's body copy, which is the written caption, so "remix the transcript" was quietly sending somebody's ad copy instead of the script their creator performed; the detail modal now labels **Caption** and **Transcript** as separate blocks so it's visible which one the button sends. **The transcript is TikTok-only in practice**: Meta's ad-transcript endpoint reads Facebook's *exposed captions*, which Ad Library video ads don't carry, so it came back empty every time — the modal drops the Transcript block and the Remix button on that tab and routes the words through **Analyze Ad**, which reads the video itself. `fetchResultTranscript` keeps its Meta branch so re-enabling it is a one-line change in `openCard` if that ever improves. **Opening a card costs nothing.** It used to fetch the transcript on open so the words were on screen by the time you'd read the caption — which billed a ScrapeCreators credit for the act of *looking* at a card, the one thing here anyone does idly, thirty cards to a page. The modal's Transcript block now starts `idle` and offers **Get transcript — 1 credit**; `TranscriptState` gained that phase and the modal's fallback state is `{ phase: 'idle' }`, not `{ phase: 'loading' }`. `transcriptCache` still keys by card, so pulling the words and then remixing them stays **one credit, not two**, and a card paid for once stays paid for across closing the modal. Both handoff buttons carry an `ArrowUpRight` and name their destination's job (**Analyze Ad**, **Remix Transcript**) because both leave the app; **Remix stays disabled until Get transcript has returned words** — that gate is what keeps the credit on a button the member pressed, as well as stopping a bounce to Scripts with an empty box. Fetching is `onFetchTranscript` and is deliberately separate from `onRemix`: the 10-credit `use_ai_as_fallback` retry used to call `onRemix(result, true)`, so a button labelled "Transcribe with AI" quietly left the app; both it and the error-state "Try again" now fetch in place. The card grid's hover-stack Remix is the one shortcut that still fetches on click — that's a deliberate press on a labelled button rather than an idle open, so it stays, and its title names the credit. Error copy is ScrapeCreators-specific and sits **above** the kie rules in `friendlyError.ts` (both services use 401/402, and the generic kie rule would tell a member to replace the wrong key). Note the vendor answers an **unrecognised key with 402 "out of credits", not 401** — verified live — so that one message has to name both causes. The **swipe file shipped** since (bank key `swipes`, migration 0019, filed by the Bank's Swipe File tab and seeded by `utils/mockData.ts`) — see the `swipes` bullet in the root CLAUDE.md for what a row holds and why it stores no video. Still **no Instagram SEARCH** (their reels search is Google-indexed and self-describes as best-effort; the card shape is identical, so it's a small add later) — but Instagram is no longer absent from the app: the Outlier Vault below is 872 Instagram reels, and `fetchInstagramPost` (`/v1/instagram/post`, 1 credit) is wired for their media.


## The Outlier Vault — `vault/`

**The tab a member lands on, and the only part of Outliers that costs nothing.** Outliers' original shape asked a member to think of a phrase, spend a credit, and hope — before the app could help at all. The vault removes that first step: 872 hand-harvested Instagram reels that already went big, each carrying its **hook line**, its **reusable template**, the whole **transcript**, its category, its structural hook patterns and its engagement as harvested. It is the third option in the header's one `SegmentedToggle` (**Outlier Vault · TikTok · Meta Ads**), and `DiscoverView` — not `DiscoverPlatform` — is what that toggle is keyed on: the vault is a fixed library, never a platform, so keeping it out of the platform union is what stops every `Record<DiscoverPlatform, …>` in the app growing a key with no search, no cursor and no credits behind it. It takes its **own** persisted slot (`:view`, not the old `:platform`), so every member — new or returning — lands here once.

**It ships as static files, not as rows.** `scripts/build-vault.py` reads the corpus out of Massimo's `1000 Outliers` folder and writes `public/vault/library.json` (~1.7MB, ~550KB over the wire) plus one 400px webp cover per row. Re-run it after the corpus grows; nothing else needs touching, because the **facets are derived from the rows** (`facetCounts`) rather than hardcoded, so a bigger corpus grows the folder row and the Hook filter on its own. There is deliberately no Postgres table and no R2 prefix: the library is identical for every member and read-only, so a synced copy would be 872 rows of the same thing per account. `loadVault` caches one fetch per page load and **nulls the cache on failure** — a rejected promise held there would fail the retry button forever.

**Watching is free; only a FILE costs a credit.** No video url is stored, because every Instagram media link is signed and dies within hours — a link baked into the build would be dead before anyone clicked it. But the fix for that is not to charge for playback: the detail modal embeds **Instagram's own player** (`embedUrl` → `/{p|reel}/{code}/embed`, no login, no key), so a member can watch all 872 without spending anything. This replaced a "Load video — 1 credit" button over the cover, which billed for the act of LOOKING — the one thing you do idly with 872 hooks in front of you, and the surest way to teach someone not to browse. The credit is now spent only on **Analyze Ad** and **Download**, the two that need an actual file, and the card carries a `pointer-events-none` play glyph because every row is now watchable (the card is already the button; a second control doing the same thing is not one).

Two limits on the embed are **structural, because the frame is cross-origin**, and neither has a workaround: we cannot autoplay it (the member presses play inside Instagram's player — one click we can't remove), and we cannot read the media url out of it, which is precisely why Analyze still buys its own copy. Don't try to harvest it. Instagram's chrome rides along — a header with **View profile** and a footer with the live like count — which duplicates a little of our reading column and puts a blue CTA next to Analyze Ad. It is technically easy to crop with an oversized iframe in an `overflow-hidden` box and that is **deliberately not done**: it would strip a creator's attribution and the link back to their profile off their own video, in a tool whose whole job is redistributing other people's work. A taken-down post renders Instagram's own "unavailable" state, which explains itself better than anything we'd write.

Download and Analyze Ad go through `ensureVideo`, which resolves the url via `/v1/instagram/post` and **caches it for the session only** (persisting it would restore a library of dead players — the failure the search tab's 6h TTL exists to avoid, with none of the upside, since the row itself is already permanent). The cache lives on `VaultBrowser`, not per card, so loading a video and then analysing it is **one** credit, and paging a card out of the DOM doesn't lose what it cost. **Remix Transcript is free** and must stay that way: the search tab bills for those words because it has to buy them from the platform, and every row here was transcribed when the library was built.

**Browsing needs no key at all**, which is the whole point — so `ConnectScrapeCreators` is armed `!apiKey && !isVault` and re-arms only when a member flips to a paid tab. Putting a credentials dialog in front of the free tab is exactly the friction the vault exists to remove. Everything that genuinely needs the key says so on its own button rather than greying silently (`videoBlocked`).

**The amber badge is a different multiple from the search tab's and has to keep saying so.** Outliers scores a video against its own creator's following; a vault row carries `engagement ÷ the library's median engagement`. Both are honest, neither is the other, so the badge wears `MULTIPLE_TITLE` and the modal spells it out as "16x the library median". It reuses `bandFor`'s 2x/5x/10x floor, so a row under 2x shows no badge — 649 of the 872 are under it, which is what makes the top of the grid worth reading.

**Folders are the landing screen, and opening one is a click** (August 2026, `vault/VaultFolders.tsx`). The vault arrives as a wall of folder tiles — **All Outlier Videos 872 · Educational 432 · Storytelling 309 · Myth busting 49 · Authority 35 · Comparison 28 · Day in the life 13**, plus **Starred** once something is in it — each a three-up mosaic of that folder's biggest outliers over a gold folder glyph, its count as a badge on the picture. Clicking one opens the grid inside it; the header's **Folders** button comes back out. This **reverses** the shape that shipped first (a `SegmentedToggle` with All selected on arrival, so hooks were on screen immediately) at Massimo's request, and the reasoning it reversed is worth keeping: a folder screen with no hooks behind it puts the vault's one job — something worth stealing, on screen, immediately — behind a click. Two things pay that back and both are load-bearing. **All Outlier Videos leads the screen**, so the old landing is the first click available. And **typing in the header's field skips the screen entirely** — `browsing` is `openFolder !== '' || query.trim() !== ''`, so a query opens the grid across the whole library, on the reasoning that typing is a request to see hooks, not folders. Folders stay **derived from the rows** (`byCategory`, ordered by size like `facetCounts`), so a corpus rebuild grows the screen on its own. **All Outlier Videos takes one cover from each of the three biggest folders**, not the library's own top three — those all live in Educational, so the tile came out a pixel copy of the Educational one beside it. **The folder counts sum to 866, not 872** — six rows carry no category at all, so they live in All Outlier Videos and belong to no folder. That is the harvest being honest, not an off-by-six; don't "fix" it with an Other folder that says nothing about what's inside it. **On a phone the tile is two-up, and that is what put the count on the picture**: a 375px screen leaves the footer ~126px, and a name sharing that with a number and a chevron got ~46px — every folder read "Stor…". The count moved onto the mosaic as the same badge a card wears for its category, the chevron is `hidden sm:block` (a one-word name has nowhere to wrap, and there is no hover state on a touch screen for it to answer), and the name is `line-clamp-2` over a `min-h-[44px]` footer so "Day in the life" wraps without leaving the row beside it ragged. The artifact this corpus came from merges the six categories into three tabs (Educational / Storytelling / *Myth & More*) to keep its tab bar short; the app has room for the real six and does not inherit that merge.

**Accents: the vault wears Outliers' gold, and the two handoff buttons wear their destination's.** The toggle's active segment tints to **`#D9A404`** (its `outliers` accent) when open — a literal, because **the app's `gold-*` Tailwind family is `#4C1D95`, which is purple**: it belongs to the Products bank and is simply misnamed, so `bg-gold-500` here paints the folders the wrong colour entirely. Ad Analyzer carries its `#FF5257` as a literal for the same want-of-a-family reason. The active label takes a `light:` darker gold (`#8A6A00`) because #D9A404 on a white surface is 2.32:1 — fine as a fill, unreadable as 13px text; the darker one is 5.07:1. The modal's **Analyze Ad** is `#FF5257` and **Remix Transcript** is `bg-scripts-500`, each copying its own app's primary button exactly (solid fill, `border-white/15`, inset sheen, `btn-soft-shadow`) — both buttons LEAVE the app, so each wears the colour of where it goes, the same idea as the card's hover stack borrowing the destination's dock glyph. Scripts' is a token and flips with the theme; the two literals can't, which is correct, since neither source app's does either. The same gold marks a **folder**: the tile's glyph disc and the `FolderOpen` beside the open folder's name. Sort, Hook and Starred keep their own 36px chrome — they filter what's in a folder, they don't choose one.

**One navigation out of a folder, not two.** The row above the grid is **Folders** (a back button) + the open folder's name, then Sort / Hook / Starred on the right — the folder chips are gone with the toggle, because a row of them beside a Folders button is two controls doing one job, which is the same argument that took the category dropdown out when the chips went in. The cost is real and accepted: switching folders is two clicks now instead of one, which is why the back button leads the row. The name beside it is not decoration — it is the only thing on screen saying which slice of 872 rows is under you. **Backing out clears `pattern` and `starredOnly` and the query, keeping `sort`**: the folder screen counts the whole library, so a filter still armed behind it would be state with nothing on screen describing it, and re-entering All Outlier Videos would then show a fraction of the 872 the tile had just promised. Sort survives because it changes what's at the top of a folder, not what's in it. The panel still `flex-wrap`s with `justify-between`, so the filters tuck onto their own line when they don't fit beside the back row, with one hairline under the pair either way. The filter group carries `max-w-full` as well as `shrink-0` — `shrink-0` alone pins it at max-content, so on a 375px phone the Starred pill and the counter sat off the right edge of a row that doesn't scroll.

**Authority and Myth busting are separate folders**, and a merge was tried and reverted back when they were segments in a toggle: folding one into the other (`Myth busting & Authority`, 84) was meant to buy row width and bought **1px**, because the combined label cost what the dropped segment saved. Tiles have no width problem at all, so there is even less reason now — but if a pairing is ever wanted, do it as a fold map keyed category→folder rather than a hardcoded folder list, so the folders stay derived from the rows and a corpus rebuild still grows new ones on its own.

**Every facet count is scoped to the OTHER active filters, never to the whole library.** The hook menu's counts are taken over the rows matching the query + folder + starred. This is the difference between a number that describes the corpus and one that predicts what clicking it gives you, and only the second is any use next to a control. The library-wide version shipped first and was wrong both ways: inside **Authority** (35 rows) the hook menu still advertised "Plain statement 286" when 10 were in reach, and **13 of its 27 options had nothing there at all**, so picking one produced an empty grid with a number on screen insisting there were hundreds. A hook with no rows in the open folder is now simply absent from the menu — except the one already PICKED, which is kept with its real `0`, because dropping it would orphan the trigger and that 0 is the on-screen explanation for the empty grid. The **folder tiles** are the deliberate exception and count the whole library, which is honest there because backing out to them clears everything that could narrow one. `allCategories` (library-wide) is still what validates the open folder, so a category dropped by a corpus rebuild coerces back to the folder screen rather than stranding a member in a folder that no longer exists.

**The card's outlier multiple rides in the STATS ROW, not on the frame.** It stacked above the category chip in the corner and was two badges deep over the reel's own on-screen hook text — the one thing the picture is there to show. In the footer it leads the row of numbers it belongs to (multiple · likes · comments · date), read across the grid as a column. Still solid amber, so it reads as a score rather than as a third statistic; the category chip keeps the corner to itself.

**The card leads with the HOOK, not the picture.** Every other grid in the app puts the image first because the image is the output; here the output is the sentence. Three fixed lines (`h-[4.875em]`), so the likes/comments row underneath sits at the same height across a row and can be read as a column — same reasoning as `ResultCard`'s two-line caption clamp. The date is a **month and year**, not "8mo ago": the search grid counts backwards because a two-week-old winner is a live trend, and every row here is months old by construction, so a relative count would print a wall of "1y ago" that says nothing.

**60 cards reach the DOM at a time**, with a free "Show more — N left" where the search tab says "Load more — 1 credit". `content-visibility` is the usual lever and is wrong here: it carries size containment, so `.offscreen-idle` may only go on a box sized by its own geometry, and these cards are sized by their text.

**Stars are browser-local** (`usePersistedState`, own key) and deliberately not the `swipes` bank: they mark rows in a read-only library that no bank picker ever reads, which is why `TileStarButton` grew a `title` override — its default tooltip promises a picker sort that would be a lie here. The header's **+** clears the query and the filters and **never the stars**, same rule as every other panel reset in the app.

**`VaultBrowser` carries no hand-written `useCallback`, on purpose.** It owns an 872-row grid whose cards are `memo`'d, so it needs stable handler identities — and the React Compiler produces them, but only if it can compile the component at all. A manual `useCallback` whose declared deps don't match what the compiler infers (a `useState` setter, typically) makes it skip the **whole** component, taking the memo on every card with it. Hand-rolling the memoization here was the thing preventing the memoization; `npx eslint .` is what reports it. Same reason `settle` is a module-scope helper: a `try` inside the component body is the other way to make the compiler bail, and the paging reset adjusts state **during render** against a signature rather than in an effect.
