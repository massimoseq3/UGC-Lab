# Playground — `playground/`

Create section of UGC OS — the dock tile sits between B-Roll and Edit. This file loads when Claude works with files under `src/apps/playground/`; the app-wide rules stay in the root [CLAUDE.md](../../../CLAUDE.md).

## Job

Free-form Image / Video / Music — tabs in that order, landing on **Image**, because the loop it's used for is "make a still, then animate it". That loop is one click: an image tile's hover stack (and the preview modal) carries an **Animate** action that switches to Video with the still inlined as the start frame and the prompt that made it seeded in the bar (`handleAnimateImage`), going through the same `promptStash` as a manual tab switch so the Image tab keeps its own draft. Each mode remembers its own model under `playground:<task>[:<mode>]` — Image/Music via `ModelPicker`'s own persistence, Video written by the panel itself since `ModelSidePanel` leaves persistence to its caller; without that write every Image → Video flip reset the pick to the registry default. Prompt bar, mode tabs, model picker, model-aware ref slots + drag-drop (images everywhere; Seedance 2 adds audio/video reference clips; Gemini Omni adds characters / designed voices / a trimmed source clip under a 7-slot quota). `@`-mentions reference Products / Influencers / B-Rolls and auto-attach the asset. Uploaded audio/video refs are memory-only (pruned from the persisted draft — too big for localStorage).

**Image and Video carry a batch count** (`BatchCountStepper`, capped at 4, sharing the **model row** at `size='xl'` + `stacked`): Playground is where a prompt gets TRIED, so a run of one is the wrong unit most of the time. `handleSubmit` snapshots the prompt, refs, inferred mode and resolved model ONCE and then calls an inner `runOne` N times, so every member of the run is identical by construction and each is its own task / tile / history row. **Music is excluded** — Suno already returns a pair of tracks for a single call, so a count there would bill twice for something the API hands over anyway. The count rides in the persisted draft (`PromptPanelState.batchCount`, absent on older drafts, clamped on hydrate). **It sits beside the model, not in the constraint row** (August 2026, Massimo's call): a video model that declares every dimension it has — Seedance's resolution, aspect, duration and audio — already fills that line at 375px, so a fifth pill wrapped it onto a second row and the footer grew 56px on exactly the models with the most to fit. It reads better there anyway, since the count is the one control in that row that isn't a property of the OUTPUT: the four chips describe the clip, this describes the run, and so does the model beside it. `stacked` because at the 58px picker-row height a number and its word side by side float mid-pill, and the word ("clips" / "images") is what keeps a bare stepper on a model row from reading as a nudge on the model itself. Its departure is also why the constraint row is now gated on **`hasOutputSettings`** rather than on `mode !== 'music'` — the stepper used to hold that line open unconditionally, so a model declaring no constraints would otherwise render it as an empty 8px margin over Generate.

**The video mode is INFERRED from the filled slots, then reconciled with the picked model in both directions — a run is only refused when the model takes no images at all.** `inferVideoMode` reads the slots (start+end → frames, start → image, refs → reference) and knows nothing about the model; the reconciliation right after it is what makes the two agree. Both directions are real: an image-to-video-only model (Kling 3.0 Turbo) can't take a reference image but can animate it as a start frame, and a **frame-less** model (Seedance 2.5, Gemini Omni 1.0 — though not its Flash 1.1 sibling, which does have frame fields) has no `first_frame_url`/`last_frame_url` at all and folds every attached image into its reference array — which is exactly what those models' `buildVideoInput` branches already do with a stray frame. Only the first direction existed, so attaching a start frame **and** a reference image inferred `image-to-video`, Seedance 2.5 doesn't declare it, and the run was refused with a toast naming a limitation the model doesn't have — reported as "it said Seedance 2.5 doesn't accept reference images", on a generation that would have run fine. When the mode lands on reference-to-video the frame slots are sent AS references, in shot order ahead of the explicit ones, or the downgrade would trade a false error for a silent drop. **Check `buildVideoInput` before refusing a run over an undeclared mode** — the declared modes say what the model calls its inputs, not whether the pictures reach it.

**A frame and a reference attached together resolve per model, through `mixedImageInputPolicy`, and every outcome is toasted.** There is no universal answer here — the providers designed three different things, and a surface that guesses either drops an input silently or sends a 400:

- **`merged`** (Gemini Omni 1.0, Gemini Omni Flash 1.1, Grok) — both inputs reach the model, so everything is sent and nothing is said, because nothing was traded. 1.0 and Grok get there with one flat `image_urls` array that has no frame/reference distinction at all; Flash 1.1 keeps real `first_frame_url` / `last_frame_url` fields BESIDE `image_urls` and simply accepts the pair. The policy answers "what happens when both arrive", not "how many fields does the body have" — which is why the two shapes share one value.
- **`reference`** (MiniMax H3, Kling 3.0 Omni, Seedance 2.5) — a reference RE-ROUTES the request and the frame rides along as a reference image. The mode is forced to reference-to-video so it agrees with the body the builder was going to produce anyway (`minimaxH3Route` / `klingOmniRoute` pick 'reference' the moment a reference is present). Both inputs reach the model, but the frame stops being frame one, which is a real change to what the member gets and is toasted as such.
- **`exclusive`** (the Seedance 2.0 family, the Wan 3.0 family, and the undeclared default) — the provider forbids the pair outright: kie documents first/last-frame and multimodal reference-to-video as "three mutually exclusive scenarios [that] cannot be used simultaneously". The frames win — the frame slot is a deliberate act, not where pictures land by default — and the references are dropped and named, with the way to get them honoured instead. **The drop itself happens in the model's own `buildVideoInput` branch, not here and not in the hosting step**, which is the half that was missing until August 2026: the toast said "rendering from the frames" while the Seedance 2.0 body still carried `reference_image_urls` beside `first_frame_url`, putting a pair the provider forbids on a run the member had committed to. `startPlaygroundVideoTask` hosts references unconditionally on purpose (merged-input models need them), so the builder is the only place left that knows the policy AND sees both groups.
- **`frames-only`** (Seedance 1.5 Pro, Kling 3.0, Wan 2.7) — no reference input at all. Only reachable by attaching references under one model and switching to another, since Playground hides the ref strip for these.

Two rules hold it together. **The policy lives on the registry entry, never in this file** — `mixedImageInputs` on `ModelEntry`, resolved through `mixedImageInputPolicy`, so adding a model is a registry edit. **Undeclared falls to `exclusive`, not `merged`**, because the costs aren't symmetrical: a wrong `exclusive` drops an input and says so, a wrong `merged` sends a combination the provider rejects — a 400 on a run already paid for. And `startPlaygroundVideoTask` hosts whatever it is handed (references are hosted whenever present, like the audio/video strips): it is transport, the policy call is the caller's, and the `else if` that made it a second unwitting gate is what dropped the references one layer below the code that decided to send them.

**Presets open from a `Presets` pill in the prompt box's TOOLBAR** (September 2026), leading the row ahead of Enhance, with the long "UGC Prompt Presets & Visual Styles" name carried by the slide-over it opens. It was a 48px labelled header row INSIDE the box, on top of the field: the box spent 48px above and 38px below on its own chrome before a single line of prompt, in the one panel whose entire job is that field. Everything in the toolbar acts on the prompt and appending a preset is exactly that, so the pill belongs there and the row costs nothing. The slide-over lists **visual styles first**, then the presets — both do exactly one thing, append a block of direction to the prompt, and a look is the broader decision of the two (it applies to whatever you were going to make; a preset is one specific shot). The styles are `CONTINUOUS_STYLES` plus the member's `styles` bank, drawn with the same `StyleTile` and the same preview art as the B-Roll and Characters pickers (`components/styleArt.ts` holds the artwork and the per-app accents, split out of `StyleModal.tsx` so a host that lists styles without opening the modal doesn't drag the modal in). **Nothing renders as "active":** Playground keeps no style state of its own — `applyStyle` appends the brief and the prompt is then the member's to edit like anything else they typed, which is also why creating a style still lives in B-Roll's picker, the one that owns the reference-frame analysis. Image mode appends `styleBriefForStill` (every brief ends on camera movement and cutting cadence a single frame can't express), falling back to the plain brief for UGC Realism, where the still-scoped helper returns null.

**A `Voice Profile` box sits directly under the prompt box, and what it holds is appended to the prompt at generate time** (September 2026, `components/VoiceCard.tsx` + `composePrompt.ts`). It is the one part of a UGC video prompt that must NOT change between generations — the same person has to speak in every clip of an ad — so it was being re-pasted two lines under every rewrite and re-selected around every time the prompt changed. A field of its own means the prompt box holds only the shot, and the voice survives Clear, Enhance, Undo and a whole new idea. **Nothing is wrapped around it**: what is sent is the prompt, a blank line, then the text verbatim, because "as if you typed it on the end" is the contract the box is offered under and a label we invented would be a word in the prompt the member never wrote. It is composed onto `promptText` in `handleSubmit` rather than travelling as its own parameter, so the in-flight tile, the history row and Copy prompt all show the string the model was actually given; the empty-prompt backstop still reads `state.prompt`, since a voice with nothing to say in it isn't a generation. **Video only, and never Motion Control** — a voice says nothing about a still or a music track, and that model takes no audio at all. `composePlaygroundPrompt` lives in its own module because a component file that also exports a plain function loses Fast Refresh. **This is what the `videoPrompt` handoff is for, and why it now stashes**: Scripts puts a Send to Playground button on every shot, so the payload arrives over and over, and it must swap the prompt and NOTHING else — the Voice box, the references and the model all survive by construction (`setState` spreads the draft). The mode flip stashes the outgoing tab like `handleModeChange` does and restores the Video tab's own refs; without the stash an image draft was silently overwritten by the incoming prompt, and without the restore you arrived on a video prompt carrying the Image tab's attachments. The stash invariant still holds afterwards — it keeps the NON-active modes, and the live video prompt is written back into it on the way out — so an Image → Video round trip brings the sent shot back, not the draft it replaced.

**It starts OPEN, and folds away in one click** (Massimo's call, September 2026 — it shipped folded a few days earlier and the default was flipped on sight). The box is the reason the card is there: folded-by-default, a member who never opened it never saw what goes in it, and a dashed pill on a bar that said nothing else reads as one more thing to skip. The cost is real and is why the fold exists at all — this column has no height to spare (it sits under a prompt field whose own floor was cut to 150px to keep it and its toolbar on screen), and an open box costs 78px more, which on an 800px window put the column into scroll with the *simplest* model selected. The fold is **persisted** (`PromptPanelState.voiceOpen`, absent → open, so older drafts open too), so a member who doesn't want it pays that height once rather than every session. Folded, the header row is the whole card at rest (48px): the fold chevron on the left and the dashed **Voice** pill centred against an empty right gutter (the `Optional` pill that used to sit there came off in September 2026 with the References card's own). **The whole row folds it, not just the chevron** — a 24px target on a 48px bar that is otherwise dead space made the fold something you had to aim at. The chevron stays a real button so the control keeps its `aria-expanded` and its keyboard focus, and both it and the Voice pill `stopPropagation` so neither fires the row's toggle on the way up; `SectionPresetPill.onClick` takes the event for exactly that. Folded WITH a profile in it, one dim truncated line rides under the header — a fold that hid the text entirely would read as the voice having been cleared — and clicking that line opens the box. **There is deliberately no Clear button**: it's a plain textarea, emptying it is select-all-delete, and a destructive control on a set-once field is one misclick from re-pasting a paragraph — the References card's Clear exists only because attachments can't be deleted by typing.

**The heading IS the preset opener** — Influencers' `SectionPresetPill` (dashed ring + chevron in plain ink), lifted into `components/SectionCard.tsx` when this became its second caller, at `size='sm'` so it matches the References card's own 13px title rather than standing 14px under it. It opens a right-edge `SlideOver`, the same chrome as the prompt presets one step above. **The card says "Voice", not "Voice profile"** — the placeholder inside it already says what it is ("Describe your voice. Added to the end of every prompt"), and the word only needed saying once. **A preset row is a NAME, not a paragraph**: fourteen full profiles rendered at once is a wall of prose in which every entry opens "Female in her mid 20s speaking with a…", so the line that distinguishes them is the hardest to find. A row is the accent, who's speaking it, and three trait words off the profile (`VoicePreset.traits` — a clamp of the prose would say nothing the row's own name hasn't); clicking it expands that ONE row to the whole thing plus the button that applies it, so the list can't grow back into the wall it replaced. Two `Dropdown` filters head it — gender and accent region — and both need `tier="panel"`, not decoration: this slide-over is `z-[80]` and a default-tier menu paints at `z-[60]`, i.e. behind the panel its own trigger is on. `VOICE_PRESETS` (`voicePresets.ts`) are **complete profiles, not templates** — gender and age, the accent by name, tone and pitch, pacing, then concrete delivery quirks — for the same reason the Characters presets fill all 28 fields: a one-line "British accent" leaves the model to invent the rest, and what it invents is the flat announced voice these exist to avoid. The London female entry is Massimo's own reference profile, verbatim; every other one was written against its register.

**Nothing in the References card says "Optional"** (Massimo's call, September 2026). It said it three times at one point — a corner tag on every frame slot, then one pill at the card header, then again on the `Attachments` group — and the word came off all three: everything in this column that isn't marked otherwise is optional, and the card that is unmistakably a pile of extras is the last one that needs telling. What the header pill still carries is Omni's live **`n/7` slot quota** and nothing else, because that is a limit rather than a reassurance — until it landed here it only ever surfaced as an error toast AFTER a member had spent it (the arithmetic is `utils`-side in `omniQuota.ts`, shared with the strip's cap and with the checks OmniInputsSection refuses on, so the three readouts can't drift). Motion Control still gets no pill at all: its two inputs really do gate the run, which is what its red dots are for.

**Every reference slot the active model accepts sits in one `SectionCard` titled References** (August 2026), with a **Clear** on its header once anything is attached (it empties every slot and leaves the prompt alone — that's the member's writing, not a reference). It renders exactly where the slot block already did, so it inherits the model's own capabilities instead of adding a second set of conditionals: Music has no slots and gets no card, nor does a text-only video model (`hasAnyRefSlot`); Motion Control's section takes the card over — but **`isMotionControl` must stay in the card's own gate**, because that model declares `modes: ['motion-control']` and no `supportsReferenceImages`, so `hasAnyRefSlot` is false for it; without the term the card never rendered, its section went with it, and the model became impossible to run at all (a regression shipped in #437 and fixed in the follow-up). Motion Control's three controls are `RefGroup`s of their own (August 2026) — Character image / Driving video / Follow the — where they used to be one wrapping row of a slot, a pill and a toggle with **no labels**: both input names lived as captions INSIDE the empty slots and so vanished the moment you filled them. It is also the one place `RefGroup`'s `required` is honest, since the run refuses without both, and the clip's duration ceiling rides on the Driving video label rather than only appearing as an error after the upload; Omni's characters/voices/clip stack under the images; the Seedance clip strips share their row inside it. Image mode's single group still gets the card — one mode reading structurally differently to save 22px is the worse trade. `RefGroup` takes an optional `filled` for the status dot and its label is now small-caps; the **frame slots deliberately have no dot**, since a picture versus a dashed box outshouts a 6px one. **An Omni input with nothing in it is a chip in one shared `Attachments` row; the moment it holds something it opens out into its own labelled group above** (September 2026). Empty, the three of them were three label rows each carrying a single dashed add card — 186px spent offering attachments nobody had attached, in a column whose whole job is the prompt box underneath. Filled, each still gets its heading, its count and its list, so the collapse only ever takes away the state with nothing to show; Voices and Source clip share a row only when BOTH hold something, the same rule the images-beside-clip-strips row follows. The chip row is a **wrapping flex row, never a grid with a breakpoint**: this panel's width doesn't track the viewport's — above `md` it's a fraction of the window, so a small desktop leaves it as narrow as a phone leaves it wide, and a `md:grid-cols-3` truncated "Character" to "Chara…" on a 1000px window while giving a phone the full three across. `flex-1 basis-[112px]` decides per row instead. Every chip carries a helper line (`0/3`, `0/3`, `≤ 10s`) because one of them has to — the clip's ceiling, which a member should meet before the upload rather than as an error after it — and a lone subtitle under one of three identical cards reads as that card being different in kind. **Omni's characters are a 2-column grid of `MediaCard`, matching voices and the source clip** — the three Omni-only inputs read as one list of attachments instead of a tile grid stacked over two card lists. `MediaCard` takes a `thumb` so the character still shows its face in the icon chip's place, and no `accent`: a tint that marks bank-backed rows made one of the three look like a different kind of thing. **Reference images stay 64px `ImageTile` squares with a dashed add tile**, in both Image and Video mode — they were briefly cards too and it was reverted, because on a reference image the PICTURE is the point and a 28px chip beside a filename makes "did I attach the right photo?" the smallest thing on the row. **A frame slot is TWO shapes** (September 2026, `FrameSlot`): EMPTY it's the same 40px `MediaAddCard` every other attach-something control wears, FILLED it opens out to an `aspect-[2/1]` tile — not 16:9, since these sit directly above the prompt box and every pixel there is one it loses; the frame inside is `object-contain`, so the ratio only sets a filled slot's height. An empty slot needs room for one word and a filled one needs room for the picture, and the single 2:1 shape paid the picture's price either way — 124px of dashed box holding a 28px icon, twice over, in the card's normal (empty) state. When one of the pair is filled the grid stretches the other to match, so a lone frame sits beside a full-height drop target rather than a 40px card pinned above an 84px gap.

**The reference-clip strips sit BESIDE the reference images**, stacked, when a model takes both (the Seedance 2 family) — images left, audio over video on the right. The images row is one 64px tile high whether it holds nothing or three, so on that model it was a column of dead space next to an Add tile while the clip cards took a full row of their own underneath. Either kind alone spans the width: the split only pays when there's something to put in the gap, and the tiles want the width when the clips aren't there to claim it (`items-start`, so a filled image grid doesn't stretch the clip column). **That, plus the prompt section's floor coming down from 206px to 150px** (the box's fixed chrome — then a 48px preset row and a 38px toolbar, now the toolbar alone — plus ~4 lines of field), is what puts the prompt box and its toolbar on screen with Seedance 2 selected without scrolling: measured 575px of content in a 493px port before, 493 after. A floor is what the box collapses TO under pressure, not the size it normally renders at — `grow` still hands it every spare pixel the moment the column has one. **Music's two controls sit ABOVE the prompt box** (August 2026) — model row, then the Instrumental / With lyrics `SegmentedToggle` at `h-12`, then the box you write in, reading top to bottom. Image and Video keep theirs in the footer because those genuinely ARE output settings (resolution, aspect, duration) picked on the way to Generate; Music has none, so its footer was a lone hand-rolled toggle standing in for a row of chips, sized `h-10` to match chips that don't exist in that mode. It's a real `SegmentedToggle` now at the same height as B-Roll's Dialogue Clips / B-Roll Clips pair — the same question asked of a generation — which is what added the `playground` accent to `SegmentedToggle`. **The scrolling body column is `min-h-full`, never `h-full`.** Both make it at least the port, so the prompt box keeps a ceiling to shrink against and `grow` still fills a short panel — but `h-full` also caps it AT the port, so the scroller never learns its content is taller. Pick a model with a lot of inputs (Seedance 2: two frame slots, a ref strip, and both clip strips) and the References card alone outgrew the port: the prompt box was pushed past the bottom edge and clipped there with no scrollbar to recover it, while the wheel fell through to the page behind. **The footer stack runs on the app's shared control sizes** (August 2026): the model trigger is the 58px picker row (`ModelPicker row`, the same geometry as `ScriptModelRow` and the bank/style rows in Scripts and B-Roll) with the batch stepper `shrink-0` beside it at the matching `size='xl'`, the constraint pills under it are `size='lg'` (48px, the Characters generate bar's), and everything in the column sits 8px apart. `row` exists alongside `large` because `large` is for a trigger that SHARES a row with its chips — Characters' bar puts both at 48 — while this one owns its row. **Several clips are zipped by picking them ON the grid, never in a modal that lists them again** (September 2026, Massimo's call). The Download-clips *picker* was removed here in August 2026 and stays removed — B-Roll keeps one because its list is ONE storyboard, a finite set of takes exported together, while this list is every clip the member has ever made — but the underlying want survived it, and the answer is that the wall of tiles you are already scrolling IS the picker. A **Select** pill in the history header (Video tab, grid view, and only once there's a clip to pick) turns every video tile into its own checkbox: the tile toggles instead of opening the preview, an unselected one dims to 60% and lifts back to full on hover, and the tick takes the top-RIGHT corner the `TileActionStack` vacates. **The transport stays live while you pick** — play, pause and mute are exactly what you reach for deciding which take to keep, and both handlers already `stopPropagation`, so pressing one never ticks the tile. The gesture takes over the panel's own 57px header rather than raising a band under the scroll port, and it carries **no "N of M selected" tally**: the count rides on the Download button, and a second copy of it beside Select all is what clipped that link at panel width (this pane's width doesn't track the viewport's, so no breakpoint fixes it). Nothing is preselected — this list runs back weeks. Zipping goes through the shared `utils/downloadZip`, one file per clip named `<index>-<prompt slug>` in the order the grid showed them, into `playground-clips-<YYYY-MM-DD>.zip`; a success clears the selection and leaves select mode. `zipClips` sits at MODULE scope on purpose — a try/catch in the component body makes the React Compiler skip the whole component, and this is the grid that must not re-render while the member types beside it. `components/ClipDownloadModal` stays where it is for B-Roll's two modes. **Its tiles only hold their media while they're near the scroll window** (`hooks/useNearViewport`, root = the scroller): a member with 60 clips was mounting 60 `<video>`s in the grid, which is 60 blob reads out of IndexedDB and far more decoders than a browser hands out — past its budget the extra elements never paint, so the tab stalled on a black grid. **Only the CLIPS release, though** — `release: true` on the video tile, the list row's video branch and `ClipDownloadModal`, all three of which size their FRAME rather than let the media do it. A still keeps whatever it loaded: its tile is sized by the picture and its placeholder by the declared aspect ratio, so a still that released would change height above the viewport and drag the grid under the pointer (reported twice, September 2026 — the second time against Characters, after a revert took the default away). See `hooks/useNearViewport.ts`. **A list row names the model that made it** (`components/ModelPill`, `chrome` variant), on its own line above the meta pills — the same reading order Characters' list row uses, so a row looks the same across the two apps. List only in the history itself: the grid is a wall of pictures and a caption on each is exactly the chrome that shape exists to avoid. **The preview modal names it too** (`media` variant, above the prompt), for both stills and clips and whichever view they were opened from — the modal is where an output is actually judged, and it is the one surface that can answer "which model made this?" for a grid tile that deliberately doesn't say. It's `media` rather than `chrome` because that modal is a literal black overlay in both themes, like every other label in it, and it takes `shrink-0`: the side column overflows on a short viewport and a flex child with no floor is squashed — measured 5px tall against its natural 19px. **Every history card carries a Reuse (`ArrowLeft`) button beside Copy prompt** (September 2026) — grid tile, list row and preview modal, for all three kinds — putting that generation's prompt back in the box and REPLACING what's there. It sits right after Copy prompt because the two are siblings: one hands the words to the clipboard, the other hands them straight back to the field, which is what you wanted every time you copied one. The arrow points LEFT, at the panel the prompt is going to. `handleReusePrompt` swaps the prompt and **nothing else** — the Voice box, the references and the model all survive, the same contract the `videoPrompt` handoff runs on — and no mode switch is involved, because the grid is filtered to the active mode so a card's prompt always belongs to the tab it lands in. It flips the phone's pane to `prompt` (the grid is the pane you pressed it from) and deliberately raises **no toast**: the box visibly changes, which is better feedback than a line of copy. It genuinely replaces, with no undo of its own — `PromptPanel`'s stack only tracks changes made inside the box — which is what the button says it does and how every other prompt handoff into this app already behaves. `useCallback` is not optional on the handler: the grid is `memo`'d against hundreds of rows and a fresh identity per render re-renders the whole list on every keystroke.

**A music track is played by the app, never by the browser** (September 2026). Every music surface here — the grid tile and the list row — rendered a native `<audio controls>`, which is the one control in the app that ignores the theme outright: its own grey slab, its own type, its own overflow menu, three of them stacked down a panel whose every other tile is custom chrome. They wear **Voiceovers' transport** instead, and it moved to shared modules to get here: `utils/audioPlayback.ts` (the app-wide one-clip-at-a-time slot, `resolveAudioUrl`, the peak decoder) and `components/Waveform.tsx` (whole clip drawn at rest, filling left to right, click to seek — `playedClass` is what makes it wear this app's accent), both lifted out of `voice-studio/`. The **artwork doubles as the play button**, the way the voice avatar does over there — a cover is the obvious thing to press, and it leaves the card's body for the words. The waveform is collapsed until the track plays and closes when it ends, since a card at rest is something you read; actions ride in the standard `TileActionStack` on the artwork, so a music tile's hover column sits where the image and video tiles' beside it do. `hooks/useAudioPlayback.ts` is the transport itself and is **per tile**, not per list: the element is built on the first press (a history of dozens of tracks has no business opening dozens of media elements), the card then holds it so a paused track keeps its waveform, and the shared slot still pauses whoever was playing. Voiceovers' History keeps its own list-level copy of that logic, which predates the hook.


**The Voice card carries no `card-soft-shadow`**, and that is not an oversight. It is the LAST child of an input column that is `min-h-full` with the prompt box taking every spare pixel through `grow`, so its bottom edge lands exactly on the scroll port's clip edge at every window size — and a scroller clips its descendants' shadows. The 8px under it belongs to the generate band, which is outside the port and can't lend the shadow any room. So the shadow never rendered downward at all: what it drew was a halo down the sides stopping dead at the bottom corners, which reads as the card being sliced off. Reported in light mode (September 2026), because that is the only theme where the shadow is visible in the first place. Don't fix it with `pb` on the column — bottom padding on a scroll container is scrolled content, and the gap above the band would change as you scroll (root `CLAUDE.md`).

**The list row's `<video>` carries `#t=0.1` on its src**, and it is load-bearing: with `preload="metadata"` Safari fetches duration and dimensions but decodes no frame, so the element painted as an empty black box — the clip was there and invisible until you pressed play, while the grid tiles (which autoplay muted on hover) looked fine. The media fragment forces a seek to 0.1s and with it a decode. Same fix as B-Roll's history `CoverTile`; don't drop it from either.
