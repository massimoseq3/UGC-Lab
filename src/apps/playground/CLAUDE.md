# Playground — `playground/`

Create section of UGC OS — the dock tile sits between B-Roll and Edit. This file loads when Claude works with files under `src/apps/playground/`; the app-wide rules stay in the root [CLAUDE.md](../../../CLAUDE.md).

## Job

Free-form Image / Video / Music — tabs in that order, landing on **Image**, because the loop it's used for is "make a still, then animate it". That loop is one click: an image tile's hover stack (and the preview modal) carries an **Animate** action that switches to Video with the still inlined as the start frame and the prompt that made it seeded in the bar (`handleAnimateImage`), going through the same `promptStash` as a manual tab switch so the Image tab keeps its own draft. Each mode remembers its own model under `playground:<task>[:<mode>]` — Image/Music via `ModelPicker`'s own persistence, Video written by the panel itself since `ModelSidePanel` leaves persistence to its caller; without that write every Image → Video flip reset the pick to the registry default. Prompt bar, mode tabs, model picker, model-aware ref slots + drag-drop (images everywhere; Seedance 2 adds audio/video reference clips; Gemini Omni adds characters / designed voices / a trimmed source clip under a 7-slot quota). `@`-mentions reference Products / Influencers / B-Rolls and auto-attach the asset. Uploaded audio/video refs are memory-only (pruned from the persisted draft — too big for localStorage).

**The prompt box's header row is "UGC Prompt Presets & Visual Styles"** (August 2026) and its slide-over lists **visual styles first**, then the presets. Both do exactly one thing — append a block of direction to the prompt below — so they share one row rather than costing the column another 48px above the box the whole panel exists to fill, and a look is the broader decision of the two (it applies to whatever you were going to make; a preset is one specific shot). The styles are `CONTINUOUS_STYLES` plus the member's `styles` bank, drawn with the same `StyleTile` and the same preview art as the B-Roll and Characters pickers (`components/styleArt.ts` holds the artwork and the per-app accents, split out of `StyleModal.tsx` so a host that lists styles without opening the modal doesn't drag the modal in). **Nothing renders as "active":** Playground keeps no style state of its own — `applyStyle` appends the brief and the prompt is then the member's to edit like anything else they typed, which is also why creating a style still lives in B-Roll's picker, the one that owns the reference-frame analysis. Image mode appends `styleBriefForStill` (every brief ends on camera movement and cutting cadence a single frame can't express), falling back to the plain brief for UGC Realism, where the still-scoped helper returns null.

**Every reference slot the active model accepts sits in one `SectionCard` titled References** (August 2026), with a **Clear** on its header once anything is attached (it empties every slot and leaves the prompt alone — that's the member's writing, not a reference). It renders exactly where the slot block already did, so it inherits the model's own capabilities instead of adding a second set of conditionals: Music has no slots and gets no card, nor does a text-only video model (`hasAnyRefSlot`); Motion Control's section takes the card over — but **`isMotionControl` must stay in the card's own gate**, because that model declares `modes: ['motion-control']` and no `supportsReferenceImages`, so `hasAnyRefSlot` is false for it; without the term the card never rendered, its section went with it, and the model became impossible to run at all (a regression shipped in #437 and fixed in the follow-up). Motion Control's three controls are `RefGroup`s of their own (August 2026) — Character image / Driving video / Follow the — where they used to be one wrapping row of a slot, a pill and a toggle with **no labels**: both input names lived as captions INSIDE the empty slots and so vanished the moment you filled them. It is also the one place `RefGroup`'s `required` is honest, since the run refuses without both, and the clip's duration ceiling rides on the Driving video label rather than only appearing as an error after the upload; Omni's characters/voices/clip stack under the images; the Seedance clip strips share their row inside it. Image mode's single group still gets the card — one mode reading structurally differently to save 22px is the worse trade. `RefGroup` takes an optional `filled` for the status dot and its label is now small-caps; the **frame slots deliberately have no dot**, since a picture versus a dashed box outshouts a 6px one. **Omni's characters are a 2-column grid of `MediaCard`, matching voices and the source clip** — the three Omni-only inputs read as one list of attachments instead of a tile grid stacked over two card lists. `MediaCard` takes a `thumb` so the character still shows its face in the icon chip's place, and no `accent`: a tint that marks bank-backed rows made one of the three look like a different kind of thing. **Reference images stay 64px `ImageTile` squares with a dashed add tile**, in both Image and Video mode — they were briefly cards too and it was reverted, because on a reference image the PICTURE is the point and a 28px chip beside a filename makes "did I attach the right photo?" the smallest thing on the row. The frame slots (start / end) are `aspect-[2/1]`, not 16:9 — they sit directly above the prompt box and every pixel there is one it loses; the frame inside is `object-contain`, so the ratio only sets the slot's height.

**Reference audio and reference videos share a row** when a model takes both (the Seedance 2 family): two stacked full-width upload cards cost the prompt box its height in a column that also carries frames, ref images and the settings stack. Either one alone spans the width. **The footer stack runs on the app's shared control sizes** (August 2026): the model trigger is the 58px picker row (`ModelPicker row`, the same geometry as `ScriptModelRow` and the bank/style rows in Scripts and B-Roll), the constraint pills under it are `size='lg'` (48px, the Characters generate bar's), and everything in the column sits 8px apart. `row` exists alongside `large` because `large` is for a trigger that SHARES a row with its chips — Characters' bar puts both at 48 — while this one owns its row. **Download clips** — the history header's neutral pill on the Video tab opens the shared `components/ClipDownloadModal` (lifted out of B-Roll so the two can't drift), which zips whatever stays ticked. It opens with **nothing picked**, unlike B-Roll's, which pre-ticks each card's cover take: B-Roll's list is one storyboard, this one is every clip the member has ever generated here, so opening it all-ticked would mean unticking dozens to get the two they came for. A video row carries no title, so the label is its prompt (clamped to two lines) over a relative-time meta line — the model name was on that line and came off, since it's the same for a whole run and so tells no two clips apart — and the zip name is positional (`playground-clip-03`) since `playground-${id}` is unique but unreadable in a folder. Video only — the picker previews with a `<video>`, and images/music already download one-tap from their tiles. **Its tiles, and the history grid's, only hold their media while they're near the scroll window** (`hooks/useNearViewport`, root = the scroller): a member with 60 clips was mounting 60 `<video>`s in the grid and 60 more the moment the picker opened, which is 120 blob reads out of IndexedDB and far more decoders than a browser hands out — past its budget the extra elements never paint, so the picker opened onto a black grid and the tab stalled. Ticking is unaffected: the picked set lives in the modal, so Select all zips clips that were never scrolled to.
