# Playground — `playground/`

Create section of UGC OS — the dock tile sits between B-Roll and Edit. This file loads when Claude works with files under `src/apps/playground/`; the app-wide rules stay in the root [CLAUDE.md](../../../CLAUDE.md).

## Job

Free-form Image / Video / Music — tabs in that order, landing on **Image**, because the loop it's used for is "make a still, then animate it". That loop is one click: an image tile's hover stack (and the preview modal) carries an **Animate** action that switches to Video with the still inlined as the start frame and the prompt that made it seeded in the bar (`handleAnimateImage`), going through the same `promptStash` as a manual tab switch so the Image tab keeps its own draft. Each mode remembers its own model under `playground:<task>[:<mode>]` — Image/Music via `ModelPicker`'s own persistence, Video written by the panel itself since `ModelSidePanel` leaves persistence to its caller; without that write every Image → Video flip reset the pick to the registry default. Prompt bar, mode tabs, model picker, model-aware ref slots + drag-drop (images everywhere; Seedance 2 adds audio/video reference clips; Gemini Omni adds characters / designed voices / a trimmed source clip under a 7-slot quota). `@`-mentions reference Products / Influencers / B-Rolls and auto-attach the asset. Uploaded audio/video refs are memory-only (pruned from the persisted draft — too big for localStorage).

**Image and Video carry a batch count** (`BatchCountStepper`, last chip in the footer row, capped at 4): Playground is where a prompt gets TRIED, so a run of one is the wrong unit most of the time. `handleSubmit` snapshots the prompt, refs, inferred mode and resolved model ONCE and then calls an inner `runOne` N times, so every member of the run is identical by construction and each is its own task / tile / history row. **Music is excluded** — Suno already returns a pair of tracks for a single call, so a count there would bill twice for something the API hands over anyway. The count rides in the persisted draft (`PromptPanelState.batchCount`, absent on older drafts, clamped on hydrate).

**The video mode is INFERRED from the filled slots, then reconciled with the picked model in both directions — a run is only refused when the model takes no images at all.** `inferVideoMode` reads the slots (start+end → frames, start → image, refs → reference) and knows nothing about the model; the reconciliation right after it is what makes the two agree. Both directions are real: an image-to-video-only model (Kling 3.0 Turbo) can't take a reference image but can animate it as a start frame, and a **frame-less** model (Seedance 2.5, Gemini Omni) has no `first_frame_url`/`last_frame_url` at all and folds every attached image into its reference array — which is exactly what those models' `buildVideoInput` branches already do with a stray frame. Only the first direction existed, so attaching a start frame **and** a reference image inferred `image-to-video`, Seedance 2.5 doesn't declare it, and the run was refused with a toast naming a limitation the model doesn't have — reported as "it said Seedance 2.5 doesn't accept reference images", on a generation that would have run fine. When the mode lands on reference-to-video the frame slots are sent AS references, in shot order ahead of the explicit ones, or the downgrade would trade a false error for a silent drop. **Check `buildVideoInput` before refusing a run over an undeclared mode** — the declared modes say what the model calls its inputs, not whether the pictures reach it.

**A frame and a reference attached together resolve per model, through `mixedImageInputPolicy`, and every outcome is toasted.** There is no universal answer here — the providers designed three different things, and a surface that guesses either drops an input silently or sends a 400:

- **`merged`** (Gemini Omni, Grok) — one flat `image_urls` array with no frame/reference distinction. Everything is sent and nothing is said, because nothing was traded.
- **`reference`** (MiniMax H3, Kling 3.0 Omni, Seedance 2.5) — a reference RE-ROUTES the request and the frame rides along as a reference image. The mode is forced to reference-to-video so it agrees with the body the builder was going to produce anyway (`minimaxH3Route` / `klingOmniRoute` pick 'reference' the moment a reference is present). Both inputs reach the model, but the frame stops being frame one, which is a real change to what the member gets and is toasted as such.
- **`exclusive`** (the Seedance 2.0 family, the Wan 3.0 family, and the undeclared default) — the provider forbids the pair outright: kie documents first/last-frame and multimodal reference-to-video as "three mutually exclusive scenarios [that] cannot be used simultaneously". The frames win — the frame slot is a deliberate act, not where pictures land by default — and the references are dropped and named, with the way to get them honoured instead. **The drop itself happens in the model's own `buildVideoInput` branch, not here and not in the hosting step**, which is the half that was missing until August 2026: the toast said "rendering from the frames" while the Seedance 2.0 body still carried `reference_image_urls` beside `first_frame_url`, putting a pair the provider forbids on a run the member had committed to. `startPlaygroundVideoTask` hosts references unconditionally on purpose (merged-input models need them), so the builder is the only place left that knows the policy AND sees both groups.
- **`frames-only`** (Seedance 1.5 Pro, Kling 3.0, Wan 2.7) — no reference input at all. Only reachable by attaching references under one model and switching to another, since Playground hides the ref strip for these.

Two rules hold it together. **The policy lives on the registry entry, never in this file** — `mixedImageInputs` on `ModelEntry`, resolved through `mixedImageInputPolicy`, so adding a model is a registry edit. **Undeclared falls to `exclusive`, not `merged`**, because the costs aren't symmetrical: a wrong `exclusive` drops an input and says so, a wrong `merged` sends a combination the provider rejects — a 400 on a run already paid for. And `startPlaygroundVideoTask` hosts whatever it is handed (references are hosted whenever present, like the audio/video strips): it is transport, the policy call is the caller's, and the `else if` that made it a second unwitting gate is what dropped the references one layer below the code that decided to send them.

**The prompt box's header row is "UGC Prompt Presets & Visual Styles"** (August 2026) and its slide-over lists **visual styles first**, then the presets. Both do exactly one thing — append a block of direction to the prompt below — so they share one row rather than costing the column another 48px above the box the whole panel exists to fill, and a look is the broader decision of the two (it applies to whatever you were going to make; a preset is one specific shot). The styles are `CONTINUOUS_STYLES` plus the member's `styles` bank, drawn with the same `StyleTile` and the same preview art as the B-Roll and Characters pickers (`components/styleArt.ts` holds the artwork and the per-app accents, split out of `StyleModal.tsx` so a host that lists styles without opening the modal doesn't drag the modal in). **Nothing renders as "active":** Playground keeps no style state of its own — `applyStyle` appends the brief and the prompt is then the member's to edit like anything else they typed, which is also why creating a style still lives in B-Roll's picker, the one that owns the reference-frame analysis. Image mode appends `styleBriefForStill` (every brief ends on camera movement and cutting cadence a single frame can't express), falling back to the plain brief for UGC Realism, where the still-scoped helper returns null.

**Every reference slot the active model accepts sits in one `SectionCard` titled References** (August 2026), with a **Clear** on its header once anything is attached (it empties every slot and leaves the prompt alone — that's the member's writing, not a reference). It renders exactly where the slot block already did, so it inherits the model's own capabilities instead of adding a second set of conditionals: Music has no slots and gets no card, nor does a text-only video model (`hasAnyRefSlot`); Motion Control's section takes the card over — but **`isMotionControl` must stay in the card's own gate**, because that model declares `modes: ['motion-control']` and no `supportsReferenceImages`, so `hasAnyRefSlot` is false for it; without the term the card never rendered, its section went with it, and the model became impossible to run at all (a regression shipped in #437 and fixed in the follow-up). Motion Control's three controls are `RefGroup`s of their own (August 2026) — Character image / Driving video / Follow the — where they used to be one wrapping row of a slot, a pill and a toggle with **no labels**: both input names lived as captions INSIDE the empty slots and so vanished the moment you filled them. It is also the one place `RefGroup`'s `required` is honest, since the run refuses without both, and the clip's duration ceiling rides on the Driving video label rather than only appearing as an error after the upload; Omni's characters/voices/clip stack under the images; the Seedance clip strips share their row inside it. Image mode's single group still gets the card — one mode reading structurally differently to save 22px is the worse trade. `RefGroup` takes an optional `filled` for the status dot and its label is now small-caps; the **frame slots deliberately have no dot**, since a picture versus a dashed box outshouts a 6px one. **Omni's characters are a 2-column grid of `MediaCard`, matching voices and the source clip** — the three Omni-only inputs read as one list of attachments instead of a tile grid stacked over two card lists. `MediaCard` takes a `thumb` so the character still shows its face in the icon chip's place, and no `accent`: a tint that marks bank-backed rows made one of the three look like a different kind of thing. **Reference images stay 64px `ImageTile` squares with a dashed add tile**, in both Image and Video mode — they were briefly cards too and it was reverted, because on a reference image the PICTURE is the point and a 28px chip beside a filename makes "did I attach the right photo?" the smallest thing on the row. The frame slots (start / end) are `aspect-[2/1]`, not 16:9 — they sit directly above the prompt box and every pixel there is one it loses; the frame inside is `object-contain`, so the ratio only sets the slot's height.

**The reference-clip strips sit BESIDE the reference images**, stacked, when a model takes both (the Seedance 2 family) — images left, audio over video on the right. The images row is one 64px tile high whether it holds nothing or three, so on that model it was a column of dead space next to an Add tile while the clip cards took a full row of their own underneath. Either kind alone spans the width: the split only pays when there's something to put in the gap, and the tiles want the width when the clips aren't there to claim it (`items-start`, so a filled image grid doesn't stretch the clip column). **That, plus the prompt section's floor coming down from 206px to 150px** (the box's fixed chrome — a 48px preset row and a 38px toolbar — plus ~4 lines of field), is what puts the prompt box and its toolbar on screen with Seedance 2 selected without scrolling: measured 575px of content in a 493px port before, 493 after. A floor is what the box collapses TO under pressure, not the size it normally renders at — `grow` still hands it every spare pixel the moment the column has one. **Music's two controls sit ABOVE the prompt box** (August 2026) — model row, then the Instrumental / With lyrics `SegmentedToggle` at `h-12`, then the box you write in, reading top to bottom. Image and Video keep theirs in the footer because those genuinely ARE output settings (resolution, aspect, duration) picked on the way to Generate; Music has none, so its footer was a lone hand-rolled toggle standing in for a row of chips, sized `h-10` to match chips that don't exist in that mode. It's a real `SegmentedToggle` now at the same height as B-Roll's Dialogue Clips / B-Roll Clips pair — the same question asked of a generation — which is what added the `playground` accent to `SegmentedToggle`. **The scrolling body column is `min-h-full`, never `h-full`.** Both make it at least the port, so the prompt box keeps a ceiling to shrink against and `grow` still fills a short panel — but `h-full` also caps it AT the port, so the scroller never learns its content is taller. Pick a model with a lot of inputs (Seedance 2: two frame slots, a ref strip, and both clip strips) and the References card alone outgrew the port: the prompt box was pushed past the bottom edge and clipped there with no scrollbar to recover it, while the wheel fell through to the page behind. **The footer stack runs on the app's shared control sizes** (August 2026): the model trigger is the 58px picker row (`ModelPicker row`, the same geometry as `ScriptModelRow` and the bank/style rows in Scripts and B-Roll), the constraint pills under it are `size='lg'` (48px, the Characters generate bar's), and everything in the column sits 8px apart. `row` exists alongside `large` because `large` is for a trigger that SHARES a row with its chips — Characters' bar puts both at 48 — while this one owns its row. **There is no Download-clips zip picker here** (removed August 2026). B-Roll keeps one because its list is ONE storyboard — a finite set of takes exported together as an edit; this list is every clip the member has ever generated, which is a reel to scroll rather than a deliverable to package, and every tile already downloads in one tap from its own hover stack. `components/ClipDownloadModal` stays where it is for B-Roll's two modes. **Its tiles only hold their media while they're near the scroll window** (`hooks/useNearViewport`, root = the scroller): a member with 60 clips was mounting 60 `<video>`s in the grid, which is 60 blob reads out of IndexedDB and far more decoders than a browser hands out — past its budget the extra elements never paint, so the tab stalled on a black grid. **A list row names the model that made it** (`components/ModelPill`, `chrome` variant), on its own line above the meta pills — the same reading order Characters' list row uses, so a row looks the same across the two apps. List only in the history itself: the grid is a wall of pictures and a caption on each is exactly the chrome that shape exists to avoid. **The preview modal names it too** (`media` variant, above the prompt), for both stills and clips and whichever view they were opened from — the modal is where an output is actually judged, and it is the one surface that can answer "which model made this?" for a grid tile that deliberately doesn't say. It's `media` rather than `chrome` because that modal is a literal black overlay in both themes, like every other label in it, and it takes `shrink-0`: the side column overflows on a short viewport and a flex child with no floor is squashed — measured 5px tall against its natural 19px. **The list row's `<video>` carries `#t=0.1` on its src**, and it is load-bearing: with `preload="metadata"` Safari fetches duration and dimensions but decodes no frame, so the element painted as an empty black box — the clip was there and invisible until you pressed play, while the grid tiles (which autoplay muted on hover) looked fine. The media fragment forces a seek to 0.1s and with it a decode. Same fix as B-Roll's history `CoverTile`; don't drop it from either.
