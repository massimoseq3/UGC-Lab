# Bank — `finder/`

Library section of UGC OS. This file loads when Claude works with files under `src/apps/finder/`; the app-wide rules stay in the root [CLAUDE.md](../../../CLAUDE.md).

## Job

Banks browser (Products / Characters / Scripts / Voices / B-Rolls / **Visual Styles** / **Swipe File**). The Swipe File tab is Outliers' data shown here, and a card **opens the very same detail view Outliers does** rather than a form — `SwipeDetail.tsx` adapts the row back into a `DiscoverResult` (`discover/services/swipe.ts`) and renders `discover/components/ResultDetailModal`, so Analyze Ad, Remix Transcript and the permalink are all where they were when you saved the ad. That's a deliberate cross-app import: the alternative is a second copy of a 340-line modal that would drift from the original within a release, and the shared-idiom rule outranks app self-containment here. Everything specific to a SAVED ad lives in `SwipeDetail` — the expired `mediaUrl` and its **Restore video — 1 credit** re-resolve, and a transcript written back to the row so it's bought once. See the root CLAUDE.md's `swipes` bullet for the rules that hold it together. Visual Styles (bank key `styles`) holds the saved visual looks B-Roll distils from reference frames — `StyleForm` edits the name + brief (the frames are read-only thumbnails). **The Product form autosaves** — 700 ms after the last change, on close, and on unmount (bank switch, dock switch), so dropping an extra angle and clicking away can't lose it. A product that doesn't exist yet is created as an **unconfirmed draft** (`confirmed: false`, the same orange dot a bulk-added photo lands in) and the Add button confirms it; an existing row is written in place. The plumbing is `ProductForm`'s `onAutosave` → `Finder.handleAutosaveProduct`, which returns the row as stored so the form can adopt the asset refs and stop re-uploading the same bytes; `addProduct`/`updateProduct` take `{ silent: true }` because a toast per keystroke is noise (`saveProductDraft` uses it too, so a bulk add reports once). **What an open form accumulates lives in one `FormScratch` object** — the row its autosaves write into (as the in-flight PROMISE, so a submit racing an autosave waits on the one add) and the photos it has already persisted — and every handler reads that object BEFORE its first `await`. Closing the form flushes it and the unmount flush lands later still, both after the close handler has reset the scratch: while those were two refs cleared in place, a late flush read back a null row id, decided the product didn't exist yet and added it a SECOND time. Two rows, one blob — and deleting either copy purged the shared photo along with its Supabase `assets` record, which is what left the survivor on the package placeholder for good. `updateProduct` / `deleteProduct` now also refuse to purge a blob another product row still shows (`productAssetInUse`), the same `stillReferenced` shape `updateModel` uses. Everything that writes `scratchRef` sits above the memoized callbacks that read it — the React Compiler forbids modifying a value a hook already captured. The form is keyed on `editingId` so pressing Add with a form open starts a genuinely new row. Layout: the photos scroll on the left, the fields on the right in **four named sections** (Identity / Audience / Selling / Offer) under a `SegmentedToggle` jump strip that scroll-spies and shows each section's filled count. **Each section is a `SectionCard`** (August 2026): it was a left-aligned small-caps eyebrow over a hairline running off to the right — the shape `SectionCard` exists to replace, and one that reads as a divider BETWEEN blocks rather than a container around one. The glyphs already declared in `SECTIONS` finally render, on the card headers, and each header repeats that section's filled count beside the fields it counts (the jump strip keeps its own). **Exactly one `StatusDot`, on Product name** — the only required field; neutral dots on the nine optional ones would be decoration, and the header's `1/2` answers "what's still missing" at the right scale. The other five forms wear the same shape where there IS a group and skip it where there isn't: a **Details** card in `ScriptForm`, **Style** in `StyleForm`, **Voice** + **Delivery** in `VoiceForm` (mirroring the Voiceovers panel it edits presets for, Scene / Tone bare underneath), one card per DNA group in `ModelForm` (its headings were already the right shape, just left-aligned and unbordered), and no card at all around `BRollForm`'s lone prompt or the two big text boxes in Script and Style. A required field's `*` is now its dot; the save button moved into the header, because a slab pinned across the bottom of the field column read as the end of the form and hid the fact that it scrolls. `.scroll-fade-b` (index.css) fades a scroll port's bottom edge **only while there's more below** — a permanent fade is decoration, one that comes and goes is the affordance. Drop a photo (and optionally paste listing/product-page copy — authoritative for claims/specs/offer) to auto-fill via `extractProductInfo` (`CHAT_MODEL_DEFAULT`), re-runnable from the "Auto-fill" button. An `Auto-fill / Photo only` toggle sat above the photo for a stint and was **removed August 2026** — one control, permanently on Auto-fill for nearly everyone, above the one thing on that column worth looking at; a photo attached without a read is still what you get whenever extraction fails, and the Auto-fill button under the picture is the way to run one later. **Every way of adding a photo goes through one gate** (`services/imageValidation.ts`: `imageRejectionReason` for a single file, `partitionImageFiles` for a batch) — the tile, the file picker, a drop, an extra angle, Bulk add. It **toasts** the reason and **names the format** ("AVIF isn't a supported image format — use JPG, PNG, or WebP"): the old inline `extractError` renders at the bottom of the field column below four section cards, i.e. off screen, so a rejected AVIF looked exactly like nothing happening — which is most of what "my product image won't show up" turned out to be. `accept` is a filter and not a guarantee, so the file picker is validated exactly like a drop is (it wasn't, and skipped the 10 MB cap entirely). Its other half is `REQUIRED_KEYS`, now **`productName` alone**: a name is what makes the row pickable, and gating Add on a description was gating it on the write-up the member had just declined. Only the name renders a `*`; products carry optional deep-context fields `keySpecs` / `objections` that flow into Scripts + B-Roll prompts. (A third, `customerLanguage` — voice-of-customer phrases — was **removed July 2026**: it duplicated what pain points already carry in the buyer's own words, and it was one more box between a photo and a saved product. Rows saved with it keep the stored text; nothing reads or writes it.) A product also carries up to four **extra angles** (`Product.extraImages`, "More Angles" strip under the hero shot) — the box open, what's inside, the label. They ride along in the same auto-fill vision call (one object, several shots — the prompt says so explicitly, so it never reads them as a bundle), and every **image-picking** BankPicker (`expandProductImages`: RefTiles / FrameSlot / VideoInputSlot / B-Roll's `ExtraRefsRow` / the Influencers edit modal) lists one tile per photo so a scene that needs the open box can attach the open box. Pickers that pick the *product itself* (B-Roll's product slot, Scripts) leave the flag off — they need the real row id. B-Roll picks **per scene** which of these photos each shot gets — see `services/productAngles.ts`.
