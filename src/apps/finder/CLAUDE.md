# Bank — `finder/`

Library section of UGC OS. This file loads when Claude works with files under `src/apps/finder/`; the app-wide rules stay in the root [CLAUDE.md](../../../CLAUDE.md).

## Job

Banks browser (Products / Characters / Scripts / Voices / B-Rolls / **Visual Styles** / **Swipe File**). Every tab's grid is **two across on a phone except Characters, which is three** (August 2026): a character card is a portrait thumbnail and a name, so it stays readable at a third of a 375px screen — and this is the tab you scroll looking for a face, where half again as many faces per screen is the whole job. A landscape character sheet spans all three columns there (`col-span-3`). The Swipe File tab is Outliers' data shown here, and a card **opens the very same detail view Outliers does** rather than a form — `SwipeDetail.tsx` adapts the row back into a `DiscoverResult` (`discover/services/swipe.ts`) and renders `discover/components/ResultDetailModal`, so Analyze Ad, Remix Transcript and the permalink are all where they were when you saved the ad. That's a deliberate cross-app import: the alternative is a second copy of a 340-line modal that would drift from the original within a release, and the shared-idiom rule outranks app self-containment here. Everything specific to a SAVED ad lives in `SwipeDetail` — the expired `mediaUrl` and its **Restore video — 1 credit** re-resolve, and a transcript written back to the row so it's bought once. See the root CLAUDE.md's `swipes` bullet for the rules that hold it together. Visual Styles (bank key `styles`) holds the saved visual looks B-Roll distils from reference frames — `StyleForm` edits the name + brief (the frames are read-only thumbnails). **The Product form autosaves** — 700 ms after the last change, on close, and on unmount (bank switch, dock switch), so dropping an extra angle and clicking away can't lose it. A product that doesn't exist yet is created as an **unconfirmed draft** (`confirmed: false`, the same orange dot a bulk-added photo lands in) and the Add button confirms it; an existing row is written in place. The plumbing is `ProductForm`'s `onAutosave` → `Finder.handleAutosaveProduct`, which returns the row as stored so the form can adopt the asset refs and stop re-uploading the same bytes; `addProduct`/`updateProduct` take `{ silent: true }` because a toast per keystroke is noise (`saveProductDraft` uses it too, so a bulk add reports once). **What an open form accumulates lives in one `FormScratch` object** — the row its autosaves write into (as the in-flight PROMISE, so a submit racing an autosave waits on the one add) and the photos it has already persisted — and every handler reads that object BEFORE its first `await`. Closing the form flushes it and the unmount flush lands later still, both after the close handler has reset the scratch: while those were two refs cleared in place, a late flush read back a null row id, decided the product didn't exist yet and added it a SECOND time. Two rows, one blob — and deleting either copy purged the shared photo along with its Supabase `assets` record, which is what left the survivor on the package placeholder for good. `updateProduct` / `deleteProduct` now also refuse to purge a blob another product row still shows (`productAssetInUse`), the same `stillReferenced` shape `updateModel` uses. Everything that writes `scratchRef` sits above the memoized callbacks that read it — the React Compiler forbids modifying a value a hook already captured. The form is keyed on `editingId` so pressing Add with a form open starts a genuinely new row. Layout: the photos scroll on the left, the fields on the right in **four named sections** (Identity / Audience / Selling / Offer) under a `SegmentedToggle` jump strip that scroll-spies and shows each section's filled count. **Each section is a `SectionCard`** (August 2026): it was a left-aligned small-caps eyebrow over a hairline running off to the right — the shape `SectionCard` exists to replace, and one that reads as a divider BETWEEN blocks rather than a container around one. The glyphs already declared in `SECTIONS` finally render, on the card headers, and each header repeats that section's filled count beside the fields it counts (the jump strip keeps its own). **Exactly one `StatusDot`, on Product name** — the only required field; neutral dots on the thirteen optional ones would be decoration, and the header's `1/2` answers "what's still missing" at the right scale. The other five forms wear the same shape where there IS a group and skip it where there isn't: a **Details** card in `ScriptForm`, **Style** in `StyleForm`, **Voice** + **Delivery** in `VoiceForm` (mirroring the Voiceovers panel it edits presets for, Scene / Tone bare underneath), one card per DNA group in `ModelForm` (its headings were already the right shape, just left-aligned and unbordered), and no card at all around `BRollForm`'s lone prompt or the two big text boxes in Script and Style. A required field's `*` is now its dot; the save button moved into the header, because a slab pinned across the bottom of the field column read as the end of the form and hid the fact that it scrolls. `.scroll-fade-b` (index.css) fades a scroll port's bottom edge **only while there's more below** — a permanent fade is decoration, one that comes and goes is the affordance. Drop a photo (and optionally paste listing/product-page copy — authoritative for claims/specs/offer) to auto-fill via `extractProductInfo` (**`CHAT_MODEL_STRONG`, Gemini 3.6 Flash**, back on this tier in September 2026 after a stint on GPT 5.6 Luna for the cost — see the rewrite below, which turned this call into a fourteen-field research brief held to a long contract, which is the job that tier is kept for. Vision rides its `openai-chat` transport with the photo inline as an `image_url` part. **What to watch if it moves again:** `<READ>` is a verbatim OCR pass, so a thin read shows as small print missing from Proof rather than as worse prose, and the customer-voice fields are the first to slide back into market-segment language — judge it on a dense back-of-pack label, not a clean hero shot), re-runnable from the "Auto-fill" button. **The read outlives the form** (August 2026): the RUNNING promise is handed to `Finder.handleDetachExtraction` → `adoptDetachedExtraction` on the way out — from the X, and from the unmount, so closing the form and switching bank tab behave identically — and the result is written into the row the form was already autosaving into. Two things make that work. The form's `onAutosave` hands back the row **id** as well as the row, so `flushToRowId()` can flush what's unsaved and then name the product to write into; the id rides as a PROMISE (`rowIdRef`), because a detach arriving mid-save has to wait for that save rather than poll a ref until it fills in. And the file is encoded onto the form BEFORE the call starts, so there is never a window where a read is running against a product with no picture to land in. It used to hand over the FILE and re-run `saveProductDraft`, which billed the member a second time for one photo — and only from the X, so a bank-tab switch killed the read outright, which is what "I can't go to another tab without it stopping" was. If the member reopens that product while the read is still running, the landing bumps `Finder`'s `formSeed` and the open form re-seeds from the row — otherwise its next keystroke autosaves the pre-extraction copy straight over the result. **The read emits its own working notes first, and that is the whole anti-generic mechanism** (August 2026): the prompt used to say "work in two steps, do step 1 silently" — transcribe the packaging, inventory the object — and then "output ONLY the JSON object", which left the grounding pass instructed and structurally impossible, so the model wrote every field from what products in general are like. It now opens with a `<READ>` block (verbatim transcription of every word on the packaging, physical inventory, positioning, and the category's real buying criteria) that the parser slices off and throws away: its value is that it exists in context BEFORE the fields, so a spec can be checked against a label the model has already written down. **Output is tagged blocks, not JSON** — the fields are dense prose and five of them are newline-separated lists, which fights JSON string escaping the whole way (models compress inside JSON to protect the closing brace), and one stray character used to throw a whole extraction away at `JSON.parse`. It's read back with the shared tolerant reader `utils/xmlBlocks.ts` (the leaf half of B-Roll's parser, promoted out of `broll-studio/` once a second app needed it), which absorbs a missing closing tag instead of losing the block; `cleanLines` strips the bullet markers models add to a list despite instructions, since those go straight into the script prompt. Only both anchor fields coming back empty throws — that's a refusal or a wrong format, not a dropped tag, and overwriting the form with fourteen blanks would be worse than saying so. **The ban list, the worked examples and the per-field quotas all came back in September 2026, and the profile became a research BRIEF** — Massimo's call, written out as a spec and handed over ("now it's too vague"), reversing the August trim that took exactly those three things out. What replaced ten summary boxes is fourteen fields: the ten, minus Key Specs, plus **unique mechanism, current alternatives, not for, proof** and **before / after**. Three rules carry the weight. **Tier 1 / Tier 2** splits what may be read off the label (facts, exact numbers, never rounded) from what may be reasoned out of the category (audience, pain, alternatives, objections, benefits, before/after, hooks) — category truth is fair game at full confidence, brand truth is forbidden unless it is printed. **Five fields are written in the customer's own words** — first person, contractions, the moment it bites — with a banned-word list, two worked useless/usable pairs, and the test that a line has to be liftable into a script as a talking-head line. And a **bracketed placeholder is now reserved for a brand fact only the seller can supply** (price, guarantee, clinical number, review count): anywhere the model could write from the category, a bracket is a failure, which is what keeps the red wash below a short list of things that genuinely need the member. `<READ>` is unchanged and still what keeps it grounded. **A sixth new field, HOOK ANGLES — 6 to 8 ready-made openers — shipped with the brief and came out within the day**, and the reason is worth keeping: it was labelled as hard as anything in the Scripts prompt ("raw material for ONE opener, never a menu, never lifted verbatim") and that was not enough, because the failure is not disobedience — a list of finished openers is the most immediately usable thing in the prompt and it wins on availability. Reported from **Remix**, where it does the most damage: the source ad's hook was excellent and its SHAPE was the thing to adapt, and the take opened on a product hook angle instead, with the source's structure gone. Every other field in this brief is material a hook gets BUILT from; nothing here may arrive pre-built. **Every one of those placeholders is painted red in the form** (`BracketGrowArea` / `BracketInput`, `components/ExpandableText.tsx`, and the field's Expand modal passes `highlightBrackets`): the read deliberately leaves `[insert your clinical result]` wherever it had no fact, so the wash IS the list of what the member still has to write in — without it they're ten paragraphs of prose with the gaps buried inside them. The chrome (border, fill, radius) moves onto the WRAPPER so the field itself can be transparent over the mirror, which turns `focus:` into `focus-within:`; both layers take the same `padClass`/`textClass` so they wrap identically. The grow variant needs no scroll sync at all — nothing scrolls, `AutoGrowTextarea` sets the height and the mirror is `inset-0` of that same box — which is why it isn't `BracketHighlightArea`, whose fixed-height scroll port is the shape a prompt box needs. **`<CTA>` is the one field that may never hold a placeholder**: it's a spoken line, and a CTA that has to be filled in before it can be read stops the script. The prompt asks for the ordinary one ("Shop now", "I'll link it below") and `normalizeCta` enforces it — anything bracketed, multi-line, or over 44 chars is replaced with `Shop now` outright.

Three things were added in August 2026 after a product photo that simply never extracted. **Every image is downscaled to 1536px before the call** (`utils/visionImage.ts`, promoted out of `character-studio/utils/thumbnail.ts` — Characters had done this since it shipped and this surface never had): a listing photo is routinely 3000-6000px and rides in the body as base64, which is a third again on top of the file, and the model resamples to its own tile size regardless, so those megabytes were pure upload time charged against this call's timeout. **That is the WIRE copy only — the photo saved to the bank is the original file, byte for byte** (verified: a 4000px/8.1MB drop stores 4000px/8.1MB and sends 1536px). A product photo is a reference image that gets attached to real image and video generations, so it has to stay at full quality; the downscaled copy is a local inside `toVisionDataUri`, used once in the request body and dropped. Never write it back to the row. **A truncated answer is salvaged** rather than thrown away — this is the call site `TruncatedResponseError.partial` was written for, since the fourteen fields are independent and the block reader absorbs a missing closing tag; the anchor-field test is what keeps it honest. And a response with neither a name nor a description **retries once with a brevity override** (a shorter `<READ>`, fields at the short end of their range, reasoning dropped to medium), because that failure is the model spending its whole output budget on the transcription — asking for the same thing smaller is a genuinely different run, where re-rolling the identical call would not be. A hard error (no key, no credits, a refusal, a dropped connection) never reaches the retry. The failure is now **toasted through `humanizeError`**, not left to the inline `extractError`, which renders at the bottom of a scrolling column under four section cards — off screen on any normal window, so a two-word "Extraction failed" was the whole of what a member ever saw. The same sentence reaches a one-file grid drop, through `saveProductDraft`'s `onFinish` reason. An `Auto-fill / Photo only` toggle sat above the photo for a stint and was **removed August 2026** — one control, permanently on Auto-fill for nearly everyone, above the one thing on that column worth looking at; a photo attached without a read is still what you get whenever extraction fails, and the Auto-fill button under the picture is the way to run one later. **Every way of adding a photo goes through one gate** (`services/imageValidation.ts`: `imageRejectionReason` for a single file, `partitionImageFiles` for a batch) — the tile, the file picker, a drop, an extra angle, Bulk add. It **toasts** the reason and **names the format** ("AVIF isn't a supported image format — use JPG, PNG, or WebP"): the old inline `extractError` renders at the bottom of the field column below four section cards, i.e. off screen, so a rejected AVIF looked exactly like nothing happening — which is most of what "my product image won't show up" turned out to be. `accept` is a filter and not a guarantee, so the file picker is validated exactly like a drop is (it wasn't, and skipped the 10 MB cap entirely). Its other half is `REQUIRED_KEYS`, now **`productName` alone**: a name is what makes the row pickable, and gating Add on a description was gating it on the write-up the member had just declined. Only the name renders a `*`; every other field is optional, and the deep-context ones (`objections`, plus the five the September 2026 brief added) flow into the Scripts prompt, with `beforeAfter` also reaching B-Roll's. **Two fields have been removed over the life of this form and both follow the same rule — out of the type, the UI and every prompt, with the stored text left alone in the row's JSONB.** `customerLanguage` (voice-of-customer phrases) went in **July 2026** for duplicating what pain points already carry in the buyer's own words; it came back for one afternoon in September as part of the brief and went straight out again for the same reason. `keySpecs` (Key specs & facts) went in **September 2026**, its job absorbed by **Proof**, which lists the same checkable numbers and then says how much weight each one actually carries with a stranger — a spec list with no weighting was the field both Scripts and B-Roll had to spend a labelled instruction defending against. A product also carries up to four **extra angles** (`Product.extraImages`, "More Angles" strip under the hero shot) — the box open, what's inside, the label. They ride along in the same auto-fill vision call (one object, several shots — the prompt says so explicitly, so it never reads them as a bundle), and every **image-picking** BankPicker (`expandProductImages`: RefTiles / FrameSlot / VideoInputSlot / B-Roll's `ExtraRefsRow` / the Influencers edit modal) lists one tile per photo so a scene that needs the open box can attach the open box. Pickers that pick the *product itself* (B-Roll's product slot, Scripts) leave the flag off — they need the real row id. B-Roll picks **per scene** which of these photos each shot gets — see `services/productAngles.ts`.

## Searching a bank

The toolbar carries a **search box** (September 2026), the one thing a Finder window has that this one didn't. It is handled ONCE for all seven banks, and `bankRow.ts` is what makes that possible: `describeRow(bankType, item)` flattens any bank item into a title, a subtitle, a kind, a thumbnail ref, a date, its star, and a lowercased `search` haystack. Seven banks draw seven different cards because seven kinds of thing look different; the filter reads one description for all of them — so **adding a bank means adding one case there**, not a case per surface that drifts from the others. The haystack is deliberately wider than the title (a script's body, a b-roll's prompt, a swipe's transcript): what you remember about a script is a line IN it. Query terms are ANDed and order-free, so "glow serum" finds a row that calls itself "Serum, Glow Lab". A query that matches nothing gets its own **No matches** state, never the bank's empty state — an "Add your first product" button under a failed search reads as an empty bank when the tab beside it says 24.

The search **clears on every bank switch** (a query carried across tabs lands you on an empty grid whose tab reads a count), and hides while a form is open and while a bank is empty.

**A bank is a grid of cards, and only that.** A per-bank **grid / list switcher** shipped beside the search in September 2026 and came out the same month (Massimo's call): the argument for it was that a script and a voice preset are a name and a date wearing a card, so a wall of identical rectangles is the worst way to find one — but the answer to that is a better card, not a second way to draw the same rows plus a control asking which. What it actually cost was a whole parallel surface (`BankRows.tsx`, its column headers, its own sort wiring, its own swipe-detail open state in `BankList`) and a toggle in the toolbar that was fighting the bank switcher for width. Search is what finds a row now. Don't reintroduce it; the sort dropdown and the search box are the two lenses this screen has.

**Two tabs are day-grouped rather than dated card by card** — B-Rolls, and (September 2026) **Scripts**: a still is recognised by when it was shot and a script by the session it was written in, so both stack under `DayPill`s and the card drops the date it used to carry in its own footer. `dayGroupsOf` in `BankList.tsx` is the shared half and returns **null under a NAME sort**, which is the whole point of it: A→Z has no days to group by, so the grid goes flat and the dates come back. B-Rolls can't reach that branch (it sorts by date only); Scripts can. The same grouping is in `BankPicker` for both banks, because picking from a bank and browsing one are meant to read the same.

`BankSidebar.tsx` **travels**: `BankPicker` mounts the same component whenever a picker can reach more than one bank, which is why its icons come off `BANK_CONFIG` (Finder kept a second, identical table until September 2026) and why it takes a `showFrom` — `md` here, where it owns the window, and `lg` inside a modal that is already inset from the viewport.

**The banks moved off the top row and down the left** (`BankSidebar.tsx`, September 2026) — Finder's source list, and the fix for a real collision rather than a style note. The tab strip and the toolbar shared one 57px line: six tabs want ~820px, and once search joined the row the last tab scrolled off the end on a 1440px laptop. Everything tried to buy that width back was a tax on something else (a 140px search field, hiding **Bulk Add**'s label — reverted on sight, and rightly: the label is the button). Down the side the banks cost a fixed 204px, every bank is legible at once, and the toolbar has its whole line back for search, sort and the two buttons. The header's left slot is now the bank's NAME, which is also what gives that row a left edge.

Its geometry is **Characters' preset-picker rail**, deliberately: that rail shipped first, and a second one two pixels off it reads as sloppy. What it does not borrow is that file's local `RailRow` — it paints the Influencers accent, and it **disables a row whose count is zero**, which is right for a filter (nothing to scroll to) and wrong for a bank, since an empty bank is exactly the one you open to put the first thing in. Two more rules: the icons take the ROW's colour, never `BANK_CONFIG[bank].accent` — some of the seven are unreadable at any moment (Scripts' `#24365A` vanishes into a dark page; in light mode the gold fails instead) and seven accents down one column is a paint chart. And the rail is **`hidden md:flex`**: 204px is more than half a phone, so below `md` it doesn't render and the `SegmentedToggle` tab strip is still the switcher, in a header of three deterministic rows — tabs, then the buttons, then search on a row of its own (`order-last`). Search was a loose item under `flex-wrap` first, and at 375px the Products tab pushed Add onto a line of its own: four stacked rows on the screen with the least to give.

**A bank card draws a thumbnail, never the still** (September 2026). The Product, Character and B-Roll cards (and `BankItemCard`, so every picker) resolve their picture through `useThumbUrl`, sized to the card; each card's Download resolves the full picture itself through `getUrl`, and the forms behind the cards are unchanged. → root `docs/performance.md`.
