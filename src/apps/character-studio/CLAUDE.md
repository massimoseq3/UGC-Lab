# Influencers — `character-studio/`

Create section of UGC OS. This file loads when Claude works with files under `src/apps/character-studio/`; the app-wide rules stay in the root [CLAUDE.md](../../../CLAUDE.md).

## Job

Form → portrait image, or (Portrait / Influencer Sheet toggle) a multi-panel reference sheet (turnaround + expressions + full body; scene/pose/camera fields ignored; prompt layout swaps with orientation). **The Portrait / Sheet toggle picks the output kind ONLY** — resolution and aspect are shared across both modes and never reset by a flip (both used to, silently undoing a deliberate 4K or 9:16 pick and multiplying the credit cost); a sheet's grid needs a long axis, so 1:1 renders it vertically without touching the stored portrait aspect. Same rule in `InfluencerEditModal`'s Edit Character / Character Sheet toggle, which seeds both settings from the image being edited. Resolution defaults to 1K (key `:resolution:v3`). Sheets save as their own bank Model entry (named like a portrait; stamped as both `characterImage` and `sheetImage`). **Everything in a lineage saves under the source character's name** (`nameGenerator.ts`): the source portrait keeps the bare name, a sheet takes " - Character Sheet", an edit takes the visual style it was rendered in ("Mia - Claymation", off the row's `styleName` stamp) or the next free number ("Mia 2") — `uniqueBankName` dedupes against the bank so two variants can't be offered one name. An unsaved lineage's fallback name is **seeded on the lineage id**, so the modal and the gallery suggest the same person. Horizontal (16:9) outputs span a full row in the gallery, and in `BankPicker` a sheet spans both columns only when its image measures landscape (`onLandscape`) — a 9:16 sheet is a normal one-column tile. The gallery header's view toggle is **Single / List / Grid** (persisted, default Grid): **Single** shows only what's happening now — the running gen, else the newest character — floating on a graph-paper `Stage` (`.stage-grid`, edge-masked), over a row of named action pills and then a collapsed **Prompt data** JSON dropdown (Copy JSON), with a **+** in the header that empties the frame to "Awaiting generation" until a newer generation arrives (`clearedId`, keyed to the newest row's id, so it resets itself). It exists for screen recording, where a reel of past characters is on camera; nothing is deleted and the history is one toggle away. A running gen renders at the shape it will land in — the same `GeneratingTile` as everywhere else, wrapped in an accent glow (a scanning sweep over it was tried and cut: the drifting blobs already read as alive, and the sweep made a calm frame busy). `useFitFrame` sizes the frame to hug the image (aspect ratio + whichever axis runs out first), so the badge and the glow sit on the picture's own edges. Drop a reference photo anywhere to auto-fill every field via vision-based DNA extraction. **Every analysed photo lands in the reference library** (`useReferenceLibrary` + `ReferenceLibrarySlideOver`): the **Extract Character DNA** row opens it — the whole row, plus a chevron, exactly like the Load Character Preset row it sits beside — rather than a bare file dialog, since browsing, bulk-adding and reusing an old analysis all live in the panel (which has its own drop zone); dropping straight on the row still works. It's a right-edge slide-over that takes a **bulk** drop (3 at a time, `runPool`), lists each analysis day-grouped under a `DayPill` with its own DNA one-liner (`describeRefProfile`), and refills the form from any row on a click — so a face is analysed once, not once per session. A lone dropped photo still fills the form the moment it lands; a bulk drop never does — the member picks. The library is deliberately **local-only and thumbnail-only**: rows persist to localStorage (capped at 60, newest-first) carrying the extracted `profile` plus a ~224px JPEG data URI (`utils/thumbnail.ts`), because nothing re-sends a reference photo after its one vision call, and keeping the full-size original would mean an IndexedDB asset no bank row points at — which the orphan sweep deletes on the next sign-in. State lives in `CharacterStudio`, not the panel, so a batch keeps running with it closed; `activeRefId` (persisted) is the pointer the autofill pill and the library share, and clearing it detaches the reference without deleting the row (the library is history, so "New" leaves it alone). A row with neither a profile nor a live analysis failed — its Retry is offered only while the source file is still in session memory, since only the thumbnail survives a refresh. Display name rebranded from "Characters" — folder, ids, types, and LLM prompts keep the character naming.
