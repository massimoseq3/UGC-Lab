# Influencers — `character-studio/`

Create section of UGC OS. This file loads when Claude works with files under `src/apps/character-studio/`; the app-wide rules stay in the root [CLAUDE.md](../../../CLAUDE.md).

## Job

**One press can fire up to four characters** (`BatchCountStepper` in the generate bar, capped at 4, default 1) — a portrait is a casting call and the first face is almost never the one you keep, which until now meant pressing Generate four times and watching four separate charges tick past. The run fans out as N parallel `launchGen` calls sharing a `batchId` (with each member's `batchIndex`), stamped onto the in-flight entry AND carried onto the finished `characterHistory` row, because a batch's members land one at a time and the stage has to hold the group across that transition. Generate then **follows the run to the view that can show it**: a batch goes to Grid, a single character to Single — except when the member is already ON the Single stage, where it stays, since that's the view people record and being thrown out of it on every press would undo a deliberate choice. **The Single stage takes a LIST of slots, not one item**: 2 side by side, 3 side by side, 4 as a 2×2 (`stageGridClass`), each cell its own `FittedFrame` so a 16:9 sheet and a 9:16 portrait can share a row without either being letterboxed, and each cell swapping from `GeneratingTile` to the grid view's own `HistoryTile` (given a `frameStyle`, which switches its image to `object-contain` in a measured cell) as its member finishes. Slots are resolved by `batchKeyOf` — an unstamped gen is a group of one keyed by its own id, so nothing needs a "batch of 1" branch — and a **pinned** character is deliberately a single cell, because a pin is one face someone chose to have on camera rather than a run. Gens belonging to some other run are counted in the caption (`StageCaption`), never crowded onto the stage. `viewMode` lives in `CharacterStudio` (same localStorage key it always had) so Generate can move it; `GalleryPanel` is still memoized and both new props are stable.

Form → portrait image, or (Portrait / Influencer Sheet toggle) a multi-panel reference sheet (turnaround + expressions + full body; scene/pose/camera fields ignored; prompt layout swaps with orientation). **The Portrait / Sheet toggle picks the output kind ONLY** — resolution and aspect are shared across both modes and never reset by a flip (both used to, silently undoing a deliberate 4K or 9:16 pick and multiplying the credit cost); a sheet's grid needs a long axis, so 1:1 renders it vertically without touching the stored portrait aspect. Same rule in `InfluencerEditModal`'s Edit Character / Character Sheet toggle, which seeds both settings from the image being edited. Resolution defaults to 1K (key `:resolution:v3`). Sheets save as their own bank Model entry (named like a portrait; stamped as both `characterImage` and `sheetImage`). **Everything in a lineage saves under the source character's name** (`nameGenerator.ts`): the source portrait keeps the bare name, a sheet takes " - Character Sheet", an edit takes the visual style it was rendered in ("Mia - Claymation", off the row's `styleName` stamp) or the next free number ("Mia 2") — `uniqueBankName` dedupes against the bank so two variants can't be offered one name. An unsaved lineage's fallback name is **seeded on the lineage id**, so the modal and the gallery suggest the same person. Horizontal (16:9) outputs span a full row in the gallery, and in `BankPicker` a sheet spans both columns only when its image measures landscape (`onLandscape`) — a 9:16 sheet is a normal one-column tile. The gallery header's view toggle is **Single / List / Grid** (persisted, default Grid): **Single** shows only what's happening now — the running gen, else the newest character — floating on a graph-paper `Stage` (`.stage-grid`, edge-masked), over a row of named action pills and then a collapsed **Prompt data** JSON dropdown (Copy JSON), with a **+** in the header that empties the frame to "Awaiting generation" until a newer generation arrives (`clearedId`, keyed to the newest row's id, so it resets itself). It exists for screen recording, where a reel of past characters is on camera; nothing is deleted and the history is one toggle away. **Single shows the newest character by default, or a pinned one.** The `Frame` button in every grid tile / list row's action stack puts that character on the stage and switches the view there, so the click has a visible result; a `Newest` pill appears in the header to undo it. The pin (`ai-ugc-lab:influencers:single-pin`) stores the id it picked AND which row was newest at the time, so it **retires itself the moment a newer generation lands** — the same self-resetting trick as `clearedId`, and without it finishing a character and finding the stage still holding an older one reads as a failed generation. A pin whose row was since deleted falls through to the newest too. Every `SingleView` callback targets the item actually on the stage; they used to read `characterHistory[0]` directly, which was only ever the same row because the stage was always the newest one. **`InfluencerEditModal` wears the **`SectionCard`** its own controls column has worn since #437 (August 2026) — it was the one surface in this app that never got the shape lifted out of it. Its reference thumbnails and its visual style were two unlabelled affordances stacked on each other, which is why the add card had to pin `Optional` and its count into its own corners; now a **References** card carries both, with the add tile joined into the thumbnail grid (Playground's `RefTiles` shape) and the count on a `SectionLabel`. **Visual Style moved OUT of the prompt box**, where it had ridden as a header row "on top of whatever is typed below": B-Roll made the opposite call for its own style row a week later — the look is something the render is built FROM, like the reference photos — so the app was holding one of each, and the two now agree. No dots in that card: nothing in it gates Generate (the base image does, and it's on the right), so every dot there could only ever be green or neutral. **An in-flight tile is clickable everywhere**** (Single, grid, list) and opens the editor on the generation that is still running — waiting on a render just to reach the controls you were going to use on it was the whole friction. That works because `finishGen` writes the history row under **the generation's own id**, so `GalleryPanel` can anchor the editor by id (`previewId`, not a row snapshot) and the same anchor resolves to the pending gen first and the finished row on arrival, with no remount. `pendingItemFromGen` shapes the gen as the row it's about to become with an **empty `imageRef`**, which is the flag `InfluencerEditModal` reads to return NO outputs rather than a synthetic dead tile — that keeps Generate disabled until there's a base image, and the modal's own in-flight tiles are what's on screen meanwhile (its `lineageInFlight` matches `(g.lineageId ?? g.id)`, since a form gen carries no lineageId). A running gen renders at the shape it will land in — the same `GeneratingTile` as everywhere else, wrapped in an accent glow (a scanning sweep over it was tried and cut: the drifting blobs already read as alive, and the sweep made a calm frame busy). `useFitFrame` sizes the frame to hug the image (aspect ratio + whichever axis runs out first), so the badge and the glow sit on the picture's own edges. **Every finished row names the model that drew it** (`item.modelId` was always stored, and the in-flight tile already showed it — only the finished ones didn't): a hover-only label on the grid tile's bottom-left, clear of the action stack and stepping aside for the inline name input like the stack does; a line above the meta pills on the list row, the same shape `InFlightRow` uses so a row reads identically rendering or finished; and `Model · when` on the Single view's caption, the one place a stage holding a single character can state it outright. **The Load Character Preset / Extract Character DNA pair is a FIXED band** under the tab toggle, outside the scroll container entirely (August 2026). It was a `sticky top-0` child of the scroller, and sticky only pins once the scroll has started: at scroll-top the row sat in normal flow and every overscroll bounce floated it, so two rows that are panel chrome read as loose. A row that must never move doesn't belong inside the thing that moves — the scroller's mask now feathers both its edges instead of the row carrying its own gradient. `InfluencerEditModal`'s reference thumbnails are the shared 64px `ImageTile` / `AddTile` (`components/video/refInputParts`), not a four-up `grid` of `aspect-square` cells, which drew each one ~110px in that half-modal column. **The editor's outputs gallery is TWO across and day-grouped** (August 2026): it packed three to a row, but that column is half a modal, so the third tile cost every face the size it needed to be judged at — which is the only thing that gallery is for. It matches the main gallery's base grid now (`grid-cols-2`, landscapes spanning the row) and carries that gallery's `DayPill`s, so a lineage edited across several days reads in here the way it reads out there; `SessionOutput` gained the `createdAt` it needed to group by. Drop a reference photo anywhere to auto-fill every field via vision-based DNA extraction. **Every analysed photo lands in the reference library** (`useReferenceLibrary` + `ReferenceLibrarySlideOver`): the **Extract Character DNA** row opens it — the whole row, plus a chevron, exactly like the Load Character Preset row it sits beside — rather than a bare file dialog, since browsing, bulk-adding and reusing an old analysis all live in the panel (which has its own drop zone); dropping straight on the row still works. It's a right-edge slide-over that takes a **bulk** drop (3 at a time, `runPool`), lists each analysis day-grouped under a `DayPill` with its own DNA one-liner (`describeRefProfile`), and refills the form from any row on a click — so a face is analysed once, not once per session. A lone dropped photo still fills the form the moment it lands; a bulk drop never does — the member picks. **Every nested drop zone MUST `stopPropagation()`.** `CharacterStudio`'s root div carries a full-area drop handler that also calls `addFiles`, and React synthetic events travel the REACT tree (so a body-portaled `SlideOver` is still a child of it) — without the stop, one drop on the DNA pill or in the library ran `addFiles` twice: two rows, two vision calls, two charges on the member's key, and the form auto-filled twice. `addFiles` also keeps a short signature-keyed dedup window (`DOUBLE_FIRE_WINDOW_MS`) as belt-and-braces, since it is the entry every path shares and a vision call costs real credits. The library is deliberately **local-only and thumbnail-only**: rows persist to localStorage (capped at 60, newest-first) carrying the extracted `profile` plus a ~224px JPEG data URI (`utils/thumbnail.ts`), because nothing re-sends a reference photo after its one vision call, and keeping the full-size original would mean an IndexedDB asset no bank row points at — which the orphan sweep deletes on the next sign-in. State lives in `CharacterStudio`, not the panel, so a batch keeps running with it closed; `activeRefId` (persisted) is the pointer the autofill pill and the library share, and clearing it detaches the reference without deleting the row (the library is history, so "New" leaves it alone). A row with neither a profile nor a live analysis failed — its Retry is offered only while the source file is still in session memory, since only the thumbnail survives a refresh. Display name rebranded from "Characters" — folder, ids, types, and LLM prompts keep the character naming.
