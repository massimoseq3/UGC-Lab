# Influencers — `character-studio/`

Create section of UGC OS. This file loads when Claude works with files under `src/apps/character-studio/`; the app-wide rules stay in the root [CLAUDE.md](../../../CLAUDE.md).

## Job

**One press can fire up to four characters** (`BatchCountStepper` in the generate bar, capped at 4, default 1) — a portrait is a casting call and the first face is almost never the one you keep, which until now meant pressing Generate four times and watching four separate charges tick past. The run fans out as N parallel `launchGen` calls sharing a `batchId` (with each member's `batchIndex`), stamped onto the in-flight entry AND carried onto the finished `characterHistory` row, because a batch's members land one at a time and the stage has to hold the group across that transition. Generate then **follows the run to the view that can show it, but only ever TOWARDS the grid**: a batch fired from the list goes to Grid, and everything else stays where the member already was — including the Single stage, which is the view people record on, so being thrown out of it on every press would undo a deliberate choice. It used to pull a run of ONE onto that stage, which meant Single was the view members actually sat in whatever the toggle's default said; **the grid is the view** (Massimo's call, August 2026) and only the `Frame` button and the toggle put anyone on the single stage now. **The Single stage takes a LIST of slots, not one item**: 2 side by side, 3 side by side, 4 as a 2×2 (`stageGridClass`), each cell its own `FittedFrame` so a 16:9 sheet and a 9:16 portrait can share a row without either being letterboxed, and each cell swapping from `GeneratingTile` to the grid view's own `HistoryTile` (given a `frameStyle`, which switches its image to `object-contain` in a measured cell) as its member finishes. Slots are resolved by `batchKeyOf` — an unstamped gen is a group of one keyed by its own id, so nothing needs a "batch of 1" branch — and a **pinned** character is deliberately a single cell, because a pin is one face someone chose to have on camera rather than a run. Gens belonging to some other run are counted in the caption (`StageCaption`), never crowded onto the stage. `viewMode` lives in `CharacterStudio` (same localStorage key it always had) so Generate can move it; `GalleryPanel` is still memoized and both new props are stable.

The Physical tab reads **Identity → Face & Skin → Eyes → Hair → Wardrobe**: skin and realism is what decides whether a render reads as a photograph at all, so it's the group a member fills first rather than the one they reach past eye shape and hair texture (August 2026). Form → portrait image, or (Portrait / Influencer Sheet toggle) a multi-panel reference sheet (turnaround + expressions + full body; scene/pose/camera fields ignored; prompt layout swaps with orientation). **The Portrait / Sheet toggle picks the output kind ONLY** — resolution and aspect are shared across both modes and never reset by a flip (both used to, silently undoing a deliberate 4K or 9:16 pick and multiplying the credit cost); a sheet's grid needs a long axis, so 1:1 renders it vertically without touching the stored portrait aspect. Same rule in `InfluencerEditModal`'s Edit Character / Character Sheet toggle, which seeds both settings from the image being edited. Resolution defaults to 1K (key `:resolution:v3`). Sheets save as their own bank Model entry (named like a portrait; stamped as both `characterImage` and `sheetImage`). **Everything in a lineage saves under the source character's name** (`nameGenerator.ts`): the source portrait keeps the bare name, a sheet takes " - Character Sheet", an edit takes the visual style it was rendered in ("Mia - Claymation", off the row's `styleName` stamp) or the next free number ("Mia 2") — `uniqueBankName` dedupes against the bank so two variants can't be offered one name. An unsaved lineage's fallback name is **seeded on the lineage id**, so the modal and the gallery suggest the same person. Horizontal (16:9) outputs span a full row in the gallery, and in `BankPicker` a sheet spans both columns only when its image measures landscape (`onLandscape`) — a 9:16 sheet is a normal one-column tile. The gallery header's view toggle is **Single / List / Grid** (persisted, default Grid): **Single** shows only what's happening now — the running gen, else the newest character — floating on a graph-paper `Stage` (`.stage-grid`, edge-masked), over a row of named action pills and then a collapsed **Prompt data** JSON dropdown (Copy JSON), with a **+** in the header that empties the frame to "Awaiting generation" until a newer generation arrives (`clearedId`, keyed to the newest row's id, so it resets itself). It exists for screen recording, where a reel of past characters is on camera; nothing is deleted and the history is one toggle away. **Single shows the newest character by default, or a pinned one.** The `Frame` button in every grid tile / list row's action stack puts that character on the stage and switches the view there, so the click has a visible result; a `Newest` pill appears in the header to undo it. The pin (`ai-ugc-lab:influencers:single-pin`) stores the id it picked AND which row was newest at the time, so it **retires itself the moment a newer generation lands** — the same self-resetting trick as `clearedId`, and without it finishing a character and finding the stage still holding an older one reads as a failed generation. A pin whose row was since deleted falls through to the newest too. Every `SingleView` callback targets the item actually on the stage; they used to read `characterHistory[0]` directly, which was only ever the same row because the stage was always the newest one. **`InfluencerEditModal` wears the **`SectionCard`** its own controls column has worn since #437 (August 2026) — it was the one surface in this app that never got the shape lifted out of it. Its reference thumbnails and its visual style were two unlabelled affordances stacked on each other, which is why the add card had to pin `Optional` and its count into its own corners; now a **References** card carries both, with the add tile joined into the thumbnail grid (Playground's `RefTiles` shape) and the count on a `SectionLabel`. **Visual Style moved OUT of the prompt box**, where it had ridden as a header row "on top of whatever is typed below": B-Roll made the opposite call for its own style row a week later — the look is something the render is built FROM, like the reference photos — so the app was holding one of each, and the two now agree. No dots in that card: nothing in it gates Generate (the base image does, and it's on the right), so every dot there could only ever be green or neutral. **Every finished tile carries a `←` Reuse Prompt action** — the grid tile's and list row's `⋮` menus and the Single view's pill row — putting that character's parameters back in the form (August 2026). It sits **directly after Copy Prompt** in all three, because it's the same object headed somewhere else: copy puts the parameters on the clipboard, reuse puts them in the column on the left, and the arrow points at where they land. It is the gallery half of the `{ }` box on that column — one takes a prompt out and back in through text, this one skips the text. `handleReuseProfile` (in `CharacterStudio`, so it's stable for the memoized panel) overlays the row's snapshot on a fresh `createEmptyProfile()` rather than setting it directly, so a row written before a field existed leaves that field blank instead of absent; it detaches the active reference photo for the same reason "Clear all" does, and on a phone it flips to the Controls pane — the mirror of Generate flipping to Gallery, without which a tap looks like nothing happened. Resolution and the Portrait/Sheet toggle are deliberately NOT restored (they're the member's current cost settings, and quietly moving someone to 4K multiplies what the next press charges); the aspect ratio rides along because it's part of the profile snapshot and is a shape rather than a price. **The grid tile and the list row keep FOUR controls and put the rest behind a `⋮`** (`TileMenuButton` / `TileMenuItem`, September 2026, Massimo's call): the tile stack reads Download · Save · Edit · Delete · ⋮, the list row Download · Save · Delete · ⋮, and the menu spells out **Copy Prompt · Reuse Prompt · Show in Single View · Make Character Sheet** (plus **Edit Image** in the list, which has no room for a fifth circle) in Title Case beside their glyphs. Seven unlabelled circles down a tile was a column you had to hover to read — a copy page, a left arrow, a frame and a grid all learned from tooltips — and on the list row it was worse than illegible: that panel is a quarter of a half-pane, so the line gets 155px at a 1084px window and seven ~28px buttons want 178. Both ways of exceeding that lose a button *silently* — `flex-nowrap` inside the row's `overflow-hidden` cut **Delete** off on every portrait row under about a 1350px window, and wrapping instead pushes the second line past the panel's own bottom edge where the same clip eats it. Four fit; the wrap stays as the backstop. Two things the ⋮ needs that are easy to miss: its open state lives with the CALLER (the stack has to be held visible while the pointer is over the menu rather than the tile), and on the list row it and `TileDeleteButton` both take the **always-visible** skin — that row is not a `group`, so the default hover fade never comes back, which is how the list-row Delete had been `opacity-0` at every width. **An in-flight tile is clickable everywhere**** (Single, grid, list) and opens the editor on the generation that is still running — waiting on a render just to reach the controls you were going to use on it was the whole friction. That works because `finishGen` writes the history row under **the generation's own id**, so `GalleryPanel` can anchor the editor by id (`previewId`, not a row snapshot) and the same anchor resolves to the pending gen first and the finished row on arrival, with no remount. `pendingItemFromGen` shapes the gen as the row it's about to become with an **empty `imageRef`**, which is the flag `InfluencerEditModal` reads to return NO outputs rather than a synthetic dead tile — that keeps Generate disabled until there's a base image, and the modal's own in-flight tiles are what's on screen meanwhile (its `lineageInFlight` matches `(g.lineageId ?? g.id)`, since a form gen carries no lineageId). A running gen renders at the shape it will land in — the same `GeneratingTile` as everywhere else, wrapped in an accent glow (a scanning sweep over it was tried and cut: the drifting blobs already read as alive, and the sweep made a calm frame busy). `useFitFrame` sizes the frame to hug the image (aspect ratio + whichever axis runs out first), so the badge and the glow sit on the picture's own edges. **It follows the DECODED file, not the requested ratio** (`useNaturalRatio`, read off the `<img>`'s `naturalWidth/Height` on load; the requested string is only the shape held before a picture exists). The two are routinely different — the picker offers 9:16 / 16:9 / 1:1 and GPT Image 2 answers a 9:16 request with a 1024×1536 file — and `ratioOf` maps every non-16:9, non-1:1 string to 9:16, so a portrait sat `object-contain` in a frame 18% too tall and `bg-black light:bg-zinc-200` painted the letterbox as a pale bar above and below the character. Both fitted surfaces do it: `SingleCard` inline, and the multi-slot stage through `StageCell`, which owns the state its `HistoryTile` reports into (`onNaturalRatio`). The unfitted grid tile never had the bug — it's `block h-auto w-full` and hugs its own image. **The grid tile and the list row render the portrait's THUMBNAIL** (`useHistoryTileActions`' `full` flag off, September 2026 — `utils/mediaThumbs.ts`), and only the fitted Single-stage tile and `SingleCard` read the original: a wall of 4K portraits re-decoded on every scroll back was what made the gallery go black-then-appear on the way up. Downloads always re-resolve the original. **Every finished row names the model that drew it** (`item.modelId` was always stored, and the in-flight tile already showed it — only the finished ones didn't): a hover-only label on the grid tile's bottom-left, clear of the action stack and stepping aside for the inline name input like the stack does; a line above the meta pills on the list row, the same shape `InFlightRow` uses so a row reads identically rendering or finished; and `Model · when` on the Single view's caption, the one place a stage holding a single character can state it outright — sitting **directly under the picture** in dim `ink-600`, not at the foot of the card under Prompt data, where it was a lone line of chrome holding the panel's bottom gap open and a caption three controls away from its subject. **`SingleCard` is keyed on its item**, like the multi-slot branch beside it: the stage swaps the character rather than unmounting the card, so without it `TileDeleteButton`'s internal two-click ARMED state carried over and the next character opened already armed. Its `useHistoryTileActions` `deleting` flag is scoped to the item id for the same reason and is the bug that made this visible — `confirmDelete` deliberately leaves it SET on success (the tile is about to disappear with its row, and clearing it would flash the button back to life on the way out), which is only safe while the tile actually unmounts; as a bare boolean on the Single stage it stayed true against the row that replaced it, and the `if (deleting) return` guard then refused every further delete behind a spinner that never stopped. **The Load Character Preset / Extract Character DNA pair is a FIXED band** under the tab toggle, outside the scroll container entirely (August 2026). **A third control rode that band and is GONE** — `PromptJsonModal`, a `{ }` square opening the whole character as one editable JSON box, removed September 2026 (Massimo's call: a third prompt tool in a band that already had two, and clutter). Its copy half survives as **one glyph-only Copy circle on the panel header bar**, beside the tab toggle — the whole prompt (`buildImagePrompt`, the union of the two scoped `CopyPromptButton`s on the tab dividers) in one click, which is why it sits on the panel's own bar rather than on a divider that belongs to one tab. Its PASTE half went with the button: `fieldsFromPromptJson` is still exported beside `buildImagePrompt` and nothing calls it, kept on purpose because the door was removed and not the room — the parser is tolerant about SHAPE and strict about KEYS (this app alone emits three section layouts over the same fields, and a member pasting from an LLM makes a fourth; section names are walked through and discarded, only keys the form owns are taken, and a stray `layout` / `direction` / note is ignored rather than refused), which is the expensive half to rewrite. Read git history for the box itself before rebuilding one. The two rows left keep their **three label tiers** (`Preset` / `Extract` below `sm`, then the full names): the third control is what made them necessary, and with the band back to two they simply have room to spare — a shorter label at phone width is still the right label, not a bug to undo. It was a `sticky top-0` child of the scroller, and sticky only pins once the scroll has started: at scroll-top the row sat in normal flow and every overscroll bounce floated it, so two rows that are panel chrome read as loose. A row that must never move doesn't belong inside the thing that moves — the scroller's mask now feathers both its edges instead of the row carrying its own gradient. **That row opens `PresetPickerModal` — a CENTRED modal over one scrolling grid, not the 380px right slide-over it was** (August 2026), and the two scoped pills further down the column (`Physical Presets` / `Scene & Pose Presets`) open the same component with their own title, merging only their tab's keys. Its geometry is now the app's shared picker shape — `BankPicker` was rebuilt onto it in September 2026, rail and all — and it arrives on `.modal-pop` (see the root CLAUDE.md); a **`subtitle` is the scoped callers' alone**, naming which part of the form a pick fills. The unscoped one read "Pick a recipe to fill the form" under "Character Presets", which is the title said twice, and is gone (Massimo's call). **Every SECTION TITLE is the same button one level finer** (August 2026): Identity, Face & Skin, Eyes, Hair, Wardrobe, Pose & Action, Camera and Setting each open the picker scoped to that group's own keys, so a member who likes one template's hair and another's wardrobe can take exactly that rather than the whole recipe or the whole tab. One `PresetPillButton` serves both altitudes through a `tone`: the tab divider keeps the glassy **influencers** tint (it's the line that separates two tabs and has to stay louder than the eight headings under it), and a section title is **neutral ink** — Massimo's call — keeping the heading's own `text-sm font-semibold` and borrowing only the chrome that says *button*, the dashed ring and the chevron. State is the `FieldGroup` being picked for, not a flag per group, and the modal is mounted only while one is open, so a group added to `TABS` gets its own picker with no wiring; `applyScopedPreset`'s `cameraDevice` guard is what keeps the Camera group's pick from blanking the always-on photorealism string. A slide-over is the wrong shape for a picture library: three faces across meant the starters alone ran past a screen, and a member's own characters were only reachable by scrolling past every built-in. The modal gets five or six across at a size a face is still judgeable at (see the rail note below for the exact widths) and pages the grid in on scroll (`PAGE = 30`, grown from the scroller's own `onScroll` rather than an IntersectionObserver sentinel — the arithmetic is two subtractions and can be watched without a second async system in the middle) so a few hundred image decodes don't mount on open. Card names are **centred**, like every other bank card in the app (`ImageCard`'s own `centerName`) — they were the one left-aligned label. **A card is named `<Scene> <Gender> <n>`** — "Kitchen Female 2" — built by the build script and numbered within its scene + gender group. The export's own descriptive name ("Braided Blonde on the Sofa") describes the picture you can already see; what the label has to say is where this one sits in a library you scan by scene, which is also what the rail files it under. That name survives as `title`: it's the card's tooltip (with the shot note after it) and it's in the search haystack, so "braided blonde" still finds her. Search covers the whole DNA besides, so "freckles" and "wood slat wall" find the character they describe. **The two libraries are ONE scroll, in labelled sections** (Massimo's call, August 2026): your own characters, then the template library **grouped by style** — "Handheld Mic", "Car", "Kitchen" — one `DayPill` per group, in the library's own order. Splitting on a change of key rather than bucketing is what lets a group page in behind the rows above it. Your own characters stay a SINGLE group: their style is keyword-guessed off free text and plenty of rows have none, so grouping those would file the same face under a different heading each time it was extracted. They were a toggle that swapped the grid for a week, on the theory that a member with 35 characters shouldn't scroll past all of them to reach a template — the jump below is the cheaper answer to that, and it keeps everything the picker holds in one list you can simply keep scrolling. **Navigating that scroll is a left RAIL — the table of contents of the grid** (Massimo's call, August 2026), in two labelled blocks: **Library** (Your Characters / Templates) then **Style** (All Styles, then every style the templates are filed under). Every row does ONE thing — it scrolls to that section — and every row's highlight means ONE thing: where you are. It follows the scroll, the way the Ad Analyzer's section toggle follows its read, so the rail can never disagree with what's on screen (`handleScroll` walks the rendered sections and takes the last whose heading has passed `SPY_OFFSET` below the port's top; tops only increase, so it stops at the first one still below). Two shapes were tried on the way here and both were worse: the styles as a `Dropdown` on the filter bar — eleven options behind a click, on a panel whose whole job is browsing — and then a rail that FILTERED, which reads as a set of tabs and hides the ten other looks the moment you glance at one. Navigating costs nothing the filter saved, because the section a jump lands on is the same handful of cards the filter would have left, and the rest of the library is still one scroll away. Search and gender stay real filters on the bar above the grid, because they cut ACROSS the sections rather than picking one. A jump raises the page count to cover its target's index first (taken off `filtered`, which knows the whole list, rather than off the DOM) and then waits a frame for React to lay the rows out — `scrollTop` set against a list that hasn't grown yet just clamps to the old bottom — and the measure RETRIES for a few frames rather than firing blind, since a jump that measured against nothing would scroll to the end. Everything is measured with `getBoundingClientRect`, never `offsetTop` (`sectionTopWithin`): the scroller isn't a positioned element, so a section's `offsetTop` is counted from the modal panel and carries the header + filter bar with it — about a row of cards' worth of error, which is exactly how far the jump used to overshoot. The tracker holds a section KEY, and an unknown one (a search retired that section) falls back to the first rendered section — which is what the top of a re-filtered list means, and is also why an empty bank needs no special case: its section simply isn't there to be scrolled into. A row whose count is 0 has nowhere to go and is **disabled and dimmed** rather than dropped, since a vanishing row would move the rest of the rail under the pointer. The panel is **`max-w-6xl`** and the grid **five across, six at `xl`**, so a card stays ~142px beside a 204px rail — the size a face is still judgeable at, which is what six across at `max-w-5xl` was buying. **Below `lg` there is no room for a rail beside a grid of faces**, so the same two controls ride the bar: the `SegmentedToggle` (Your Characters — "Yours" below `sm`, where the full wording truncated — / Templates) and the style `Dropdown`, which is the rail's Style block as a menu, one option per section, jumping exactly as the rows do and reading the section you're in because the spy owns its value. **Mount the picker only while it's open** — every caller does, and the page count and the rail's highlight are per-opening because of that, with no effect resetting anything; left mounted behind `open={false}` it kept both while its scroller (a new element each time) started at the top, so the rail lit the section you left off in while the grid showed the first. Narrowing the list (search or gender) resets the page count AND the scroll, or a filter applied after scrolling to card 200 renders 200 cards of a 12-card result. **One facet on the bar beside the search box: Gender, as a `SegmentedToggle`** — three options, all worth seeing without a click, counted against search alone so a library that grows keeps its own tallies. The rail's counts are the SIZE OF THE SECTION each row scrolls to (a style's own templates; your characters are one section of their own whatever their style, and "All Styles" carries the whole list, which is what the top of it holds), tallied under search and gender, so a count can never promise more than the grid delivers. The rows call that field `setting` and always will — it's the build script's own word for the shot category — but the member's word for it is **Style** (Massimo's call, August 2026): "Handheld Mic" and "Talking Head" are how a shot is shot, not where it is, and the two the library really does name by place (Kitchen, Car) are still styles of UGC ad. `styleOrder` is built from the TEMPLATES only: a style is a place in the list now, and a bank-only style (keyword-guessed off free text) would be a row that scrolls nowhere. **Shot type (Close-up / Medium / Full body) was a third facet and was cut**: a starter is picked by who and where, and three framings across the library mostly shrank the grid without answering anything. **Nothing may move when you use it**, which takes three rules, all of them reported before they were found. Every count renders in a fixed-width `CountSlot` (`min-w-[2ch]` + `tabular-nums`), because a live count going from "All 76" to "All 9" takes ~5px with it and slides every segment to its right — in the rail that would shift a row's own label under the pointer. The phone's style trigger takes a **fixed 190px** rather than fitting its content, because its label swings from "All Styles" to "Holding Product" and a self-resizing trigger shoves the gender toggle along the row on every pick. And the styles keep the **library's own order** (the source folder's shot numbering, baked into the row order by the build script) rather than sorting by count, which would reshuffle the rail every time a search changed the tallies. Every row always renders, including at zero — a vanishing one moves the ones under it, and a count of 0 answers "why is there nothing there" before you click it. **The panel is `z-[60]`, not the `z-[70]` a picker would normally take.** `AnchoredPopover` portals every menu in the app at `z-[60]` over a `z-[55]` catcher — the lowest overlay tier, since its job is escaping a scrolling panel's clip, not covering a modal — so at `z-[70]` this panel painted over its own style menu, which is what "the dropdown opens behind the modal" was. Sharing the tier lets DOM order decide and the menu, appended to the body later, wins: the same arrangement `InfluencerEditModal` and its chips rely on. The style menu is exactly such a menu, so the tier is load-bearing — don't raise it. Gender is **bucketed** rather than matched (`genderBucket`), because a bank row's profile is free text and a facet built from raw values lists two spellings of one thing; a bank row's style is keyword-matched off its `location` + `background`, which is a guess, but a guess that files it under the right style more often than not filing it at all. The **starters are static files** — `public/presets/library.json` built by `scripts/build-character-presets.py`, fetched on first open and never before (nothing pays 252KB for a picker that isn't used) — and the nine `PRESET_*` consts they replaced are gone from `types.ts` along with their bundled JPEGs. Their pictures ship in **two tiers**, and the split is load-bearing. The cover was 400px on its long edge and came out **223x400**, against a card that is ~155 CSS px wide — 310 device px on the 2x screens these are looked at on — so every face in the library was upscaled from a picture smaller than the hole it sat in; it was reported as simply looking low quality, and `thumbs/` is 502x900 at q80 (~37KB) now. `full/` is the source's own 768x1376 at q85, and it is fetched **only when a member saves that template**, which is why the grid doesn't pay its ~105KB a card. **Templates become bank rows, and that is how they reach every other app** (`saveStarterToBank`, August 2026): until then a member could load a face into the form and still not attach that face anywhere — the DNA travelled and the picture didn't. A bank row is the app's own answer to "use this character elsewhere", so saving puts the full portrait in IndexedDB (mirrored to R2) under a real `Model`, pickable in Playground, B-Roll and Scripts by the route a generated character already takes. **Two ways in.** Here, a `TileActionStack` on the card saves it outright. Everywhere else, **`BankPicker` offers the whole library inside its characters bank** (Massimo's call, August 2026 — "use the templates just as I would my own characters"): the unsaved ones render as stand-in `Model`s under the same style headings, and PICKING one writes it in and hands the caller the row it just became, so nothing downstream ever receives a `Model` whose `characterImage` is a static URL it can't keep. That picker carries **a bucketed Gender toggle and the same Style rail this one has**, both counted against the other and both covering the member's own rows as well as the templates — it fits the rail because it is a centred modal too now, and below `lg` a `Dropdown` stands in for it exactly as here — and that menu is the one caller of `Dropdown`'s `tier="panel"`, because `AnchoredPopover` defaults to the app's LOWEST overlay tier and the picker's panel is `z-[80]`: at the default tier the trigger visibly opened onto nothing. `flattenJsonProfile`, `genderBucket`, `settingFromProfile` and `buildSearch` all live in `presets/service.ts` so the two pickers facet and search by one copy. The row stamps **`Model.presetId`**, which is what draws the green tick on a template already saved — matching on the name can't, since the member is free to rename it afterwards — and the bank name is the export's descriptive `title` ("Braided Blonde on the Sofa"), not the card's "Handheld Mic Female 1": in a bank of characters a scene-and-index label says nothing about which face it is. The rule those nine were written to demonstrate still governs anything added to that folder: every field filled, and the DETAILED option wherever the field offers one. `InfluencerEditModal`'s reference thumbnails are the shared 64px `ImageTile` / `AddTile` (`components/video/refInputParts`), not a four-up `grid` of `aspect-square` cells, which drew each one ~110px in that half-modal column. **The editor's outputs gallery is TWO across and day-grouped** (August 2026): it packed three to a row, but that column is half a modal, so the third tile cost every face the size it needed to be judged at — which is the only thing that gallery is for. It matches the main gallery's base grid now (`grid-cols-2`, landscapes spanning the row) and carries that gallery's `DayPill`s, so a lineage edited across several days reads in here the way it reads out there; `SessionOutput` gained the `createdAt` it needed to group by. Drop a reference photo anywhere to auto-fill every field via vision-based DNA extraction. **Every analyzed photo lands in the reference library** (`useReferenceLibrary` + `ReferenceLibraryModal`): the **Extract Character DNA** row opens it — the whole row, plus a chevron, exactly like the Load Character Preset row it sits beside — rather than a bare file dialog, since browsing, bulk-adding and reusing an old analysis all live in the panel (which has its own drop zone); dropping straight on the row still works. It's a `Modal` that takes a **bulk** drop (3 at a time, `runPool`), holding the full 86vh only once the list is long enough to carry its search box, lists each analysis day-grouped under a `DayPill` with its own DNA one-liner (`describeRefProfile`), and refills the form from any row on a click — so a face is analyzed once, not once per session. A lone dropped photo still fills the form the moment it lands; a bulk drop never does — the member picks. **Every nested drop zone MUST `stopPropagation()`.** `CharacterStudio`'s root div carries a full-area drop handler that also calls `addFiles`, and React synthetic events travel the REACT tree (so a body-portaled `Modal` is still a child of it) — without the stop, one drop on the DNA pill or in the library ran `addFiles` twice: two rows, two vision calls, two charges on the member's key, and the form auto-filled twice. `addFiles` also keeps a short signature-keyed dedup window (`DOUBLE_FIRE_WINDOW_MS`) as belt-and-braces, since it is the entry every path shares and a vision call costs real credits. The library is deliberately **local-only and thumbnail-only**: rows persist to localStorage (capped at 60, newest-first) carrying the extracted `profile` plus a ~224px JPEG data URI (`utils/thumbnail.ts`), because nothing re-sends a reference photo after its one vision call, and keeping the full-size original would mean an IndexedDB asset no bank row points at — which the orphan sweep deletes on the next sign-in. State lives in `CharacterStudio`, not the panel, so a batch keeps running with it closed; `activeRefId` (persisted) is the pointer the autofill pill and the library share, and clearing it detaches the reference without deleting the row (the library is history, so "Clear all" leaves it alone). A row with neither a profile nor a live analysis failed — its Retry is offered only while the source file is still in session memory, since only the thumbnail survives a refresh. Display name rebranded from "Characters" — folder, ids, types, and LLM prompts keep the character naming.
